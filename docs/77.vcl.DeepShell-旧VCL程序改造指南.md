# DeepShell 旧 VCL 程序改造指南

> audience: ai, developer
> status: design-contract

## 1. 改造原则

旧程序改造不要一次性重写业务。先把基础设施迁到 DeepShell，再逐步迁业务视图。

顺序：

```text
主窗体结构
Command
MRU / Layout
Settings
日志 / 状态
Provider
Governance
```

## 2. 识别现有区域

先在旧主窗体中标出：

```text
菜单
工具栏
左侧树
右侧属性
主工作区
底部日志
状态栏
设置窗体
最近文件
```

然后映射到 DeepShell：

```text
菜单/工具栏 -> Command Surface
左侧树 -> StructureWindow + StructureProvider
右侧属性 -> InspectorWindow + InspectorProvider
主工作区 -> MainHost + MainViewProvider
底部日志 -> Bottom Area + StatusManager
设置窗体 -> SettingsHost + SettingsPageProvider
最近文件 -> RecentService
窗口位置 -> LayoutService
```

## 3. 迁移主窗体

旧：

```pascal
TFormMain = class(TForm)
```

新：

```pascal
TFormMain = class(TDeepMainForm)
```

先保留旧业务 Frame，把它挂入 `MainHost`。不要马上拆业务逻辑。

## 4. 迁移菜单和按钮

旧：

```pascal
procedure TFormMain.btnDeleteClick(Sender: TObject);
begin
  DeleteSelected;
end;
```

新：

```pascal
Commands.RegisterCommand(
  ShellCommand('app.delete', 'Delete')
    .RiskLevel(3)
    .GateKey('app.delete_gate')
    .OnExecute(DeleteSelected));
```

按钮只绑定命令，不直接执行业务。

## 5. 迁移 MRU

旧程序常见问题：

- 最近文件写 INI。
- 最近项目写 JSON。
- 窗口状态分散在多个地方。

改造后：

- 最近项目进入 RecentService。
- 窗口和折叠进入 LayoutService。
- 正式应用通过 SettingsStore / DB1 保存。

## 6. 迁移设置窗体

旧设置窗体不要整体塞进 DeepShell 核心。改成多个 `ISettingsPageProvider`：

```text
GeneralPageProvider
DatabasePageProvider
LLMPageProvider
BusinessRulesPageProvider
```

Shell 只负责显示设置宿主和 OK / Apply / Cancel。

## 7. 迁移日志

旧：

```pascal
MemoLog.Lines.Add(...)
```

新：

```pascal
Status.Info(...);
Status.Warning(...);
Status.Error(...);
Status.Progress(...);
```

底部输出区统一显示。

## 8. 迁移结构树

旧树节点如果绑定业务对象指针，要改成 `TShellObjectRef`：

```text
Node.Data = TShellObjectRef
```

Provider 内部再用 Id 查真实对象。

## 9. 分阶段验收

第一阶段：

- 旧业务仍能运行。
- 主窗体继承 `TDeepMainForm`。
- 三段折叠和布局恢复可用。

第二阶段：

- 菜单和工具栏迁到 Command。
- MRU 和设置迁到 Shell 服务。

第三阶段：

- 结构树、主视图、探查器迁到 Provider。
- 高风险命令接 Governance observe。

## 10. 禁止事项

- 不要一次性删除旧业务逻辑。
- 不要把旧窗体所有控件塞进 Shell 核心。
- 不要保留按钮直接执行高风险操作。
- 不要继续散落写 INI / JSON / YAML。
- 不要让旧树节点保存裸业务对象指针。
