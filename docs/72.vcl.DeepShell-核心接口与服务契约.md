# DeepShell 核心接口与服务契约

> audience: ai, developer
> status: design-contract

## 1. 设计原则

DeepShell 通过接口接入下游能力。Shell 核心只依赖契约，不直接依赖业务对象、数据库实现、LLM、WebView2 或 Governance 具体单元。

核心规则：

- Shell 不持有业务 `TObject`。
- Shell 使用稳定引用 `TShellObjectRef`。
- 所有服务通过 `IShellServiceRegistry` 注册。
- 所有 UI 操作通过 Command。
- 所有跨模块通信通过 EventBus。

## 4. Command

```pascal
TShellCommand = record
  Id: string;
  Caption: string;
  Hint: string;
  Category: string;
  ShortcutText: string;
  Visible: Boolean;
  Enabled: Boolean;
  Checked: Boolean;
  CapabilityId: string;
  GateKey: string;
  RiskLevel: Integer;
  PurposeKey: string;
end;

IShellCommandManager = interface
  procedure RegisterCommand(const ACommand: TShellCommand);
  procedure Execute(const ACommandId: string);
  procedure UpdateCommandState(const ACommandId: string; AEnabled, AVisible: Boolean);
end;
```

实际实现可使用 callback 或 command handler 注册。所有菜单、工具栏、右键菜单、快捷键必须绑定 Command。

`TShellCommand` 是 record。注册时 CommandManager 保存的是值拷贝。注册后不要修改原始 record 期待 UI 自动更新；运行时状态变更必须通过 `IShellCommandManager.UpdateCommandState` 或等价的 command state API 完成。

### 4.1 ShellCommand builder

文档示例中出现的 `ShellCommand(...)` 是建议提供的 fluent builder，不是 Delphi 内建语法。实现 DeepShell MVP 时必须二选一：

1. 提供 `TShellCommandBuilder` 和 `ShellCommand` 工厂函数。
2. 不提供 builder，并把所有示例改成显式 record 初始化。

推荐提供 builder，降低下游注册命令的样板代码：

```pascal
Commands.RegisterCommand(
  ShellCommand('app.scan.run', 'Run Scan')
    .Category('Run')
    .Shortcut('Ctrl+R')
    .RiskLevel(1)
    .OnExecute(RunScan));
```

如果实际实现尚未提供 builder，AI 不得照抄 fluent 示例生成不可编译代码；应使用当前代码库已有 API。

## 5. EventBus

```pascal
TDeepShellEventKind = (
  sekProjectOpened,
  sekProjectClosed,
  sekContextChanged,
  sekObjectSelected,
  sekViewChanged,
  sekLayoutChanged,
  sekLogAdded,
  sekIssueAdded,
  sekTaskStarted,
  sekTaskFinished,
  sekServiceStatusChanged
);

TDeepShellEvent = record
  Kind: TDeepShellEventKind;
  Context: TShellContext;
  ObjectRef: TShellObjectRef;
  MessageText: string;
  Data: string;
end;
```

```pascal
IShellEventBus = interface
  function Subscribe(AKind: TDeepShellEventKind; AHandler: TProc<TDeepShellEvent>): string;
  procedure Unsubscribe(const AToken: string);
  procedure Publish(const AEvent: TDeepShellEvent);
end;
```

规则：

- 每个 Shell 实例一个 EventBus。
- 订阅返回 token。
- 窗体销毁时必须取消订阅。
- DeepShell VCL EventBus 是 UI-safe 分发：如果 `Publish` 在主线程调用，handler 同步执行；如果 `Publish` 在后台线程调用，handler 通过 `TThread.Queue` 投递到主线程后执行，`Publish` 不等待 UI handler 完成。
- handler 必须短小，不能在 handler 中执行长任务。
- 后台 worker 需要同步结果时，不应依赖 `Publish` 的返回时机，应使用任务/回调自己的同步机制。

### 6.2 Main View Provider

```pascal
TShellViewKind = (
  svkControl,
  svkFrame,
  svkHtml,
  svkMarkdown,
  svkText,
  svkExternal
);

TShellViewInfo = record
  ViewId: string;
  ViewKind: TShellViewKind;
  Title: string;
  Content: string;
  Control: TControl;
end;

IShellMainViewProvider = interface
  function ProviderId: string;
  function CanOpen(const ARef: TShellObjectRef): Boolean;
  function GetViewForObject(const ARef: TShellObjectRef): TShellViewInfo;
end;
```

`svkHtml`、`svkMarkdown`、`svkExternal` 只描述视图意图，不表示 Shell 核心负责渲染。

渲染边界：

- Shell 只提供 `MainHost` 挂载容器和视图生命周期。
- HTML 渲染由下游 `IShellMainViewProvider` 或可选 renderer service 自带控件实现，例如 WebView2 adapter、CEF adapter 或纯文本 fallback。
- Markdown 渲染由下游 provider 或 renderer service 转成控件 / HTML / 文本。
- `svkExternal` 由下游决定打开外部浏览器、外部编辑器或专用窗口。
- `TDeepMainForm` 核心不得直接依赖 WebView2、CEF、Markdown 渲染库或外部进程启动策略。

### 6.4 Control / Frame 挂载规则

`svkControl` 和 `svkFrame` 用于下游 Provider 直接提供 VCL 控件。

规则：

- Provider 创建控件，Shell 负责挂载到 `MainHost`。
- 控件的 `Owner` 推荐是 Shell 主窗体或 MainHost 所在窗体，避免 Provider 释放后控件悬空。
- Shell 挂载时设置：

```pascal
AControl.Parent := MainHost;
AControl.Align := alClient;
```

- Shell 切换视图时负责从 MainHost 移除旧控件；是否释放旧控件由 `TShellViewInfo` 后续实现中的 ownership 字段决定。
- 第一版可采用简单规则：Provider 交给 Shell 的 Control 由 Shell 拥有并释放。
- 如果下游需要缓存多视图控件，应实现 ViewCache / MainViewProvider 自己管理生命周期，并在契约中明确 Shell 不释放。
- `svkFrame` 本质也是 `TControl`，区别只在 Provider 语义上表明它是 `TFrame`。

实现注意：`TShellViewInfo.Control` 让接口单元依赖 VCL `TControl`。如果未来要抽到非 VCL 核心，应把 VCL 挂载契约拆到 `DeepBase.VCL.DeepShell.Intf`，不要放 Core 包。

## 10. Governance Service

```pascal
TShellGovernanceDecision = record
  Allowed: Boolean;
  Mode: string;
  RiskLevel: Integer;
  GateKey: string;
  ActionKey: string;
  MessageText: string;
  UserHint: string;
  EvidenceId: string;
  DetailJson: string;
end;

IGovernanceService = interface
  function IsEnabled: Boolean;
  function EnterGate(const AGateKey: string; const AContextJson: string):
    TShellGovernanceDecision;
end;
```

第一版默认 `NullGovernanceService` 总是返回 `Allowed=True`。真实 OCGS adapter 后续接入。

使用结构化结果的原因：

- CommandManager 可以按 `RiskLevel` 决定反馈方式。
- UI 可以显示 `MessageText` 和 `UserHint`。
- 日志和 Evidence 可以记录 `EvidenceId`。
- 后续 OCGS 返回更多细节时不需要改变 Command 执行链路。
