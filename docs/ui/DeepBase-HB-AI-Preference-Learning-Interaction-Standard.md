# DeepBase HB AI 偏好学习交互标准规范
## DeepBase HB AI Preference Learning Interaction Standard ("[让我学习]" · v1.0)

> **法源地位**：DeepBase HB 人机行为交互标准与偏好沉淀架构法定标准  
> **裁定时间**：2026-09-07（Human 架构裁定收口）  
> **核心受众**：HB 控件研发、DeepBase AI 运行时组、AsWish、唤金及所有下游智能体应用  
> **核心原则**：AI 先想人只确认 · 显式适用范围 · 杜绝一次选择变永久规则 · 可回溯可自省

---

## 1. 核心定位与术语大白话解释

在完成一项重要的 AI 选择后（例如选定了一条沟通话术、确认了一处界面设计、裁决了一项代码架构差异），系统可以提供一个核心交互入口：

```text
[让我学习]
```

### 1.1 什么是“偏好学习（Preference Learning）”？
> **大白话**：软件不是只机械地记住“你选了第 2 个”，而是**逐渐弄懂“你为什么觉得第 2 个更好”**，并将这个判断沉淀为后续可以复用的认知资产。

### 1.2 核心目的与底线澄清
* **真正做的是**：让 AI 弄清楚人刚才为什么这样选，并将这个原因打上适用范围标签，在以后的类似场景中自动提供给 AI 参考；
* **绝对不是**：在本地或云端偷偷重新微调或训练一个底层基础大模型。第一阶段的本质是**“原因提取 + 范围标签 + 偏好检索 + 上下文注入”**。

## 2. 交互过程与闭环全景图

```text

                │
                ▼
       [ 人类选中方案 B ]

                ▼
      点击 [让我学习] 按钮
                │
                ▼
 ┌─────────────────────────────────────────────────────────────┐
 │  AI 自己对比各方案差异，反思并给出可能原因 (0–9 多选 Deck)：│
 │                                                             │
 │  我猜你选择方案 B，可能因为：                               │
 │  [√] 1. 结构更精炼 / 表达更自然 (特征 A)                    │
 │  [ ] 2. 约束更少 / 更加简短平实 (特征 B)                    │
 │  [√] 3. 冗余度低 / 无多余说辞感 (特征 C)                    │
 │  [√] 4. 符合既定设计惯例 / 日常习惯 (特征 D)                │
 │  [ ] 5. 初始开销更低 / 切入平缓 (特征 E)                    │
 │  ──────────────────────────────────────────                 │
 │  [ 8 ] 换一批原因 (Regenerate)                              │
 │  [ 9 ] 我自己说明 (Free Input / 框架否定)                   │
 │  [ 0 ] 算了，不记录 (Back / Dismiss)                        │
 └─────────────────────────────────────────────────────────────┘
                │
                ▼ (用户利用 1–7 多选勾选 1 + 3 + 4 并点击确认)
 ┌─────────────────────────────────────────────────────────────┐
 │  AI 输出学习提议与范围声明 (防学错确认弹层)：               │
 │                                                             │
 │  我准备这样记住：                                           │
 │  “在【当前目标对象/适用场景】中，优先偏好【特征 A + C + D】”│
 │                                                             │
 │  [√ 确认记住]      [ 修改适用范围 ]      [ 取消 ]           │
 └─────────────────────────────────────────────────────────────┘
                │
                ▼ (用户最终确认)
       [ 沉淀入 DeepBase Core 偏好库 (见 DeepBase-AI-Human-Judgment-Memory.md) ]
                │
                ▼ (下一次同类场景工作时)
“根据你之前在【当前场景】偏好【特征 A + C】的记录，已为你优先推荐本方案”
```

## 3. 核心交互原则与防错防线

### 3.1 原则一：AI 必须先自己想，人只做快速确认
> [!CAUTION]
> **严禁将劳动推脱给人类**：绝对禁止弹出一个空无一物的大文本输入框，冷冰冰地要求用户：“请详细写下你为什么选择这个方案”。用户来使用软件是为了省时间，不是来给 AI 写小论文！

* **正确路径**：
  1. AI 自动将“被选中的方案”与“被放弃的方案”做语义差分比对；
  2. AI 自己先猜出 3~5 个最高概率的原因候选（通过 HB 1–7 多选呈现）；
  3. 人类只需鼠标点选或按数字小键盘进行勾选、取消或补充。

---

### 3.2 原则二：必须严密防止“学错”（防过度泛化）
人的一次选择，**绝对不能自动变成永久生效的死规则**！
* *反面案例*：用户本次针对特定紧迫情境做出的单次折中选择，绝不代表用户“永远喜欢该极端特征”。如果系统盲目学成全局死规则，会导致后续交互全面失真。
* **防护机制 —— 显式标注适用范围（Scope Tagging）**：
  AI 在保存偏好前，必须显式说明适用范围，供用户把关：
  - `只对当前目标实体生效`（Target Entity，如特定对象/特定文件）
  - `只对同类场景聚类生效`（Scenario Cluster，如特定业务流程或任务类型）
  - `作为一般性参考建议`（Global Weak Prior，弱偏好，权重低）

---

### 3.3 原则三：后续必须让用户看得见它真的学会了（可解释与可追溯）
当后续 AI 受到历史偏好影响而调整了候选方案时，必须在界面上给予**轻量透明的显影提示**：
> “根据你之前偏好【特征 A + 特征 C】的记录，已为你优先推荐本方案。”

* 严禁每次长篇大论打扰用户；
* 但必须保证：**AI 为什么越来越这样推荐，用户在界面上随时能看懂、能溯源、能一键撤销该偏好**。

## 4. 架构分层职责与跨层隔离铁律

本功能横跨交互、基座与业务三层，必须执行严密的职责隔离：

```text
+-------------------------------------------------------------------------------+
|  【唤金 / AsWish 业务领域层】 (Product Domain Layer)                           |
|  • 负责业务语义的解释与翻译：                                                 |
|    - 唤金解释：喜欢怎样的人际距离、什么话术太油腻、哪些人该冷处理             |
|    - AsWish 解释：喜欢高对比度线条、讨厌嵌套弹窗、可以接受 2px 误差           |
|  • 负责将通用偏好转换为业务 Prompt 或规则权重                                 |
+-------------------------------------------------------------------------------+
                                        ▲
                                        │ 纯领域映射 (注入产品实体)
                                        │
+-------------------------------------------------------------------------------+
|  【DeepBase Core / AI 学习记录基础设施】 (Generic Preference Infrastructure)   |
|  • 提供通用偏好存储契约：                                                     |
|    - TargetId / ChoiceArtifact / SelectedOption / ConfirmedReasons            |
|    - ScopeTags (通用范围标签) / CreatedAtUtc / IsActive / Weight              |
|  • 提供检索与匹配接口：GetApplicablePreferences(ContextTags) 供下一次参考      |
|  • 纯机制沉底：绝对不包含销售、客户、联系人、代码节点、界面布局等任何业务专有名词|
+-------------------------------------------------------------------------------+
                                        ▲
                                        │ 纯数据驱动 (解耦)
                                        │
+-------------------------------------------------------------------------------+
|  【DeepBase HB 偏好交互层】 (Learning Interaction Layer)                       |
|  • 负责 [让我学习] 视觉入口控件与挂载槽位                                     |
|  • 负责驱动 1–7 多选候选卡组、换一批 (8)、自己说 (9)、取消 (0)                |
|  • 负责呈现学习结果摘要卡片与范围微调控件                                     |
|  • 纯交互呈现：绝不处理具体业务逻辑，绝不存储任何业务数据                     |
+-------------------------------------------------------------------------------+
```

### 跨层禁令
1. **HB 层**：严禁出现 `Contact`（联系人）、`Sales`（销售）、`SpecNode`（规约节点）；
2. **DeepBase 层**：严禁硬编码 AsWish 的 4 树逻辑或唤金的微信消息逻辑；
3. **产品层**：严禁各自私造一套“原因选择卡组”或各自搞一套离散偏好存储文件。

## 5. 与“UI 四自”质量检查标准的天然契合

`[让我学习]` 原语是系统实现“四自交付”的最强抓手：

* **服务【自营销】**：
  用户通过这个入口直观看见：**“软件正在越来越懂我”**，建立长期的技术确定性与归属感；
* **服务【自承接】**：
  用户做完主裁决后，不直接面对空虚的界面，而是自然进入可选的“调教与确认”正向支线；
* **服务【自成长】**：
  使“自成长”彻底摆脱玄学，成为**由用户亲手确认、带范围标签、立即可验证的真实偏好资产**；
* **服务【低客服】**：
  后续推荐发生变化时，用户能直接看到“因为你上次选了……”，消除机器黑盒带来的疑惑与抱怨。

## 6. 后续工程研发验收清单（Engineering AC）

后续承接本特性的开发团队，必须逐一验证以下 10 项标准方可交付：

- [ ] **AC-PL-01**：在一次真实完成的业务选择后，界面能优雅弹出或平滑展开 `[让我学习]` 入口；
- [ ] **AC-PL-02**：AI 能够自动对比选定项与备选项，生成 2~5 项合理的原因候选；
- [ ] **AC-PL-03**：原因候选区采用标准 HB Choice 1–7 多选模式，支持多项组合勾选与取消；
- [ ] **AC-PL-04**：支持按 `9` 唤起人类覆写输入，允许用户打破 AI 猜测自己补充理由；
- [ ] **AC-PL-05**：在最终持久化前，系统必须向用户显式展示“我准备记成……”的范围声明卡片；
- [ ] **AC-PL-06**：未经用户显式确认，系统绝对不得将临时选择静默升级为永久偏好；
- [ ] **AC-PL-07**：偏好记录必须包含明确的适用范围标识（Scope），不得无界全局滥用；
- [ ] **AC-PL-08**：DeepBase 偏好基础设施能够成功持久化，并在下一次同类上下文启动时被快速检出；
- [ ] **AC-PL-09**：后续 AI 推荐结果能够携带轻量偏好追溯标（“根据你之前的偏好...”）；
- [ ] **AC-PL-10**：用户在设置中心或详情卡中，能够随时查看并一键删除已记住的历史偏好。
