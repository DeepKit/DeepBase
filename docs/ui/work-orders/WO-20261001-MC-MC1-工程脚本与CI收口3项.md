## 项 3：CI 固定非 UTC 时区

**基线（B13 裁定口径）**：`.github/workflows/delphi-ci.yml` 当前 7 个 job 均 `runs-on: [self-hosted, delphi-windows]`、无任何 TZ 设置。B10 验收 §5.5 曾裁「CI 不固定时区」（本机 UTC+8 已有鉴别力）；乙 B13 从**反向偏移**补了更硬理据——负偏移机器上偏差符号翻转，UTC+8 与 UTC 两台都测不出「提前 vs 延迟」的**方向错**。⇒ 择机在 CI 加 `tzutil` 设固定非 UTC 偏移。

**边界（防范围蔓延）**：本项只加时区固定，**不替代**乙 B14 的调用点可测性债（假时钟贯穿性），也不同层。

**判据（静态为主，运行期如实登记未验）**：
1. 固定步置于全部 build/test 步**之前**（每个 job 或顶层 anchor 均可，以实现方式为准），命令形如 `tzutil /s "<时区名>"`；
2. 时区名以 `tzutil /l` 实测存在为准（命令原文留档）；所选偏移与本机默认 UTC+8 可区分，且与 B13 论证兼容（方向可鉴别）；
3. `.github/workflows/delphi-ci.yml` YAML `safe_load` 解析通过；steps 计数变化与 diff 一致；
4. **运行期效果未验**（self-hosted runner 未接通，GitHub 两次 run 均 cancelled，见派单总表 §三）⇒ 清清楚楚登记「未验」，不宣称 CI 已验证时区；
5. `git diff` 恰为 `.github/workflows/delphi-ci.yml`。
