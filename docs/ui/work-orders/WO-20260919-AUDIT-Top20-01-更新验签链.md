### 2. 改法

1. 签名信任根本地化：算法名不接受远端自述，由本地配置固定为 `rsa-sha256`（与 `AutoUpdate:853-857` 已有的"RSA 权威 + 无公钥即拒"fail-closed 模式对齐）；删除 `sha256` 伪签名分支。
2. `StageAndVerifyPackage` 引入强制策略：`SignatureRequired` 默认为真；`PackageHash` 与 `Signature` 任一缺失即拒绝（不再有"字段为空→跳过"路径）。开发豁免走显式 `SetInsecureDevMode`（已有 `:287`）且 Release 构建编译期剔除。
3. manifest 验签 payload 收敛为唯一函数 `BuildManifestSignaturePayload`（`:246` 已存在），两路径统一调用，消灭 U-02 双实现。
4. URL 入口集中校验：scheme=https + 主机白名单 + 下载 URL 只允许来自已通过验签的 manifest。
5. `AutoUpdate` RSA 输入改为对文件原始字节（或明确的单层摘要）签名，与签名方协议（78a ADR r1 §2.7）对齐；删除双重 SHA256。
6. 门禁返回类型统一接甲单 A6 的 `TGateVerdict`（`Core\DeepBase.Gate.Verdict.pas`）：上述所有校验函数返回 `gvApproved/gvRejected/gvIndeterminate`，调用侧仅 `gvApproved` 可达安装执行路径；缺字段/异常/未知算法一律 `gvRejected`。
7. 中期：抽 `DeepBase.Update.Contracts` 单元统一 `TUpdateInfo` 与 payload 编解码（AU-06），Updater/AutoUpdate 只做编排。

### 3. 验收标准

- 负向用例四连：①manifest 不带 `signature` 字段 → 拒绝；②`signatureAlgorithm: "sha256"` → 拒绝（未知/禁用算法）；③合法 RSA 签名但经路径 A/B 分别验证 → 两条路径同时通过；④`download_url` 指向 http/白名单外主机 → 拒绝。
- `AutoUpdate` KAT：用 openssl/.NET 对文件**原始字节**签一次名，客户端验签通过（证明单层摘要语义）。
- 全量回归：`Tests` 中既有 Updater/AutoUpdate 用例全绿；UpdaterHelper 工具链（`Tools\UpdaterHelper` 不传 `--sha256` 跳过的同型缺陷）随单收编。
