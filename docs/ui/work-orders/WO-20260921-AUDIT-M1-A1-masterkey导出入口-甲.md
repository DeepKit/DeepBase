## 一、问题（一句话）

M2（`9387222`）把 UBS2 v2 凭据信封的 KEK 熵源**收敛为用户机密 `~/.deepbase/master.key`（0600）**，machine-id 降级为 AAD。
⇒ **该文件一旦丢失/损坏，全部凭据永久不可解密**，且**当前无任何显式的查看/导出/备份入口** —— 用户无从自保。

---

## 二、任务清单

### P1｜**显式导出/备份入口**（最小安全可用）

- 提供**明确的**导出/备份命令（CLI 优先），把 `master.key` 输出到用户指定路径；
- 导出物须**自验**：导出后回读校验一致（长度 + 内容哈希），不一致即失败退出；
- **默认权限**：导出文件 `0600`（Windows：仅当前用户 ACL）；
- **不新增**任何"以明文开关绕过"的运行时旁路（H8）。

### P2｜**强风险告诫 + 可验证指引**

- 导出前/后向用户**明确告知**：该文件是全部凭据的唯一熵源，**丢失即永久不可恢复**；
- 输出中给出**明确的存放建议**（离线介质/密码管理器），并与 `UBS2Migrator` 迁移窗口的关系说清。

### P3｜**完整性可检测**

- 提供**只读**的"密钥存在性与指纹"查询（如 SHA-256 前 N 位），供用户核对备份是否一致；
- 指纹查询**不得**泄露密钥本体。

### 明确不在本单

- 不做多设备迁移/密钥托管/云端备份（若需完整产品形态，报主控上推老板）。
