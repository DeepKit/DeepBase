## 〇、为什么现在做

乙 P1/P2/P2b 已经把门禁**最危险的洞**（fail-open：扫 0 文件仍报绿、参数写错静默回落默认根）堵上了。

本单的目的就是让这句话**可以被机械回答**。

## 一、必做五件事（逐项实测 + 给出结论，不写「理论上」）

### 1.1 旧脚本与新门禁是否同源 —— 明确处置

- **现状（主控实测）**：仓内同时存在 `Scripts/check_encoding.ps1`（旧，PowerShell）与 `09_工程脚本/encoding-gate/check_pas_encoding.js`（新，Node）。
- **必答**：两者是否在做同一件事？若是 ⇒ **删旧留新**（AGENTS.md：重写/重构后删旧代码，禁留两套）；若否 ⇒ 写明职责边界。
- **禁止**：两个都留着、各自跑、结论互相打架。

### 1.2 `Tools/` 是否在编码门禁扫描面内

- **现状（主控实测）**：`Tools/` 下有 **67 个 `.pas`**；编码门禁报「972 个 .pas」。
- **必答**：972 里**含不含**这 67 个？给独立复算（`git ls-files '*.pas' | wc -l` 与门禁计数对照），若不含 ⇒ 说明原因并给出**是否应当纳入**的结论。

### 1.3 `eol-gate` 计数漂移

- **现状**：甲 A1 结论 §六-4 登记「`eol-gate` 计数 1433→1426 漂移」。
- **必答**：漂移的根因是什么（基线条目变化？扫描面变化？）；当前计数**可解释、可复现**吗？

### 1.4 DUnitX `--run` 短名静默 0 命中

- **现状**：甲 A1 §六-2 登记「DUnitX `--run` 短名静默 0 命中」（写短名 ⇒ 匹配不到 fixture ⇒ 跑 0 个却可能报成功）。
- **必答**：这是**测试框架行为**还是**本仓用法问题**？若是前者 ⇒ 在门禁/测试脚本里加「**匹配数为 0 ⇒ EXIT≠0**」的守卫（与 P1 §〇 同一 fail-closed 口径）；若是后者 ⇒ 改用法并在说明里写死。

### 1.5 两个 `.dpr` 在门禁外

- **现状（主控实测）**：`09_工程脚本/` 下 `grep 'TestNewModules\|DeepBaseArchitectureTests'` ⇒ **0 命中**，两件 `.dpr` 不在任何门禁内。
- **必答**：是否应当纳入（与甲 D3「全库 `.dpr` 编译门」联动——**D3 建成后这两件必须在其覆盖清单里**）；本单只需给出**明确结论 + 清单**，编译门本体由 D3 交付，**不得在此重复造门**。
