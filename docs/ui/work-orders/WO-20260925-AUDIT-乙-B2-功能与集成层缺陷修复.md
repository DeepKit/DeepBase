## 一、电商与外部集成（4 条，资金类优先）

### B2-01 [Critical] Firebase 适配器布尔读写类型错位

- 文件：`Features/DeepBase.Commerce.Adapter.Firebase.pas:301-337`
- 代码事实：写路径 `WrapValue(Boolean)` 落 `TJSONBool`，读路径用 `TryGetValue<string>('booleanValue')` 取——**`is_active` 恒读成 False**，商户激活状态永远失效。
- 期望：读写类型对称（读走布尔字段的正确取值方式）。
- 判定：写入 `true` 后读回 `true` 的用例（须覆盖 `is_active` 字段）；既有解析测试不回归。

### B2-07 [Critical] 加密备份未解密即读

- 文件：`Features/DeepBase.CloudBackup.pas:2540`
- 代码事实：`LZip.Open(LArchivePath, zmRead)` 直接打开**未解密**的加密归档。
- 期望：先走解密通道得到临时明文，再开 zip；失败即中止（fail-closed）。
- 判定：加密备份往返用例 EXIT=0；损坏密文用例 EXIT≠0 且不留半开临时文件。

### B2-08 [Critical] 更新零验签 + 回滚恒空

- 文件：`Features/DeepBase.Updater.pas:1610-1623`
- 代码事实：`InstallDownloadedUpdate` 无任何签名/哈希校验即安装；`FilesToBackup[0] := '*.*'` 使备份列表恒为空 ⇒ 更新失败无法回滚。
- 期望：安装前必须验签（自签公钥体系即可，密钥随仓库配置注入，禁止硬编码私钥——见 A2-01 同型教训）；备份列出**真实受影响文件清单**；任一环节失败 ⇒ 拒绝安装并保留现场。
- 判定：无签名/坏签名包拒绝安装（EXIT≠0）；好签名包安装成功且备份清单非空、条数可核对。
- 收敛说明：本单不裁决签名算法选型（多模型会议已定方向：fail-closed + 可替换验证器实现），乙实现时选仓库现有能力优先（先翻现有依赖，见全局规则 6）。

### B2-10 [High] OpenAI 分支强制注入流式
