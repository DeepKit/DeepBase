而**双重编码乱码是合法 UTF-8**（「日志导出」被误按 GBK 解码后再存成 UTF-8 ⇒ 「鏃ュ織瀵煎嚭」），
⇒ **门禁恒绿，内容却是垃圾**。

**已知实锤样本（不用你找，就是它）**：
`CodeReview/20260920-AUDIT-甲-证据/R7/R7-gates-run.txt` —— 内容级乱码，合法 UTF-8，门禁从未抓到。

⇒ 结论与甲 D6 那条是同一个洞的两个面：

> **「编码门禁 EXIT=0」不等于「中文正确」；「证据门禁 EXIT=0」不等于「证据可信」。**

一个证据文件如果内容失真，它作为**证据**的价值就是零，而门禁还在给它发绿牌。这比源码乱码更危险——
源码乱码会在编译期显形，证据乱码不会在任何地方显形。

## 一、必做

### 1.1 加丙-C 检测（只做这一类，理由见 §三）

**⚠️ 主控实测的坑，先读这一条再动手**：教科书写法 `line.encode('gbk').decode('utf-8')` 在**本仓真实样本上会漏检**——
`R7-gates-run.txt` 含 `U+E6E6`（GB18030 PUA 区），`encode('gbk')` 直接抛 `UnicodeEncodeError` ⇒ 整行跳过，**已知样本反而抓不到**。

主控对该文件亲测过的可行写法（`gb18030` 是 `gbk` 超集，能吃下 PUA）：

```python
r = line.encode('gb18030').decode('utf-8', errors='replace')
```

实测结果（本仓真实样本，不是构造的）：

| 行 | 原文前 20 字 | 还原后 | 替换符数 |
|---|---|---|---|
| 1 | `缂栫爜闂ㄧ閫氳繃锛?72` | `编码门禁通过…` | 3 |
| 3 | `璇佹嵁缂栫爜闂ㄧ閫氳繃` | `证据编码门禁通过：扫…` | 4 |
| 5 | `琛屽熬闂ㄧ閫氳繃` | `行尾门禁通过：检查了 1425 个文件…` | 1 |

⇒ 判定条件建议：`还原前后不相等` **且** `替换符占比 ≤ 阈值（主控建议 20%，你自己实测定并写进说明）` ⇒ 报丙-C。
替换符占比过高的行是**不可逆损坏**，归丙-A/丙-B 面（本单只登记不判）。

输出要求：
- 逐条 `路径:行号: 原文 → 还原后（替换符 N）`，可人读；
- 汇总一行 `扫描 N 件 / 命中 M 行`；
- 与 `--list-files` 同族：覆盖面 SSOT 仍在门禁里，不写死在 README。
- **负面控制必须做**：正常中文行（如 `编码门禁通过：975 个 .pas`）经同一函数后必须 `还原前后相等` 或替换符占比超标，**不得判成乱码**。

### 1.2 存量单列，**只减不增**

首轮必然命中一批（已知的就有 R7 那件）。
**禁止**把存量录进「豁免基线」当默认 —— 那等于把洞盖上。

做法沿用甲 D8 同一立场：
- 存量以 `mojibake-evidence-backlog.json`（或同族命名）**单列清单**，可核、可递减；
- 门只拦**新增**：清单外的命中 ⇒ EXIT≠0；
- 每修一件，清单减一行；**加条目必须显式说明**，门要能挡住静默加入。

### 1.3 fail-closed 三条（照门禁族既有标准）

| 情形 | 必须 |
|---|---|
| `readdir` 任一子树失败 | EXIT≠0 + 打印失败路径 |
| 扫描计数为 0 | EXIT≠0 |
| 检出清单外的新增双重编码 | EXIT≠0 |

### 1.4 负向样本（≥3 例，各型独立）

1. 构造一份双重编码的 `.md`/`.txt` 证据 ⇒ 必红，且定位到行；
2. 构造一份**正常中文**（非双重编码）⇒ **必绿**（防过度兜底，别把正常中文也判成乱码——GBK 试探的误报面要实测过）；
3. 构造一份**纯 ASCII** 证据 ⇒ 必绿；
4. 存量清单内的一件 ⇒ 不报红（证明「只拦新增」真的生效，不是全豁免）。
