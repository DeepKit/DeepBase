### P1【删三段 legacy 解密路径 —— 老板裁定「旧锁去掉」】

**现状（主控实测，`Core/DeepBase.Crypto.AES.pas`）**：解密侧有 **4 条分支**，其中 3 条为 legacy 弱路径 ——

| 分支 | 行位 | 密钥派生 | MAC | 处置 |
| :--- | :--- | :--- | :--- | :--- |
| v3（当前写入） | ~880-890 | `PBKDF2(pwd, 随机盐, 100000)` | `SimpleCryptoMacKeyV3(pwd,盐)`（带盐） | **保留** |
| **v2** | ~895-900 | 无盐 | `SimpleCryptoMacKey(pwd)`（**无盐单轮**） | **删除** |
| **v1** | ~912-939 | `DeriveSalt(pwd)`（**确定性盐**） | `SimpleCryptoMacKey(pwd)`（无盐单轮） | **删除** |
| **无头 legacy** | ~941-955 | `DeriveSalt(pwd)`（**确定性盐**） | 无 | **删除** |

**改法（唯一定稿）**：
1. 删除上述 v2 / v1 / 无头三条分支；解密侧**只保留 v3**；
2. 旧格式输入 ⇒ **明确 `raise`（清晰异常，如「不支持的旧密文格式，已按安全策略移除」）**，**禁静默降级 / 禁回退 / 禁开关**（H8）；
3. 连带清理（确认无其他调用者后）：`SimpleCryptoMacKey`（无盐单轮）、`DeriveSalt`（确定性盐）；
4. 同步修 `Tests/Test.DeepBase.Crypto.pas`（现 `:1053` 仍调用 `DeriveSalt`）；
5. **补负向测试**：v1 格式 / v2 格式 / 无头格式的密文送入 `Decrypt` ⇒ **必须 `raise`**，逐个断言。

**产品干预登记（必做）**：登记 `PI-甲-R7-CRYPTO-LEGACY-REMOVAL`，写明**行为变更**：
