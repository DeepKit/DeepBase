## 〇、主控实测确认（不是转述）

`09_工程脚本/build-ownership/check_build_ownership.js`：

```
:16   function arg(name, dflt) {                                        ← 私有 arg()，未复用 gate-args.js
:20   const ROOT = path.resolve(arg('root', 'D:/_Progs/02Business/DeepBase'));   ← 硬编码绝对路径
:45   const buildFiles = walk(ROOT, ['.dpk', '.dproj', '.dpr'], []);
```

**两条缺陷，第一条是安全洞级的：**

1. **默认 ROOT 是写死的绝对路径** `D:/_Progs/02Business/DeepBase`。
   ⇒ 在 CI 检出目录 / 别的盘 / 任何隔离工作树里**不传 `--root` 时**，`walk` 扫到一个不存在的目录
   ⇒ **得到 0 个文件 ⇒ 0 违规 ⇒ EXIT=0 ⇒ 报绿**。
   这就是 P1 §〇 那一类的洞，只是换了一道门——**而这道门正是我们在用的五道门之一**。
2. **自带一套私有 `arg()`**，没有复用 `09_工程脚本/gate-args.js` ⇒ 参数解析规则与其余四道门不同源，
   大小写 / 缺值 / 未知参数的处理口径分裂（P2 §3.3 修的就是这类分裂）。

## 一、必做三件事

### 1.1 默认 ROOT 改为**脚本自身相对**（与其余门同口径）

参照 `check_build.js` / 编码门禁已采用的写法：默认基准绑定到**脚本所在位置的上级**，
不再使用任何绝对路径。⇒ 无论检出到哪个目录，默认就是「这个仓」。

### 1.2 fail-closed 三条（照抄门禁族既有标准，不要发明新口径）

| 情形 | 必须 |
|---|---|
| `readdir` 任一子树失败 | **EXIT≠0** + 打印失败路径 |
| 扫描到的构建文件计数为 **0** | **EXIT≠0**（空扫描不是通过） |
| 产物单元/prod 面计数为 0 | **EXIT≠0** |

**禁止**「跳过并继续报绿」的任何形态。

### 1.3 参数解析并入 `gate-args.js`

删除私有 `arg()`，改为 `require('../gate-args.js')`。
⇒ 让大小写不符、缺值、未知参数、值形似参数这些情形与其余四道门**同一套规则**。
