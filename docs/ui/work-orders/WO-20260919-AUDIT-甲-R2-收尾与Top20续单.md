## 1、⚠️ 对甲 R1 两处判断的纠正（本单开工前须先确认）

### 纠正 1：Top20 #9 **未被撤回**，甲的"无实际安全缺陷"判断不成立

甲 R1 回执 R5 说明称「#09 无实际安全缺陷（A2 撤回）」。**主控复核：A2 只撤回了三条（Manifest.Verifier / Browser.CDP / EHAI CreateExplicit），不含 #09。**

| 项 | 内容 |
|---|---|
| 文件:行 | `Core\DeepBase.Authorization.pas:300`（`FThreadCurrentUsers: TDictionary<TThreadID, TUser>`）、`:1614-1622`（`AddOrSetValue(TThread.CurrentThread.ThreadID, AUser)` / `Remove(...)`）、`:1149-1153` |
| 实测 | 以 `TThread.CurrentThread.ThreadID` 作为身份映射键 |
| **真实缺陷** | **ThreadID 会被操作系统复用**：线程退出后其 ID 可分配给新建线程。若线程退出路径未执行 `Remove`（异常路径、`finally` 缺失、线程被强制终止），新线程复用同一 ID 即继承前一线程的 user ⇒ **身份串号越权**。这是真实缺陷，不是"无缺陷" |
| 报告表述修正 | 原报告"裸 `TUser` 指针"**表述不准**（`TUser` 是值类型存于字典，非指针）。但**风险本身成立**，只是机理是"ThreadID 复用"而非"悬垂指针"。见本单 A14 |

### 纠正 2：Top20 #10 **未修且归属判错**，应归甲

甲 R1 回执称「#10 跨入乙整改面」。**主控复核：#10 = `Core\Crypto.AES` 模式静默降级，正是甲 A4 正在改的文件，不存在跨入乙面的理由。**

| 项 | 内容 |

| 文件:行 | `Core\DeepBase.Crypto.AES.pas:24`（`TAESMode = (aesECB, aesCBC, aesCFB, aesOFB, aesCTR, aesGCM)`）、:375-441（非 GCM 分支硬编码 CBC） |
