## 一、主控实测事实（本单立论依据）

| 文件 | `ls-files --eol` | blob 前 64 字节 | blob 大小 | 工作树大小 | 判定 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `Tests/Test.DeepBase.Browser.Selectors.pas` | `i/-text w/crlf` | `EF BB BF`(BOM) + `EF BF BD`(**U+FFFD**) + `E2 BA B7` + `\0 n \0 i \0 t \0` … | **10,470** | 5,234（UTF-8 修复版） | **UTF-16LE + 替换字符双重损坏**；blob 恰为工作树 2.0 倍 |
| `Core/DeepBase.Schema.pas` | `i/-text w/-text` | `EF BB BF` + 正常 ASCII | 51,626 | 51,626 | blob **全文件 NUL = 0**、大小一致，却仍判 `-text` ⇒ **成因待查** |

**为什么这是严重缺陷**：UTF-16 存储的 `.pas` 在 git 中无法 diff、无法 clean/smudge、EOL 立法对其完全失效；`U+FFFD` 出现意味着该文件**曾被错误转码且损坏已不可逆**。且它**已经进了 HEAD**。
