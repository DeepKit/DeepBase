| 文件 | `ls-files --eol` | blob 前 64 字节 | blob 大小 | 工作树大小 | 判定 |

**★ 2026-09-20 主控已锁定成因（本项从「待查」转为「已定」）**：

```
Core/DeepBase.Schema.pas
  blob = 工作树（逐字节相同，True）；NUL = 0；CRLF 行 970 + LF-only 行 12 = 982 行
  行尾构成：961 行以 \r\r\r\r\n 结尾（4 个 CR）
  git diff = 970/970；--ignore-cr-at-eol = 961/961（无法消除）
  git diff | cat -A 显示每行为 ...^M^M^M^M$
```

**成因 = 961 行行尾为 4 个 CR。** `.gitattributes` 的 `text` 属性只规范化单个 `\r\n`，剩余 3 个 CR 仍造成逐行差异。全库 959 个 `.pas` 扫描，**多重 CR 文件仅此 1 件**。

**危害**：Delphi 编译器把每个 CR 视为换行 ⇒ 该文件 **1 行源码占 4 个行号**，编译错误行号、静态分析行号、按行索引的门禁结论**全部错位**。

**归属裁定（主控）**：该文件**不属甲 R4、不属乙 R3，是「无主畸形文件」**。乙**无需再申报归属**；只读诊断随时可做；**修复动作（961 行 `\r\r\r\r\n` → `\r\n`）归入 K6 前置修复，由主控在 K6 发射时统一执行，乙不得单独提交**。

**顺带**：乙在 L1 提出的「13 件 `_audit_recheck/*.txt|*.log` 同类异常」线索，主控已查实**成因不同** —— 那 13 件的 NUL 占比恒定 ≈ 50%（UTF-16LE 特征，系 PowerShell 重定向默认编码所致），**非行尾畸形**，与 Schema.pas 不可互为对照组。据此新开 **L9** 与 **H18**。
