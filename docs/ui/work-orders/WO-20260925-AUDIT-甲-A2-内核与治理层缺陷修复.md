## 一、安全 fail-closed 组（3 条，最高优先）

### A2-01 [Critical] 硬编码许可密钥兜底

- 文件：`Core/DeepBase.License.pas:152-167`
- 代码事实：`LICENSE_CI_SECRET = 'DeepBase-License-CI-Only'`（:154）；`ResolveLegacyLicenseSecret` 在环境变量（`LICENSE_LEGACY_SECRET_ENV`）缺失且 `{$IFDEF CI}` 时 `Result := LICENSE_CI_SECRET`（:165）——源码内常量密钥兜底，读二进制者可伪造许可签名。
- 期望：删除常量与 `{$IFDEF CI}` 兜底分支；环境变量缺失 ⇒ 抛 `Core/DeepBase.Exceptions.pas` 中具体异常拒绝运行；保留显式配置注入路径。
- 判定：删常量后全仓 `rg LICENSE_CI_SECRET` 零命中；缺失 env 的用例 EXIT≠0 且异常类型正确；正常注入路径用例 EXIT=0。

### A2-02 [High] 配置解密失败 fail-open

- 文件：`Core/DeepBase.Configuration.pas:806-812`
- 代码事实：except 后把 Base64 **密文原样** `AddOrSetValue` 当明文值，上层拿到密文继续运行。
- 期望：解密失败一律抛异常（或按调用方语义置 nil 并由上层拒绝启动），禁止密文入配置表。
- 判定：负样本（损坏密文）用例 EXIT≠0 且报解密异常；正常往返用例值一致。

### A2-04 [Critical] 密钥解密按版本字节降级

- 文件：`Core/DeepBase.KeyManager.pas:1078-1106`
- 代码事实：解密仅凭 `AData[0]=$02` 分派 AES-GCM，其余一律落未认证 CBC——翻掉首字节即把认证加密降级为可篡改密文。
- 期望：加密方案判定不得由数据首字节单点决定；用带密钥的封装/版本标记（如 key id + 显式算法枚举的头部结构），未知/被篡改版本 ⇒ 拒绝而非降级。
- 判定：翻首位字节用例必须失败（fail-closed）；原有合法密文往返 EXIT=0。

## 二、运行时稳定性组（3 条）

### A2-03 [High] SelfTerminator 命令行激活即 Halt

- 文件：`Core/DeepBase.AutoFix.SelfTerminator.pas:87-96`
- 代码事实：`HandleFatal` 仅凭 `Active` 标志走终止链路，一个命令行 flag 即可让进程自杀被外部触发。
- 期望：致命终止需二次条件（配置签名/显式确认源），flag 单独不足以 Halt。
- 判定：仅置 flag 的用例不终止（EXIT 继续跑）；带确认源的用例才触发且走完整清理。

### A2-05 [Critical] CSPRNG 缩放因子塌缩

- 文件：`Core/DeepBase.Math.Random.pas:467`
- 代码事实：`(Value shr 11) * (1.0 / (1 shl 53))`——常量在 32 位语义下 `1 shl 53` 退化为 `1 shl 21`，缩放因子错误，随机数高位异常收缩，熵损失数量级。
- 期望：修正为正确的 64 位缩放（Delphi 中须用 `Int64` 承载，如 `(1 shl 53)` → `Int64(1) shl 53` 或改用 `System.Math` 既有实现；先查 RTL 有没有现成的再自己写）。
- 判定：统计用例（大样本均值/分布/去重率）不得再出现高位塌缩特征；调用方单元既有测试全绿。

### A2-08 [Critical] 虚拟滚动 0 高度项死循环

- 文件：`Core/DeepBase.VirtualScroll.pas:466-471`
- 代码事实：高度为 0 的项 `CurrentOffset` 不递增，循环永不退出。
- 期望：每轮迭代强制 `CurrentOffset` 至少推进一个单位（或高度 0 项按 1 处理）。
- 判定：构造含 0 高度项的数据，调用 EXIT=0 且有界返回；常规用例回归绿。

## 四、事件/资源/注入面组（3 条）

### A2-10 [Critical] 事件监听比较忽略 Data 自指针

- 文件：`Core/DeepBase.HB.Core.pas:1207-1218`
- 代码事实：`FListeners.Contains(AListener)` 对 `TNotifyEvent` 只比 `Code` 指针（即方法地址），不比 `Data`（实例 Self）——多实例注册同一方法时第二个被误判「已存在」；`RemoveListener` 摘错实例。
- 期望：自定义比较器同时比对 `Code` 与 `Data`（`TMethod` 全等）。
- 判定：两实例注册同类名方法 ⇒ 两次都生效、按实例各摘各的；单实例增删回归绿。

### A2-11 [High] SQL 标识符白名单过宽 + 关键字黑名单缺项

- 文件：`Core/DeepBase.SQL.Utils.pas:59-73,89-91`
- 代码事实：`IsLetter` 放行 Unicode 标识符；关键字黑名单缺 `REPLACE/WITH/EXEC/CALL/BEGIN/COMMIT/GRANT/COPY`。
- 期望：标识符限 ASCII `[A-Za-z0-9_]`；黑名单补齐上述关键字；补单位测试逐词覆盖。
- 判定：黑名单逐词用例 EXIT≠0；合法标识符用例 EXIT=0。

### A2-12 [High] 日志队列无上限

- 文件：`Core/DeepBase.Logging.pas:705-712`
- 代码事实：`FLogQueue` 入队无背压，日志洪峰内存无限增长。
- 期望：设可配置上限 + 丢弃计数（丢失可观测，不许 OOM）。
- 判定：超上限压测：内存有界且丢弃计数准确；常规顺序不丢。

### A2-15 [High] PG 日志表判断永假

- 文件：`Persistence/DeepBase.SQLLogger.pas:560`

- 判定：对 `DriverName='PG'` 的假连接走 PG 分支；SQLite 分支不回归。

### A2-16 [High] SQLite 专有语法写入 PG

- 文件：`Persistence/DeepBase.Persistence.Authorization.FireDAC.pas:704-705`
- 代码事实：`INSERT OR IGNORE INTO auth_user_roles` 在 PG 必抛语法错误。
- 期望：按方言分派 upsert（PG `ON CONFLICT DO NOTHING`；SQLite 保留）；复用 A2-15 建立的方言常量表。
- 判定：双方言用例分别 EXIT=0；重复插入幂等。
