### A4 ·（P1-3）加密栈三处新缺陷（主控复核新发现，原报告未覆盖）

**A4-① CBC IV 复用（🔴）**

| 项 | 内容 |
|---|---|
| 文件:行 | `Core\DeepBase.Crypto.AES.pas:182`（构造内 `GenerateIV`）、`:254-257`（`GenerateIV` 实现）、`:396` 与 `:404`（`LIVCopy := Copy(FIV)`）、`:609`（Decrypt 用 `FIV`） |
| 问题 | `FIV` 仅构造时生成一次；此后同一实例每次 `Encrypt` 都从同一 `FIV` 拷贝 ⇒ **同实例多次加密 IV 复用**。非 GCM 分支（375–441）无认证，相同明文前缀产出相同密文，可被块重排/篡改 |
| 改法 | 每次 `Encrypt` 进入非 GCM 分支时先 `GenerateIV`（或对 GCM 外的模式在方法内生成局部 `LIV` 并作为输出前缀落盘）；同步改造 `Decrypt` 从密文头读取 IV。建议输出格式统一为 `IV(16) || Ciphertext`，并提供显式版本字节 |
| 验收标准 | 同实例连续两次加密同一明文，密文**不相等**；新增单元测试断言该性质 |
| 证据要求 | 测试输出 + `git diff --stat`；若改动影响已落盘密文的可解密性，须在提交信息中显式声明并给出迁移路径 |
| 阻塞他仓 | 否 |
