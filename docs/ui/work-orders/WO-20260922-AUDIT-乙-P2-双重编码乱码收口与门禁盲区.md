## 一、背景

主控在复核甲 A-1 证据 `06-bypass-grep.txt` 时发现文件内嵌乱码 `'鏃ュ織瀵煎嚭 - '`，溯源得：

```
Tools/LogAnalyzer/LogAnalyzer.MainForm.pas:997
  实际字节： ... '\xe9\x8f\x83\xe3\x83\xa5\xe7\xb9\x94\xe7\x80\xb5\xe7\x85\x8e\xe5\x9a\xad - ' ...
  该文件：valid_utf8 = True, U+FFFD = 0, NUL = 0, BOM = True
```

`鏃ュ織瀵煎嚭` 即「日志导出」经 **GBK 误读 → 以 UTF-8 重编码** 的双重编码乱码。

**门禁缺口**：`check_pas_encoding.js` 现行检测面为 `非法UTF-8 / U+FFFD / BOM / NUL / 孤立CR`，**对合法 UTF-8 的双重编码乱码零感知** ⇒ 该文件在 `973 个 .pas 全部通过 / EXIT=0` 的绿单之内。这与乙 R7 的 S-1「内容级乱码（合法 UTF-8 双重编码，门禁抓不到）」是**同机制、同类缺陷**，且不是孤例。

1. **G6 检测生效**：在基线快照（HEAD）上跑编码门禁，G6 命中集合 = 主控 §二 清单的子集或超集，且**主控逐件复核命中项确为乱码**（禁止把正常中文判违规）；
