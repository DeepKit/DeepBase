## 一、P1 交付：CloudBackup 归档落盘目标守卫

### 1.1 缺陷确认（复现）

工单所述缺陷经实测复现：`Features/DeepBase.CloudBackup.pas` 非加密备份分支的
`LArchivePath := TPath.Combine(FConfig.LocalBackupPath, LBackupId + '.zip')`
后直接 `TFile.Move(LTempPath, LArchivePath)`，目标已存在时抛
`ERROR_ALREADY_EXISTS` ⇒ 同一 `LBackupId` 二次备份直接失败。

关键复现障碍（写测试时发现，工单未预告）：`GenerateBackupId` 原为**私有非虚**方法，
且内部按时间戳生成，测试无法固定 ID ⇒ 无法逼近缺陷路径。

### 1.2 修复内容

| 文件 | 位置 | 改动 |
| :--- | :--- | :--- |
| `Features/DeepBase.CloudBackup.pas` | 类声明 | `GenerateBackupId` 由 `private` 提升为 `protected`，并加 `virtual` |
| `Features/DeepBase.CloudBackup.pas` | 非加密归档分支（原 :1935-1939） | 补 delete-then-move 守卫：`if TFile.Exists(LArchivePath) then TFile.Delete(LArchivePath);` 置于 `TFile.Move` 之前 |
| `Core/DeepBase.Exceptions.pas` | :172 | 新增 `EBackupInvalidIdException = class(EBackupException)` |

守卫语义与工单指定的三处同型正确实现（`HealthSignal:160-161` / `Guardian:305-306` /
`KeyManager:735-740`）一致：先删陈旧目标再 move，目标唯一化。
**未**给 `if Assigned(FEncryptor)` 分支加守卫 —— 工单已注明该分支的 `TFile.Delete`
删的是源 `LTempPath`，不构成目标守卫，但其路径不产生 `LArchivePath` 同名冲突（加密分支
目标名含加密后缀），故按工单范围只修非加密分支。

`EBackupInvalidIdException` 的来源：P1 前置复扫时发现备份 ID 直接进入
`TPath.Combine` 构造落盘路径，无白名单校验（与已闭环的 `Test_BackupId_PathTraversal`
用例同源）。本回执按"最小范围"原则仅登记、未在 R7 内扩大为独立缺陷修复 ——
详见 §四「范围外发现」。
