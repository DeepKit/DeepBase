## 一、三处待订正（主控已逐条亲算出正确值，交付方照此改）

### F1 · 加速比 6.06× 不可复算

**现文**（§2.3）：「全线程加速比 **6.06×**（相对组 1 单线程）」

**主控亲核**：证据件 `CodeReview/20261002-AUDIT-甲-MOE-EV-证据/本机-packed4bit-GEMM-基线.tsv` 的三组读数是
单线程 126.910 / 112.722 / 111.685 ms、全线程 18.268 / 16.383 / 13.597 ms。九种组合全部算过：

| 组合 | 比值 |
|---|---|
| 组1单 / 组1全（= 该行自称口径「相对组 1 单线程」） | **6.9471** |
| 组2单 / 组2全（= TSV 的 `all_threads_speedup` 6.8806） | **6.8806** |
| 组3单 / 组1全（九种中最接近 6.06 的） | 6.1137 |
| 其余六种 | 6.1705 / 6.8171 / 7.7464 / 8.2139 / 8.2902 / 9.3337 |

**没有任何组合等于 6.06**。唯一可能来源是 `docs/moe-ev-bench/run-bench.ps1` 第 84 行打印到控制台、
未进 TSV 的第一臂比值（该臂 warmup=3 与 3 组循环的 warmup=1 不同，读数本就可不同）。

**订正要求（二选一，须写明）**：

- (a) 改用可复算值并写清是哪个组合，例如「全线程加速比 **6.8806×**（组2 单线程中位 ÷ 组2 全线程中位，即 TSV `all_threads_speedup`）」；
- (b) 若坚持用第一臂的 6.06，则**必须把该臂的原始读数补进留档**（TSV 增加两行 `first_arm_single_ms` / `first_arm_all_ms`），
  并把口径标注从「相对组 1 单线程」改为「相对第一臂单线程读数（warmup=3）」。

### F2 · 「离散度」两个口径混用且未声明公式

**现文**：§2.3 报「单线程离散度 7.3% / 全线程 14.6%」，§一 E7 又引「上游自定 33.1% 的 run-to-run 噪声底」，
两者并列但**都没写公式**。

**主控亲算**：

| 口径 | 本机单线程 | 本机全线程 | 上游 3 次（14.7760/14.6655/20.1408） |
|---|---|---|---|
| **样本 sd(n−1) / 均值**（= `docs/moe-ev-bench/run-bench.ps1` 第 96 行 `Get-Spread`） | 7.26% | 14.61% | 18.94% |
| **极差 / 均值**（= 上游 `spread 33.1%` 的口径） | **13.00%** | **29.04%** | **33.13%** |

**订正要求**：在 §2.3 的口径表里**显式写出公式**（现在只写「组间离散度」四个字），并把**两个口径都列**。
同时补一句影响说明：按上游自己的口径，本机全线程离散度是 **29.04%**（不是 14.61%），与上游 33.13% **同一量级**；
因此「本机比上游全模型最好档慢 1.26×」这一 **26% 的差异落在双方噪声底之内**（本机三组本身横跨 1.042×~1.400×），
引用它时必须与这句放在一起。结论件已声明「严格说不可对标」，订正后要把噪声底这句话补足。
