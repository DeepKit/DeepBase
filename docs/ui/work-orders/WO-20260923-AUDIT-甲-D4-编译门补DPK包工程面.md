## 一、为什么这不只是"少扫一类"

`FMX/DeepBase.FMX.HB.Choice.pas(940) E2003 'ColorToARGB'` 之所以能被 D3 撞见，
只是因为 **`Tools/FMXGallery/hbtheme_fmx_gallery.dpr` 恰好引用了它**。

⇒ 也就是说：**当前这道门能否发现生产缺陷，取决于有没有一个恰好引用它的 exe 工程。**
这个依赖太脆弱——画廊工程哪天删了、或改成不再引用该文件，生产缺陷就彻底隐身了。

**本单把这条脆弱依赖去掉。**

## 三、必做四件事

### 3.1 包工程纳入编译面

- `git ls-files '*.dpk'` 全量纳入；统计行仍必须打印
  **`DPK总数 / 成功 / 失败 / 被跳过 / 失败子路径`**，且 `被跳过=0` 这条语义不变；
- 层数 layering：T0/T1/T2 由外部清单决定，**代码里不得写死路径白名单**。

### 3.2 三条 fail-closed 扩展到包面

既有的三条（readdir 失败 ⇒ EXIT=2 / 计数为 0 ⇒ EXIT=2 / 任一 BUILD_EXIT≠0 ⇒ EXIT=1）**逐条对 `.dpk` 也要成立**，并各配 1 例负向样本。

### 3.3 负向样本补齐

现有 16 例**全部保留**（不得替换），新增至少 3 例：
1. `--manifest` 指向不存在文件 ⇒ **EXIT≠0**；
2. 清单为空 ⇒ **EXIT≠0**；
3. **故意改坏一个 `.dpk`** ⇒ 在包面上真红（证明包是真被编译，不是只被枚举）。

**保留正对照**（合法包 ⇒ `EXIT=0`），它堵的是「门恒红」这一反向失效——那是本门设计里最该保留的一处。

### 3.4 成本如实申报

你在 D3 已下修过一次预估（全量 1 分 37 秒热 / 4 分 03 秒冷）。本单把 25 个包加进来后，**重测一次耗时并写进 README**（不要沿用旧数字）。
