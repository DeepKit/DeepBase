### 3.9 ConfigDB / DataDB 文件命名与查找约�?

> 本节定义 DB1 / DB2 的文件命名规则和查找顺序，供所有集�?DeepBase 的应用统一遵循�?

- **应用名（AppName�?*：默认使用主 EXE 文件名（不含扩展名）。例如：
  - `DeepBase.exe` �?`AppName = DeepBase`
  - `MyApp.exe` �?`AppName = MyApp`
- **配置库（DB1�?*：`{AppName}Config.db`
  - 本项目示例：`DeepBaseConfig.db`
- **业务数据仓库（DB2，推荐命名）**：`{AppName}Data.db`
  - 本项目示例：`DeepBaseData.db`

**ConfigDB（DB1）查找顺序：**

1. �?`root.txt` 指定�?ProjectRoot 目录下查找：
   - `{ProjectRoot}/{AppName}Config.db`
2. 若未找到，则回退到用户目录下�?APPDATA 路径�?
   - Windows：`%APPDATA%/{AppName}/{AppName}Config.db`
   - 其它平台：`~/.{appname}/{AppName}Config.db`
3. 若以上位置仍未找到：
   - 初始化返回错误码 `ecConfigDBNotFound`
   - **不再自动创建新的 ConfigDB**，避免多程序之间误共享或误生成空库�?

> 说明�?
> - 本文其它章节中出现的 `config.db`，均应理解为“当前应用的 `{AppName}Config.db`（ConfigDB / DB1）”�?
> - ConfigDB 的表结构和预置键值由�?3 章统一规定；其它程序（DeepBaseRun、业务应用等）应复用这些表名�?Key 约定，仅按需要扩展�?

#### 13.4.3 迁移执行器伪代码

```pascal

  Scripts: TArray<string>;
  Script: string;
  Version: Integer;
  Applied: TList<Integer>;
begin
  // 1. 确保 SchemaMigrations 表存�?
  EnsureMigrationTable;

  // 2. 获取已应用的版本列表
  Applied := GetAppliedVersions;

  // 3. 扫描并排序迁移脚�?
  Scripts := ScanMigrationScripts(MigrationsPath);
  TArray.Sort<string>(Scripts, TComparer<string>.Default);

  // 4. 按顺序执行未应用的脚�?
  for Script in Scripts do
  begin
    Version := ExtractVersion(Script);  // V001 -> 1
    if Applied.Contains(Version) then
      Continue;

    // 5. 事务内执�?
    FConnection.StartTransaction;
    try
      ExecuteScript(Script);
      RecordMigration(Version, Script);
      FConnection.Commit;
      Log(llInfo, 'Migration', Format('Applied %s', [Script]));
    except
      on E: Exception do
      begin
        FConnection.Rollback;
        Log(llError, 'Migration', Format('Failed %s: %s', [Script, E.Message]));
        raise;
      end;
    end;
  end;

  // 6. 更新 SchemaInfo.SchemaVersion
  UpdateSchemaVersion(GetHighestVersion);
end;
```

| 向后兼容 | 尽量不删除字段，先标记废�?              |

| 备份优先 | 生产环境迁移前自动备�?                |
