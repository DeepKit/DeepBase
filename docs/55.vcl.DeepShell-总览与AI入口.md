# DeepShell / TDeepMainForm 总览与 AI 开发入口

> audience: ai, developer
> status: design-contract
> scope: VCL desktop application shell

## 1. 本文件的作用

这是 AI 或开发者在 DeepBase 基础上开发新的 VCL 桌面软件时必须先读的入口文件。

读完本文件后，应该知道：

- 新程序从 `TDeepMainForm` 起步，而不是从空 `TForm` 起步。
- `DeepShell` 是桌面壳体系，`TDeepMainForm` 是继承入口。
- 哪些能力由壳内置，哪些由下游 Provider / Service 注入。
- 新软件的最小开发步骤、启动顺序、禁止事项和验收边界。

如果当前仓库还没有实现 `VCL/DeepBase.VCL.DeepShell.*.pas`，先按本文和 71-78 号文档实现 DeepShell 基础壳，再开发下游软件。

## 2. 命名约定

```text
体系名：DeepShell
入口基类：TDeepMainForm
命名空间：DeepBase.VCL.DeepShell.*
运行时包：DeepBaseVCL.dpk
设计时包：dclDeepBaseVCL.dpk（第二阶段再注册）
```

下游新程序主窗体应该继承：

```pascal
type
  TMainForm = class(TDeepMainForm)
  protected
    procedure RegisterServices; override;
    procedure RegisterCommands; override;
    procedure RegisterProviders; override;
  end;
```

## 3. DeepMainForm 的定位

`TDeepMainForm` 是可复用的 VCL 桌面软件母体。它解决每个工具型软件都重复搭建的基础设施：

- 标准主窗体结构
- 上 / 中 / 下三区折叠
- 左右悬浮工具窗
- Command / 菜单 / 工具栏 / 快捷键统一
- Context / EventBus
- MRU / 最近工作现场
- Layout / 窗口状态
- Theme / i18n
- Settings 宿主
- 状态栏 / 日志 / 任务进度 / 错误提示
- Provider / Service 接入
- Governance 预留门禁字段

它不直接实现业务：

- 不扫描项目
- 不生成结构树
- 不计算属性
- 不执行业务 SQL
- 不调用 LLM
- 不绑定 WebView2
- 不直接运行浏览器自动化
- 不直接执行高风险外部命令

## 6. 主窗体结构

DeepMainForm 的主窗体由这些区域组成：

```text
+--------------------------------------------------+
| MainMenu / ToolBar / Command Surface              |
+--------------------------------------------------+
| Top Area: Summary / Context / Key Metrics         |
+--------------------------------------------------+
| Middle Area: Main Workspace / View Host           |
+--------------------------------------------------+
| Bottom Area: Logs / Issues / Tasks / Diagnostics  |
+--------------------------------------------------+
| StatusBar                                         |
+--------------------------------------------------+

Floating Left : Structure / Navigation Window
Floating Right: Inspector / Properties Window
```

### 6.1 上中下三区折叠

三段都要可折叠：

- 上区折叠后保留一行摘要。
- 中区折叠后保留当前视图标题、最近视图和“恢复主工作区”入口。
- 下区折叠后只保留状态栏，错误或长任务可提示用户展开。

折叠状态由用户决定，并通过 LayoutService 保存。MRU 记录最近项目或最近视图关联的 layout key。

## 7. 新软件的最小代码形态

```pascal
unit MyApp.MainForm;

interface

uses
  DeepBase.VCL.DeepShell.MainForm;

type
  TMainForm = class(TDeepMainForm)
  protected
    procedure RegisterServices; override;
    procedure RegisterCommands; override;
    procedure RegisterProviders; override;
  end;

implementation

procedure TMainForm.RegisterServices;
begin
  inherited;
  // 注册业务服务：项目服务、数据库服务、LLM 服务、浏览器服务等。
  // 不要在这里直接搭 UI 控件。
end;

procedure TMainForm.RegisterCommands;
begin
  inherited;
  // 注册业务命令。所有菜单、按钮、快捷键都走 Command。
end;

procedure TMainForm.RegisterProviders;
begin
  inherited;
  // 注册 StructureProvider / MainViewProvider / InspectorProvider。
end;

end.
```

DPR 启动顺序参考。最终 `.dpr` 仍需链接 `DeepBase.Persistence.Manager.FireDAC`，否则 `DeepBase.InitializeOrRaise` 无法注册 DB1 连接适配器：

```pascal
uses
  DeepBase.Manager,
  DeepBase.Persistence.Manager.FireDAC;

begin
  Application.Initialize;
  DeepBase.InitializeOrRaise;
  try
    Application.CreateForm(TMainForm, MainForm);
    Application.Run;
  finally
    DeepBase.Finalize;
  end;
end.
```

如果程序启用 Governance，则在 DeepBase 初始化和服务注册之后，以 `gmObserve` 接入。详见 75 号文档。

## 8. 服务和 Provider 的分工

DeepShell 只认识接口，不持有业务对象指针。

Shell 内部用稳定引用表达当前对象：

```pascal
TShellObjectRef = record
  Id: string;
  Kind: string;
  ProviderId: string;
  DisplayName: string;
end;
```

下游 Provider 根据 `ProviderId + Id` 找回真实业务对象。Shell 不传递业务 `TObject`，避免生命周期和类型转换混乱。

## 10. 配置与状态规则

DeepBase 的配置铁律：

- 唯一外部定位文件是 `root.txt`。
- 正式应用的配置、状态、治理规则应进入 DB1 / ConfigDB 或框架 SettingsStore。
- 不要在下游项目散落 JSON / INI / YAML 配置文件。

DeepShell 核心不直接硬依赖 Db1 实现单元。它只依赖：

```text
IShellSettingsStore
IShellLayoutService
IShellRecentService
```

正式应用可以注册 DB1-backed SettingsStore。测试和 Demo 可以使用内存 fake store。

## 11. Governance 接入原则

第一版 DeepMainForm 只预留治理字段：

```text
Command.CapabilityId
Command.GateKey
Command.RiskLevel
Command.PurposeKey
Command.RequiresEvidence
```

真实 Governance 第二阶段接入：

```text
CommandManager.Execute
  -> GovernanceService.EnterGate
  -> 真实业务执行
```

首次接入必须用 `gmObserve`，只记录 Evidence，不阻断。稳定后再对 L2/L3 高风险命令切 `gmEnforce`。

## 12. 严禁事项

开发 DeepShell 或基于它开发新软件时，不要做这些事：

- 不要让 `TDeepMainForm` 直接依赖 WebView2、CEF、LLM、Db1、doQry、Connection Pool、Governance 实现单元。
- 不要在 Shell 层保存业务对象指针。
- 不要在按钮 `OnClick` 里直接执行业务动作，应走 CommandManager。
- 不要在 UI 线程执行长任务、SQL、网络请求、LLM 调用或浏览器自动化。
- 不要把业务设置页写进 Shell 核心。
- 不要把项目 A 的布局状态恢复到项目 B。
- 不要创建散落的 JSON / INI / YAML 配置文件。
- 不要让中区折叠后没有恢复入口。

## 14. AI 开发新软件的工作流

AI 接到“基于 DeepBase 开发一个新的 VCL 程序”时，按这个流程：

1. 阅读本文件和 71-76 号文档。
2. 检查 `VCL/DeepBase.VCL.DeepShell.*.pas` 是否存在。
3. 如果不存在，先实现 DeepShell MVP，而不是直接新建空 `TForm`。
4. 新程序主窗体继承 `TDeepMainForm`。
5. 在 `RegisterServices` 注册业务服务。
6. 在 `RegisterCommands` 注册业务命令。
7. 在 `RegisterProviders` 注册结构、主视图、探查器 Provider。
8. 业务按钮、菜单、快捷键全部绑定 Command。
9. 高风险命令填 `GateKey / RiskLevel / PurposeKey`。
10. 用 fake service 先跑 Demo，再接真实 Db1 / doQry / LLM / WebView2。
11. 按 78 号验收清单验证。

## 15. 第一版完成定义

DeepShell 第一版完成时，应满足：

- `TDeepMainForm` 可继承并启动。
- 上中下三区可折叠并恢复。
- 左右悬浮窗可显示、隐藏、保存位置。
- MRU 可记录最近项目、最近文件、最近视图。
- Layout 可恢复主窗体和三区状态。
- Theme / i18n 可切换或至少可注册。
- Settings 窗体可打开，支持 OK / Apply / Cancel。
- Command / EventBus / Context / ServiceRegistry 可用。
- Demo 不接真实数据库也能启动。
- 核心不硬依赖 Db1、doQry、Governance、LLM、WebView2。
