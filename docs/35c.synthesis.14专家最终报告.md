## R3 关键发现

### 集成与 API 一致性（评分：4/10）

**这是 v0.4 最大的盲区。** 四份文档各自内部质量已达 7-8/10，但模块间的"胶水"基本是空白：

| 问题 | 严重度 |
|------|--------|
| `SafeQuery` 返回 `TFDQuery`，`MapRow` 接受 `TDictionary<string, Variant>` — 桥接层完全缺失 | **P0** |
| `TClipboardGuard = class(IClipboardGuard)` 语法无效 — `class` 不能继承 `interface` | **P0** |
| `FAuditor` 的跨文档幽灵字段 — 32 用 `TBodyZeroAuditorImpl`、34 用 `RecordUIAOperation`，接口未定义 | **P0** |
| `AddWatchTarget` 接口声明与实现签名不一致（多出 `ExpectedPath` 参数） | **P0** |
| 无 Composition Root — 谁创建 `TSQLCipherCompatibilityConfig`？谁注入 `IWindowMonitor` 和 `TFunc<IClipboardGuard>` 到 `TUIAEngineWin32`？ | **P1** |
| `Guard.Save()` 调用责任未约定 — 34 的 `DoClipboardPaste` 直接调用 `SetContent`，从未调用 `Save`。如果 Guard.Create 时剪贴板被占用且 `FSaved=False`，`SetContent` 会覆盖用户剪贴板且无内容可恢复 | **P1** |

**一句话：四个模块各自是好的零件，但还没组装成一辆能开的车。**

### 版本演化鲁棒性（评分：6/10）

| 威胁 | 概率 | 影响 |
|------|------|------|
| **CEF 输入框定位失败** — `TUIAElementLocator` 无 web selector 能力 | 高 | 粘贴完全不可用 |
| **SQLCipher 定制编译绕过 cipher 预设** — VendorLib 动态加载未实现 | 中高 | 数据库无法打开 |
| **多微信实例 FindElement 歧义** — 两个同名 `WeChat.exe` 无法区分 | 中 | 粘贴到错误实例 |
| **Schema 破坏性变更** — 无部分兼容模式（全有或全无） | 中 | SafeQuery 整体失败 |

## 最终结论：v0.4 是否是最优设计？

**v0.4 内部模块设计已接近 8/10 水平，但模块间集成点只有 4/10。** 这不是"设计不够好"，而是审查的视角不同——前两轮的 10 位专家都在审查**模块内部**的正确性（加密对不对、并发有没有 bug、API 语法能不能编译），第三轮的集成专家第一次验证了**模块间的连线**，发现连线断了。

**v0.4 + 以下 4 项 P0 修复 = 可以进入实现的最终设计：**

| # | P0 修复 | 工作量 |
|---|---------|--------|
| 1 | 补充 32→33 数据桥接层（`SafeQueryAsDict` 或明确转换工具函数） | 文档 1 章节 |
| 2 | 修复 `class(IClipboardGuard)` → `class(TObject, IClipboardGuard)` + 声明 `_AddRef`/`_Release` | 文档 1 行 |
| 3 | 声明 `TBodyZeroAuditorImpl` 完整接口 + 统一 34 的 `FAuditor` 字段 | 文档 2 处 |
| 4 | 修复 `AddWatchTarget` 接口签名 → 拆分 `AddWatchTargetWithPath` 或合并到接口 | 文档 1 处 |
| 5 | 补充 Composition Root 章节（谁创建谁注入谁） | 文档 1 章节 |
| 6 | 文档化 `Guard.Save` 契约 + CEF 定位策略方向 | 文档 2 节 |

**以上修复后综合评分预估 8.0/10。**
