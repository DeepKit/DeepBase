# 06. AI 辅助开发指南

> 本文档规范 AI 工具（Cursor/Copilot/Claude/Warp）在 UniBase 项目中的使用，确保 AI 生成的代码复用现有库、遵循规范。

---

## 第一部分：核心原则

### 1. 搜索优先原则 ⚠️

**AI 在生成任何代码前，必须先搜索项目中是否已有相关实现。**

```
❌ 错误流程：用户请求 → AI 直接生成代码
✅ 正确流程：用户请求 → 搜索现有代码 → 找到则复用 → 未找到才生成
```

### 2. 禁止重复造轮子

| 功能 | 必须使用 | 禁止 |
|------|----------|------|
| 配置读写 | `UniBase.Config` | TIniFile/TRegistry |
| 国际化 | `UniBase.I18n.T()` | 硬编码字符串 |
| 日志记录 | `UniBase.Logger` | OutputDebugString |
| 窗体状态 | `UniBase.FormState` | 手动保存位置 |
| MRU 列表 | `UniBase.MRU` | 自建最近文件列表 |
| 数据库访问 | `UniBase.DB.DoQry` | 裸 SQL 拼接 |

### 3. 复用优先级

```
1. UniBase Core 模块（最高优先）
2. 项目公共单元 (UT.*.pas / BT.*.pas)
3. ThirdParty 已集成库
4. Delphi RTL/VCL/FMX 标准库
5. 生成新代码（最后选择）
```

## 第二部分：AI 常见错误与纠正

### 1. 重复造轮子（最高频）

```pascal
// ❌ 错误：自己写配置读取
var Ini: TIniFile;
begin
  Ini := TIniFile.Create('config.ini');
  try
    Result := Ini.ReadString('Section', 'Key', '');
  finally
    Ini.Free;
  end;
end;

// ✅ 正确：使用 UniBase API
Result := UniBase.GetConfig('Section.Key', '');
```

### 2. 违反分层架构

```pascal
// ❌ 错误：View 中直接写 SQL
procedure TfrmMain.btnSaveClick(Sender: TObject);
begin
  FDQuery1.SQL.Text := 'INSERT INTO users (name) VALUES (:name)';
  FDQuery1.ParamByName('name').AsString := edtName.Text;
  FDQuery1.ExecSQL;
end;

// ✅ 正确：通过 Controller 处理
procedure TfrmMain.btnSaveClick(Sender: TObject);
begin
  FController.SaveUser(edtName.Text);
end;
```

### 3. 忽略内存管理

```pascal
// ❌ 错误：对象泄漏
procedure ProcessData;
var List: TStringList;
begin
  List := TStringList.Create;
  List.LoadFromFile('data.txt');
  ProcessList(List);
  // 忘记 Free！
end;

// ✅ 正确：try/finally 保护
procedure ProcessData;
var List: TStringList;
begin
  List := TStringList.Create;
  try
    List.LoadFromFile('data.txt');
    ProcessList(List);
  finally
    List.Free;
  end;
end;
```

### 4. 硬编码字符串

```pascal
// ❌ 错误：硬编码
ShowMessage('操作成功');
ConnectionString := 'D:\Data\mydb.db';

// ✅ 正确：国际化 + 配置化
ShowMessage(T('Operation completed'));
ConnectionString := UniBase.GetConfig('Database.Path', 
  TPath.Combine(UniBase.RootPath, 'data.db'));
```

### 5. 线程安全问题

```pascal
// ❌ 错误：子线程直接更新 UI
TTask.Run(
  procedure
  begin
    lblStatus.Caption := '完成';  // 危险！
  end
);

// ✅ 正确：通过 Queue 回到主线程
TTask.Run(
  procedure
  begin
    TThread.Queue(nil,
      procedure begin lblStatus.Caption := T('Completed'); end
    );
  end
);
```

## 第三部分：绝对禁止清单

| 禁止项 | 原因 | 替代方案 |
|--------|------|----------|
| 硬编码中文字符串 | 无法国际化 | `T('...')` |
| `OutputDebugString` | 非标准日志 | `UniBase.Logger` |
| `TIniFile`/`TRegistry` | 配置碎片化 | `UniBase.Config` |
| 裸 SQL 字符串拼接 | SQL 注入风险 | `DoQry` 参数化 |
| `Application.ProcessMessages` 循环 | 卡死风险 | `TTask.Run` |
| `TThread.Synchronize` | 死锁风险 | `TThread.Queue` |
| 全局变量存储状态 | 测试困难 | 依赖注入/单例属性 |
| View 直接访问 DataModule | 架构混乱 | 通过 Controller |
| Controller 操作 UI 控件 | 耦合过紧 | 通过 IView 接口 |

## 第四部分：分层访问规则

```
┌─────────────────────────────────────┐
│  View (窗体/Frame)                  │ ← 只处理 UI 展示和用户输入
│  - 可访问 UniBase.I18n, FormState   │
│  - 不写业务逻辑，不直接访问数据库   │
├─────────────────────────────────────┤
│  Controller                         │ ← 业务逻辑协调
│  - 可访问 UniBase.Logger            │
│  - 通过 IView 接口或回调更新 UI     │
├─────────────────────────────────────┤
│  Model / uDM                        │ ← 数据访问和领域模型
│  - 可访问 UniBase.DB.DoQry          │
│  - 不依赖 View 或 Controller        │
└─────────────────────────────────────┘
```

## 第五部分：提示词模板

### 简洁版（推荐）

```
你是 Delphi/UniBase 开发专家。遵循以下铁律：

1. **搜索优先**：写任何代码前，先搜索项目中是否已有类似实现
2. **复用 UniBase**：配置用 GetConfig、日志用 Log、翻译用 T()
3. **分层严格**：View 只管 UI，Controller 管逻辑，Model 管数据
4. **内存安全**：对象创建必有 Free，用 try/finally 保护
5. **禁止硬编码**：字符串用 T()，配置用 GetConfig

禁止使用：TIniFile, TRegistry, OutputDebugString, Application.ProcessMessages
```

### 极简版（一句话）

```
写代码前先搜索项目现有实现，优先复用 UniBase API（GetConfig/Log/T），严格遵守 View-Controller-Model 分层，对象创建后必须 try/finally Free。
```

## 第六部分：强制复用检查点

**AI 在以下场景必须先搜索现有实现：**

| 意图 | 必须搜索 | 复用目标 |
|------|----------|----------|
| 读取任何配置 | `GetConfig` | UniBase.Config |
| 显示提示信息 | `ShowMessage.*T\(` | T() + 标准对话框 |
| 记录日志 | `Log.*LogDebug.*LogError` | UniBase.Logger |
| 发起 HTTP 请求 | `THTTPClient` | 检查是否有封装好的 Service |
| 解析 JSON | `TJSONObject` | 检查 Model 层是否已有解析 |
| 加密解密 | `Encrypt.*Decrypt` | UniBase.Security |
| 数据库查询 | `TFDQuery.*ExecSQL` | DoQry 或 uDM 封装 |

## 第七部分：标准代码模板

### 配置读写

```pascal
// 读取
Value := UniBase.GetConfig('Section.Key', 'DefaultValue');
IntVal := UniBase.GetConfigInt('Section.IntKey', 0);
BoolVal := UniBase.GetConfigBool('Section.BoolKey', False);

// 写入
UniBase.SetConfig('Section.Key', NewValue);
```

### 国际化

```pascal
Caption := T('Window Title');
ShowMessage(T('Operation completed'));
ShowMessage(TFmt('Processed %d items', [Count]));
```

### 日志记录

```pascal
UniBase.Log(llInfo, 'ModuleName', 'Operation completed');
UniBase.Log(llError, 'ModuleName', 'Failed: ' + E.Message);
```

### 异步操作

```pascal
TTask.Run(
  procedure
  var Data: TMyData;
  begin
    Data := LoadDataFromServer;  // 耗时操作
    TThread.Queue(nil,
      procedure begin UpdateUI(Data); end  // 主线程更新 UI
    );
  end
);
```

## 第八部分：AI 自检清单

### 生成代码前

- [ ] 是否先搜索了项目中的类似实现？
- [ ] 是否复用了 UniBase.Config/I18n/Logger？
- [ ] 是否有硬编码中文需要改为 T()？

### 生成代码后

- [ ] 异步操作是否用了 TTask.Run + TThread.Queue？
- [ ] 是否用接口解耦了 View 和 Controller？
- [ ] 所有对象创建是否有对应的 Free？
- [ ] SQL 是否全部参数化？
