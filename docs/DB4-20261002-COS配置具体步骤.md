## 〇、先做一件事：COS 到底是给什么用的（这决定了后面每一步）

**不是"给 DB4 存文件"，是给客户端升级包装载分发。** 证据链：

| # | 事实 | 出处 |
|---|---|---|
| U1 | 客户端更新走 `GET /dk/updates/manifest`，服务端在其中返回 `package_url` + `package_hash` + 签名 | 交接说明 §16.5（`:1036`）、§16.10 |
| U2 | 「客户端只认 `package_url` 字符串，**不感知 COS**。付毅侧建腾讯云 COS bucket + 备案 `download.deepkit.top`（或 CDN 域名）后，王维在 `update_manifests.package_url` 填真 URL + 生成短期签名 URL。域名/CDN 切换对客户端零改动」 | 交接说明 §16.9（`:1113`）**原文** |
| U3 | 包路径形态已有实例：`https://download.deepkit.top/ds/1.3.0/deepsync-1.3.0-win64.zip?sign=...&expires=...` | 交接说明 `:1078` |
| U4 | 客户端对升级包有五道校验：文件 hash → 包签名 → manifest payload 重算 → `manifest_hash` → manifest 签名，任一失败且 `signature_required=true` ⇒ `usFailed` 不安装 | 交接说明 §16.5「客户端校验顺序」；`Features/DeepBase.Update.Contracts.pas` |

### ⚠ 决策材料的一处事实订正（须同步改）

`docs/DB4-20261002-COS未配置决策材料-草稿.md` §一 F6 写「**本仓无任何需求文档描述** COS 用途」、
§五 A1 默认「D1 = 无书面需求」——**这两条已被 U1–U3 推翻**：用途有书面定义（升级包分发），
且交接说明 `:1113` **点名责任人是付毅**。
⇒ 该决策材料"三选一"里的 **O1（不配）已不成立**：升级包分发没有 COS/对象存储就没有落点。
⇒ 本步骤文档替代该材料的 §四 D1 问题——那个问题已经有答案了。

### ⚠ 另一个必须知道的硬闸门（交接说明没写，王维照说明做必踩）

客户端下载 URL 有一道**主机白名单 fail-closed 门禁**：

| # | 事实 | 出处 |
|---|---|---|
| G1 | `ValidateUpdateEndpointUrl(AUrl, AAllowedHosts)`：**空名单直接拒绝**，不提供"空=放行"语义 | `Features/DeepBase.Update.Contracts.pas:140` |
| G2 | 白名单的默认锚点 = **客户端初始化时人工配置的 `UpdateUrl` 的 host**；未显式配 `UpdateHostWhitelist` 时只认这一个 host | `Features/DeepBase.Updater.pas:905-913` |
| G3 | 亦即：`UpdateUrl` 是 `https://api.deepkit.top/dk/updates/manifest`，则 `package_url` 的 host **也必须是 `api.deepkit.top`** | G2 的推论 |
| G4 | 若 `package_url` 填 `https://download.deepkit.top/...` 而 `UpdateUrl` 是 `api.deepkit.top` ⇒ **客户端 fail-closed 拒绝下载，升级直接失败** | G1+G2+G3 合取 |
| G5 | 解法二选一：**(a)** COS 自定义域名就复用 `api.deepkit.top` 的路径前缀（如 `https://api.deepkit.top/downloads/ds/...`）；**(b)** 客户端侧显式把 `download.deepkit.top` 加进 `UpdateHostWhitelist`（`DeepBase.Updater.pas:328` 是可写属性） | G1–G4 的解法 |

⇒ **这是全流程唯一会让功能"配通了却用不了"的点**，必须在建桶前定掉，否则白花钱。
交接说明 §16.9 说"域名/CDN 切换对客户端零改动"——**这句话只在 G5 的 (a) 或 (b) 满足时成立**，
必须补一条说明给王维（见 §六）。

## 二、逐步操作

### S0 · 定域名方案（**先做这个，10 分钟**）

回答一个问题：**COS 的对外域名，和客户端 `UpdateUrl` 的 host，是不是同一个？**

- **同一个**（推荐，走 G5-a）：后续 COS 自定义域名填 `api.deepkit.top`，路径用 `/downloads/` 前缀。
  好处：客户端零改动、白名单天然通过。
- **不同一个**（走 G5-b）：COS 用 `download.deepkit.top`，但**必须**在客户端初始化处把该 host
  显式加进 `UpdateHostWhitelist`（`Features/DeepBase.Updater.pas:328`）。
  代价：客户端要发一版；且今后每加一个下载域都要改客户端。

> 建议 **(a)**。CDN/域名切换的自由度用"改 `UpdateUrl` 路径"来换，比"每加一个域就发一版客户端"便宜。

### S1 · 域名备案（最先启动）

1. 域名须已在腾讯云 DNS 解析（或已转入）。
2. 提交 ICP 备案 + **腾讯云接入备案**（两个都要，只做 ICP 不能在腾讯云用 CDN）。
3. 备案号下来前：COS 只能用默认域名 `<Bucket>-<AppId>.cos.<region>.myqcloud.com` 做**内测**，
   自定义域名与 CDN 都不通。
4. 备案通过后：把 CNAME 指向腾讯云提供的加速域名。

**验证**：腾讯云控制台备案状态 = 「已备案」；`dig download.deepkit.top` 返回 CNAME 且最终落到腾讯云。

### S2 · 云账号与 CAM（不要用主账号密钥）

1. 登录腾讯云 → 访问管理 CAM → **用户** → 新建子用户，命名 `cos-deepkit-deploy`。
2. 权限策略选**自定义策略**，只授予目标桶的操作（**不要**用 `QcloudCOSFullAccess` 全局策略）：

   ```json
   {
     "version": "2.0",
     "statement": [{
       "effect": "allow",
       "action": [
         "cos:PutObject", "cos:GetObject", "cos:DeleteObject",
         "cos:HeadObject", "cos:ListParts", "cos:AbortMultipartUpload"
       ],
       "resource": ["qcs::cos:ap-guangzhou:uid/<你的APPID>:deepkit-download/*"]
     }]
   }
   ```
3. 保存 **SecretId / SecretKey**（只显示一次）。**这两个值就是交接说明里
   `COS_SECRET_ID` / `COS_SECRET_KEY` 的填写内容**，但**不给王维**——见 §四边界表。

**验证**：用子账号 key 调一次 `cos ls`/`HeadObject` 成功；用同一 key 访问**别的**桶返回 `AccessDenied`。

### S3 · 建存储桶

| 配置项 | 取值 | 为什么 |
|---|---|---|
| 名称 | `deepkit-download`（全局唯一，重名就加后缀） | 与 `COS_BUCKET` 对应 |
| 地域 | **ap-guangzhou**（或离主要客户最近的地域） | 客户端在国内；跨地域下载慢且贵 |
| 访问权限 | **私有读写** | **绝不能公有读**：升级包靠签名 URL 授权，公有读等于谁都能拿安装包 |
| 服务端加密 | SSE-COS（可选，成本极低） | 合规加分项 |
| 版本控制 | **开** | 防误删/覆盖已发布安装包 |
| 多 AZ | 看预算（标准存储建议开） | 可用性 |
| 存储类型 | 标准存储 | 升级包会被反复下载，不适合低频/归档 |

**验证**：桶详情页四项（私有读写 / 版本控制开 / 地域 / 加密）逐项截图留档。

### S4 · 自定义域名 + CDN + HTTPS

1. 桶 → **域名管理** → 自定义源站域名 → 填 S0 定下的域名（如 `api.deepkit.top`）。
2. 回源鉴权：**不开**（因为用签名 URL 控制，不靠回源鉴权）。
3. 开启 **CDN 加速**（国内流量经 CDN 更省，且客户端下载体验好）。
4. 配置该域名的 **HTTPS 证书**（腾讯云免费证书即可，注意 3 个月一续）。
5. 把 CNAME 指到腾讯云给的加速域名。

**验证**：`curl -I https://<你选的域名>/` 返回 403（私有桶的预期响应，说明域名+HTTPS 通了，只是没签名）；
有证书却返回证书错误 = S4 未完成。

### S5 · 目录约定 + 上传首个真包

路径沿用交接说明 `:1078` 的既有形态：

```text
/ds/<version>/deepsync-<version>-<platform>.zip
例：/ds/1.3.0/deepsync-1.3.0-win64.zip
```

1. 上传第一个真包（用 S2 的子账号，不要用主账号）。
2. **立刻算好它的 sha256 并小写去前缀**——这个值就是 `package_hash`，
   客户端第一步校验就是它（`NormalizePackageHash` 去 `sha256:` 前缀 + 小写）。
3. 版本控制已开 ⇒ 同路径重复上传不会丢历史，可回滚。

**验证**：`sha256sum` 本地算出来的值，与控制台对象属性里显示的 ETag/自校验值**一致**。

### S6 · 生成签名 URL 交给王维

1. 用子账号密钥生成**短期有效**的预签名 URL（签名参数含过期时间）。
2. 把「URL + `package_hash` + `signature` + `manifest_hash` + `manifest_signature`」这一组交给王维，
   由他填进 `update_manifests.package_url` 及相关字段。
3. 签名算法按交接说明 §16.10：**RSA-SHA256（PKCS#1 v1.5）**，base64；包签名与 manifest 签名
   用同一私钥（env `UPDATE_SIGN_RSA_PRIVATE_KEY_PEM`），**与 license 的 Ed25519 隔离**。

> ⚠ 注意 §16.10 明写这条：返回体里的 `signature_algorithm` / `signature_required`
> **不被客户端消费**，写任何值都不改变行为——所以别指望改这两个字段"放宽验证"。

**验证**：拿签名 URL 能下载到完整文件；过期后同一 URL 返回 403。

### S7 · 外网拉取验证 + 白名单核对（**最容易在这里翻车**）

1. 从**外网**（不是腾讯云内网）`curl -O '<签名URL>'`，下载后 `sha256sum` 比对等于 S5 的值。
2. **核对 host**：这个 URL 的 host 必须与客户端 `UpdateUrl` 的 host 一致，
   或已在客户端 `UpdateHostWhitelist` 里（见 §〇 G4/G5）。
3. 若是 G5-b 方案：确认客户端那一侧已发版且含新 host。

**验证**：外网下载成功 + hash 一致 + host 在白名单内 ⇒ 三者全绿才叫"配通了"。
只绿前两条 = 客户端仍会拒绝，**功能等于没配**。

### S8 · 生命周期与轮转

| 项 | 做法 |
|---|---|
| 生命周期规则 | 删「临时/测试前缀」下 7 天前的对象；正式 `/ds/` **不设自动删除** |
| 密钥轮转 | 每 **90 天**换一次 SecretKey（旧 key 保留 7 天并存期后删除） |
| 用量告警 | 配存储容量 + 外网下行流量告警（CDN 流量是持续成本） |
| 证书续期 | HTTPS 证书 3 个月一续，设日历提醒 |

## 三、成本预估（不写死数字，控制台可当场估算）

| 项 | 计费方式 |
|---|---|
| 存储 | 按 GB·月，标准存储 |
| 外网下行流量 | 按 GB（**这是主要持续成本**，客户端每次升级都走它） |
| CDN 流量 | 通常比 COS 直连外网便宜，且国内更快 |
| 请求次数 | 按万次 |
| 备案 / 证书 | 备案免费；腾讯云免费证书 0 元（3 个月续） |

⇒ 用腾讯云控制台「价格计算器」按"预计月活 × 平均包体 × 月升级次数"算，比任何估算数字都准。

## 六、必须补给王维的一条说明

交接说明 §16.9「域名/CDN 切换对客户端零改动」**需要补边界**。建议追加：

> `package_url` 的 **host 必须与客户端已配置的更新端点 host 一致**
> （或在该客户端版本的白名单内）。客户端对下载 URL 有主机白名单 fail-closed 校验，
> 空名单或名单外主机**直接拒绝下载**，不会降级、不会提示"请手动下载"。
> ⇒ 若最终使用独立下载域（如 `download.deepkit.top`），请在实施前告知我方，
> 我方需在客户端侧登记该 host 后才能联调。

**这条不补的后果**：王维按现有说明填一个独立下载域 ⇒ 客户端全部升级失败，
且现象是"静默拒绝"（fail-closed 只报 `usFailed`，不明说 host 不在名单）⇒ 极难定位。
