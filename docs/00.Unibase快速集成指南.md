## 0. 外部程序集成 UniBase（一页说明）

本节面向已经有自己 Delphi 工程的开发者，目标是：

- 在现有程序中初始化 UniBase（配置 + 日志 + i18n + 主题 + 安全）
- 集成 **DoQry** 做业务数据库访问
- 集成 **LLM 模块** 调用大模型
- 采用 `root.txt + DB1 + DB2 + DB3` 的统一目录与数据库布局，便于重构与迁移

> **不强制安装设计时包**：
> 
> - 如果只是做运行时集成（不在 IDE 里拖控件），可以**只把 `Core/` 源码加入项目或 Library Path**，直接 `uses UniBase.*` 即可，不必安装 `dclUniBaseCore.dpk`。
> - 设计时包安装仅用于在 IDE 里使用 VCL/FMX 控件（如 `TI18nLabel`, `TFormStateHelper` 等）。

### 0.1.0 delphi适配要求

1. 尽量使用TFrame或TLayout，分担主窗体责任；

2. 所有控件和初始属性必须在设计时设置好；如非必要，尽量少在运行时创建控件和调整属性；

3. 所创建的pas | dfm | fmx 文件，必须以utf8 + bom 的格式保存，以免出现乱码；

   写代码前，必须阅读：**D:\_Progs\05docs\delphi程序开发约定指南.md**

### 0.1.1 样例数据库（快速开始）

UniBase 提供了一个完整的样例数据库，包含所有 17 个表：

```
data/样例Config.db  →  复制并重命名为 {AppName}Config.db
```

**快速开始步骤**：

1. 复制 `data/样例Config.db` 到你的项目目录
2. 重命名为 `{AppName}Config.db`（如 `MyAppConfig.db`）
3. 在 EXE 同目录创建 `root.txt`，内容为数据库所在的绝对路径
4. 调用 `UniBase.Initialize` 即可

### 0.1 为什么要在其它程序集成 UniBase？

对一个已有 Delphi 工程，引入 UniBase 的直接收益：

1. **配置集中到 config.db**
   - 原来散落在 `INI/Registry/JSON` 里的配置，统一迁移到 SQLite `Settings` 表，方便备份、迁移和环境切换。
2. **root.txt + 多库布局（DB1 + DB2 + DB3）统一管理**
   - `root.txt` 锚定项目根目录；
   - `DB1 = config.db`（框架与应用配置）
   - `DB2 = data.db`（业务数据库：可选，或使用 PG 等外部库）
   - `DB3+ = 其他功能库`（如 Studio、Tray 或业务子系统独立 DB）
   - 所有路径通过 UniBase.Manager 统一计算，便于重构、迁移到新目录或多实例部署。
3. **基础设施统一**
   - 配置：`UniBase.Config`
   - 日志：`UniBase.Logging`（文件 + SQLite）
   - 国际化：`UniBase.i18n` + Studio 翻译工具
   - 窗体状态：`UniBase.FormState` / `TFormStateHelper`
   - 安全/密钥：`UniBase.Security`（DPAPI）
   - 业务数据访问：`UniBase.DB.DoQry`
   - LLM 调用：`UniBase.LLM`
4. **渐进式重构友好**
   - 可先只接入 `root.txt + config.db` 和日志；
   - 然后逐步迁移配置、i18n、MRU、热键等，不需要“大爆炸式重写”。

### 0.3 root.txt + DB1 + DB2 + DB3 布局（非常重要）

UniBase 推荐所有程序集成使用统一的磁盘布局。

#### 0.3.1 从 root.txt 到 {AppName}Config.db 的解析流程（最易出错）

1. **确定应用名 AppName**
   
   - 默认：`AppName = ExtractFileNameWithoutExt(ParamStr(0))`，也就是 EXE 文件名去掉扩展名；
   - 例如：`MyApp.exe` → `AppName = 'MyApp'`。

2. **读取 root.txt 得到 RootPath**
   
   - 查找顺序：
     
     1. `<exe_dir>\\root.txt`
     2. `%APPDATA%\\<AppName>\\root.txt`
   
   - `root.txt` 要求：
     
     - 第一行是**存在的绝对目录路径**，例如：
       
       ```text
       D:\\Projects\\MyAppRoot
       ```
     
     - 不要加引号、不写相对路径、不写 INI 段落头（`[Paths]` 等）。
   
   - 如果找不到 root.txt，则 `InitializeEx` 会尝试在 EXE 目录或 `%APPDATA%` **自动创建** 一个 root.txt，并把对应目录作为 RootPath。

3. **推导配置库 {AppName}Config.db**
   
   - Manager 代码等价于：
     - `ConfigFileName := AppName + 'Config.db';`
     - 首先尝试：`ConfigDBPath := RootPath + '\\' + ConfigFileName;`
     - 若文件不存在，则回退到：`%APPDATA%\\<AppName>\\<AppName>Config.db`。
   - 如果两个位置都找不到，就报错 `Config database not found`，UniBase 无法初始化。

4. **典型错误示例**（建议在联调时检查）：
   
   - `root.txt` 写了相对路径，如 `..\\data`，导致 Manager 无法识别（要求绝对路径）；
   - 把配置库命名为 `config.db` 或放在 `RootPath\\data\\config.db`，但没有命名为 `{AppName}Config.db` 放在 RootPath；
   - `root.txt` 指向了一个目录 A，而你却把 `{AppName}Config.db` 放在目录 B；
   - EXE 改名为 `MyApp2.exe`，但仍然只创建了 `MyAppConfig.db`，此时 Manager 会去找 `MyApp2Config.db`。

> 建议：
> 
> - 每个外部程序在第一次集成时，明确约定“EXE 名 + RootPath + {AppName}Config.db”三者；
> - 通过一个小测试程序调用 `UniBase.InitializeEx` 并输出 `RootPath` 和 `ConfigDBPath`，确认路径无误后再接入业务代码。
> 
> 如果希望用 UI 引导最终用户选择 RootPath，可以复用 `TDBInitWizard`（单元 `VCL/UniBase.VCL.DBInitWizard.pas`），它会帮助写入/清理 EXE 目录下的 `root.txt`，然后再调用 `UniBase.InitializeEx`。

#### 0.3.2 DB1/DB2/DB3 角色划分

1. **DB1：配置数据库 config.db（必选）**
   
   - 引擎：**SQLite（UTF-8，WAL 模式）**。
   
   - 物理文件名：`{AppName}Config.db`（例如 `MyAppConfig.db`）。
   
   - 典型位置：
     
     - `RootPath\\MyAppConfig.db`，或
     - `%APPDATA%\\MyApp\\MyAppConfig.db`（当 EXE 目录只读时）。
   
   - 作用：
     
     - 存放 UniBase 自己的表（SchemaInfo/ProjectInfo/Settings/FormStates/Languages/I18nTexts/Logs/MRU/Hotkeys/Queries/Themes/LLMConfiguration/LLMCalls/...）；
     - 外部程序也可以安全地在此库中增加自有配置表，但**建议与 UniBase 表区分 Schema 或前缀**。
   
   - Schema 版本：
     
     - 当前版本：`SchemaInfo.SchemaVersion = '0.3'`；
     - 版本范围由 `UniBase.Schema` 中的 `MIN_COMPATIBLE_SCHEMA_VERSION` / `MAX_COMPATIBLE_SCHEMA_VERSION` 控制。
   
   - **其它程序连接 DB1 的规范**：
     
     - 只要根据上节规则找到 `ConfigDBPath`，即可按普通 SQLite 打开；
     
     - 推荐 PRAGMA/参数（以 Delphi FireDAC 为例）：
       
       ```delphi
       Conn := TFDConnection.Create(nil);
       Conn.DriverName := 'SQLite';
       Conn.Params.Database := ConfigDBPath;       // = UniBase.ConfigDBPath 或上一节约定的路径
       Conn.Params.Values['LockingMode'] := 'Normal';
       Conn.Params.Values['Synchronous'] := 'Normal';
       Conn.Params.Values['JournalMode'] := 'WAL';
       Conn.Params.Values['OpenMode'] := 'CreateUTF8';
       Conn.LoginPrompt := False;
       Conn.Connected := True;
       ```
     
     - 其它语言/驱动：
       
       - 连接字符串中建议开启 `journal_mode=WAL`、`synchronous=NORMAL`；
       - 一律使用 UTF-8 文本；
       - 不要关闭 WAL 或强制 `DELETE` 日志模式，否则会影响 UniBase 并发访问。
     
     - 并发与写入约束：
       
       - 如果 UniBase 进程正在运行，外部程序**尽量只读访问** DB1（读取 Settings、Queries、Languages 等）；
       - 如需写入 Settings 等配置项，建议：
         - 在应用内使用 `UniBase.Config.SetConfig` 完成（推荐）；或
         - 在**离线维护工具**中修改（此时停掉业务程序，避免并发写入冲突）。
     
     - 禁止操作：
       
       - 不要 `DROP/ALTER` UniBase 自带的表结构（SchemaInfo/Settings/Logs/...）；
       - 不要手动更改 `SchemaInfo` 中的版本号；
       - 不要对 UniBase 表做 `VACUUM INTO` 后替换文件，除非确定版本兼容且已停止所有 UniBase 进程。

2. **DB2：业务数据库 Data.db（可选）**
   
   - 物理文件名示例：`MyAppData.db` 或独立的 PostgreSQL/其它 RDBMS。
   - 典型位置：`RootPath\\data\\MyAppData.db` 或专用 DB 服务器。
   - 访问方式：
     - 由你的 `uDM` 或仓储层创建自己的 `TFDConnection`（针对 SQLite/PG 等）；
     - 使用 `UniBase.DB.DoQry`（推荐）或自有封装进行访问；
     - **不要把业务数据混在 config.db 里**。

3. **DB3 及更多：扩展子系统数据库（如 Studio/Tray/日志分析等）**
   
   - 可以为不同子应用或工具分库：
     - `StudioConfig.db` – Studio 自己的设置与项目索引；
     - `Tray.db` – Tray 工作台的日志/快捷命令等；
     - 其他业务子系统的独立 DB。
   - 所有这些 DB 都可以通过 `root.txt` + 约定路径派生出来，避免在代码中硬编码绝对路径。

> 迁移/重构时，只要：
> 
> 1. 把整个 RootPath 目录移动到新位置；
> 2. 更新 `root.txt` 第一行；
> 3. 外部程序无需改代码，就能使用新的配置库和数据路径。

#### 0.3.3 在 Settings 中约定 DB2/DB3 连接配置（统一规范）

为了让**不同程序可以按同一个规范读取 DB2/DB3 配置**，建议所有项目在 `Settings` 表中使用以下 Key：

1. **DB2 – 业务 SQLite（本地文件）**
   
   - 推荐含义：本机 SQLite 业务库，例如 `MyAppData.db`；
   - 建议 Key：
     - `DB2.Type` = `SQLite`
     - `DB2.Path` = 业务库路径：
       - 若以盘符开头（`C:\` / `D:\`），视为绝对路径；
       - 否则视为**相对 `RootPath` 的相对路径**（例如 `data\\MyAppData.db`）。
     - （可选）`DB2.ReadOnly` = `True`/`False`
   - 任何程序都可以按以下逻辑构造连接（Delphi/FireDAC 示例）：
   
   ```delphi
   uses
     UniBase.Manager, UniBase.Config, FireDAC.Comp.Client;
   
   function CreateDB2Connection: TFDConnection;
   var
     Path, FullPath: string;
   begin
     Path := UniBase.Config.GetConfig('DB2.Path', 'data\\MyAppData.db');
     if TPath.IsPathRooted(Path) then
       FullPath := Path
     else
       FullPath := TPath.Combine(UniBase.RootPath, Path);
   
     Result := TFDConnection.Create(nil);
     Result.DriverName := 'SQLite';
     Result.Params.Database := FullPath;
     Result.Params.Values['LockingMode'] := 'Normal';
     Result.Params.Values['Synchronous'] := 'Normal';
     Result.LoginPrompt := False;
     Result.Connected := True;
   end;
   ```

2. **DB3 – 业务 PostgreSQL（或其它远程 RDBMS）**
   
   - 推荐含义：主业务 PostgreSQL 数据库；
   - 建议 Key：
     - `DB3.Type` = `PostgreSQL`
     - `DB3.Server` = 服务器地址（如 `127.0.0.1` / `db.mycorp.com`）
     - `DB3.Port` = 端口（缺省 `5432`）
     - `DB3.Database` = 数据库名
     - `DB3.User` = 用户名
     - `DB3.Password` = 密码（建议使用 UniBase.Security 加密后存储，对外暴露前先解密）
   - 构造连接示例（Delphi/FireDAC）：
   
   ```delphi
   uses
     UniBase.Manager, UniBase.Config, FireDAC.Comp.Client;
   
   function CreateDB3Connection: TFDConnection;
   var
     Server, Database, UserName, Password: string;
     Port: Integer;
   begin
     Server   := UniBase.Config.GetConfig('DB3.Server', '127.0.0.1');
     Database := UniBase.Config.GetConfig('DB3.Database', 'mydb');
     UserName := UniBase.Config.GetConfig('DB3.User', 'postgres');
     Password := UniBase.Config.GetConfig('DB3.Password', '');  // 如使用加密，可先调用 Security 解密
     Port     := StrToIntDef(UniBase.Config.GetConfig('DB3.Port', '5432'), 5432);
   
     Result := TFDConnection.Create(nil);
     Result.DriverName := 'PG';
     Result.Params.Values['Server']   := Server;
     Result.Params.Values['Database'] := Database;
     Result.Params.Values['User_Name']:= UserName;
     Result.Params.Values['Password'] := Password;
     Result.Params.Values['Port']     := IntToStr(Port);
     Result.LoginPrompt := False;
     Result.Connected := True;
   end;
   ```

> 约定：
> 
> - 所有使用 UniBase 的程序（主程序、工具、服务）都应尽量复用以上 `DB2.*` / `DB3.*` Key；
> - 这样任何一个新工具，只要能访问 DB1（config.db），就可以按相同规范读出 DB2/DB3 配置信息，并建立自己的连接；
> - 若未来实现统一的“数据库配置窗体”，也应直接读写这些 Key，以保证兼容性。

#### 0.3.4 DB1 表访问规范（对外开放程度）

为了避免外部程序误操作 DB1（config.db）导致框架异常，这里给出一个**按表分类的访问建议**：

1. **内部核心表（禁止直接写，必要时只读）**
   
   - `SchemaInfo`
     - 作用：记录当前 Schema 版本号、创建/升级时间；
     - 约定：仅由 UniBase 自己创建和维护；外部程序只可只读查看版本，不得修改。 
   - `ExceptionReports`
     - 作用：记录异常上报信息（堆栈、截图、环境等）；
     - 约定：写入由异常捕获/上报模块负责，外部程序仅做只读分析。 

2. **配置类表（可读写，但推荐通过 UniBase API 或官方工具）**
   
   - `Settings`
   - `ProjectInfo`
   - `Languages`
   - `I18nTexts`
   - `Themes`
   - `Hotkeys`
   - `Queries`
   - `LLMConfiguration`
   - 约定：
     - 这些表承载应用配置、国际化、主题、快捷键、查询与 LLM 配置；
     - 外部程序**可以在停机维护工具中直接读写**，但运行时推荐通过 `UniBase.Config` / `UniBase.i18n` / `UniBase.Theme` / `UniBase.DB.DoQry` / `UniBase.LLM` 等模块间接访问；
     - 若需要新增字段/行，应保持向后兼容，避免删除或重命名现有列。

3. **状态与日志类表（只读优先，写入由 UniBase 模块负责）**
   
   - `Logs`
   - `MRU`
   - `LLMCalls`
   - 约定：
     - 这些表主要用于记录运行时行为和调用历史；
     - 外部程序通常只需要**读取**（用于诊断、统计、看板），不要直接插入或更新记录；
     - 清理历史数据建议通过专用工具或脚本（如按时间批量删除），而不是单行手动编辑。

4. **状态类表（内部使用为主）**
   
   - `FormStates`
   - 约定：
     - 由 `UniBase.FormState`/`TFormStateHelper` 等模块自动读写，记录窗体位置/大小/窗口状态；
     - 外部程序一般无需操作此表，如需“重置窗口布局”，可以整体删除某些 `FormName` 对应记录，而不建议逐字段改值。

> 总结：外部程序集成 UniBase 时，**主要与 Settings/Queries/LLMConfiguration 等“配置类表”打交道**；
> 其它表尽量视为内部实现细节，仅做只读或通过官方模块间接访问。

### 0.4 不安装设计包的最小集成步骤

1. **把 UniBase 源码加入工程**：
   - 项目选项中将 `UniBase\Core` 加入 Search Path；
   - 如需 VCL 控件源码（但不安装包），可将 `UniBase\VCL` 也加入 Search Path。
2. 在你的 `.dpr` 中 `uses UniBase.Manager;`，然后按下节的方式初始化。
3. 后续只通过代码使用 UniBase 功能（Config/Logging/DoQry/LLM 等），不依赖设计时组件面板。

### 0.5 在程序入口初始化 UniBase

以 VCL 程序为例：

```delphi
program MyApp;

uses
  Vcl.Forms,
  UniBase.Manager,
  MainFormUnit in 'MainFormUnit.pas' {MainForm};

begin
  Application.Initialize;

  // 初始化 UniBase（使用 root.txt + config.db）
  if not UniBase.Initialize then
  begin
    ShowMessage('Failed to initialize UniBase: ' + UniBase.LastError);
    Halt(1);
  end;

  Application.CreateForm(TMainForm, MainForm);
  Application.Run;

  // 程序结束前清理
  UniBase.Finalize;
end.
```

> 提示：第一次运行前，可使用 **UniBase Studio** 或 CLI 创建/初始化 `config.db`，并在 EXE 或 `%APPDATA%` 下生成 `root.txt`。

### 0.4 集成 DoQry：统一的业务数据库访问

前提：你已经有一个指向业务数据库的 `TFDConnection`（例如 PostgreSQL/SQLite），**它与 UniBase 的 config.db 连接是两条线**。

1. 在应用初始化成功后（`UniBase.Initialize` 之后）调用一次：

```delphi
uses
  UniBase.Manager, UniBase.DB.DoQry;

procedure InitDoQry;
begin
  // RootPath 用于定位 logs/ 与 queries 定义
  UniDbInit(UniBase.RootPath);
end;
```

2. 在需要访问业务库的地方创建查询上下文：

```delphi
uses
  UniBase.DB.DoQry, FireDAC.Comp.Client, DBClient;

procedure TUserService.ListActiveUsers(AConn: TFDConnection);
var
  Ctx: TUniQueryContext;
  Data: TClientDataSet;
  Rows: Integer;
begin
  Ctx := UniDbMakeContext(AConn, udbPostgreSQL, 30);  // 或 udbSQLite

  Data := TClientDataSet.Create(nil);
  try
    // ProcName 可以是 Queries 表中的逻辑名，也可以直接写 SQL
    Rows := UniDbSelect(
      'user.list_active',                        // 推荐：在 Queries 表维护
      '{"status": "active", "limit": 100}',  // JSON 参数
      Data,
      Ctx
    );

    // TODO: 遍历 Data，映射为实体
  finally
    Data.Free;
  end;
end;
```

3. 常用 DoQry API：
- `UniDbExec`            – 执行 INSERT/UPDATE/DELETE，返回受影响行数
- `UniDbSelect`          – 执行查询，填充 `TClientDataSet`
- `UniDbScalar`          – 执行标量查询，返回单值
- `UniDbInsertReturningId` – 插入并返回自增 ID
- `UniDbBeginTx` / `UniDbRunInTx` – 事务封装

详细行为可参考：`Core\UniBase.DB.DoQry.pas` 与 `Tests\Test.UniBase.DB.DoQry.pas`。

### 0.5 集成 LLM：统一大模型调用

LLM 配置和调用依赖 **UniBase 的 config.db**（使用 `LLMConfiguration`, `LLMCalls`, `LLMPromptTemplates` 表）。

1. 先在 `LLMConfiguration` 中填好 Provider、API Key、Model 等（推荐用 UniBase Studio 的 LLM 配置面板）。

2. 在代码中创建 `TUniBaseLLM`，共享 UniBase 的配置数据库连接：

```delphi
uses
  UniBase.Manager, UniBase.LLM;

procedure TestLLM;
var
  LLM: TUniBaseLLM;
  Ok: Boolean;
  Resp: string;
begin
  // 使用 UniBase.ConfigDB（配置库），不要传业务库连接
  LLM := TUniBaseLLM.Create(UniBase.ConfigDB);
  try
    Ok := LLM.Chat('用一句话介绍 UniBase 框架。', Resp, 'Default');
    if Ok then
      ShowMessage(Resp)
    else
      ShowMessage('LLM 调用失败');
  finally
    LLM.Free;
  end;
end;
```

3. 常用 LLM API：
- `Chat(const Prompt: string; out Response: string; const ConfigName: string = 'Default')` – 最简单调用
- `Chat(const Prompt: string; out Response: TLLMChatResponse; ...)` – 需要 Token/耗时/错误详情时
- `ChatAsync(..., OnComplete, ...)` – 异步调用，回调在主线程触发
- `ExecuteTemplate` – 基于数据库中定义的 Prompt 模板执行
- `TestConnection` – 测试某个配置是否可用

更详细行为见：`Core\UniBase.LLM.pas` 以及 Studio 中的 LLM 配置/历史界面。

## 3. 架构分层与职责

### 3.1 逻辑分层模型

```text
View (Form/Frame) → Controller (Application Service)
                        ↓
                     Domain (Entity + Domain Service)
                        ↓
             Data Access (uDM + DoQry + 外部服务网关)
```

**View 层**

- 只负责 UI 展示与收集输入；
- 通过 Controller 接口调用业务逻辑；
- 可以使用：
  - `TI18nLabel/TI18nButton/TI18nMenuItem` 绑定 `TextKey`
  - `TConfigEdit/TConfigCheckBox/TConfigSpinEdit` 自动绑定配置
  - `TFormStateHelper` 自动保存/恢复窗口状态
- **禁止**：
  - 直接访问 `TFDConnection/TFDQuery` 或执行 SQL；
  - 读写 INI/Registry/自建 JSON 配置；
  - 直接使用 `TIniFile`/`OutputDebugString`。

**Controller 层**

- 编排业务流程，调用 Domain Service/Repository/uDM；
- 可以访问：`UniBase.Config/Logger/DoQry` 与业务 `uDM`；
- 通过 IView 接口或回调更新 UI，而不是直接持有具体 Form 类型；
- 异步模式统一使用：`TTask.Run + TThread.Queue`。

**Domain 层**

- 包含实体类型和纯业务逻辑；
- 不依赖 VCL/FMX/FireDAC/UniBase 控件；
- 应当有较高的单元测试覆盖率。

**Data Access（uDM/DoQry）**

- 只负责数据库连接、查询与事务控制；
- 不包含业务规则，不引用 VCL/FMX；
- 推荐通过 DoQry 的参数化查询接口访问数据。

```batch

Tests\\Win32\\Debug\\UniBaseTests.exe --xmloutput=TestResults.xml --exitbehavior=Continue
```

## 7. AI 行为红线（必须遵守）

AI 在本仓库中 **绝对禁止**：

- 新增 INI/Registry/随机 JSON 文件作为配置来源；
- 在任何地方硬编码中文/英文用户提示文本；
- 直接使用 `Application.ProcessMessages` 循环或 `TThread.Synchronize`；
- 在 View 中直接创建和执行 `TFDQuery.ExecSQL`；
- 在 DataModule 中引用 `Vcl.Forms`/`Dialogs` 或直接操作 UI；
- 引入全局变量保存业务状态（当前用户/订单等）。

AI 必须：

- 先搜索现有实现，再决定是否写新代码；
- 复用 `Core/`、`VCL/`、`FMX/` 中已存在的模块和模式；
- 遵守 `docs/01`、`02`、`07`、`08`、`09` 中的所有分层与安全约束；
- 在回答中说明：
  - 复用了哪些现有模块；
  - 新增了哪些最小必要改动；
  - 如何编译与测试这些改动。
