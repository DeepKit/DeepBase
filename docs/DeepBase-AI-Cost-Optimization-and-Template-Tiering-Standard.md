## 1. 核心原则：能查不调，分层阶梯

为了控制下游桌面端与云端 AI 运行成本，DeepBase 提供统一的底层调用抽象：

> ### 核心公理：能不用大模型解决的事情，就不要调用大模型。
> * **能通过本地缓存/静态模板查出来的，不重复调用大模型；**
> * **能通过低开销轻量模型局部修改的，不启动高阶重型模型；**
> * **高价值、长上下文、多约束重构任务，才路由至高阶模型。**

---

## 2. 通用调用的三级阶梯（Generic 3-Tier Invocation Hierarchy）

DeepBase AI 运行时调度器支持以下三级阶梯：

```text
       [ 应用层触发 AI 请求 ]
                  │
                  ▼
┌──────────────────────────────────────────────┐
│  Tier 1: 本地模板/缓存命中 (Template Cache)  │ ───► [命中静态或参数化槽位] ───► 本地替换返回 (Token = 0, 延迟 < 5ms)
└──────────────────────────────────────────────┘
                  │ (未命中 / 需语义泛化)
                  ▼
┌──────────────────────────────────────────────┐
│  Tier 2: 低成本轻量级模型 (Fast / Cheap LLM)  │ ───► [轻量润色 / 结构微调] ───► 快速返回 (成本极低, 延迟 < 300ms)
└──────────────────────────────────────────────┘
                  │ (高歧义 / 复杂推理 / 冲突解决)
                  ▼
┌──────────────────────────────────────────────┐
│  Tier 3: 强能力大模型 (High-Capacity LLM)    │ ───► 深度多轮上下文规划 (按需调用, 计入配额)
└──────────────────────────────────────────────┘
```

1. **Tier 1（本地模板与静态缓存）**：
   由应用层注册槽位或规则，DeepBase 运行时提供快速查找与变量注入，避免无效的 API 往返与 Token 开销。
2. **Tier 2（低成本轻量级模型）**：
   面向单句润色、语气微调、格式转换等简单任务，调用轻量、高速模型。
3. **Tier 3（强能力大模型）**：
   面向长文本生成、多源代码差异仲裁、深层人际或架构策略规划等重型任务。

---

## 3. 本地小模型（Local SLM）研发纪律

DeepBase 遵从 Human 架构裁定：**第一阶段基座不立项、不打包内置本地小模型（SLM）**。
* 避免消费级客户端因显存占用、跨平台驱动及打包体积造成发布阻碍；
* 优先依赖云端轻量模型 + 本地规则模板 + 偏好记忆缓存达成高性能与低成本。
