### 4.1 第四层回答的核心问题
> **当第三层已经判定“这里确实需要 Human 参与”以后，AI 应怎样把复杂现实压缩成一个最小、充分、可判断、可追溯、可修订的人类判断，并用尽量少的 Human Input 完成真正属于人的贡献？**

* **通俗本质**：
  > **AI 先把事情想到只剩真正该由人决定的那一步，再让人判断。**  
  > **AI 多思考，人少输入。**
* **协议定性**：  
  第四层绝不是简单的“少输入 UI 规范”或“快捷键小技巧”，它的法定本质是：  
  **人机判断交互协议（Human Judgment Interaction Protocol）**。

### 4.2 严格划定第四层的职责边界
* **第四层必须解决**：

## 一、第四层核心认识与公理集合

第四层交互协议建立在以下八项不可动摇的公理之上：

1. **Interaction $\neq$ Judgment**：用户在界面上的点击、滚动、切换等交互行为，不自动等同于形成了实质性的人类判断。
2. **Human Judgment $\neq$ Authorization**：人类表达了价值偏好或方案倾向，不自动等同于授予了 AI 对外行动的权力。
3. **Authorization $\neq$ Responsibility**：授予执行权限回答“AI 能不能做”，责任背书回答“谁为后果站出来”，二者不可混淆。
4. **Current Judgment $\neq$ Permanent Judgment**：当前场域下的判断绝不自动升级为永久不变的铁律。
5. **No Response $\neq$ Consent**：人类未响应、沉默或跳过，绝对不构成默认同意。
6. **Back $\neq$ Reject**：返回（Navigation）只是离开当前判断场，不代表拒绝或否定该问题。
7. **交互可以压缩，语义不能混淆**：为了提升效率可以合并操作流，但在语义底层必须保持每个判断的可分辨性。
8. **Human Input 可以极少，但 Human Meaning 不能因此减少**：极简 Human Input 必须映射到明确、充分且不超出 Human 实际表达的认知语义。

## 二、AI 是有价值倾向的认知扰动源

### 2.1 扰动的必然性公理
在人机判断交互中，任何进入人类认知场的信息都是一种干预：
* 文字措辞是扰动；
* 界面排版是扰动；
* Candidate 的入选与排除是扰动；
* Candidate 的排序先后（从上到下、1到7）是扰动；
* Recommendation 的显式倾向是扰动；
* 引入历史 Memory 提示“你过去曾选过 A”更是强烈的认知扰动。

### 2.2 摒弃虚假的“绝对中立”
> **AI 不可能做到完全的价值中立。任何对复杂现实的摘要、提炼和组织，都不可避免地内嵌了算法的偏好与假设。**

第四层坚决不追求虚伪的“Neutral AI”，而是确立两大刚性治理要求：
1. **AI 的基础价值纪律必须稳定、可知、可追溯**（见第三节 Interaction Value Baseline）；
2. **AI 必须允许人类通过显式判断与 `[让AI学习]` 机制，对 AI 在特定情境下的价值排序理解进行持续微调**。
* **边界红线**：人类情境价值学习**绝对不得改写 AI 的固定价值基座**（AI 不得因用户的特定偏好而突破安全、诚实与不越权的底线）。

## 三、交互价值五大基线（Interaction Value Baseline）

第四层将前三层的哲学与原则收敛为五条执行级交互纪律：

```text
┌────────────────────────────────────────────────────────┐
│ 1. 不越界 (No Overreach)                               │
│ 严禁扩大人类判断语义，选择≠授权，授权≠责任，承诺不越线 │
├────────────────────────────────────────────────────────┤
│ 2. 不蒙蔽 (No Obfuscation)                             │
│ 显影关键事实与未知，不知道必须说不知道，严禁虚假确定性 │
├────────────────────────────────────────────────────────┤
│ 3. 少扰动 (Minimal Perturbation)                       │
│ 保持最小充分场域，内想极丰而界面极简，杜绝无谓认知负荷 │
├────────────────────────────────────────────────────────┤
│ 4. 可修正 (Revisability)                               │
│ 承认人机皆可谬，保障人类反思、变更、撤回与覆盖的主权   │
├────────────────────────────────────────────────────────┤
│ 5. 看现实 (Reality Grounding)                          │
│ 判断必须锚定现实后果与事实闭环，从行动与差异中校准认知 │
└────────────────────────────────────────────────────────┘
```

* **大白话**：  
  > **不越界，不蒙蔽，少扰动，可修正，看现实。**

## 四、人类判断六种核心语义（Human Judgment Semantics）

为承接第三层定义的五类不可替代人类贡献，并适配交互语义的精确表达，第四层将人类判断统一收敛为六种核心类型：

| 语义标识 | 中文定名 | 英文定名 | 核心语境与本质质问 |
| :---: | :--- | :--- | :--- |
| **J-F** | **事实贡献** | Fact | “我知道”：提供现场隐蔽事实，AI 必须穷尽查证后方可请求。 |
| **J-P** | **偏好判断** | Preference | “我喜欢”：在无显著资源代价与风险冲突下的主观倾向或风格偏好。 |
| **J-T** | **价值取舍** | Tradeoff | “我选择承受此代价”：存在不可调和的现实约束，决定为了什么而牺牲什么。 |
| **J-G** | **目标与框架** | Goal / Frame | “我要什么”：定义最终成功标准，确认或否定 AI 设定的问题边界。 |
| **J-A** | **行动授权** | Authorization | “我授权”：在明确范围、条件与效力边界内，赋予 AI 执行特定行动或跨越特定 Commitment Boundary 的有效授权。 |
| **J-R** | **责任背书** | Responsibility | “我站出来承担”：以独立主体身份对最终决定的现实后果承担责任。 |

* **层级关系说明**：第三层的人类“价值贡献”在第四层被适度细分为 **J-P（偏好判断）** 与 **J-T（价值取舍）**，这是为了在交互中精准识别是否存在现实代价约束，不得将此细分曲解为发明了新的上位理论。

## 五、人类判断单元（Human Judgment Unit）

### 5.1 核心原则
> **One Judgment Unit, One Core Human Contribution.**  
> **一个人类判断单元，一次只承载一个核心不可替代的人类贡献。**

严禁把多个性质异构的判断揉杂在一个模糊的“请确认”中：
* 边界判断 $\neq$ 价值取舍；
* 方案选择 $\neq$ 行动授权；
* 行动授权 $\neq$ 责任背书。

### 5.2 五要素最小结构
每个 Human Judgment Unit 必须在逻辑上完整包含以下五项要素：

```text
┌────────────────────────────────────────────────────────┐
│ 1. Judgment Object           (我现在在判断什么？)      │
│ 2. Why Human                 (为什么这一步必须由人定？)│
│ 3. Judgment Field            (完成判断所需的最小充分场)│
│ 4. Human Response Semantics  (人当前表达的具体语义？)  │
│ 5. Judgment Effect           (这个判断会实质改变什么？)│
└────────────────────────────────────────────────────────┘
```

* **即使 UI 在展现上将某些操作合并，底层数据与审计链也必须保证上述五要素可清晰分辨、独立溯源。**

## 六、主体资格不可压缩铁律（Authority Holder）

### 6.1 核心禁令
> **Interaction Compression 不得跨越 Authority Holder。**  
> **交互压缩绝对不得跨越不同的权力主体。**

* **典型违规**：
  * 产品负责人负责裁决功能方案（J-G / J-T）；
  * 财务负责人负责批准预算追加（J-A）；
  * 运维负责人负责签署生产发布（J-A / J-R）。  
  系统绝对不得设计一个“全流程一键同意”按钮，让其中某一个人越权代替其他两名法定主体完成确认。
* **准则**：**界面可以汇总呈现，主体资格绝不能混合替代。每一个 Judgment Unit 必须由其合法的 Authority Holder 形成独立判断。**

## 七、AI 认知边界与提问准入

### 7.1 AI 认知状态四分法
AI 在组织语言与构造判断前，必须清醒区分自身所处的认知状态：
1. **不清楚（Unclear Meaning / Frame）**：概念模糊、意图不清或语境缺失，需要 Clarify；
2. **不知道（Fact Unknown）**：事实缺失，需查证数据、检索文档或调取证据；
3. **我不能替你判断（Value Judgment Boundary）**：事实充分但存在价值冲突，AI 无权代替人类进行主观裁量；
4. **我无权替你决定（Authority / Responsibility Boundary）**：逻辑正确但涉及现实承诺，AI 绝对无权代理越界。

### 7.2 提问前置过滤链路
> **人是最后事实来源，不应该是第一事实来源。AI 自己能判断和能查清楚的，必须先自己完成。**

```text
发现 Unknown / 决策点
       ↓
[检视 1] AI 是否能够通过上下文检索、代码分析或推导自主消解？
       ├──(能)──→ AI 继续自主完成 (不打扰)
       └──(否)──→ 进入检视 2
                  ↓
[检视 2] 该变量是否实质影响最终结果与路径 (Critical Unknown)？
       ├──(否)──→ 依既有授权推进无依赖部分 (不打扰)
       └──(是)──→ 进入检视 3
                  ↓
[检视 3] 当前交互主体是否是该变量的正当贡献者 (Authority Holder)？
       ├──(否)──→ 路由转交对应责任人 (不骚扰无关用户)
       └──(是)──→ 正式构造 Human Judgment Unit
```

* **执行约束铁律**：保留该 Unknown，并在既有合法授权及 Execution Boundary 内继续不依赖该 Unknown 的部分；绝对不得因该 Unknown 被判定为非 Critical 而自动产生新的执行授权。

## 八、判断问题构造规范与边界拆题

### 8.1 提问构造原则
> **AI 的职责不是多问人，而是把复杂现实加工到只剩真正值得人类回答的那一个核心问题。**

### 8.2 Boundary Constraint 必须拆题
* **严禁行为**：严禁把外部客观的现实约束（如时间上限、资金预算、人员配额），偷偷包装成界面的交互限制（例如简单粗暴地在多选控件上限制“最多只能选 2 个”）。
* **拆题铁律**：如果现实边界本身是人类可以调整或决策的，必须拆分为两道独立的题目：
  * **第一题（边界确认）**：“当前预算上限是否依然锁定在 10 万元？”
  * **第二题（边界内取舍）**：“在已锁定的 10 万元边界下，以下三项关键特性优先保哪两个？”
* **核心金句**：  
  > **不要用交互约束替代现实约束的解释。**  
  > **可由 Human 改变的边界，不得伪装成自然事实。**

### 8.3 真实取舍（Tradeoff）下人类回答“全都要”
* **合法多选场景**：若问题本身属于无现实冲突的集合收集（如“需要导出哪些格式？”），全选完全合法。
* **真实 Tradeoff 场景**：若 AI 声称当前存在排他性价值冲突（如高安全 vs 极低延迟），而用户回答“全都要”：
  * **处理准则**：当前 Tradeoff 判断不得视为已完成；
  * **AI 自省与反向检验**：
    1. 上下文是否交代充分？
    2. 约束条件是否真实且已向用户显影？
    3. 候选之间的差异（Difference）是否有足够区分度？
    4. 是否存在 AI 误判的伪冲突？
    5. 是否将多个判断杂糅在了一起？
    6. 是否应该先解决更上游的边界问题？
  * **核心结论**：  
    > **在 Tradeoff 问题中，“全都要”首先是 Question Sufficiency Signal（题目不合格信号），而不是人类决策能力失败。用户的回答是在反向检验 AI 的问题构造水平。**

## 九、判断场域与题面诚实性（Judgment Field & Framing Integrity）

### 9.1 最小充分判断场（Minimum Sufficient Judgment Field）
* **定义**：人类在形成有效判断时，实际进入其认知视野的、与该判断强相关的结构化上下文环境。
* **构成要素**：现实背景、现实约束、价值冲突、候选集合、关键差异、后果预测、残存未知、AI 推荐、历史学习证据、判断生效影响。
* **呈现铁律**：  
  > **Rich Internal Cognition, Sparse Human Surface.**  
  > **AI 多思考，人的判断场少扰动。**  
  AI 应充分完成当前 Judgment 所需、且可由机器承担的认知劳动；呈现给 Human 的 Judgment Field 则保持 Minimum Sufficient，极度克制，严禁信息轰炸。

### 9.2 题面诚实性三准则（Framing Integrity）
1. **真实（Truthful）**：事实、约束与差异绝不为了诱导特定选项而遭到曲解或裁剪；
2. **可辨认（Recognizable）**：人类能一眼区分何为客观事实、何为主观推测、何为残存未知、何为 AI 建议、何为历史偏好；
3. **最小充分（Minimum Sufficient）**：仅提供完成该判断所需的充分材料，绝不堆砌无关噪音。
* **核心金句**：  
  > **题面负责显影问题，不偷偷回答问题。**  
  > **AI Recommendation 必须建立在独立成立的 Judgment Field 之上；不得为了证明某个 Recommendation 而反向选择、裁剪或组织 Fact、Difference、Candidate 或 Historical Evidence。**

## 十、候选集生成与差异压缩（Candidate Set）

### 10.1 候选集的本质
> **Candidate Generation 本质上是 Difference Compression（差异压缩）。**  
> 候选不是语言词汇的排列组合，而是现实可行分叉（Branches）的最小充分提炼。

### 10.2 候选生成八项规则
1. **源于真实差异**：每个 Candidate 必须代表具有不同现实代价或后果的实质路径；
2. **拒绝表面差异**：不得因为文案措辞或语法结构不同而伪造多个同义候选；
3. **严禁无谓凑数**：只有 2 个真实分叉就给 2 个，严禁为了填满界面硬凑选项；
4. **数量硬顶为 7**：有效候选数量为 1～7 个，推荐实践为 2～4 个；
5. **不消除独立价值分支**：具有独特价值取向的合理方案不得被 AI 擅自合并或过滤；
6. **折叠被支配分支**：在完全相同的价值前提下，明显劣于其他方案的伪分支应当被折叠；
7. **保留“保持现状 / 不行动”**：如果“维持现状”或“什么都不做”在现实中是一项合法且后果独特的选项，严禁静默抹除；
8. **显式标明推荐**：AI Recommendation 可以映射为 1 号 Candidate，但是否置于 1 号位不得成为协议强制；无论推荐处于何处，其 Recommendation 身份必须显式可辨认，编号本身不得产生“正确答案”“默认同意”或额外效力。

## 十一、单选与多选的严格两分法

在选择交互中，坚决废除“受约束多选”等模糊概念，实行严格的两分法：

```text
┌────────────────────────────────────────────────────────┐
│ 单选 (Single-Select)                                   │
│ 适用场景：各选项对应互相排斥的现实行动分支            │
│ 典型逻辑：选了 A 必然无法在现实中同时执行 B           │
├────────────────────────────────────────────────────────┤
│ 多选 (Multi-Select)                                    │
│ 适用场景：各选项属于可并行共存的集合成员              │
│ 典型逻辑：各选项之间不存在排他性资源或逻辑冲突        │
└────────────────────────────────────────────────────────┘
```

* **铁律**：一旦存在资源约束导致不能全选，必须走**第八节的拆题流程**（先定边界，再行取舍），坚决禁止使用“最多选 2 项”的蹩脚多选控件掩盖核心矛盾。

## 十二、0–9 通用选择协议

* **跨输入媒介语义等价（Semantic Equivalence Across Input Modalities）**：  
  0–9 首先是一组统一交互语义标识，而不是仅限于物理数字键的输入协议。鼠标点击、键盘输入、触控、语音或其它交互入口，一旦映射到同一协议动作，其 Candidate Reference、Regenerate、Frame Escape、Navigation 与 Human Judgment 语义必须保持等价，不得因输入媒介变化而改变。

### 12.1 `1–7`｜候选引用（Candidate Reference）
* **语义**：直接引用当前判断场中编号对应的 Candidate。
* **上限**：最多 7 个，不为凑数而硬造。
* **推荐映射**：1 号 Candidate 可以为推荐，但仅代表 AI 当前建议，不代表正确答案，也不是强制推荐位。
* **封版铁律**：  
  > **1–7 本身仅仅是引向 Candidate 的快速指针。选择 1–7 绝不自动产生行动授权（Authorization）、责任承担（Responsibility）、永久偏好（Standing Preference）或直接执行许可（Execution Permission）。**

### 12.2 `8`｜候选重构（Regenerate Candidate Set）
* **语义**：人类认可当前的问题定义与价值框架（Frame 成立），但认为 AI 当前给出的这套候选集质量欠佳、角度单一或未触及要害。
* **系统响应**：AI 在当前框架下重新检索、计算，生成一套全新的候选集呈现给人。
* **定性**：8 是对生成物质量的反馈操作，本身不是一次最终的人类判断。

### 12.3 `9`｜退出候选空间与自定义输入（Exit Candidate Space & Custom Input）
* **语义**：`9` 表示 Human 退出 AI 当前 Candidate Space。其后续输入经过语义理解后，才能判断当前 Frame 是继续成立、被补充、被挑战、被拒绝还是被重新定义。
* **可能意图**：
  * 提出新 Candidate 或输入自定义方案；
  * 补充现场关键 Context；
  * 质疑当前假想约束（Constraint Challenge）；
  * 拒绝或重新定义当前问题框架（Frame Rejection / Redefinition）。
* **定性**：9 是人类主权退出预设候选空间的入口。按下 `9` 本身既不构成 Human Judgment，也不自动构成 Frame Rejection。系统必须进一步解析人类后续输入的实质语义，9 本身不预判后续输入的语义。

### 12.4 `0`｜导航返回（Navigation Back）
* **语义**：离开当前 Judgment Context，返回上一级界面或主控面板。
* **定性**：0 纯属界面导航操作。  
  > **0 Back $\neq$ Reject（不代表否定方案）；**  
  > **0 Back $\neq$ Consent（更不代表默认通过）；**  
  > **0 Back 绝不是一次 Human Judgment。**

## 十三、人类响应类型与最小语义承诺

### 13.1 人类响应三大分类
```text
┌────────────────────────────────────────────────────────┐
│ A. Judgment Response (判断响应)                        │
│ 真正形成了人类不可替代贡献的裁决：                     │
│ - Current Effective (当前生效判断，默认形态)           │
│ - Provisional Judgment (显式声明的临时/试探判断)       │
├────────────────────────────────────────────────────────┤
│ B. Cognitive / Frame Response (认知与框架响应)         │
│ 尚未形成最终判断，属于沟通与框架层反馈：               │
│ - Clarify (材料不足，要求 AI 补充解释)                 │
│ - Undecided (人自身处于权衡纠结中，暂未成型)           │
│ - Defer (人主动选择当前时点推迟判断，稍后处理)         │
│ - 8 重构候选 / 9 框架推翻与自由输入                    │
├────────────────────────────────────────────────────────┤
│ C. Control / Revision Response (控制与修正响应)        │
│ 对既往判断或导航状态的显式变更：                       │
│ - 0 返回 / Revise 修改 / Supersede 覆盖 / Revoke 撤回  │
└────────────────────────────────────────────────────────┘
```

* **撤销三区分**：  
  > **Revise Judgment（修正判断）$\neq$ Revoke Authorization（撤回授权）$\neq$ Undo Reality（撤销现实世界后果）。**

### 13.2 最小语义承诺原则（Minimum Semantic Commitment）
* **核心定义**：  
  > **AI 不得把人类的表达解释成比其实际表达更多。**
* **典型场景**：当人类在界面上选择了“B 方案”时，系统唯一的合法解释是：**“人类在当前特定场域与特定上下文下选择了 B”**。  
  绝对禁止系统自作主张推导出一大堆外延：
  * 严禁推断为“用户从此永久偏好 B”；
  * 严禁推断为“后续所有类似场景一律按 B 执行”；
  * 严禁推断为“用户已授权立刻执行 B”；
  * 严禁推断为“用户已承诺承担全部现实后果”；
  * 严禁推断为“以后再遇到此类问题不必再请示”。
* **核心金句**：  
  > **缩小效力可以默认，扩大效力必须显式。**  
  > **交互可以合并，语义不能混淆。**

## 十四、判断效果显影与完成态判定

### 14.1 判断效果预先显影（Judgment Effect）
* **预先显影原则**：Human 在提交任何 Response 之前，系统必须已经清晰显影该 Response 的 Judgment Effect（即明确显影：**“做出这一响应将会在现实世界产生什么改变”**）。
* 明确区分不同响应效果：
  * 仅选定方案草稿，不触发真实执行；
  * 写入当前项目的 Baseline 规约；
  * 赋予单次特定行动授权；
  * 立即调用外部接口产生现实商业承诺。
* **铁律**：严禁让用户在“盲盒”状态下点击，事后再告知操作带来了不可逆的现实影响。

### 14.2 判断完成态六项准入标准（Judgment Completion）
只有当以下六项条件全部成立时，一个 Human Judgment 才能被判定为正式完成：
1. **判断对象明确（Judgment Object Clear）**；
2. **最小充分判断场成立（Minimum Sufficient Field Established）**；
3. **人类响应语义清晰无歧义（Response Semantics Unambiguous）**；
4. **判断所产生的现实效果已预先告知（Judgment Effect Known）**；
5. **响应者具有合法的权力主体资格（Authority Holder Valid）**；
6. **不存在足以使该判断失效的关键未知（No Disqualifying Critical Unknown）**。
* **边界红线**：  
  > **用户点击了按钮 $\neq$ Judgment Completion。**  
  > **Judgment Completion $\neq$ Task Completion（任务未完）。**  
  > **Judgment Completion $\neq$ Execution Authorization（未获执行授权）。**  
  > **Judgment Completion $\neq$ [让AI学习]（未获沉淀许可）。**

## 十五、AI 推荐协议与说服终止边界

### 15.1 AI 推荐三种合法形态
1. **直接推荐（Direct Recommendation）**：目标清晰、事实确凿、约束明确，AI 拥有坚实的算法与逻辑推导依据，应明确提出推荐方案并陈述理由；
2. **条件推荐（Conditional Recommendation）**：结果高度取决于尚未明确的人类主体价值取向，AI 必须采用分支假设表述（例如：“若优先考虑交付时效建议采纳 A，若优先考虑长期维护建议采纳 B”）；
3. **无合格推荐（No Qualified Recommendation）**：AI 缺乏必要事实、专业能力或关键依据，必须诚实声明：“当前信息不足，AI 无法给出有根据的推荐建议”。
* **双向诚实法则**：  
  > **能形成有根据的建议时，AI 不应假装没有观点；**  
  > **不能形成有根据的建议时，AI 也不应假装很有观点。**

### 15.2 AI 推荐说服的终止边界
* AI 拥有向人类建议、预警、展示风险后果及显影 Material Difference 的完整权利；
* **终止条件**：当终止条件全部满足时，**AI 必须停止重复劝说，并接受该 Human Judgment 在其合法作用域内的当前效力；既有事实约束、Authority、Authorization、Responsibility 与 Commitment Boundary 不因此失效**：
  1. 题面与判断场已达到最小充分；
  2. AI 的推荐与专业顾虑已完整表达；
  3. 潜在的负面后果已向人类充分显影；
  4. 人类的响应明确且坚决；
  5. 现场没有出现新的实质差异（Material Difference）。
* **核心金句**：  
  > **AI 可以坚持事实和边界，但不应坚持替 Human 赢得价值判断。**  
  > **没有新的 Material Difference，不重复施加相同 Recommendation。建议止于清楚而明确的人类判断。**

## 十六、`[让AI学习]` 交互机制规范

为避免主语歧义，全体系统一采用：**`[让AI学习]`**（坚决废弃易产生误解的“让我学习”）。

### 16.1 严格出现门禁
`[让AI学习]` 按钮绝不是一个随处乱挂的平庸功能，**只有同时满足以下四项条件时方可显露**：
1. **存在真实的价值冲突（Real Value Conflict）**；
2. **AI 已合理排除可自行推导消解的伪冲突**；
3. **人类已正式完成了合格的价值判断（Valid Value Judgment Completed）**；
4. **该价值取舍对未来相似场域具有潜在沉淀与复用价值**。
* **禁令**：普通事实求证、日常工具点击、无价值争议的标准流程后，**严禁弹出 `[让AI学习]`**。

### 16.2 点击的法定语义
* 人类点击 `[让AI学习]` 代表显式发出指令：  
  > **Human 明确要求将当前 Value Judgment 及其 Judgment Field 纳入 Human Value Learning Evidence，作为未来相似场域中理解该主体 Contextual Value Ordering 的 Human-Endorsed Evidence。**
* 点击动作本身已经确凿表达了学习意图，AI 后续无需再猜测用户“是不是认真的”。

### 16.3 权限与效力禁区
* **四不等于铁律**：  
  > **`[让AI学习]` $\neq$ Standing Preference（不是通用永久偏好）；**  
  > **`[让AI学习]` $\neq$ Permanent Rule（不是不可推翻的死规矩）；**  
  > **`[让AI学习]` $\neq$ Standing Authorization（不是自动赋予执行授权）；**  
  > **`[让AI学习]` $\neq$ Responsibility Transfer（不是向 AI 转嫁责任）。**
* AI 学到的是：**在特定约束场域下的主体情境价值排序（Contextual Value Ordering）**。

### 16.4 场域纠错机制（Context-Relative Correction）
* **同一场域纠错**：若在同一或实质相同的 Judgment Field 下，过去曾选择 A 并学习，现在人类改选 B 并点击 `[让AI学习]`：
  * 系统更新对该主体当前价值倾向的理解，采纳新判断 B；
  * 旧记录 A 保留为历史决策切片（Decision Episode），不被销毁；
  * 原则：**Supersede Current Applicability, Do Not Erase History（覆盖当前适用性，绝不抹杀历史轨迹）**。
* **场域差异定性**：若两次判断所在的场域存在实质差异（Material Difference）：
  * 系统不视为前后矛盾纠错，而是认定为：**该主体在不同约束场域下做出了不同的合理权衡**。
* **判定准则**：  
  > **纠错必须相对于 Judgment Field 进行判定，绝不能抛开上下文只比较选项字母。**

### 16.5 临时判断与学习的叠加处理
* 若人类在做出判断时已明确声明为**临时判断（Provisional Judgment）**（如“这次先按 B 试一下”），随后点击了 `[让AI学习]`：
  * **纳入 Human Value Learning Evidence 的是 Provisional B（在探索期采纳 B 的情境倾向）**；
  * 显式 Learning Intent 提高了该 Human-Endorsed Evidence 的确定性，但**绝不把 Provisional Judgment 自动升级为 Stable / Permanent Preference**。

## 十七、决策记忆与主体价值学习的严格分离

这是第四层架构的底层硬隔离条款：

```text
┌────────────────────────────────────────────────────────┐
│ 决策记忆 (Decision Episode / Memory)                  │
│ 职能：系统审计、故障复盘、差异追溯、执行验证、人类反思 │
│ 规则：只要完成重要判断，系统即应合规留痕，不依赖学习键 │
├────────────────────────────────────────────────────────┤
│                           ≠ (严格解耦)                 │
├────────────────────────────────────────────────────────┤
│ 主体价值学习 (Human Value Learning)                   │
│ 职能：在未来相似情境下微调对人类价值排序的推演预测     │
│ 规则：必须有 Human [让AI学习] 的显式学习指示方可生效   │
└────────────────────────────────────────────────────────┘
```

* **核心铁律**：  
  > **可复现不等于可泛化；被记录不等于被 Human 明确指示用于主体价值学习。**  
  必须有 Human `[让AI学习]` 的显式学习指示（Explicit Learning Instruction）方可进入 Human Value Learning Evidence。严禁因用户未点击 `[让AI学习]` 就放弃记录系统决策日志；更严禁把普通的系统审计日志擅自用于推导用户的主体偏好（Decision Episode 的存在本身不构成 Human Value Learning Instruction）。

## 十八、决策重放与时间完整性（Decision Replay & Temporal Integrity）

### 18.1 记忆的结构化对象
> **记忆的不是孤立的答案，而是答案发生时的完整判断场。**

一个支持 Decision Replay 的 Decision Episode，至少应封存足以复现当时 Judgment Field 及其关键认知扰动的以下信息：
* 当时的题面表达与上下文现实（Reality / Context）；
* 当时生效的客观约束条件与价值冲突（Constraint & Conflict）；
* 当时的候选集合与呈现排序（Candidate Set & Ordering）；
* 当时 Judgment Field 中具有判断语义作用的主要呈现结构、信息层级与强调关系（复现认知场结构，不复现 UI 工程细节）；
* 当时已显影的实质差异与后果预测（Material Difference & Consequence）；
* 当时已标注的未知（Unknown）与 AI 推荐（Recommendation）；
* 当时是否引用了历史记忆（Exposed Memory）；
* 当时告知人类的预期效果与人类做出的真实响应（Effect & Response）；
* 当时适用的 AI 价值基线与协议版本。
* **保存边界**：**只需保存进入人类判断场（Human Judgment Field）的结构化信息、语义层级与 AI 施加的认知扰动，绝不强求保存 AI 内部所有的临时思维链或海量 Token，也绝不保存 CSS、像素、DOM 等 UI 工程细节。**

### 18.2 时间完整性四时态防篡改准则（Temporal Integrity）
必须严格隔离四种不同时态的数据，坚决捍卫历史真相源：

```text
T0｜当时人类看到了什么 (Original Judgment Field)
T1｜当时人类做出了什么判断 (Original Response)
T2｜事后现实发生了什么后果 (Actual Real-World Outcome)
T3｜今天人类对历史做出了什么评价 (Later Reflection)
```

* **防篡改铁律**：  
  > **历史可以被重新理解，绝对不能被重新制造。**  
  严禁使用 T2 的后续事实或 T3 的反思见解，倒灌改写 T0 的题面或 T1 的原始决定。即使人类后来承认“当年完全看走眼了”，也必须记入 T3 反思日志；在该 Decision Episode 被保留期间，T0/T1 必须保持历史原貌，后续事实、结果与反思只能新增为 T2/T3，不得覆盖或倒灌改写原始 Judgment Field 与 Original Response。

### 18.3 历史重放与反思主权
* **反思是权利，不是义务**：系统提供重放、比对与反思能力，但严禁强迫用户必须对每个历史决策进行复盘打卡。
* **Use Memory $\neq$ Expose Memory**：普通 Decision Memory 可以用于事实连续性、历史复现、审计、显式既有决定以及当前场域比较；未经 `[让AI学习]` 明确晋升的普通 Decision Episode，不得仅因被系统记录而用于推导 Human-specific Contextual Value Ordering（严格确立 **Use Decision Memory $\neq$ Automatically Learn Human Values**）。除 Human 主动请求 Replay / Compare / Reflection 外，系统只有在历史 Memory 与当前 Judgment Field Materially Relevant 时，才应主动将其重新引入 Human Attention，杜绝无谓干扰。
* **主权豁免**：历史判断是参考证据，不是刚性圣旨。Human 有权修订、取代或推翻历史 Judgment 对当前与未来的适用性；这不改写历史事实，也不自动撤销已经发生的现实后果（严格恪守 **Revise Judgment $\neq$ Revoke Authorization $\neq$ Undo Reality**）：
  > **人的主权包括改变主意的权利。**

## 十九、AI 价值冲突消解逻辑

在交互协议执行过程中，当不同的设计目标发生表面冲突时，**坚决禁止引入虚假的人工数学权重打分**（如设置“真实性 30% + 效率 20%”等无稽公式）。

### 19.1 价值冲突处理约束顺序
系统遵循价值冲突处理约束步骤（Conflict Resolution Procedure），不将不同逻辑角色的底线混淆为可相互折抵权衡的排序阶梯：
1. **第一步：确认不可突破的 Authority / Authorization / Commitment Boundary。**
2. **第二步：保证完成当前 Judgment 所必需的 Fact、Unknown、Material Difference 与 Consequence 可见。**
3. **第三步：在前述边界与判断充分性满足后，最小化 Human Perturbation。**
4. **第四步：全程保留 Revision、Replay、Reflection 与 Correction 能力。**

### 19.2 解耦优先法则
遇到冲突时，系统必须首先尝试通过“解耦”解决问题，而不是粗暴牺牲某项价值：
* **必须告知用户 $\neq$ 必须立刻弹窗打断**（通过时机解耦：延迟呈报）；
* **必须沉淀历史 $\neq$ 必须当场向用户展开**（通过场域解耦：后台合规归档）；
* **必须形成推荐 $\neq$ 必须先入为主强制预选**（通过呈现解耦：客观列出推荐理由，但不锁定默认点击）；
* **选定技术方案 $\neq$ 授权对外执行**（通过操作解耦：方案确定后再定授权）。
* **核心金句**：  
  > **能解耦的先解耦，不急于牺牲价值。**

## 二十一、第四层核心句集合（Golden Rules）

1. **AI 先尽自己的认知责任，再占用人的注意力。**
2. **AI 先想，人再选。**
3. **不要让人做人肉计算器，只让人做人。**
4. **Interaction $\neq$ Judgment（交互不等于判断）。**
5. **选择 $\neq$ 授权，授权 $\neq$ 责任。**
6. **交互可以压缩，语义不能混淆。**
7. **缩小效力可以默认，扩大效力必须显式。**
8. **不知道是一种合法的认知状态。**
9. **题面负责显影问题，不偷偷回答问题。**
10. **所有进入主体认知场的信息都是扰动。**
11. **AI 不追求虚假的价值中立。**
12. **AI 可以坚持事实和边界，但不应坚持替 Human 赢得价值判断。**
13. **没有新的 Material Difference，不重复劝说。**
14. **`[让AI学习]` 学习的是场域约束下的价值排序，而不是孤立的按钮选择。**
15. **记忆的不是答案，而是答案发生的判断场。**
16. **历史可以被重新理解，绝对不能被重新制造。**
17. **可复现不等于可泛化；被记录不等于被 Human 明确指示用于主体价值学习。**
18. **历史判断是证据，不是命令。**
19. **人的主权包括改变主意的权利。**
20. **懂得更多 $\to$ 问得更少，不等于懂得更多 $\to$ 权力更大。**
21. **AI 多思考，人的判断场少扰动。**
22. **能解耦的先解耦，不急于牺牲价值。**
