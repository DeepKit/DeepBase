# UniFlow 三层演进规划

> **版本**: 1.0 | **更新日期**: 2025-12-03
> 基于 12 轮深度讨论的智慧结晶，确保 MVP 超越 DevDirector 现有能力

---

## 1. 概述

### 1.1 什么是 UniFlow

UniFlow = **智能应用的操作系统**

它是 DevDirector（软件工程导演台）的**通用化**：
- DevDirector 专注"软件工程"领域
- UniFlow 可服务任何需要"智能流程编排"的业务

### 1.2 产品族架构

```
┌─────────────────────────────────────────────────────────────────┐
│                         业务应用层                               │
│  ┌─────────────┐   ┌─────────────┐   ┌─────────────┐           │
│  │ DevDirector │   │  链影工厂    │   │   其他应用   │  ...      │
│  │ 软件工程导演台│   │ 视频流水线   │   │  业务领域 X  │           │
│  └──────┬──────┘   └──────┬──────┘   └──────┬──────┘           │
├─────────┴────────────────┴────────────────┴────────────────────┤
│                    UniFlow 前端组件                              │
```

## 2. 产品内核

### 2.1 DevDirector 的核心能力（必须超越）

DevDirector 作为"软件工程导演台"已实现：

1. **项目/功能/步骤三层结构** - Project → Feature → Step (00-xx)
2. **执行记录与决策追踪** - Execution Log + Decision 档案化
3. **导演四层模型** - 剧本(Script) → 角色道具(Actor/Prop) → 分镜(Frame) → 场景流(ScenarioFlow)
4. **自然语言到界面视图** - NL → 问答 → UIScreen/UIRegion/UIControl/UIViewState
5. **四个 AI 角色协作** - 盘古(架构) / 灵子(数据) / 鲁班(前端) / 仙儿(审查)
6. **工作日志自动生成** - 按用户按日期汇总 WorkLog
7. **知识库** - Guideline/Pattern/BugCase 沉淀

### 2.2 UniFlow 与 DevDirector 对比

| 维度 | DevDirector | UniFlow MVP |
|------|-------------|-------------|
| 定位 | 软件工程专用 | 通用智能流程 |
| 角色 | 4 个 AI 角色（Prompt 级） | 11 个角色（架构级） |
| 流程 | 线性 00-xx 步骤 | 任意拓扑 Workflow |
| 扩展 | 固定能力 | Skill 可扩展 |
| 安全 | Prompt 引导（软执行） | 架构强制（硬执行） |
| 记忆 | WorkLog 日报 | 多层记忆体系 |

### 2.3 UniFlow 的组成

#### UniFlow.Core（核心层）
- **定位**：智能应用的操作系统
- **核心能力**：11 个标准化角色、Workflow 引擎、Skill 扩展机制、安全与信任边界、多层记忆体系

#### UniFlow.SoIs（前端组件 - 意图澄清）
- **定位**："言出即是" —— 可靠的氛围编程入口
- **核心价值**：修改准、维护稳（不是生成强）
- **可复用场景**：DevDirector 需求澄清、链影工厂视频意图、任何应用的用户意图可视化

#### UniFlow.SayDone（前端组件 - NL转换）
- **定位**：自然语言 → 结构化数据的引擎
- **核心价值**：高准确率、低幻觉率的 NL 转换
- **可复用场景**：DevDirector NL→UI、链影工厂 NL→脚本、任何应用 NL→领域结构

## 3. 三层演进规划

### 3.1 第一层：MVP（3个月）

> **核心命题**：证明 UniFlow 比 DevDirector 更强
> **验证场景**：洞见（Insight）决策支持系统

#### 技术栈

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| 核心引擎 | Delphi + FMX | 复用 UniBase（70+ 单元） |
| Python Skill | FastAPI + LiteLLM | HTTP API 方式调用 |
| LLM 调用 | LiteLLM | 支持 OpenRouter 多模型 |
| 本地存储 | SQLite | 隐私优先、离线可用 |
| 云端存储 | PostgreSQL（1.0+） | 可选同步 |

#### 必须实现的能力

**1. 完整的 11 角色运行时**

| 层级 | 角色 | MVP 实现程度 |
|------|------|-------------|
| 元层 (L0) | 引擎 + 督察 | 完整实现 |
| 决策层 (L4) | 总指挥 + 调度员 | 完整实现 |
| 智能层 (L3) | 智囊 | 基础实现（单 LLM） |
| 能力层 (L2) | 执行者 + 守卫 + 军械官 | 完整实现 |
| 基础层 (L1) | 后勤 + 记录员 + 通信官 | 完整实现 |

**2. Skill 基础框架**

Core Skills（内置 6 个）：
- HTTP 调用
- 数据库读写（UniBase 集成）
- 文件操作
- LLM 调用封装
- 定时触发
- 人工任务

**3. Workflow 引擎**

支持的任务类型：SystemTask、SkillTask、AgentTask、HumanTask

支持的流程结构：顺序、条件分支、并行、循环、子流程

**4. 安全机制**

三重守卫：门卫（入口）→ 监工（过程）→ 审核官（出口）

信任边界：
- 完全信任区：引擎/督察/后勤/记录员
- 有限信任区：总指挥/调度员/守卫/军械官/通信官
- 不信任区：智囊/执行者（输出必校验）

**5. 可观测性**

- 记录员自动记录所有角色行为
- 督察提供调试接口
- 完整的审计日志

#### MVP 验收标准

1. 能承载 DevDirector 核心流程
2. 能扩展新场景（如链影工厂视频流水线）
3. 可观测可调试
4. 安全可靠

### 3.2 第二层：1.0（MVP 后 +3个月）

> **核心命题**：成为可对外发布的产品

#### 增量能力

**1. Skill 生态基础**
- Official Extensions（钉钉/企微/飞书/邮件/AI服务）
- Skill SDK + 开发者文档
- Skill 市场（内部）

**2. 智能增强**
- 多 LLM 后端支持（模型网关、成本控制、降级策略）
- AI Persona 系统（性格内核统一，表现特化）
- 信任反馈闭环

**3. 跨产品协同**
- 上下文桥接（UniBase ↔ UniFlow 意图传递）
- 共享基础设施（模型网关、安全组件、审计系统）

**4. 高级流程能力**
- 长时运行 Workflow（检查点/恢复/超时/外部事件）
- 流程模板市场

#### 1.0 验收标准

1. 有完整的用户文档和开发者文档
2. 至少 20 个可用的 Official Skills
3. AI 输出有置信度，用户体验到"懂我"
4. 第三方能基于 SDK 创建 Skill

---

### 3.3 第三层：梦想状态（12个月+）

> **核心命题**：成为智能应用的基础设施

#### 梦想态愿景

**1. 完整的 Skill 生态**
- 四层信任体系：Core → Official → Community → User
- 公开的 Skill 市场（开发者激励、质量认证）

**2. AI 动态组合**
- 意图理解层：用户说自然语言 → AI 选择 Skill 组合
- 组合安全分析：数据流追踪、等效权限计算
- 意图确认机制：高风险操作必须人类确认

**3. 分布式运行**
- 跨节点 Workflow（分布式调度、故障容错）
- 多租户隔离（资源/数据/能力）

**4. 自进化能力**
- 从使用中学习（行为分析、Prompt 优化、Skill 推荐）
- 知识沉淀（最佳实践提炼、反模式识别）

## 4. 演进原则

### 4.1 12 轮讨论的核心智慧

1. **AI 是辅助不是守门人** — 必须有独立于 AI 的安全检查
2. **保护信任 > 提升能力** — 宁可少做，不要做错
3. **Skill 对用户不可见** — 用户看功能，系统选 Skill
4. **组合创造新攻击面** — 需要 Workflow 级安全分析
5. **UniFlow 是大脑不是胶水** — 核心价值是智能决策
6. **先做对，再做抽象** — 从具体 Skill 提炼 SDK
7. **复用基础设施，分离智能层** — AI 工程复用，领域智能分离
8. **软执行 vs 硬执行** — 安全关键准则必须硬执行
9. **状态管理是隐藏的复杂性** — 需要专门的状态管理层

### 4.2 渐进式采用路径

```
第一天：总指挥 + 执行者 + 守卫 + 后勤（最小系统）
第一周：+ 调度员（复杂流程）
第一月：+ 智囊 + 军械官（AI 能力）
第一季：+ 通信官 + 完整记忆（复杂集成）
```

## 5. 产品间的关系

| 关系 | 说明 |
|------|------|
| SoIs 调用 SayDone | SoIs 的澄清官和草图师底层使用 SayDone 的 NL 转换能力 |
| SoIs 输出到 DevDirector | Loop A 结果导入导演台；Loop B 在导演台定位节点 |
| DevDirector 基于 UniFlow | DevDirector 流程可映射为 UniFlow Workflow |
| SayDone 基于 UniFlow | SayDone 的 AI 能力通过 UniFlow 智囊角色实现 |
| 所有产品基于 UniBase | 共享配置/日志/数据库/i18n/安全等基础设施 |
