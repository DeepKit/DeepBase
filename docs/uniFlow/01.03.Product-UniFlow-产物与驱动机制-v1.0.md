# UniFlow 产物与驱动机制

> 定义 UniFlow 系统中的产物类型、归属关系，以及引擎和督察的驱动/调试机制。

## 1. 产物分类与归属

### 1.1 产物分类总览

| 产物类型 | 说明 | 生命周期 | 主管角色 |
|----------|------|----------|----------|
| **临时产物** | 计算中间结果、临时文件 | 任务内 | 后勤 |
| **过程产物** | 日志、审计记录、上下文 | 持久 | 记录员 |
| **结果产物** | 最终输出、用户可见成果 | 持久 | 执行者→守卫→总指挥 |
| **状态产物** | 系统/任务状态、检查点 | 运行时 | 调度员 + 后勤 |
| **知识产物** | Few-shot、向量记忆、学习成果 | 持久 | 记录员 + 智囊 |
| **配置产物** | Skill/Prompt 定义、模板 | 持久 | 军械官 |

### 1.2 产物详细定义

#### 1.2.1 临时产物（Temporary Artifacts）

```
┌─────────────────────────────────────────────────────────────┐
│                      临时产物                                │
│                                                             │
│   定义：任务执行过程中产生的中间数据，任务结束后可丢弃        │
│   主管：后勤                                                 │
│                                                             │
│   示例：                                                     │
│   • LLM 推理的中间 token                                    │
│   • 临时文件（/tmp/uniflow_xxx）                            │
│   • 计算缓存                                                │
│   • 下载的临时资源                                          │
│                                                             │
│   存储位置：内存 / 临时目录                                  │
│   清理策略：任务完成后自动清理                               │
└─────────────────────────────────────────────────────────────┘
```

**后勤职责**：
- 分配临时存储空间
- 设置容量和时间限制
- 任务结束后执行清理
- 紧急情况下强制回收

#### 1.2.2 过程产物（Process Artifacts）

```
┌─────────────────────────────────────────────────────────────┐
│                      过程产物                                │
│                                                             │
│   定义：系统运行过程中产生的记录性数据，用于审计和回溯        │
│   主管：记录员                                               │
│                                                             │
│   示例：                                                     │
│   • 操作日志（谁在何时做了什么）                             │
│   • 审计记录（决策依据、安全事件）                           │
│   • 上下文快照（某时刻的状态）                               │
│   • 错误记录（异常堆栈、恢复操作）                           │
│                                                             │
│   存储位置：日志文件 / 数据库                                │
│   保留策略：根据合规要求，通常 90-365 天                     │
└─────────────────────────────────────────────────────────────┘
```

**记录员职责**：
- 自动记录所有角色行为
- 提供查询和回放接口
- 确保审计日志不可篡改
- 定期归档和清理

#### 1.2.3 结果产物（Result Artifacts）

```
┌─────────────────────────────────────────────────────────────┐
│                      结果产物                                │
│                                                             │
│   定义：任务执行的最终输出，用户可见的成果                   │
│   主管：执行者 → 守卫 → 总指挥（流水线式）                   │
│                                                             │
│   示例：                                                     │
│   • 生成的文案/代码                                         │
│   • API 响应数据                                            │
│   • 生成的文件（图片、视频、文档）                          │
│   • 执行操作的确认（"会议室已预订"）                         │
│                                                             │
│   存储位置：根据类型（内存/文件/数据库）                     │
│   保留策略：由业务决定                                       │
└─────────────────────────────────────────────────────────────┘
```

**流水线职责**：
```
执行者 ──生成──▶ 守卫(审核官) ──校验──▶ 总指挥 ──交付──▶ 用户

   │                  │                    │
   │ 负责产出         │ 负责质量把关       │ 负责最终交付
   └─────────────────┴────────────────────┘
```

#### 1.2.4 状态产物（State Artifacts）

```
┌─────────────────────────────────────────────────────────────┐
│                      状态产物                                │
│                                                             │
│   定义：系统和任务的运行时状态，用于恢复和监控               │
│   主管：调度员（任务状态）+ 后勤（系统状态）                 │
│                                                             │
│   示例：                                                     │
│   • Workflow 实例状态（当前步骤、变量值）                    │
│   • 任务队列状态（待执行、执行中、已完成）                   │
│   • 检查点（用于任务恢复）                                   │
│   • 资源使用状态（内存、连接池）                             │
│                                                             │
│   存储位置：内存（主）+ 数据库（持久化检查点）               │
│   保留策略：运行时保持，任务完成后归档或清理                 │
└─────────────────────────────────────────────────────────────┘
```

**调度员职责（任务状态）**：
- 维护 Workflow 实例状态
- 创建检查点支持恢复
- 追踪任务进度

**后勤职责（系统状态）**：
- 监控资源使用
- 管理连接池状态
- 提供健康检查数据

#### 1.2.5 知识产物（Knowledge Artifacts）

```
┌─────────────────────────────────────────────────────────────┐
│                      知识产物                                │
│                                                             │
│   定义：从历史执行中提炼的可复用知识                         │
│   主管：记录员（存储）+ 智囊（使用）                         │
│                                                             │
│   示例：                                                     │
│   • Few-shot 示例库                                         │
│   • 向量化的历史对话/文档                                   │
│   • 用户偏好模型                                            │
│   • 错误模式和修复方案                                      │
│                                                             │
│   存储位置：向量数据库 / 知识图谱                           │
│   保留策略：持久，定期更新和优化                             │
└─────────────────────────────────────────────────────────────┘
```

**记录员职责**：
- 持久化存储知识
- 提供检索接口
- 管理知识生命周期

**智囊职责**：
- 从知识库检索相关内容
- 在 Prompt 中使用知识
- 产出新知识（经审核后入库）

### 1.4 记忆淘汰策略

```
┌─────────────────────────────────────────────────────────────┐
│                    记忆生命周期管理                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   记忆类型        │ 淘汰策略        │ 触发条件              │
│   ────────────────┼─────────────────┼─────────────────────  │
│   短期记忆        │ 会话结束清理    │ 会话超时/主动关闭     │
│   工作记忆        │ 任务完成清理    │ Workflow 完成/取消    │
│   长期记忆        │ LRU + 重要度    │ 容量阈值/定时清理     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**长期记忆淘汰算法**：

```typescript
interface MemoryEvictionPolicy {
  // 容量限制
  maxEntries: number           // 最大条目数（默认 100000）
  maxSizeBytes: number         // 最大存储大小（默认 1GB）
  
  // 淘汰策略
  strategy: 'lru' | 'lfu' | 'importance_weighted'
  
  // 重要度权重（strategy = importance_weighted 时）
  importanceWeights: {
    accessFrequency: 0.3       // 访问频率
    recency: 0.2               // 最近访问时间
    userFeedback: 0.3          // 用户反馈评分
    sourceQuality: 0.2         // 来源质量
  }
  
  // 保护规则
  protected: {
    minAge: 86400000           // 24小时内不淘汰
    pinned: string[]           // 永不淘汰的条目 ID
    minImportance: 0.8         // 高重要度不淘汰
  }
  
  // 定时清理
  cleanupSchedule: {
    interval: 3600000          // 每小时检查
    batchSize: 1000            // 每批清理数量
    targetUtilization: 0.8     // 目标使用率
  }
}

// 淘汰执行
interface EvictionResult {
  evictedCount: number
  freedBytes: number
  duration: number
  nextScheduled: Date
}
```

**向量记忆淘汰**：

```typescript
interface VectorMemoryEviction {
  // 相似度去重
  deduplication: {
    enabled: true
    similarityThreshold: 0.95   // 相似度阈值
    keepStrategy: 'newest'      // 保留最新/评分最高
  }
  
  // 聚类压缩
  clustering: {
    enabled: true
    minClusterSize: 10
    compressionRatio: 0.5       // 压缩到 50%
  }
  
  // 冷数据归档
  archival: {
    coldThreshold: 2592000000   // 30天未访问
    archiveStorage: 's3'        // 归档位置
    retrievable: true           // 可按需恢复
  }
}
```

## 2. 引擎驱动机制

### 2.1 引擎核心职责

```
┌─────────────────────────────────────────────────────────────┐
│                        引擎 (Engine)                         │
│                      "战争机器 | 摄影机"                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   核心理念：纯程序、无智能、绝对可靠                         │
│                                                             │
│   职责：                                                     │
│   1. 角色生命周期管理（创建、销毁、重启）                    │
│   2. 消息路由（角色间通信管道）                              │
│   3. 事件循环（驱动系统运转）                                │
│   4. 健康监控（心跳、异常检测）                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 3. 督察调试机制

### 3.1 督察核心能力

```
┌─────────────────────────────────────────────────────────────┐
│                       督察 (Inspector)                       │
│                     "总监察长 | 监制"                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   核心理念：特权观测者，可穿透所有边界                        │
│                                                             │
│   能力：                                                     │
│   1. 状态查看 - 任何角色的内部状态                           │
│   2. 断点控制 - 暂停/单步/继续                               │
│   3. Mock 注入 - 模拟任何角色的输入/输出                     │
│   4. 性能剖析 - 收集执行指标                                 │
│   5. 紧急干预 - 强制停止/重启                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 状态查看接口

```
// 督察状态查看 API

interface InspectorStateViewer {
    
    // 获取角色状态
    getRoleState(roleType: RoleType): RoleState {
        return {
            status: "running" | "paused" | "failed",
            metrics: {
                requestCount: number,
                errorCount: number,
                avgLatency: number,
                lastActivity: DateTime
            },
            internalState: any  // 角色特定状态
        }
    }
    
    // 获取 Workflow 实例状态
    getWorkflowState(instanceId: string): WorkflowState {
        return {
            workflowId: string,
            currentStep: string,
            variables: Map<string, any>,
            history: StepExecution[],
            startTime: DateTime,
            status: "running" | "waiting" | "completed" | "failed"
        }
    }
    
    // 获取记忆状态
    getMemoryState(sessionId?: string): MemoryState {
        return {
            shortTerm: MemoryEntry[],
            working: MemoryEntry[],
            longTermStats: {
                totalEntries: number,
                lastUpdated: DateTime
            }
        }
    }
    
    // 获取消息队列状态
    getMessageQueueState(): QueueState {
        return {
            pending: number,
            processing: number,
            completed: number,
            failed: number,
            oldestPending: DateTime
        }
    }
}
```

### 3.3 断点控制接口

interface InspectorProfiler {

    startProfiling(options?: ProfileOptions): ProfileSession {
        // options: { duration?, sampleRate?, includeMemory?, includeNetwork? }
    }

    stopProfiling(session: ProfileSession): ProfileReport

    getRealtimeMetrics(): RealtimeMetrics {
        return {

            avgLatency: number,       // 平均延迟（ms）
            p99Latency: number,       // P99 延迟
            errorRate: number,        // 错误率
            cpuUsage: number,         // CPU 使用率
            memoryUsage: number,      // 内存使用
            activeWorkflows: number   // 活跃 Workflow 数
        }
    }
    
    // 获取角色级别指标
    getRoleMetrics(roleType: RoleType): RoleMetrics {
        return {
            requestCount: number,
            successCount: number,
            errorCount: number,
            avgProcessTime: number,
            maxProcessTime: number,
            queueDepth: number
        }
    }
}

interface ProfileReport {
    duration: number,
    samples: ProfileSample[],

        totalRequests: number,
        totalErrors: number,

        hotspots: Hotspot[],       // 耗时最多的位置
