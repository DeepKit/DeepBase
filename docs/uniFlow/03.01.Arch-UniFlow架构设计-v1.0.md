# UniFlow 架构设计

> **版本**: 1.0 | **更新日期**: 2025-12-03
> 本文档定义 UniFlow 的技术架构，开发时应结合《Agent系统软件设计完整指导手册》

---

## 1. 概述

### 1.1 架构定位

UniFlow 是**智能应用的操作系统**，提供：
- 11 个标准化角色的运行时
- Workflow 流程引擎
- Skill 扩展机制
- 安全与信任边界
- 多层记忆体系

### 1.2 开发方法论

UniFlow 开发应遵循 `00.ai智能体架构规划2025-12-03.md`（Agent系统软件设计完整指导手册）中的：
- **设计模式**：Reflection、Tool Use、Planning、Multi-Agent、Evaluator-Optimizer
- **Prompt工程**：XML 标签隔离、思维链、Few-Shot 示例
- **评估体系**：单元测试、模型评估、黄金数据集
- **降级策略**：自动重试、输出修复、传统方法兜底

## 3. 11 角色架构

### 3.1 角色层级

| 层级 | 角色 | 职责 | 信任级别 |
|------|------|------|----------|
| L0 元层 | 引擎(Engine) | 系统生命周期管理 | 完全信任 |
| L0 元层 | 督察(Inspector) | 调试与可观测性 | 完全信任 |
| L4 决策层 | 总指挥(Commander) | 任务分解与分配 | 有限信任 |
| L4 决策层 | 调度员(Dispatcher) | 流程编排与调度 | 有限信任 |
| L3 智能层 | 智囊(Advisor) | AI 推理与建议 | 不信任 |
| L2 能力层 | 执行者(Executor) | 执行具体任务 | 不信任 |
| L2 能力层 | 守卫(Guard) | 安全校验 | 有限信任 |
| L2 能力层 | 军械官(Quartermaster) | Skill 管理 | 有限信任 |
| L1 基础层 | 后勤(Logistics) | 资源管理 | 完全信任 |
| L1 基础层 | 记录员(Chronicler) | 日志与审计 | 完全信任 |
| L1 基础层 | 通信官(SignalOfficer) | 外部通信 | 有限信任 |

### 3.2 角色交互原则

1. **单向依赖**：高层可调用低层，低层不能调用高层
2. **接口隔离**：角色间通过接口通信，不直接访问内部状态
3. **输出校验**：不信任区角色的输出必须经过守卫校验
4. **消息驱动**：角色间通过标准消息协议通信

### 3.3 角色接口定义

详见 `UniFlow-接口契约定义.md`

## 4. Workflow 引擎

### 4.1 任务类型

| 类型 | 说明 | 示例 |
|------|------|------|
| SystemTask | 系统内置任务 | 变量赋值、条件判断 |
| SkillTask | 调用 Skill | HTTP 请求、数据库查询 |
| AgentTask | AI 推理任务 | 内容生成、意图理解 |
| HumanTask | 人工介入任务 | 审批、确认 |

### 4.2 流程结构

支持的流程结构：
- **顺序执行**：A → B → C
- **条件分支**：if/else、switch
- **并行执行**：fork/join
- **循环**：while、for-each
- **子流程**：嵌套 Workflow

## 5. Skill 框架

### 5.1 Skill 定义

```pascal
type
  ISkill = interface
    function GetMetadata: TSkillMetadata;
    function Execute(const AInput: TSkillInput): TSkillOutput;
    function Validate(const AInput: TSkillInput): TValidationResult;
  end;

  TSkillMetadata = record
    Name: string;
    Version: string;
    Description: string;
    InputSchema: TJSONSchema;
    OutputSchema: TJSONSchema;
    TrustLevel: TTrustLevel;  // Core/Official/Community/User
    Permissions: TPermissions;
  end;
```

### 5.2 Skill 信任层级

| 层级 | 来源 | 信任度 | 执行环境 |
|------|------|--------|----------|
| Core | 内置 | 完全信任 | 直接执行 |
| Official | 官方认证 | 有限信任 | 权限约束 |
| Community | 社区贡献 | 低信任 | 沙箱隔离 |
| User | 用户自建 | 不信任 | 严格沙箱 |

### 5.3 Core Skills（MVP）

1. **SkillHTTP** - HTTP 调用
2. **SkillDatabase** - 数据库读写（基于 UniBase）
3. **SkillFile** - 文件操作
4. **SkillLLM** - LLM 调用封装
5. **SkillTimer** - 定时触发
6. **SkillHuman** - 人工任务

## 6. 安全机制

### 6.1 三重守卫

```
请求 ──> [门卫] ──> 处理 ──> [监工] ──> 输出 ──> [审核官] ──> 响应
         入口校验      过程监控           出口校验
```

### 6.2 信任边界

| 区域 | 角色 | 约束 |
|------|------|------|
| 完全信任区 | 引擎/督察/后勤/记录员 | 无额外校验 |
| 有限信任区 | 总指挥/调度员/守卫/军械官/通信官 | 权限检查 |
| 不信任区 | 智囊/执行者 | 输出必须校验 |

### 6.3 安全原则

1. **硬执行优于软执行** - 安全规则由架构强制，不依赖 Prompt
2. **最小权限** - 每个角色只拥有完成任务所需的最小权限
3. **纵深防御** - 多层校验，单点失败不导致安全漏洞
4. **可审计** - 所有操作记录在案，可追溯

## 7. 记忆系统

### 7.1 记忆层级

| 层级 | 生命周期 | 存储 | 用途 |
|------|----------|------|------|
| 工作记忆 | 单次请求 | 内存 | 当前任务上下文 |
| 会话记忆 | 单次会话 | 内存/Redis | 对话历史 |
| 持久记忆 | 长期 | 数据库 | 用户偏好、历史决策 |
| 知识库 | 永久 | 向量库 | 领域知识、最佳实践 |

### 7.2 记忆管理

- **记录员**负责写入记忆
- **后勤**负责读取记忆
- **智囊**可查询知识库

### 9.3 数据存储策略

**本地优先原则**：
- 每个应用独立 SQLite 数据库
- 离线可用，保护用户隐私
- 决策数据默认不上传

**可选云同步（1.0+）**：
- 用户主动选择同步内容
- PostgreSQL 存储同步数据
- 用户账号、Skill 市场元数据

### 9.4 UniBase 复用

| UniBase 组件 | UniFlow 用途 |
|--------------|-------------|
| UniBase.LLM + LLM.Manager | Advisor 角色 LLM 调用 |
| UniBase.StateMachine | Workflow 任务状态 |
| UniBase.EventBus | 角色间消息通信 |
| UniBase.WorkerQueue | 异步任务执行 |
| UniBase.Scheduler | Timer Skill |
| UniBase.Config | 配置管理 |
| UniBase.Logging | 日志系统 |

### 9.3 遵循的开发约定

参考 `D:\_Progs\05docs\delphi程序开发约定指南.md`：
- 文件命名：前缀 + 功能描述（如 `CtrlWorkflow.pas`、`ModelSkill.pas`）
- 零目录结构：代码文件放项目根目录，通过前缀区分层级
- 四层隔离：View / Ctrl / Model / uDM
- UTF-8 + BOM 编码
