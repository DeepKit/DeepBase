# 如是（SoIs）

> **言出即是** —— 你说是，就是

## 定位

**如是** 是 DevDirector 的上层对话系统，提供"可靠的氛围编程"体验。

```
┌─────────────────────────────────────┐
│          如是（SoIs）               │  ← 用户对话层
│     自然语言交互 · 意图澄清          │
├─────────────────────────────────────┤
│          述成（SayDone）            │  ← 结构化转换引擎
│     自然语言 → 结构化数据            │
├─────────────────────────────────────┤
│        导演台（DevDirector）         │  ← 场景管理 · 节点定位
│     场景树 · 变更追踪 · 精确修改      │
└─────────────────────────────────────┘
```

## 核心价值

**修改准、维护稳** —— 不是"生成强"

- 不是让事情变得更复杂，而是更简单、更可靠
- 氛围编程的问题：不确定性、难以长期维护
- 如是的解决：精确定位问题节点，在正确位置修改

## 工作流程

### Loop A：构建循环（步骤 1-8）

1. 用户提出需求
2. 系统澄清（许多选项可默认）
3. 画出界面草图
4. 用户要求修改
5. 2-4 循环迭代
6. 切入小分支，继续迭代
7. 导入到导演台
8. 生成第一版程序

### Loop B：维护循环（步骤 9-13）

9. 用户运行程序，提出修改意见
10. 在导演台上找到对应节点
11. 与用户对话澄清（用户可直接调整）
12. 生成修正后的程序
13. 继续 9-12 循环

## 节点粒度

从大到小：

```
项目 → 场景 → 步骤 → 功能点 → 代码块
```

用户一般看大的，出了问题才往下找小的。

## 与 SayDone 的关系

- **SayDone（述成）**：底层引擎，负责自然语言→结构化数据转换
- **SoIs（如是）**：上层体验，负责用户对话、意图澄清、流程引导

SayDone 的能力被 SoIs 调用，但 SayDone 也可独立使用。

## 运行模式

如是支持两种运行模式：

### 模式 A：集成模式（与导演台一体）

```
用户 → 如是 → 述成 → 导演台 → 生成程序
```

- 作为 DevDirector 的子面板运行
- 完整功能：澄清 → 草图 → 导入导演台 → 生成代码
- 数据持久化到 SQLite
- 记录 HistoryEvent

### 模式 B：独立模式（轻量级）

```
用户 → 如是独立版 → 导出 JSON/SVG
```

- 可单独运行的轻量级应用
- 核心功能：澄清 → 草图 → 导出文件
- 无需数据库，结果导出为 JSON/SVG
- 可后续导入导演台

**独立模式架构：**

```
┌───────────────────────────────┐
│         如是 SoIs 独立版        │
├───────────────┬───────────────┤
│   需求输入     │   点选澄清     │
├───────────────┼───────────────┤
│       草图预览（SVG）         │
│   状态流图  │  线框图       │
├───────────────┴───────────────┤
│   导出：JSON / SVG / Markdown  │
└───────────────────────────────┘
```

## 技术栈

- Delphi FMX（跨平台界面）
- SQLite（本地数据存储）
- liteLLM（AI 能力接入）

## 后台角色架构

### 如是专属角色

| 角色 | 英文 | 功能 | AI |
|------|------|------|----|
| 澄清官 | Clarifier | 分析用户需求，生成点选选项 | 🤖 需要 |
| 草图师 | Sketcher | 根据选项实时生成界面草图 | 🤖 需要 |
| 定位员 | Locator | Loop B 中定位问题节点 | 🤖 需要 |
| 方案师 | Proposer | 提供修改建议方案 | 🤖 需要 |
| 默认官 | Defaulter | 根据规则推断智能默认值 | ✓ 纯程序 |
| 进度官 | Tracker | 流程控制、状态跟踪 | ✓ 纯程序 |

### 共用角色（与述成共享）

**总导演/调度员** (Director) - ✓ 纯程序
- 运行时总指挥，纯程序逻辑，不用 AI

**能力执行类**：
| 角色 | 功能 | AI |
|------|------|----|
| AI代理 | 意图理解、内容生成 | 🤖 需要 |
| 共情官 | 情感感知、体验优化 | 🤖 需要 |
| 记忆官 | 上下文管理、历史记忆 | 🤖 Embedding |

**质量守护类**：
| 角色 | 功能 | AI |
|------|------|----|
| 守卫员 | 格式验证、安全检查 | 🔒 硬关卡（纯程序） |
| 自检员 | AI输出自审、幻觉检测 | 🤖 需要 |
| 比对员 | 变更分析、影响评估 | 🤖 代码LLM |

**保障类**：
| 角色 | 功能 | AI |
|------|------|----|
| 监工 | 独立观察、平级制衡 | ✓ 纯程序 |
| 回滚员 | 故障恢复、状态回滚 | ✓ 纯程序 |

### 设计原则

**AI归AI、程序归程序**：
- 🤖 需要智能的用 AI（理解、生成、分析）
- ✓ 需要可靠的用纯程序（流程控制、状态管理、回滚）
- 🔒 硬关卡不可绕过（守卫员）

详见：[后台角色架构图](ui/SoIs-04-后台角色架构.svg)

## 交互设计原则

**点选优先，非聊天式**：
- 用户第一次输入需求后，后续尽量用点选
- 系统提供智能默认值，用户可快速确认
- 减少输入负担，提高澄清效率
