## 🔍 第一阶段：文档与架构审查 (1-2天)

### 1.1 文档完整性检查

**检查清单**:

- [ ] **README.md** 
  - 包含安装步骤
  - 包含配置说明
  - 包含快速开始示例
  - 示例代码可直接运行

- [ ] **CHANGELOG.md**
  - 记录所有版本变更
  - 格式规范清晰

- [ ] **集成指南** (Examples/ 目录)
  - 至少 5 个示例项目
  - 每个示例有说明文档

### 1.2 架构设计审查

**检查要点**:

1. 打开 `Core/` 目录，检查模块依赖：
   - 核心模块不应依赖 VCL/FMX
   - 无循环依赖

2. 检查分层架构：
   ```
   Core (底层) → VCL/FMX (UI层) → ThirdParty (扩展层)
   ```

3. 检查线程安全标记：
   - 搜索 `TMonitor` 或 `TCriticalSection` 使用

**验收标准**: 
- 🔴 P0: 无循环依赖
- 🔴 P0: 分层架构正确
- 🟡 P1: 接口设计符合 SOLID

## 🔍 第二阶段：静态代码分析 (2-3天)

### 2.1 编译验证

**执行步骤**:

1. 打开 Delphi IDE
2. 打开 `UniBaseCore.dpk`
3. 编译 Win32 版本：Project → Build
4. 编译 Win64 版本：切换平台后 Build

**验收标准**:
- 🔴 P0: 零错误
- 🟡 P1: 零警告（或仅有可接受的警告）

### 2.2 代码质量检查

**手动检查要点**:

1. **资源释放检查**
   - 搜索 `Create` 调用，确认有对应的 `Free`
   - 检查 `try-finally` 块使用

2. **异常处理检查**
   - 关键路径是否有异常处理
   - 异常信息是否有意义

3. **TODO/FIXME 检查**
   ```
   当前已知 TODO (4处，非关键):
   - UniBase.Updater.pas: 跨平台签名验证
   - UniBase.PluginManager.pas: 插件签名验证
   - UniBase.Memory.pas: 弱引用机制
   ```

## 🔍 第五阶段：安全专项测试 (2-3天) ⚠️ 重点

### 5.1 加密模块验证

**测试文件**: `Core\UniBase.Crypto.pas`

**验证项目**:

1. **AES-256 加密**
   ```pascal
   // 使用已知测试向量验证
   // 明文: "Hello World"
   // 密钥: 32字节密钥
   // 验证密文是否正确
   ```

2. **RSA 签名**
   - 验证签名生成
   - 验证签名验证
   - 测试无效签名拒绝

3. **HMAC-SHA256**
   - 使用 RFC 4231 测试向量验证

### 5.2 支付安全测试 ⚠️ 必须人工执行

**测试文件**: 
- `ThirdParty\Payment\UniBase.Payment.WeChatPay.pas`
- `ThirdParty\Payment\UniBase.Payment.Stripe.pas`

**测试场景**:

| 测试项 | 操作 | 预期结果 |
|--------|------|----------|
| 有效签名 | 使用正确密钥签名 | 验证通过 |
| 无效签名 | 篡改签名内容 | 验证失败 |
| 过期时间戳 | 使用过期时间戳 | 拒绝请求 |
| 重放攻击 | 重复发送相同请求 | 检测并拒绝 |
| 金额篡改 | 修改订单金额 | 签名验证失败 |

### 5.3 Webhook 安全测试

**测试步骤**:

1. 模拟有效 Webhook 请求 → 应处理成功
2. 模拟无效签名请求 → 应拒绝
3. 模拟重放请求 → 应拒绝

**验收标准**:
- 🔴 P0: 所有安全测试通过
- 🔴 P0: 无法绕过签名验证
