## 1. 架构定位：HB Human Behavior Infrastructure 运行时层

```
+-----------------------------------------------------------------------------------------------+
|  【产品业务层】(DeepCommerce 唤金 / AsWish / DeepRW / Assayer / DeepDsh)                       |
```

## 2. 控件生命周期统一模型（7-Step Lifecycle Pipeline）

所有 HB 体系控件（无论是静态放置还是运行时动态生成）必须严格遵循以下 **7 步标准生命周期**：

```
    [1. Create] ────── 实例化并分配基础资源
         ↓
  [2. BindToken] ───── 绑定当前主题 Token 实例，注入色彩/字号/间距
         ↓
  [3. BindState] ───── 绑定两轴基础状态与已注册的状态槽实例
         ↓
[4. AttachTouchpoint] 挂载触点 ID 与四自转换契约 (UserState Before/After)
         ↓
    [5. Render] ────── 依托 GDI+ 缓存池与局部脏区进行确定性绘制 (禁止裸 Paint)
         ↓
[6. EmitTelemetry] ─── 触发遥测度量与触点事件输出
         ↓
   [7. Dispose] ────── 释放 GDI 句柄、注销 Theme 监听、持久化会话快照
```

> 命名理由：避免与 UI 布局测量（Measure/Arrange 通用语义）冲突。

### 2.1 严禁裸 Paint 执行机制
> [!CAUTION]
> **严禁裸 Paint**：禁止任何控件在未完成 `BindToken`、`BindState` 或 `AttachTouchpoint` 前直接调用 `Paint`。  
> **执行机制**：`THbCustomControl` 基类通过模板方法（Template Method）强制执行生命周期顺序。在 `Paint` 入口处前置运行时断言：若未完成 `BindToken` 即进入 `Paint`，直接抛出 `EHbLifecycleViolation` 异常，将纪律从人工走查升级为运行时可执行防御。

### 2.2 生命周期失败路径契约
在 7 步流水线中，任一步骤抛出未捕获异常时：
1. 触发 `OnLifecycleError` 事件进行异常上下文记录与错误定位；
2. 流程无条件进入 `Dispose` 步骤执行已分配资源的兜底清理；
3. `Dispose` 必须具备幂等性（Idempotent，支持多次重复调用且无任何副作用或二次异常）。

## 3. 两轴状态 + 可插拔状态槽协议

> 修改理由：基座源码严禁携带业务枚举，业务状态由产品层注入。

为了严格区分 UI 基座的本质职责与业务领域的动态扩展，HB 确立 **两轴基础状态（基座内建） + 可插拔状态槽（业务层注入）** 架构协议：

```
+-----------------------------------------------------------------------------------------------+
|                           两轴基础状态 + 可插拔状态槽架构协议                                 |
+---------------------------------------------------------------+-------------------------------+
|                 【基座两轴核心状态】 (内建枚举)               |     【业务可插拔状态槽】      |
+-------------------------------+-------------------------------+-------------------------------+
|       【1. 视觉交互态】        |       【2. 动作意图态】       |    【IHbStateSlotProvider】   |
|        (Visual State)         |        (Action State)         |      (产品层显式注入)         |
| • vsUnknown                   | • asIdle (静默待命)           | • Slot: 'business' (业务槽)   |
| • vsCreated / vsReady         | • asWaitingConfirm (待确认)   | • Slot: 'trust' (信任槽)      |
| • vsFocused / vsSelected      | • asProcessing (执行中)       | • Slot: 'custom' (自定义扩展) |
| • vsProcessing (流转中)       | • asCommitted (已提交归档)    |                               |
| • vsSuccess / vsWarning       | • asAborted (已放弃/退回)     |                               |
| • vsError / vsDisposed        |                               |                               |
+-------------------------------+-------------------------------+-------------------------------+
```

### 3.1 状态槽提供者接口契约
基座只定义槽协议接口，严禁在基座源码中定义任何下游业务枚举：

```pascal
unit DeepBase.HB.StateSlot.Types;

interface

type
  /// <summary>
  /// 可插拔状态槽提供者接口 - 由下游业务层实现并注入
  /// </summary>
  IHbStateSlotProvider = interface
    ['{A1B2C3D4-E5F6-4A5B-8C9D-0E1F2A3B4C5D}']
    function GetSlotId: string;      // 槽标识，如 'business' / 'trust'
    function GetStateLabel: string;  // 当前状态显示文本
    function GetStateRank: Integer;  // 状态权重/严重度等级
  end;

implementation

end.
```

### 3.2 状态槽注册与下游扩展示例
下游产品通过 `THbRuntime.RegisterStateSlot` 显式注册状态槽（遵循显式注册 + 工单号审计风格）：

```pascal
// 示例：由唤金业务层注册，非基座内容
type
  THuanjinBusinessSlot = class(TInterfacedObject, IHbStateSlotProvider)
  public
    function GetSlotId: string;
    function GetStateLabel: string;
    function GetStateRank: Integer;
  end;

function THuanjinBusinessSlot.GetSlotId: string;
begin
  Result := 'business';
end;

function THuanjinBusinessSlot.GetStateLabel: string;
begin
  // 映射唤金业务层私有枚举（如 bsNeedFollowUp）
  Result := '需跟进';
end;

function THuanjinBusinessSlot.GetStateRank: Integer;
begin
  Result := 2;
end;

// 唤金产品启动时显式注册状态槽
```

## 4. Design Token 版本治理协议（Token Migration Protocol）

随着全系产品（唤金、AsWish、DeepRW、Assayer）规模扩大，必须建立严格的 Token 版本迁移机制，**严防各业务侧偷偷魔改 Token 导致视觉系统碎片化**：

```
                 [Token v3.0] ──── 初始基准
                      │
                      │ 引入新语义色 (向下兼容)
                      ▼
                 [Token v3.1] ──── 标记部分过时字段为 Deprecated
                      │
                      │ 运行自动化迁移工具 (Token Migration Tool)
                      ▼
                 [Token v4.0] ──── 彻底移除过时色值，发布新主版本
```

### 治理规则
1. **SSOT 唯一真相源**：所有调色板与 Token 定义必须且只能存在于 `DeepBase.HB.Core.pas` 与 `DeepBase.HB.Palettes.pas`；
2. **严禁私有覆盖**：下游业务若需临时覆盖特定场景色彩，必须通过 `THbTheme.RegisterOverride` 显式注册并附带工单编号，禁止私自 Hack 控件绘制函数；
3. **废弃周期（Deprecation Policy）**：任何被淘汰的 Token 属性必须保留至少 2 个次版本（Minor Version）的警告过渡期，并通过 IDE Hint/Warning 引导迁移。

## 5. 跨线程安全与消息分发契约（Thread Safety & Dispatch）

1. **UI 线程守卫**：
   - 所有涉及 UI 重绘、Token 切换广播、触点状态跃迁的代码，必须在主线程执行；
   - 严禁在 UI 线程调用 `Sleep` 或同步阻塞的 RPC / SQL 操作；
2. **后台工作线程向 UI 派发标准**：
   - 严格禁止使用 `TThread.Queue`（容易在窗体销毁后引发悬挂指针 AV）；
   - **必须统一使用 `TThread.ForceQueue`**，并在闭包中校验控件 Handle 与 Assigned 守卫：
     ```pascal
     TThread.ForceQueue(nil, procedure
     begin
       if Assigned(TargetControl) and TargetControl.HandleAllocated then
         TargetControl.UpdateState(...);
     end);
     ```
3. **DPI 动态切换拦截（`WM_DPICHANGED`）**：
   - 基类捕获 DPI 变化消息后，依次调用 `BeforeDpiChange` $\rightarrow$ `RecalculateMetrics(NewPPI)` $\rightarrow$ `Invalidate`，确保多显示器拖拽零卡顿。
