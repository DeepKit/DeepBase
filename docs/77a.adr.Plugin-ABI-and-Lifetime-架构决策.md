## 1. 背景

DeepBase.Plugins 公共基础设施（由 Assayer 插件系统升级而来）需在**多宿主**（Assayer、DeepCompare Gateway P6）之间冻结稳定的 ABI 与生命周期规则。前两轮评审暴露了超时语义三处冲突、TBytes 跨模块所有权不明、依赖循环无检测等致命问题，本 ADR 统一收口。

## 2. 决策

### 2.1 ABI 版本模型：主/次双版本 + 能力协商

| 常量 | 语义 | 加载规则 |
|------|------|---------|
| `PLUGIN_ABI_MAJOR` | 接口布局（方法签名、参数约定） | **宿主与 DLL 必须完全相等**，否则拒绝加载 |
| `PLUGIN_ABI_MINOR` | 向后兼容的扩展（新增可选能力） | **宿主 MINOR ≥ 插件 MINOR** 即可加载 |

- 宿主与 DLL 必须编译**同一份** `DeepBase.Plugins.Contracts.pas` 单元；
- 加载时同时校验：ABI 常量、编译器版本标识、RTL 标识，任一不匹配拒绝加载并告警；
- **接口 GUID 一经发布禁止改动**；契约扩展只能通过**接口继承**新增（新接口新 GUID，旧插件无需改动即可继续加载）；禁止修改已有接口方法签名。

### 2.2 Lease/Invoke 门禁与超时语义（全文档统一）

- Manager **不直接暴露** `IPluginContract` 引用给宿主业务代码；调用方经 `AcquireLease(PluginName, Timeout)` 获取临时引用，用完 `ReleaseLease` 归还；
- **Lease drain 统一语义**：由 Manifest 声明 `unload_timeout_ms`，宿主钳制在 **10–300 秒**，默认 **300 秒**；超时后进入 `psPendingRestart`（无法维持服务时再转 `psError`）并告警；**禁止超时后强制 FreeLibrary**——Windows 进程内无法安全强制卸载引用非零的 DLL，强制卸载必然导致后续访问野内存崩溃；
- Unload（单独卸载）与热重载（ReloadPlugin）中的 Lease 等待使用**同一语义**，无第二条规则；
- 禁止插件向宿主传递**跨边界长期引用**（自身接口存入宿主全局对象、注册长期回调等），所有跨边界引用限定在单次调用（Lease 生命周期）内。

### 2.3 稳定 ABI 与跨边界内存所有权

正式产品线 ABI 冻结为纯 C 数据面：

- 固定导出函数名和 `stdcall`；
- 不透明句柄、固定宽度整数、显式错误码；
- 输入使用 `PByte + Length`；输出使用 `PByte + Capacity + ActualLength`，容量不足返回明确错误并报告所需长度；
- 允许插件分配输出时，必须由同一 DLL 导出 `FreeBuffer` 释放；
- 禁止跨边界出现 Delphi interface、string、TBytes、动态数组、对象、Variant 和异常；
- Delphi 友好接口只允许作为宿主内部包装层。

现有 `IPluginContract/TBytes` 实现标记为实验性同编译器 ABI，不作为 Preview 冻结接口。共享内存管理器只能作为实验兼容条件，不能替代稳定 ABI。

### 2.4 错误码规范（跨边界返回的唯一通道）

| 错误码 | 含义 |
|--------|------|
| `PLUGIN_OK` | 成功 |
| `PLUGIN_LOAD_FAILED` | 加载失败（含签名/ABI 校验失败） |
| `PLUGIN_RELOADING` | 插件正在热重载，新调用请求降级处理 |
| `PLUGIN_BUSY` | 调用超时/熔断中 |
| `PLUGIN_INVALID_INPUT` | 入参校验失败 |
| `PLUGIN_INTERNAL_ERROR` | 插件内部异常（DLL 内已捕获） |
| `PLUGIN_DEPENDENCY_FAILED` | 依赖插件加载失败 |
| `PLUGIN_LEASE_TIMEOUT` | Lease 获取超时 |

### 2.5 插件依赖与环检测

- `RegisterPluginKind(..., ADependsOn: TArray<string>)` 声明依赖；
- **注册时对 ADependsOn 做 DFS 拓扑环检测**：发现环（A→B→A）拒绝注册并告警，禁止运行时死递归；
- 加载时先递归加载依赖项；依赖加载失败则当前插件跳过并标记 psError。

### 2.6 热重载时序（7 步，与 §2.2 超时语义一致）

新 DLL 写入旁路目录 → 校验签名/ABI → 暂停该插件新调用（排队或 503） → 等待 Lease 释放（上限 300 秒，超时 psError+ 人工介入） → 备份旧 DLL → Unload → 文件替换 → Load → Initialize → 恢复调用；失败回滚旧文件并 psError。

## 3. 被拒绝的备选方案

| 方案 | 拒绝理由 |
|------|---------|
| 单版本号 `PLUGIN_ABI_BUILD_VERSION` | 无法表达向后兼容语义，任何修改都强制全部插件重新编译 |
| 超时后强制 FreeLibrary 兜底 | Windows 进程内引用非零 DLL 强制卸载必崩，属不可恢复的野内存故障 |
| 跨 DLL 传递 `IPluginContract` / TBytes / string | 编译器虚表、引用计数、异常和堆所有权不稳定；即使共享内存管理器也不能作为长期 ABI |
| 不设超时、无限等待 | 死锁插件将永久阻塞 Unload/Reload，无法自动化告警与恢复 |

## 4. 实施与验收要点

- Contracts 单元嵌入 MAJOR/MINOR 常量；加载器校验逻辑纳入 TPluginVerifier；
- Lease 门禁实现于 TPluginManager（`AcquireLease/ReleaseLease` + Manifest 超时，10–300 秒宿主钳制）；
- 验收：纯 C ABI 头文件和 Delphi 声明中无管理类型；不同内存管理器配置完成调用/释放测试；热重载循环 100 次句柄不泄漏；Lease 超时进入 pending restart 且不强制卸载；依赖环注册即被拒。
