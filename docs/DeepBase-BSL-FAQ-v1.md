# DeepBase BSL 1.1 许可常见问题解答 (FAQ) - v1.0

> 版本: 1.0  
> 日期: 2026-08-29  
> 适用范围: DeepBase Layer 3 护城河资产 (AutoFix 引擎、浏览器自动化内核、治理治理内核)

---

## 1. 背景与分层许可架构

DeepBase 采用清晰的“开源基座 + 护城河可信源码”双轨许可模型：

* **Layer 1 (基础核心库) & Layer 2 (桌面 HB UI 框架)**：采用 **Apache License 2.0**，完全自由开源、允许免费商用与自由二次分发。
* **Layer 3 (护城河核心技术资产)**：采用 **Business Source License 1.1 (BSL 1.1)** 源码可用许可，向社区透明开放源码，保障技术可审计、可调试、可自托管，同时对独立商业转售与竞品剥离设立合法护城河。

---

## 2. 常见问题解答 (FAQ)

### Q1: 我可以在企业内部商业业务系统中使用 Layer 3 组件吗？
**答：完全可以。**  
根据 BSL 1.1 中的 *Additional Use Grant (附加使用授权)*，任何企业、组织或个人均可免费使用 Layer 3 组件用于**构建、运行、部署和维护内部业务应用、内部自动化工作流与自用定制系统**，无需支付任何许可费或获得额外授权。

---

### Q2: 我可以把 Layer 3 组件打包后作为独立商业产品/SDK 销售，或者提供商业托管 SaaS 吗？
**答：不可以。**  
BSL 1.1 明确禁止将 Layer 3 组件（含其衍生修改版本）作为独立的商业产品、商业 SDK、或者商业 SaaS 服务直接转售或分发给第三方。如需进行独立商业转售或 OEM 贴牌集成，须联系维护方签署单独的商业授权协议。

---

### Q3: 竞争对手可以直接将 Layer 3 的 AutoFix/Browser/Governance 剥离并集成进直接竞品中吗？
**答：不可以。**  
BSL 1.1 设立的核心目标即为保护原厂核心技术投资。任何直接与 DeepBase / DeepPulse 商业化产品竞争的软件与服务均不得包含或派生自 Layer 3 的源码资产。

---

### Q4: 如果我的开源项目不想引入 BSL 1.1 代码，系统还能正常工作吗？
**答：完全可以，且具备 Fail-Open (开箱兜底) 机制。**  
* DeepBase 的 L1/L2 与下游开源项目（如 DeepSpec）在架构设计上实现了**物理级严格单向解耦**。
* L1/L2 对 L3 拥有 **0 项编译依赖**。
* 所有需要护城河能力的功能（如自动修复、规则治理）均通过轻量接口（如 IAutoFixEngine）进行解耦。在未引入 L3 源码或插件时，系统会自动采用无损兜底实现（No-Op 或标准文本告警），保证 100% 编译通过且核心逻辑稳定运行。
