## 一、为什么需要 L8：从规范落实到经验审视

### 1.1 规范完备性不等于经验有效性
在前七层中，EHAI 完成了从哲学基础、交付原则、介入时机、交互协议、适配表达、机器语义到底层实现的全部规范化构建：
* L1～L6（已正式冻结）保证了理论体系在规范逻辑上的自洽、守界与完备；
* L7（已正式冻结）保证了具体工程实现（Concrete Realization）在代码、API 与物理路径上对上游规范的忠实贯彻（Conformance）。

然而，一个在规范上完全合规的系统，在面对纷繁复杂的真实人类社会与动态任务环境时，必然面临一个严峻的追问：
> **这套号称“高效”的人机交互规范，被具体实现并真正投入使用之后，究竟给人类带来了什么？它真的让人更高效了吗？它是否带来了意想不到的全新负担？**

这一追问无法由 L1～L7 中的任何一层回答。因为 L1～L6 是抽象规范法源，L7 是落地符合性审查。回答现实经验后果的任务，必须由一个独立的经验层承担。

### 1.2 现实不是理论的橡皮图章
科学认识论（ASTO.P03）表明，人类的一切理性构造均具有先验可谬性。一个理论无论在推导上多么严密，其经验结果必须接受物理世界与人类实践的检验。
* 经验研究的目的**绝不是为了单向证明 EHAI 必然英明神武**；
* 经验研究的核心价值，恰恰在于**发现理论的适用边界、失效场景、意料之外的摩擦以及必须修正的漏洞**；
* **现实有权告诉理论，它在哪些地方不成立。**

## 二、L8 的存在性证明与不可约残差

### 2.1 核心不可约残差：Conformance ≠ Empirical Effect
假设一个系统已经达成了极其理想的符合态：
$$\text{L1～L6 全部正确} \land \text{L7 Conformance 完全成立}$$

此时，该系统依然可能在经验世界中表现出以下极其复杂的现象：
1. **效率反噬**：严格执行 L3/L4 门禁与确认，在某些高频轻量任务中导致系统整体吞吐量严重下降，人类感到极其烦琐；
2. **认知过载**：尽管 L5 尽最大努力极简适配，但多轮澄清与选择依然占用了人类宝贵的注意力，导致判断疲劳；
3. **分群失效**：该机制对高技能专业人员极大提升了效能，但对普通非技术用户却造成了严重的理解困惑；
4. **组合劣变**：单独测试机制 A（如 Candidate-first）和机制 B（如 Explanatory preview）均表现优良，拼装到一起后却产生了认知冲突，导致用户误操作增加；
5. **长短期背离**：系统在投入使用的前两周内显著降低了错误率，但在连续使用半年后，用户产生了严重的“依赖性盲从”，整体判断质量断崖式下跌；
6. **资源成本飙升**：为了维持完整的机器语义对账，后台 Token 消耗与计算延迟大幅上升，经济可行性遭到挑战。

### 2.2 严格划定 L7 与 L8 的职责分工
上述所有现象表明：**系统“合规”绝不保证系统“产生预期的正面经验结果”**。

$$\text{Conformance} \neq \text{Empirical Effect}$$
$$\text{L7} \neq \text{L8}$$

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                 L7 与 L8 的根本职责对立                                │
├──────────────────────────────────────────┬─────────────────────────────────────────────┤
│ L7 具体实现边界 (Theory → Reality)       │ L8 现实效应与经验闭环 (Reality → Theory)    │
├──────────────────────────────────────────┼─────────────────────────────────────────────┤
│ • 审查对象：具体实现代码、API、配置与路径│ • 审查对象：真实交互产生的数据、行为与后果  │
│ • 核心问题：有没有按 EHAI 正确做出来？   │ • 核心问题：真正用起来后发生了什么？        │
│ • 判定性质：规范符合性判定 (Conformance) │ • 判定性质：客观经验效应评估 (Empirical)    │
│ • 防范目标：遗漏、误接、越权、绕过       │ • 防范目标：虚假归因、片面汇报、过度外推    │
└──────────────────────────────────────────┴─────────────────────────────────────────────┘
```

**结论**：L8 具有完全独立的经验认识论对象与不可约性，绝非 L7 的测试附录、验收报告或 Evidence 附属品。

## 三、L8 的研究对象候选界定：从相关经验结果到归因效应

### 3.1 研究对象候选界定与经验范畴（候选态且不预设归因）
在体系宏观视阈下，L8 的总体研究领域候选概括为 **EHAI 相关经验效应（EHAI-related empirical effects）**（作为候选工作统称，暂不冻结正式英文原语，亦不预设其因果归因已成立）。

为彻底杜绝先验归因偏见，在具体微观经验分析中，确立如下候选态且不预设归因的范畴界定纪律：
* **R2 归因成立前**：任何个别的具体经验对象，统一界定为在明确 Evaluation Scope 内与 EHAI mechanism / combination 的引入、存在、使用或运行相关联的 **EHAI 相关经验结果（EHAI-related empirical outcome / consequence）**；此时其因果联系尚处于待审定状态，严禁预先假定因果必然存在；
* **R2 归因成立后**：只有当经验结果通过 R2 效果归因完整性的**归因审查 / 因果贡献审查**与重大替代解释审视，获得相称证据支撑后，该部分结果才允许被称为 **归因效应（Attributed Effect）**。

全层确立根本前置不变量：
$$\text{EHAI-related} \neq \text{EHAI-attributed}$$

与 EHAI 相关联的客观事实绝不等于已经被证实是由 EHAI 机制引起的。因此全篇严格贯彻三大核心对象的层阶界分：
$$\text{Observed Outcome} \neq \text{Attributed Effect} \neq \text{Empirical Claim}$$

### 3.2 允许并鼓励研究的异构形态
L8 绝非只关注“全套系统大团圆成功”，它同等严肃地研究以下异构经验形态：
* **机制粒度**：单一 EHAI 机制（如 0–9 Choice Grammar）、局部机制组合、还是全体系端到端实现；
* **采纳程度**：部分机制采纳（Partial Adoption）、全量符合实现（Conforming Realization）乃至不合规实现（Nonconforming Realization / Comparative Baseline）；
* **效应极性**：
  - 正向结果（Positive Outcome：耗时减少、失误下降、体验改善）；
  - 负向结果（Negative Outcome：成本增加、摩擦加剧、决策迟缓）；
  - 中性 / 无显著差异结果（Neutral / No Observable Difference）；
  - 未决 / 模糊效应（Unresolved Effect：现有数据互有矛盾）；
* **时间尺度**：即时微观效应（Short-term Effect）、单次任务效应与长期纵向演化效应（Long-term Effect）；
* **组合拓扑**：独立组件效应（Component Effect）与系统级组合涌现效应（Composite Effect）。

$$\text{EHAI Empirical Effect} \neq \text{Positive Effect Only}$$
L8 坚决拒绝成为“商业成功案例汇编层”，中性、未决与负向结果对于理论演进具有同等甚至更高的科学价值。

## 四、L8 不是什么：显式非目标与边界定界

为保持 L8 的纯粹性，防止其异化为工程工具箱或商业营销词汇，必须确立以下九大显式非目标：

1. ❌ **L8 不是软件测试层（Not Software Testing Layer）**：  
   单元测试、集成测试、端到端测试关注代码是否按规格运行（属于 L7 实现支撑），L8 关注系统运行给人和现实带来了什么经验影响；
2. ❌ **L8 不是合规认证层（Not Conformance Certification）**：  
   是否发合规证书属于治理或审计事务，L8 只提供科学、诚实的经验事实与归因分析；
3. ❌ **L8 不是证据层（Not Evidence Layer）**：  
   证据（Evidence）是贯穿全体系的横切纪律，L8 生产和使用经验证据，但 L8 绝不等同于证据本身；
4. ❌ **L8 不是绩效考核层（Not KPI / OKR Layer）**：  
   企业考核员工或部门的 KPI 包含复杂的商业与组织诉求，L8 坚守学术与工程诚实，不为 KPI 涂脂抹粉；
5. ❌ **L8 不是特定的 A/B 测试方法（Not A/B Testing Method）**：  
   A/B 测试仅为众多经验研究方法之一，L8 不强制绑定任何单一统计实验方法；
6. ❌ **L8 不是数据埋点层（Not Telemetry Layer）**：  
   埋点是工程数据收集技术，L8 是对经验事实的提炼、归因与认识论主张治理；
7. ❌ **L8 不是商业营销验证（Not Marketing Validation）**：  
   严禁利用 L8 包装“客户满意度 99.9%”等营销宣传噱头；
8. ❌ **L8 不是理论确证层（Not Theory Confirmation Layer）**：  
   $$\text{Empirical Evaluation} \neq \text{Theory Confirmation}$$  
   经验评估不是为了“替理论盖章”，现实有权挑战理论并揭示理论缺陷；
9. ❌ **L8 不是终极人类价值理论（Not Ultimate Human Value Theory）**：  
   L8 只如实记录经验世界中的人类偏好、行为与满意度，绝不试图越权定义什么是“人类终极善”。

### 5.1 关键跨层边界：L6 Reality Effect 与 L8 Empirical Effect 的区别
母稿在此做出重大理论澄清，防止将 L6 的现实对账与 L8 的经验效应混淆：

$$\text{L6 Reality Effect} \neq \text{L8 Empirical Effect}$$

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        L6 Reality Effect 与 L8 Empirical Effect 对照                   │
├──────────────────────────────────────────┬─────────────────────────────────────────────┤
│ L6 现实效果闭环 (Reality-Effect Closure) │ L8 经验效应评估 (Empirical Effect)          │
├──────────────────────────────────────────┼─────────────────────────────────────────────┤
│ • 关注问题：这个动作在物理世界上真的发生了吗？• 关注问题：这种交互方式给人带来了什么长远影响？│
│ • 时间尺度：单次操作、瞬时或短期对账     │ • 时间尺度：任务级、会话级、系统级或长期演化│
│ • 判定对象：工具调用返回与外部现实状态匹配│ • 判定对象：效率、成本、负担、质量、失误与偏好│
│ • 典型举例：“邮件是否确实送达对方服务器” │ • 典型举例：“引入该邮件审批机制后，团队决策 │
│                                          │   效率是提升了还是因为审批繁琐降低了？”    │
└──────────────────────────────────────────┴─────────────────────────────────────────────┘
```
**通俗大白话**：**L6 问事情真的办成没有；L8 问这种办事方式长期到底带来了什么影响。**

## 六、三个核心对象的明确界分

经验认识论的第一防线，是严禁将观察、归因与结论混为一谈。L8 在正文中确立三大对象的核心界分：

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                         L8 三大核心对象严格区分模型                                    │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 1. Observed Outcome (现实观察结果)                                                     │
│    在特定时间、环境与样本中，客观记录到的现实测量、行为、数据或事件。                  │
│    例：“在采用 Candidate-first 界面后，该组客服人员平均工单处理时间为 12 分钟。”        │
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                     ≠ (不等于)                                         │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 2. Attributed Effect (归因效应)                                                        │
│    通过证据与替代解释审视，判定某一结果在多大程度上是由特定 EHAI 机制所引起的。         │
│    例：“经控制组与基线比对，现有证据支持/估计 Candidate-first 对提速约 3 分钟存在贡献。”│
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                     ≠ (不等于)                                         │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 3. Empirical Claim (经验主张)                                                          │
│    基于上述结果与归因，在受限的适用范围内，对 EHAI 理论或工程所作出的正式学术/工程断言。│
│    例：“在文本类客服场景下，Candidate-first 能有效缩短熟练人员的处理时长，但证据尚不    │
│         足以支持其在复杂法律咨询场景中具有普遍提速效应。”                              │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

$$\text{Observed Outcome} \neq \text{Attributed Effect} \neq \text{Empirical Claim}$$

**强制纪律**：严禁跨越归因直接从观察结果跳跃到理论主张（$\text{Observation} \not\longrightarrow \text{Theory Claim}$）。

## 七、前置门：经验评估范围 (Evaluation Scope)

### 7.1 必须确立 Evaluation Scope
任何经验研究如果脱离了具体范围，其得出的结论在科学上毫无意义。在开展任何 R1/R2/R3 判定之前，必须首先确立一个结构明确的 **经验评估范围（Evaluation Scope）**（中文名保持为候选工作名，不冻结）。

一个合法的 Evaluation Scope 包含 **七项基础必需可恢复要素** 以及 **一项条件性比较基准（Comparison Basis）**：

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              Evaluation Scope 构成要素                                 │
├──────────────────────────┬─────────────────────────────────────────────────────────────┤
│ 基础必需要素 (Base Elements)                                                           │
├──────────────────────────┼─────────────────────────────────────────────────────────────┤
│ 1. Subject / Mechanism   │ 被评估的 EHAI 机制：具体机制、组合模式或交互拓扑            │
├──────────────────────────┼─────────────────────────────────────────────────────────────┤
│ 2. Realization / Config  │ 承载该机制的具体实现：系统版本、技术栈、UI 形式与配置状态   │
├──────────────────────────┼─────────────────────────────────────────────────────────────┤
│ 3. Human / Population    │ 参与评估的人类群体：新手、专家、特定职业、生理或认知特征    │
├──────────────────────────┼─────────────────────────────────────────────────────────────┤
│ 4. Task / Situation      │ 执行的任务类型与现实情境：探索性、确定性、高危度或时间压力  │
├──────────────────────────┼─────────────────────────────────────────────────────────────┤
│ 5. Environment           │ 运行的物理与系统环境：网络延迟、干扰条件、硬件终端类型      │
├──────────────────────────┼─────────────────────────────────────────────────────────────┤
│ 6. Temporal Horizon      │ 观察的时间尺度：单次实验、连续 7 天、三个月纵向追踪         │
├──────────────────────────┼─────────────────────────────────────────────────────────────┤
│ 7. Primary Outcome Concern│ 主要关心的结果维度：耗时、准确率、注意打断、主观疲劳、成本 │
├──────────────────────────┴─────────────────────────────────────────────────────────────┤
│ 条件性比较基准 (Conditional Comparison Basis)                                          │
├──────────────────────────┬─────────────────────────────────────────────────────────────┤
│ 8. Baseline / Comparator │ 比较基线：无 AI 纯手工、旧版系统、未引入 EHAI 时的对照组     │
│                          │ （当经验主张涉及改进、差异、效应量或对比归因时必须具备）    │
└──────────────────────────┴─────────────────────────────────────────────────────────────┘
```

### 7.2 Comparator 的非必备性与比较主张纪律
母稿明确：**Baseline / Comparator 并非所有经验评估的绝对必备项。**
* 探索性观察、安全性异常捕获、可用性定性走查并不一定需要严格的对照组：
  $$\text{No Comparator} \neq \text{No Evaluation}$$
* 但若经验主张涉及“差异（Difference）”、“改进（Improvement）”、“效应量（Effect Size）”或“对比归因（Comparative Attribution）”，则必须依赖与该主张相称的合法比较基准（Baseline / Comparator）：
  $$\text{No Comparison Basis} \longrightarrow \text{No Supported Comparative Claim}$$

### 7.3 Evaluation Scope 与 L7 Assessment Scope 的严格解耦
全规范明确区分 L7 与 L8 的前置门概念，严禁混淆：

$$\text{L7 Assessment Scope} \neq \text{L8 Evaluation Scope}$$
$$\text{Conformance Scope} \neq \text{Empirical Evaluation Scope}$$

* **L7 Assessment Scope** 问的是：在物理工程中，哪些具体的代码、API 和服务需要接受 EHAI 规范管辖；
* **L8 Evaluation Scope** 问的是：在当前这次经验评估中，我们到底在何种人群、任务和时间下研究什么现实效应；
* **关系**：一个商业产品可以 100% 处于 L7 Assessment Scope 之中，但某一次 L8 研究可能仅仅针对其中一个微小的交互对话框（如某项 Choice Grammar 机制）展开专项经验评估。

## 八、R1｜现实结果完整性 (Outcome Integrity)

### 8.1 核心质问与唯实质论纪律
* **核心质问**：  
  > **在已明确的 Evaluation Scope 内，是否对所有具有实质规范或经验相关性的现实结果、代价、负担、质量与风险信号进行了完整恢复，而不存在人为遗漏、概念偷换、虚假修饰或粗暴压缩？**
* **底线法则**：**不是天下所有结果都要测，但已经显现的重要结果不能装作没看见。**
* **关键准据：实质性（Materiality）**：  
  现实世界的交互极其繁复，L8 不要求也没必要记录每一次呼吸或像素微秒刷新：
  $$\text{Every Conceivable Consequence} \neq \text{Required Outcome Set}$$
  但是，凡是在当前 Scope 内具有实质性（Material）的经验结果，严禁刻意隐瞒：
  $$\text{Known Material Consequence} \neq \text{Permissible Omission}$$
  **Materiality 的精确定义**：一个经验结果（Empirical Consequence），若其纳入或遗漏可能实质改变 Outcome characterization、Attribution 分析、Empirical Claim 的强度或适用范围，或者揭示出与上游规范相关的实质影响，则属于 L8 必须恢复的 Material 考虑范畴。
  同时确立防线：
  $$\text{Materiality} \neq \text{Ultimate Value Judgment}$$
  Materiality 是经验刻画与认识论层面的重要性判据，绝不越权等同于对人类终极善恶价值的裁判。

### 8.2 必须覆盖的结果类型
R1 要求评估方案在设计与恢复时，全面审视以下四大象限结果（允许但不冻结此分类）：
1. **预期收益（Intended Benefits）**：任务完成耗时压降、产出质量提升、错误率下降等；
2. **代价与让步（Costs & Trade-offs）**：Token 费用激增、服务器延迟、用户学习曲线成本、物理点击次数等；
3. **人类负担与主观体验（Human Burden & Subjective Experience）**：注意力打断频率、决策犹豫度、心理负荷、挫败感与感知可控度；
4. **非预期与风险信号（Unintended Consequences & Risk Signals）**：险兆事件（Near miss）、系统隐蔽失效率上升、长期的技能退化或依赖盲从、规范被形式化应付的信号。

### 8.3 R1 关键防线等式
为防范各种“挑选指标（Cherry-picking）”的学术与商业欺诈，R1 确立以下防线：

1. **指标不等于结果**：  
   $$\text{Metric} \neq \text{Outcome}$$  
   “点击率提升 20%”是数据指标，并不等于“用户真正完成了意图”。
2. **代理变量改进不等于目标改进**：  
   $$\text{Proxy Improvement} \neq \text{Target Improvement}$$  
   测试题得分提高，不代表在真实生产任务中判断力提升。
3. **局部阳性不等于整体完整**：  
   $$\text{Positive Outcome} \neq \text{Complete Outcome}$$  
   不能只汇报“用户很喜欢新功能”，而对后台崩溃率飙升视而不见。
4. **未观察到不等于不存在**：  
   $$\text{No Observed Harm} \neq \text{No Harm}$$  
   $$\text{No Observed Effect} \neq \text{No Effect}$$  
   由于样本量不足或监测盲区导致的未测出，绝不能断言为“绝对无害”。
5. **短期改善不等于长期有效**：  
   $$\text{Short-term Effect} \neq \text{Long-term Effect}$$  
   第一周由于“新鲜感效应”带来的活跃，绝不代表长期的生产力沉淀。

### 8.4 多维结果与禁止无规则强制标量聚合
全规范最严厉的认识论禁令之一：**严禁在没有合法价值通约规则的前提下，把多维度的复杂结果暴力加权为一个标量总分！**

$$\text{Multi-dimensional Outcome} \neq \text{Scalar Value}$$
$$\text{Outcome Set} \neq \text{Overall Effectiveness Judgment}$$

* **禁止默认创建所谓“EHAI 效能总分（Effectiveness Score）”**；
* 如果系统降低了 3 分钟耗时，但同时增加了 10% 的严重事故隐患，在没有得到授权的合法价值排序规则前，任何系统与资料员均**无权强行宣称其总体是“变好了”还是“变坏了”**：
  $$\text{No valid aggregation rule} \longrightarrow \text{No forced aggregate judgment}$$
* 评估报告必须如实平铺多维度的真实事实，把最终的权衡定夺权交还给治理主体。

### 8.5 效率收益与规范底线：规范约束不是优化变量
在具体实践中，最危险的倾向莫过于“为了效率践踏规范底线”。R1 确立最高伦理与规范铁律：

$$\text{Normative Constraint} \neq \text{Optimization Variable}$$
$$\text{Efficiency Improvement} \neq \text{Overall Human-AI Effectiveness}$$
$$\text{Normatively Inadmissible Gain} \neq \text{EHAI Benefit}$$
$$\text{Normatively Inadmissible} \neq \text{Legally Illegal}$$

* **规范底线绝不与技术指标平价加权**：L1 的主体性保留、L3 的必要人类介入与正式授权（Authorize），是体系的根本约束，绝不能作为与“节省 10 秒时间”放在天平两端互换的普通变量；
* **违规获得的收益不得冒充 EHAI 功劳**：  
  例如某团队在实现中擅自删除了高危转账的 Human Authorization 门禁，导致转账流程提速 70%。  
  **L8 裁定**：提速 70% 是客观存在的物理事实，必须在 R1 中如实记录；但**绝对禁止将该时间缩短记作“EHAI 带来的效能提升”**！相反，该行为必须被定性为严重的 L3/L7 违规所产生的“规范不合格得益 / 违规得益（Normatively Inadmissible Gain）”；
* **法律与规范的清晰区分**：明确 $\text{Normatively Inadmissible} \neq \text{Legally Illegal}$，EHAI 规范有效性是人机系统的内在规范，不与外部司法体系的违法概念混淆；
* **原则总结**：**事实照样记，功劳不能乱算。**

## 九、R2｜效果归因完整性 (Attribution Integrity)

### 9.1 核心质问与唯实归因律
* **核心质问**：  
  > **在明确的 Evaluation Scope 下，所观察到的现实结果是否真的由所声明的 EHAI 机制或其组合引起？重大替代解释是否被识别、评估、在可能时控制，并对仍未解决的解释明确保留其不确定性？**
* **底线法则**：**不能因为一起发生，就说是它造成；也不能因为不是唯一原因，就说它毫无贡献。**
* **审查性质**：R2 的核心是**归因审查 / 因果贡献审查**，重点在于审视因果贡献与识别重大替代解释，而非不切实际地苛求封闭孤立的绝对因果证明。
* **归因强度守恒律**：  
  $$\text{Attribution Strength} \leq \text{Evidence-Supported Attribution Strength}$$  
  归因声称的强度，必须与所持证据的方法严谨度与因果排他性精确匹配。

### 9.2 R2 关键防线等式
1. **相关不等于因果**：  
   $$\text{Association} \neq \text{Causation}$$  
   采用了 Choice Grammar 的用户流失率更低，可能仅仅是因为愿意阅读复杂选项的用户本身忠诚度就更高。
2. **采纳不等于归因**：  
   $$\text{EHAI Adoption} \neq \text{EHAI Attribution}$$  
   产品接入了 DeepBase 框架后业务大涨，可能完全是因为同期上线了大促销，不能将大涨归因于 EHAI 规范。
3. **差值不等于机制效应**：  
   $$\text{Observed Difference} \neq \text{Attributed Effect}$$  
   前后两组数据的差异，包含系统自然演化与历史漂移，不能直接等同于机制的真实影响。
4. **归因不等于唯一因果**：  
   $$\text{Attribution} \neq \text{Exclusive Causation}$$  
   承认 EHAI 发挥了正面作用，绝不等于排他性宣称所有好结果都是 EHAI 的功劳。
5. **部分有效不等于系统有效**：  
   $$\text{Positive Component Effect} \neq \text{Positive Composite Effect}$$  
   $$\text{Composite Effect} \neq \sum \text{Component Effects}$$  
   各个组件单独有效，拼装在一起可能互相抵消；反之，系统级有效也不意味着每个模块都发挥了正向作用。

### 9.3 允许部分归因与不确定归因
现实世界的人机互动极其复杂，其结果往往是高度共变的复杂系统产物：
$$\text{Reality Outcome} = f(\text{Model}, \text{Agent}, \text{UX}, \text{User Skill}, \text{Task}, \text{EHAI Mechanism}, \text{Environment})$$

因此，R2 确立极具包容性与科学诚实的规则：
* **不苛求唯一原因**：并不要求必须证明 EHAI 是导致好结果的唯一孤因；
* **支持贡献性归因（Contributory Attribution）**：允许声明“EHAI 是促成该正面改变的积极贡献因素之一”；
* **保护未决归因（Unresolved Attribution）**：  
  “本系统在上线后整体指标大幅改善，但由于同期伴随底层大模型从 GPT-4 升级为新版本，现有证据无法将两者贡献有效剥离。”  
  这是极其严谨、合法的科学结论。绝不能因为归因暂时未决就否定观察事实：
  $$\text{Unresolved Attribution} \neq \text{Invalid Observation}$$

### 9.4 归因方法中立与不冻结唯一实验工具
* **方法论自由度**：L8 决不强行要求所有经验研究都必须做大规模随机双盲对照实验（RCT）；
* **合法方法谱系**：允许采用长期纵向观察（Longitudinal）、前后对照（Before/After）、配对比较（Matched Comparison）、受控实验、质性深度访谈、自然对照与混合研究方法：
  $$\text{Valid Attribution} \neq \text{Mandatory Randomized Controlled Experiment}$$
* **约束核心**：不限方法，但**主张的硬度必须严格匹配该方法能提供的证据效力**。用简单的问卷调查只能支持“用户感知偏好”，绝对不能支持“任务底层失误率真实下降”的强因果推断。

### 9.5 重大替代解释的审视清单与上限约束
R2 要求经验归因必须主动核查并回应重大替代解释，对其进行识别、评估、在可能时控制，并对仍未解决的解释明确保留其不确定性：
* **模型自然升级**：是否是因为底层 LLM 智力提升，而非交互协议的作用？
* **用户学习效应**：用户在长期使用中自己摸索出了规律，而非界面设计降低了负担；
* **任务难度漂移**：后期测试的任务是否天然比前期简单？
* **幸存者偏差与自我筛选（Self-selection / Survivorship）**：是否不适应界面的用户已经流失，只留下了特定熟手？
* **L7 实现符合性状态的影响**：  
  $$\text{L7 Nonconformance} \neq \text{Automatic Cause of Bad Outcome}$$  
  $$\text{Unresolved Conformance Influence} \longrightarrow \text{Attribution Strength Ceiling}$$  
  已知 L7 nonconformance 应被视为经验归因中的重大替代解释与调节事实；在无法有效分离其影响时，不得把相关异常直接归因于 EHAI 规范本身，未解决的实现影响构成归因强度的天然上限；
* **评估情境自身的因果活性**：  
  $$\text{Evaluation Context Can Be Causally Active}$$  
  （即霍桑效应：人类因为知道自己正在被监测与评估，从而表现得更加谨慎与高效，这种提升属于评估行为本身引起的，而非系统日常机制的作用）；
* **未解决替代解释的防线等式**：  
  $$\text{Unresolved Material Alternative Explanation} \neq \text{Invalid Observation}$$  
  $$\text{Unresolved Material Alternative Explanation} \longrightarrow \text{Attribution Strength Ceiling}$$

## 十、R3｜经验主张完整性 (Empirical Claim Integrity)

### 10.1 核心质问与守界法则
* **核心质问**：  
  > **基于已确认的 Outcome 与 Attribution，对外发布或对内记录的经验主张，在概念、断言强度与适用范围上，是否严格限定在当前证据真正支持的边界之内？**
* **底线法则**：**证据支持多强、多广，就只能说多强、多广。**
* **主张守界双重关系式**：  
  $$\text{Empirical Claim Strength} \leq \text{Evidence- and Attribution-Supported Claim Strength}$$  
  $$\text{Empirical Claim Scope} \subseteq \text{Evidence- and Attribution-Supported Scope}$$

### 10.2 R3 关键防线等式
1. **局部效应不等于普遍规律**：  
   $$\text{Local Effect} \neq \text{General Effect}$$  
   在 Delphi 桌面环境测得的良好结论，不能直接断言在 Web 或移动端同样成立。
2. **机制验证不等于全体系验证**：  
   $$\text{Mechanism Evidence} \neq \text{Whole-System Evidence}$$  
   验证了 0–9 Choice Grammar 的优越性，不能声称“整个 EHAI 体系完全通过了实证检验”。
3. **局部成功不等于宇宙真理**：  
   $$\text{Local Success} \neq \text{Universal Success}$$  
   $$\text{Local Failure} \neq \text{Universal Failure}$$  
   在某一特定具体实现的局部受挫，不能随意断言“EHAI 理论彻底破产”。
4. **主张拔高必须提供额外证据支持**：  
   $$\text{Claim Escalation Requires Additional Support}$$  
   若要将“某场景下有效”升级为“跨行业通用”，必须补足跨行业的充分实证链条。

### 10.3 严禁越界范围扩张（Scope Expansion）
经验结论具有强烈的上下文依附性，严禁无证据支持向以下核心维度（涵盖但不限于）进行范围外推：
* **用户群体扩张**（把年轻工程师的测试结果外推给全体公众）；
* **任务领域与复杂度扩张**（把写日常总结的经验外推给医疗或法律审判）；
* **实现载体与交互形态扩张**（把 PC 复杂界面外推给手机微型屏幕）；
* **风险层级与责任外推**（把低危试算经验外推给重大资产划扣）；
* **时间尺度与演化周期外推**（把 10 分钟单次任务外推给全生命周期运营）；
* **语言、文化与地域情境扩张**（把中文语境下的表述适配外推给跨语种跨文化环境）；
* **机制范围外推**（把 Inform 的成功外推给 Authorize）；
* **运行环境与外部上下文扩张**（把低延迟实验室局域网外推给高扰动外部现场）。

$$\text{Effect Validity Is Scope-Bound}$$
$$\text{Scope Extension} \neq \text{Evidence-Preserving Operation}$$
**大白话**：**把结论说得更广，不是免费动作。**

### 10.4 保护未知（Protecting the Unknown）
科学评估的标志是敢于承认未知。L8 坚决反对非黑即白的二极管思维：
* “结果已测出，但因果归因未知”；
* “归因有微弱支持，但泛化范围未知”；
* “当前证据不足以形成确凿判定，保持未决”。
上述皆为完全合法的 L8 终审输出。**严禁为了“撰写完整报告”而逼迫研究人员在证据不足时强行给出 Yes 或 No**。
$$\text{Qualified Uncertainty 是合法输出}$$
$$\text{Unknown} \neq \text{Failure}$$

## 十一、三大不可约根的完备性候选论证

在当前的理论候选分析视阈下，经验评估阶段可能出现的系统性偏差主要集中在以下三个正交维度：

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                 L8 三大不可约根候选结构                                │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ R1 现实结果完整性 (Outcome Integrity)                                                  │
│ 解决“事实层面的诚实”：在 Scope 内到底实际发生了什么，所有收益与代价是否被完整记录？    │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ R2 效果归因完整性 (Attribution Integrity)                                              │
│ 解决“因果层面的诚实”：发生的结果跟我们做的事情到底有没有关系，排除了哪些干扰项？      │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ R3 经验主张完整性 (Empirical Claim Integrity)                                          │
│ 解决“断言层面的诚实”：面对我们测出的东西，我们到底可以说多大的话，管多宽的事？        │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 11.1 完备性候选论证 (Current Completeness Argument)
一项面向真实世界的经验评估，其潜在的学术、认识论或工程偏差，通常集中反映在三个关口：
1. **数据采集与汇报偏差**（隐瞒负面指标、代理变量偷换、伪造标量总分） $\longrightarrow$ **R1 违规**；
2. **因果推断与归结偏差**（将大促销当成框架功劳、忽视模型升级替代解释） $\longrightarrow$ **R2 违规**；
3. **结论放大与断言外推偏差**（拿一个局部的成功宣称全体系宇宙无敌、把特定场景成果免费外推） $\longrightarrow$ **R3 违规**。

当前理论分析表明，R1、R2、R3 三根联合覆盖了经验评估阶段的主要失败维度，构成了强自洽的候选根结构。

### 11.2 Root 删除攻击测试 (Deletability Test)
对 R1、R2、R3 执行逐一删除攻击推演：
1. **尝试删除 R1（现实结果完整性）**：若删除 R1，则 Attribution 无可靠的现实 Outcome 对象，归因分析失去客观事实锚点，无法防范指标挑选与隐瞒代价；
2. **尝试删除 R2（效果归因完整性）**：若删除 R2，则所观察到的裸结果（Outcome）会被直接偷换成机制引起的因果效应，无法排除模型升级或大促销等重大替代解释；
3. **尝试删除 R3（经验主张完整性）**：若删除 R3，则在局部或特定样本中测得的微弱效应可被无限外推至全局，导致经验主张严重越界。

**删除攻击结论**：R1、R2、R3 均不可删除，三根各具独立且不可约的本体判定功能。

### 11.3 Root 合并攻击测试 (Orthogonality & Merge Test)
对 R1、R2、R3 执行两两合并攻击推演：
1. **尝试合并 R1 与 R2**：$\text{Outcome Set} \neq \text{Attributed Effect}$。记录客观“发生了什么”（事实恢复）与判定“是否由机制引起”（因果审查）属于不同审级，合并将混淆事实恢复与因果归因；
2. **尝试合并 R2 与 R3**：$\text{Attributed Effect} \neq \text{Empirical Claim}$。判定局部因果贡献是否存在，与界定基于该证据能支撑多大范围与强度的断言属于不同审级，合并将混淆归因有效性与外推合法性；
3. **尝试合并 R1 与 R3**：$\text{Observed Outcome} \neq \text{Empirical Claim}$。客观数据不等于理论主张，严禁越过归因直接由裸事实跳跃到学术断言。

**合并攻击结论**：$\text{R1} \neq \text{R2} \land \text{R2} \neq \text{R3} \land \text{R1} \neq \text{R3}$，三根严格正交，**不得为了结构简化合并**。

在 L8 的推导过程中，架构组对以下 12 个潜在的“第四 Root 候选”开展了严密的独立性攻击测试：

| **Replication (可复现性)** | 本质属于归因与主张的稳健性验证，是支撑 R2 与 R3 的证据特征。 | 归入 R2/R3 证据纪律 |

| **Risk / Near Miss (风险/险兆)** | 属于负向结果与未遂结果的范畴，直接归于结果完整性。 | 归入 R1 |

## 十三、证据横切纪律 (Cross-Cutting Evidence Discipline)

证据是连接事实与信念的桥梁，但证据不是第四根：

$$\text{Evidence} \neq \text{Outcome}$$
$$\text{Evidence} \neq \text{Attribution}$$
$$\text{Evidence} \neq \text{Claim}$$

* **证据的横切定位**：Evidence 是横贯并服务于三大根的支撑纪律：
  - 在 R1 中，证据支撑“结果是否真实发生”；
  - 在 R2 中，证据支撑“因果联系是否确实存在”；
  - 在 R3 中，证据支撑“主张范围是否合法相称”；
* **证据防线与不确定状态标识**：
  $$\text{Claimable Empirical Strength} \leq \text{Evidence-Supported Strength}$$
  证据不足或尚未验证时必须显式标注其不确定状态；具体状态枚举与英文命名保持 OPEN，不在此预先冻结。禁止直接宣告理论破产，但严禁发布未经证实的论断。

## 十四、时间维度与动态情境变化纪律

经验结论绝非一劳永逸的恒久石碑。随着时间推移，外部情境必然发生漂移：

$$\text{Material Evaluation Context Change} \longrightarrow \text{Empirical Reassessment}$$

### 14.1 触发重新评估的典型情境
1. **模型能力质变**：底层大模型发生重大版本跃迁或推理架构改变；
2. **交互机制调整**：EHAI 规范条款更新或具体实现的交互界面大幅重构；
3. **人群结构改变**：系统从内部技术尝鲜者扩散到全社会大众；
4. **业务场景转移**：从非关键文娱任务转移到金融或工业控制领域；
5. **长期疲劳与适应**：用户跨越了新手期，形成了固化的心理定势。

### 14.2 变化不变量
* **变化不等于自动作废**：  
  $$\text{Material Context Change} \neq \text{Automatic Effect Invalidity}$$  
  外部环境变化触发的是对既有结论的审慎重估，不意味着旧数据瞬间全无参考价值；
* **历史支持不等于当下支持**：  
  $$\text{Past Empirical Support} \neq \text{Automatic Current Empirical Support}$$  
  禁止拿半年前在旧系统上的正面测试报告，为今天的全新系统做合法性背书。

## 十五、经验反馈与理论闭环机制

经验最终必须以受控、严肃的方式反馈回理论体系，形成自我演进的多分支闭环：

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                            经验向理论的受控闭环流向                                    │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ Qualified Empirical Finding (经 R1/R2/R3 严格检验的经验发现)                           │
│        │                                                                               │
│        ├─► 1. Empirical Support (经验支持：为上游机制在特定范围提供经验印证)           │
│        ├─► 2. Boundary / Scope Refinement (边界细化：明确适用与不适用情境)             │
│        ├─► 3. Qualified Uncertainty (有支持的不确定性：结论保持开放，留待更多证据)     │
│        └─► 4. Qualified Empirical Challenge (正式经验挑战)                             │
│                  │                                                                     │
│                  └─► Revision Candidate (理论修订议案候选)                             │
│                            │                                                           │
│                            └─► Human Authority Review & Reopen (人类终审与重开裁决)    │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 15.1 经验反馈四大铁律
1. **经验挑战不等于规范直接废止**：  
   $$\text{Empirical Challenge} \neq \text{Normative Overrule}$$  
   即便测出了严重的负面经验事实，也不能在代码或报告中单方面宣布上游规范失效；
2. **经验发现不等于理论自动改写**：  
   $$\text{Finding} \neq \text{Challenge}$$  
   $$\text{Challenge} \neq \text{Revision}$$  
   $$\text{Revision Candidate} \neq \text{Automatic Reopen}$$  
   任何上游理论条款的重开与修订，**审批权专属于 Human Authority**，严禁算法或经验报告反客为主；
3. **差结果不必然等于上游理论错误**：  
   $$\text{Bad Outcome} \neq \text{Upstream Theory Failure}$$  
   一个恶劣的经验结果，可能源于多方面的现实因素：
   - 度量工具或观察手段本身存在偏差（Measurement Issue）；
   - 具体实现存在工程性能缺陷或代码实现低劣（Implementation Issue）；
   - 具体实现存在 L7 阶段的适用性漏判、绑定错误或代码绕过后门（L7 Conformance Issue）；
   - 部署环境参数配置或调度策略失当（Configuration Issue）；
   - 该任务与场景天然超出了该机制的适用场域（Domain Limitation）；
   - 上游规范母稿的假设或规约存在理论缺陷（Upstream Normative Defect）。  
   **因果排查平等纪律**：上述各层因素均属于平等的可能解释。R2 严禁先验指定因果优先级，必须依据客观证据逐项评估其 Materiality 与 Attribution Strength，**不得预设其中任何一项必然优先，亦不得预设上游理论缺陷必然排在最后考虑**；
4. **经验支持亦受 Scope 限制**：  
   正面经验印证仅在当前评估 Scope 内有效，不得过度外推为无条件的普遍成立。

## 十八、典型极端反例库 (Extreme Counterexamples)

以下 9 个典型反例经过攻击性推演，构成检验经验评估是否符合 L8 规范的强制性反面基准：

### 反例 A：掩盖代价的报喜不报忧（Cherry-picked Glory）
* **违规现象**：评估报告大肆宣扬某客服系统在引入 L4 选择协议后“用户确认效率提升了 40%”，却刻意删除了系统导致用户由于理解疲劳而在 10 分钟后大量主动挂断电话的严重负面统计。
* **违反准则**：违反 **R1 现实结果完整性**。违背 $\text{Positive Outcome} \neq \text{Complete Outcome}$。
* **危害与纠偏**：以局部片面数据掩盖真实生产崩溃；必须平铺全量 Material 结果。

### 反例 B：偷换概念的伪标量打分（Forced Metric Smuggling）
* **违规现象**：某团队开发了一套算式：$\text{EHAI Score} = 0.7 \times \text{Speed} + 0.3 \times \text{Satisfaction}$，通过拉高反应速度的权重，宣布某高危医疗诊断系统表现“极其优秀”，掩盖了其漏诊率上升的致命事实。
* **违反准则**：违反 **R1 现实结果完整性**。违背 $\text{Multi-dimensional Outcome} \neq \text{Scalar Value}$。
* **危害与纠偏**：剥夺了治理主权者的真实权衡裁决权；禁止在没有法定规则下进行标量合并。

### 反例 C：违规得益当作体系功效（Normatively Inadmissible Glory）
* **违规现象**：产品私自解除了对银行账户大额转账的 L3 Human Authorization 门禁，使得转账流水速度加快 3 倍，团队向管理层汇报称“EHAI 带来了 300% 的业务增长”。
* **违反准则**：违反 **R1 现实结果完整性**。违背 $\text{Normatively Inadmissible Gain} \neq \text{EHAI Benefit}$。
* **危害与纠偏**：把践踏规范底线的规范违规行为包装为技术创新；事实照样记，功劳绝不能算。

### 反例 D：搭便车式的虚假归因（Free-riding Attribution）
* **违规现象**：产品上线 EHAI 框架的同一天，工程团队将后台大模型升级到了最顶尖版本。系统整体任务成功率从 50% 跃升到 85%，评估报告将全部 35% 的跃升归功于“EHAI 交互协议的胜利”。
* **违反准则**：违反 **R2 效果归因完整性**。违背 $\text{Association} \neq \text{Causation}$ 与忽略重大替代解释。
* **危害与纠偏**：贪天之功，掩盖了交互机制真实的贡献边界；必须如实分离或声明归因未决。

### 反例 E：把实验室结果外推为宇宙通行（Unchecked Scope Expansion）
* **违规现象**：在 10 名计算机系硕士研究生完成写代码测试后（测得正面增益），厂商在宣传大纲中公然宣称“EHAI 能够在全行业、全人类所有智力工作中无条件带来卓越提速”。
* **违反准则**：违反 **R3 经验主张完整性**。违背 $\text{Local Effect} \neq \text{General Effect}$。
* **危害与纠偏**：虚假承诺与学术欺诈；主张范围必须被严格封锁在测试样本的同质边界内。

### 反例 F：将暂时未决粗暴等同于理论破产（Premature Invalidation）
* **违规现象**：某次为期 3 天的早期内部走查中，由于测试数据量太少导致归因不显著，初级研究员便直接写结论“EHAI 理论彻底失效，应全面废除”。
* **违反准则**：违反 **R3 经验主张完整性**。违背 $\text{Unknown} \neq \text{Failure}$。
* **危害与纠偏**：混淆了“未证实”与“证伪”；科学允许并保护 Qualified Uncertainty。

### 反例 G：霍桑效应冒充系统固生效力（Hawthorne Contamination）
* **违规现象**：用户在测试期间知道旁边有 5 名架构师现场盯着录像，因此极其专注，失误率为零。报告据此声称该系统的交互设计“天生杜绝任何人类操作失误”。
* **违反准则**：违反 **R2 效果归因完整性**。违背评估情境自身具有因果活性纪律。
* **危害与纠偏**：将人类被监测产生的应激自律偷换为界面机制的有效性。

### 反例 H：用满意度取代客观现实有效性（Satisfaction Hijacking）
* **违规现象**：某系统满屏拟人化讨好用户，用户主观问卷满意度打满分，但其实际业务处理中发生了严重的法律事实错误。评估团队仅凭满意度宣称“交互达成了极高的客观功效”。
* **违反准则**：违反 **R1 与未来价值边界**。违背 $\text{Observed Satisfaction} \neq \text{Normative Good}$。
* **危害与纠偏**：把情绪阿谀奉承当成现实有效交付，违背 L2 交付完成态与科学诚实。

### 反例 I：私自改写上游规范条款（Rogue Normative Overrule）
* **违规现象**：某外包团队在测试中发现用户嫌两次点击太慢，便直接在经验报告中宣布“L3 的 H/A/E 规则已正式被实践推翻，本产品已将该规则废止”。
* **违反准则**：违反 **理论闭环与治理纪律**。违背 $\text{Empirical Challenge} \neq \text{Normative Overrule}$。
* **危害与纠偏**：经验有权提出质疑形成议案，但绝无私自篡改或宣布规范作废的权力。
