## 二、先把问题问对：这不是「配不配 COS」，是「谁来承担对象存储职责」

F2 证明：**DeepBase 侧没有任何功能依赖 COS**。所以决策的真实形态是三种，不是两种：

| 选项 | 含义 | 谁付代价 |
|---|---|---|
| **O1 · 不配（推荐评估）** | 明确 DB4 侧不使用 COS；需要二进制/大对象时走 PG 大对象字段或现有 `CloudSync` 通道 | 我方：**零采购、零密钥管理、零数据出境评估** |
| **O2 · 配（在 DB4 侧）** | DB4 侧自建/租用对象存储并承担密钥与合规 | 老板：采购 + `COS_SECRET_ID/KEY` 的保管与轮转 + 数据出境/等保评估 |
| **O3 · 配但由我方账号持有、DB4 侧只读** | 桶在我方账号，DB4 侧拿只读凭据 | 老板：采购 + **我方承担凭据泄漏的全部后果**（DB4 是对端服务，泄漏面在我方） |

## 三、代价对照（决策所需的全部信息）

| 维度 | O1 不配 | O2 DB4 侧配 | O3 我方账号配、DB4 只读 |
|---|---|---|---|
| 采购与年费 | 0 | DB4 侧承担 | **我方承担** |
| 密钥保管与轮转 | 无 | DB4 侧承担 | **我方承担**，且凭据要跨组织交付给对端 |
| 数据出境 / 等保 / 保密评估 | 无 | DB4 侧承担（但**业务责任在我方**） | **我方承担**，且一旦涉政/军工客户场景，桶在我方名下会成为审查项 |
| 现有功能是否受影响 | **否**（F2：仓内零引用） | 否 | 否 |
| 未来若 DB4 提出大对象需求 | 需临时选型（PG 大对象或再议），**成本可后延** | 已就绪 | 已就绪 |
| 可逆性 | **最高**（不做即无需回退） | 中（已采购的桶有最小留存期/欠费风险） | 中（同左，且凭据已交付，回滚需轮转） |
| 若判断错误的后果 | DB4 侧提需求时我方需二次决策，**延迟但不产生损失** | 可能买了用不上的桶（沉没成本） | 可能买了用不上的桶**并已把凭据交出去**（沉没成本 + 凭据面已扩散） |
