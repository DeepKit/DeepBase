# DeepShell 结构规范

> audience: ai, developer
> status: design-contract

## 1. 总原则

DeepShell 的桌面结构是：

> 主窗体轻，中间工作；左右悬浮，多区多页；上中下折叠。

主窗体不做重型 IDE，不固定塞满左中右三栏。结构树和探查器通过悬浮工具窗提供，主窗体把最大面积留给主工作区。

## 2. 主窗体区域

```text
+--------------------------------------------------+
| 1. Command Surface: menu / toolbar / quick action |
+--------------------------------------------------+
| 2. Top Area: summary / context / metrics          |
+--------------------------------------------------+
| 3. Middle Area: main workspace / view host        |
+--------------------------------------------------+
| 4. Bottom Area: logs / issues / tasks             |
+--------------------------------------------------+
| 5. StatusBar                                      |
+--------------------------------------------------+
```

### 2.1 Command Surface

放高频命令：

```text
新建
打开
保存
运行
停止
刷新
搜索
结构窗
探查窗
日志
设置
```

规则：

- 所有按钮都绑定 Command。
- 工具栏只放高频命令。
- 复杂命令进入菜单、命令面板或下游工具窗。

### 2.2 Top Area

顶部区负责全局摘要：

```text
当前项目
当前对象
当前视图
关键统计
风险提示
服务状态摘要
```

折叠后保留一行摘要，例如：

```text
DeepSpec | Delphi VCL | Pas 42 | DFM 6 | Issues 3 | Ready
```

### 2.3 Middle Area

中部是主工作区。它承载：

```text
欢迎工作台
WebView2 浏览器
编辑器
报表
表格
Diff Viewer
配置页面
业务主视图
```

中区也要可折叠。折叠后不能变成空白，必须保留：

```text
当前视图标题
最近打开视图
恢复主工作区按钮
```

### 2.4 Bottom Area

底部区负责过程信息：

```text
日志
问题
错误
任务进度
操作记录
调试信息
服务诊断
```

默认可折叠。正常状态只露状态栏；出现错误或长任务时提示用户展开。

## 3. 左侧悬浮窗

左侧悬浮窗是结构 / 导航窗。

职责：

```text
项目树
对象树
模块树
功能树
UI 层次树
搜索结果
过滤器
最近节点
异常节点
```

结构：

```text
Structure Window
├─ 上区：主结构树
└─ 下区：搜索 / 过滤 / 最近 / 异常
```

规则：

- 可显示 / 隐藏。
- 可置顶 / 取消置顶。
- 可锁定当前项目或跟随当前项目。
- 位置和大小进入 Layout。
- 树内容由 `IShellStructureProvider` 提供。

## 3.1 悬浮窗推荐实现

第一版推荐使用 VCL 原生 `TForm` 实现左右悬浮窗，不引入 Docking 框架，也不做自绘浮动面板。

推荐结构：

```text
TDeepShellToolWindow = class(TForm)
  PageControl / Panel / Splitter
```

行为规则：

- 默认是普通 owned form，由主窗体创建和释放。
- 置顶由用户命令切换，可用 `FormStyle := fsStayOnTop` 或等价 Win32 topmost 实现。
- 不默认抢焦点；显示时尽量不打断主工作区。
- 位置、大小、置顶、锁定、跟随状态进入 Layout。
- 恢复布局时必须检查显示器工作区，窗口不能落到屏幕外。
- 第一版不实现 Docking、自动隐藏、吸附边缘；这些作为第二阶段增强。

使用 `TForm` 的理由：

- 与 VCL 生命周期和多显示器行为最直接。
- Layout 保存只需要窗体 bounds 与状态，不需要保存复杂 dock tree。
- 下游产品可把结构窗拖到第二显示器。

## 4. 右侧悬浮窗

右侧悬浮窗是探查器 / 属性窗。

职责：

```text
属性
状态
来源
位置
可信度
关联
问题
决定
变更
备注
```

结构：

```text
Inspector Window
├─ 上区：属性 / 状态 / 来源
└─ 下区：关联 / 问题 / 决定 / 备注
```

规则：

- 只负责解释和辅助决策，不承载主要编辑。
- 可跟随当前对象。
- 可锁定某个对象用于对照。
- 内容由 `IShellInspectorProvider` 提供。

## 5. 折叠状态

三段区域都要记录：

```text
Visible
Collapsed
Height
LastExpandedHeight
ActiveTabId
```

折叠状态由用户决定。程序可提示展开，但不要未经用户同意频繁强制展开。

## 6. 默认布局

第一次启动：

```text
Top Area: 展开
Middle Area: 展开
Bottom Area: 折叠，只露状态栏
Structure Window: 隐藏
Inspector Window: 隐藏
```

打开项目后，可按项目类型自动显示结构窗，但必须可由用户关闭并记忆。

## 7. 禁止事项

- 不要把结构树固定塞进主窗体左侧。
- 不要让主工作区默认被日志或属性面板挤压。
- 不要让中区折叠后无法恢复。
- 不要把业务编辑功能放进右侧探查器。
- 不要在区域状态里保存具体控件树。
