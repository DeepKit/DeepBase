### 7.4 DeepAxis 桌面自动化的差异化定位

DeepAxis 是建在 DeepBase 之上的桌面智能体（perception-reasoning-action 沉积分层）。在桌面自动化赛道，DeepAxis 相对现有开源方案有结构性差异化，此处显式声明，避免后续开发者误判方向。

**双通道架构（主：UIA，补：视觉）**

DeepAxis 的桌面感知走 `DeepBase.UIA.UnifiedActuator`（SendInput + UIA accessibility）为主通道，仅在 UIA 无法覆盖的盲区（自绘控件、画布、游戏画面）用像素级视觉（找色/帧缓存/OCR）兜底。这与纯视觉坐标流方案有本质区别：

- 纯视觉方案（如 PyAutoGUI、wechat-mac-rpa）依赖 OCR/模板匹配定位元素，换 UI 版本、DPI、分辨率即退化。可复现性数据表明：纯视觉流在代表性场景表现尚可，但回归挑战场景退化为 0%——泛化能力脆弱。
- UIA 主通道不依赖屏幕像素泛化，控件语义稳定，是 DeepAxis 的护城河。视觉仅作盲区补全，不承担主路径职责。

**跨应用通用，不锁定单一应用**

DeepAxis 面向 Windows 任意桌面应用的通用自动化，不绑定单一应用（如 wechat-mac-rpa 锁 macOS 微信、browser-use 锁浏览器）。开源生态中，"UIA 主 + 视觉补 + 通用桌面"三者皆备的方案当前为空白，这是 DeepAxis 的差异化定位。

**比官方 computer-use 更前置的成本闸门**

Anthropic 官方 computer-use 纯全屏截图喂模型、不做帧间变化检测。DeepAxis 的感知层在截图与 LLM 之间设两道闸门：

1. `TFrameDiffer`：像素差分短路，屏幕静止则整屏零成本跳过（不进入帧缓存/provider）。
2. L0 帧缓存：以 provider 身份 + 截图 MD5 为键，同图复用上次识别，跳过昂贵的 vision provider 调用。

这两道闸门使 DeepAxis 在屏幕静止高频轮询场景下的 LLM/OCR 调用成本远低于纯全屏直喂方案，是比官方更前沿的优化点，属 DeepAxis 差异化价值的一部分。

**阈值不可照搬外部项目**

外部 RPA 项目（wechat-mac-rpa 等）的 OCR/Layout 阈值过拟合到特定应用版本与分辨率，移植到 DeepAxis 必须用 DeepAxis 自有样本 P95 重标定（详见 docs/94 §4 反面教材）。禁止照搬外部魔法数（如固定 RGB 容差、固定 hash 海明距离）。

**Delphi 编译型性能是加分项**

Delphi/Object Pascal 在桌面自动化无成熟开源生态，但 DeepAxis 已自建 `DeepBase.UIA.UnifiedActuator`；编译型原生性能对 `TFrameDiffer` 这类 O(n) 高频像素运算反而是加分项，不构成阻塞。
