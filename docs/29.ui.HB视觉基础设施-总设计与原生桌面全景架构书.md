## 1. 架构定位与事实分级原则

### 1.1 二层边界原则
```
+-----------------------------------------------------------------------------------------------+
|  【应用业务层】(DeepCommerce / DeepDsh / Assayer / DeepRW / DeepSync / AsWish)                 |
|  • 负责业务表单编排、DB1/DB2/API 事务绑定、业务规则校验与多步骤向导逻辑                           |
+-----------------------------------------------------------------------------------------------+
                                          │ 消费 / 组装 (只读依赖)
                                          ▼
+-----------------------------------------------------------------------------------------------+
|  【DeepBase HB 视觉基座层】(DeepBaseCore.dpk / DeepBaseVCL.dpk / DeepBaseFMX.dpk)             |
|  • 纯设计令牌系统 (10 主题 x 2 密度 x DPI 矢量缩放)                                             |
|  • 通用控件库 (THbFacetWaterfall / THbChoiceDeck / THbDialog / THbVoiceDialog / THbGrid 等)  |
|  • 四自触点契约与本地离线遥测缓冲 (Touchpoint Engine & Local Telemetry)                        |
|  • 离屏脱敏渲染器 (THbShareCardRenderer) / 全局动效调度器 (THbAnimationTicker)                 |
|  • 多显示器工作区比例锚定引擎 (THbWindowProportion) 与 Per-Monitor v2 矢量适配                  |
|  • 反事实门禁断言 (CF-VOICE-01..06) 与多线程死锁防御基础设施                                   |
+-----------------------------------------------------------------------------------------------+
```

### 1.2 核心纪律红线
1. **零硬编码色值**：所有界面绘制必须且只能从 `THbTheme.Tokens` 获取颜色、圆角、字号与间距；
2. **严禁越界反向依赖**：DeepBase 任何单元不得引用下游产品私有 Units、SQL 语句或专属业务 DTO；
3. **动效克制高级**：金色像素占比 `< 8%`（`MotionGoldMaxRatio`），低配机稳定 60fps，高刷屏稳跑 120fps；
4. **决策安全闭环（Fail-Closed）**：关键变更、高风险行为与 AI 提取字段必须经人类用户在 `THbDialog` 或 `THbVoiceDialog` 中显式确认，未确认内容绝不得直接入库；
5. **线程与死锁防御**：UI 线程禁止 `Sleep`，跨线程刷新严禁使用 `TThread.Queue`，必须使用 `TThread.ForceQueue`。

## 4. 核心向导与交互组件族深度方案

### 4.1 多层分级瀑布流向导（`THbFacetWaterfall`）
```
┌─────────────────┬───────────────────────────────────────────────────────────────────┬──────────────────────┐
│  左侧分面导轨   │                     中间多层级瀑布信息流                          │   右侧属性检查器     │
│ (Left Facet Rail│           (Hierarchical Nested Waterfall Stream)                  │  (Property Inspector)│
├─────────────────┼───────────────────────────────────────────────────────────────────┼──────────────────────┤
│ [全部类别 (12)] │ [0] 方案总览：重构视觉系统 (L0 顶层意图)                    ▼  ▾  │ ⛶ 全屏预览           │
│ [需求与意图 (4)]│     │                                                             │ 🔗 打开资源链接      │
│ [架构设计   (3)]│     ├── [1] 模块 1：0–9 预置选择卡组 (L1 一级分支)          ▼  ▾  │ ──────────────────── │
│ [门禁验证   (5)]│     │       │                                                     │ 工单: WO-005-B       │
│                 │     │       └── [2] 键位与状态机规范 (L2 二级细节)            ▾  │ 缩进: 28px/level     │
│ [x] 排除此项    │     │                                                             │ 状态: 已验证         │
│ [★] 正向聚焦    │     └── [1] 模块 2：多层瀑布嵌套流 (L1 一级分支)            ▼  ▾  │ 粒度: gMedium (适中) │
└─────────────────┴───────────────────────────────────────────────────────────────────┴──────────────────────┘
```
1. **28px 层级缩进**：$IndentPx = Depth \times Round(28 \times \frac{PPI}{96})$，保证多 DPI 矢量等比递增；
2. **L0–L5 28px 方形数字色标**：左侧固定 28px 宽面板，以对应层级 Token 为底色，白字呈现 `0..5` 数字；
3. **双折叠状态机**：`Collapsed`（左侧 `▼`/`▶` 收起子孙树）与 `IsExpanded`（右侧 `▾`/`▴` 展开详情 68px ⇄ 116px）正交解耦；
4. **六档粒度联动**：`gCoarsest (L0)` $\rightarrow$ `gCoarse (L1)` $\rightarrow$ `gMedium (L2, 默认)` $\rightarrow$ `gFine (L3)` $\rightarrow$ `gFiner (L4)` $\rightarrow$ `gFinest (全展开)`；
5. **属性检查器与全屏模态**：右侧 260px 属性面板（`THbCardProperty` 键值表 + `THbWaterfallLinkKind` 资源直达 + `PreviewFullscreen` 全屏预览）。

### 4.2 0–9 统一决策预置卡组（`THbChoiceDeck`）
- **1..7 候选键**：1 号项支持 `IsRecommended` 标记（提供参考，不宣称绝对最优）；
- **8 号固定“重新生成”** / **9 号固定“自己输入”**（触发 `OnCustomInput` 事件）/ **0 号固定“返回”**；
- **键鼠 100% 等价**：主键盘数字键、小键盘与鼠标点击严格等价，禁用项智能拦截。

## 5. 《四自产品 × Touchpoint UI》工程架构体系

### 5.1 触点状态转换契约
每一个触点单元必须明确声明：$User\_State_{before} \xrightarrow{Action} User\_State_{after}$。
- **自营销（Self-Marketing）**：用户在产品内部自然发现下一个业务价值，严禁弹窗轰炸；
- **自承接（Self-Onboarding）**：路径遵循 `问题 → 显影 → 选择 → 分流 → 下一步`，初次使用 0 人工解释完成核心任务；
- **自成长（Self-Growth）**：持续使用沉淀资产，系统学习增益保持 $\text{LG} > 0$；
- **低客服（Low-Service）**：追求“少客服 + 高成功率”，客服量下降但任务流失上升一票否决。

> 完整触点契约、YAML 结构、四自度量公式与组件职责详见 [30.touchpoint v2.0](file:///d:/_Progs/02Business/DeepBase/docs/30.touchpoint.md)。

### 5.2 G0–G4 五级工程准入门禁
任何新功能必须遵循 `G0 存在 → G1 可运行 → G2 可承接 → G3 可验证 → G4 可改善` 逐级爬坡验证。

> G0–G4 详细证据要求、7 项性能基准硬门禁与黑盒盲测一票否决规程详见 [31.hb-test v1.1](file:///d:/_Progs/02Business/DeepBase/docs/31.hb-test.md)。
