# DeepShell Command 与 Governance 集成

> audience: ai, developer
> status: design-contract

## 1. 目标

DeepShell 中所有用户动作都应进入 CommandManager。Governance 只需要拦截 Command 执行入口，就能覆盖菜单、工具栏、快捷键和右键菜单。

标准链路：

```text
按钮 / 菜单 / 快捷键 / 右键菜单
  -> CommandManager.Execute
  -> GovernanceService.EnterGate
  -> Execute handler
  -> Status / Log / Evidence
```

## 2. Command 必备字段

```pascal
TShellCommand = record
  Id: string;
  Caption: string;
  Hint: string;
  Category: string;
  ShortcutText: string;
  Visible: Boolean;
  Enabled: Boolean;
  Checked: Boolean;
  CapabilityId: string;
  GateKey: string;
  RiskLevel: Integer;
  PurposeKey: string;
  RequiresEvidence: Boolean;
end;
```

风险等级建议映射：

```text
0 = L0 只读或无风险
1 = L1 低风险
2 = L2 中风险，需要证据
3 = L3 高风险，需要门禁和问责
```

## 3. 第一版策略

DeepMainForm 第一版：

- Command 字段预留完整。
- 默认注册 `NullGovernanceService`。
- 不硬依赖 `DeepBaseGovernance.dpk`。
- 不阻断任何命令。

第二阶段：

- 添加 `DeepShell.GovernanceAdapter`。
- 通过 `IGovernanceService` 包装 OCGS `EnterGate`。
- 默认 `gmObserve`。

第三阶段：

- 对稳定的 L2/L3 命令启用 `gmEnforce`。

## 4. 什么时候必须治理

以下命令应声明 `GateKey`：

```text
删除文件
覆盖文件
批量重命名
执行 SQL 写操作
清空数据库
运行外部命令
浏览器自动化提交动作
LLM 自动修改代码
LLM 自动提交配置
发布 / 上传 / 同步
支付 / 授权 / 升级
插件加载
密钥变更
关闭安全功能
```

只读查看、切换主题、展开折叠、打开日志通常是 L0。

## 5. Governance 启动模式

首次接入：

```pascal
RegisterGovernance(gmObserve, ConfigDB, SetupGovernance);
```

`gmObserve` 记录 Evidence，不阻断。稳定后：

```pascal
GovernanceLifecycle.SwitchMode(gmEnforce);
```

切换前确认：

- Gate 已注册。
- ActionGrid 已注册。
- L2/L3 action 有 DueRule。
- Evidence 持久化已验证。
- 阻断消息可被用户理解。

## 6. SetupGovernance 职责

下游负责注册自己的能力：

```text
Purposes
Fields
Gates
Actions
DueRules
BridgeKeys
Evaluators
```

Shell 可以注册平台级命令：

```text
settings.change
layout.reset
recent.clear
secret.change
service.connect
```

业务命令由下游注册。

## 7. Context 转换

Governance 需要 JSON context。DeepShell 应从 `TShellContext` 转换：

```json
{
  "project_id": "...",
  "project_path": "...",
  "object_id": "...",
  "object_kind": "...",
  "provider_id": "...",
  "view_id": "...",
  "command_id": "...",
  "user_id": "..."
}
```

不要把业务对象直接塞进 Governance。

## 8. 失败处理

EnterGate 返回拒绝时：

- 不执行真实 handler。
- 在底部日志记录 warning。
- 状态栏显示简短原因。
- 如有详情，打开底部问题或治理详情页。
- 保留 Evidence。

## 9. 拒绝反馈策略

不同风险等级的拒绝反馈不同，避免低风险操作过度打扰，也避免高风险阻断被用户忽略。

```text
L0：通常不走 Gate；如果被拒绝，只写状态栏和 debug 日志。
L1：状态栏 + 底部日志 warning，不弹模态框。
L2：状态栏 + 非模态通知 + 底部问题区记录，可自动提示展开底部区。
L3：明确阻断反馈。使用模态对话框或聚焦的阻断面板，显示拒绝原因、需要的条件、Evidence/详情入口。
```

推荐用户体验：

- 用户主动点击的 L2/L3 命令被拒绝时，必须给可见反馈。
- 后台任务中的拒绝不要弹出多个模态框，应汇总到底部问题区。
- 拒绝消息应包含“为什么被拒绝”和“用户下一步能做什么”。
- 模态反馈只用于 L3 或会造成数据破坏的动作。
- 所有拒绝都写入日志和 Evidence。

CommandManager 应使用 `TShellGovernanceDecision` 结构化结果，而不是只用 Boolean：

```pascal
Decision := Governance.EnterGate(Command.GateKey, ContextJson);
if not Decision.Allowed then
begin
  ShowGovernanceDenied(Command, Decision);
  Exit;
end;
```

其中：

```text
MessageText：短原因，适合状态栏和日志
UserHint：用户下一步应该怎么做
EvidenceId：证据记录 id，可用于详情页
DetailJson：adapter 返回的扩展细节
```

## 10. 禁止事项

- 不要绕过 CommandManager 执行高风险动作。
- 不要在 UI 按钮事件里直接调用业务删除、提交、执行 SQL。
- 不要第一天就 `gmEnforce`。
- 不要把 Governance 具体单元放进 `TDeepMainForm` 核心 uses。
- 不要在下游项目创建 `config/governance/*.json`。
