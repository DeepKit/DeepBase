# DeepShell 桌面标准壳：原生结构规范

## 1. 定位

DeepShell 是一个可复用于多个 Windows 桌面软件的原生界面结构模板。

它不是某一个产品的临时界面方案，而是后续 Delphi/VCL 框架可以内置的标准 Shell。

适用对象包括但不限于：

- DeepSpec / 深范
- DeepUITest / 深测
- DeepGuide Studio / 深导 Studio
- DeepConfig / 深配
- DeepDev / 深构
- OCGS-Delphi 工具
- ShineOps 管理端
- 其他 Windows 桌面工具型软件

---

## 2. 总体原则

一句话：

> **主窗体轻，中间工作；左右悬浮，多区多页；上下折叠，多 Tab 承载。**

或者更短：

> **左右悬浮，中间工作；上下可折叠。**

---

## 3. 主窗体结构

主窗体不做重型 IDE，不固定塞满左中右三栏。

主窗体保留中间主工作台，由四个区域组成：

```text
+--------------------------------------------------+
| ① 工具栏                                          |
+--------------------------------------------------+
| ② 顶部可折叠摘要区 / 多页区                       |
+--------------------------------------------------+
| ③ 中部主工作区 / 主浏览区 / 主编辑区               |
+--------------------------------------------------+
| ④ 底部可折叠信息区 / 日志区 / 多 Tab 区            |
+--------------------------------------------------+
```

---

## 4. 主窗体四区说明

### 4.1 工具栏

工具栏放高频操作。

常见按钮：

```text
打开
保存
扫描
刷新
导出
结构窗
探查窗
日志
设置
```

工具栏原则：

- 不堆太多按钮；
- 只放高频动作；
- 复杂能力进入下拉菜单或悬浮窗；
- 后续不同软件可替换工具栏按钮集。

---

### 4.2 顶部可折叠摘要区

顶部区用于显示当前项目、当前对象、当前任务的总览信息。

可采用：

```text
Panel + PageControl / TabControl
```

可包含：

```text
项目摘要
扫描统计
当前基准
最近变更
当前任务
关键指标
```

折叠后只保留一行摘要，例如：

```text
DeepSpec 项目｜Delphi VCL｜Pas 42｜DFM 6｜候选功能 23｜扫描完成
```

设计原则：

- 默认可折叠；
- 信息密集但不抢主工作区；
- 适合显示全局状态和关键统计；
- 不承担主要编辑与操作职责。

---

### 4.3 中部主工作区

中部是主窗体最重要区域。

它可以根据软件类型承载：

```text
WebView2 浏览器
主编辑器
文档呈现区
报告呈现区
设计画布
表格主视图
代码/文本预览
业务主工作区
```

对于 DeepSpec，主工作区主要是：

```text
WebView2 主呈现区
```

用于显示：

```text
扫描报告
文档详情
节点详情
AI 参考摘要
代码文件说明
配置文件说明
决定记录
变更记录
```

设计原则：

- 中部保持最大面积；
- 只承担主阅读、主编辑、主浏览、主工作；
- 不固定塞入结构树和属性区；
- 左右能力通过悬浮工具窗提供。

---

### 4.4 底部可折叠信息区

底部区用于承载过程信息、状态信息、日志信息。

可采用：

```text
Panel + PageControl / TabControl
```

常见 Tab：

```text
状态
扫描日志
问题
解析错误
操作记录
变更记录
调试信息
```

折叠后只保留简短状态栏，例如：

```text
当前项目｜当前页面｜扫描完成｜发现 3 个问题
```

设计原则：

- 默认可折叠；
- 出问题时展开；
- 适合承载大量过程信息；
- 避免污染主工作区。

---

## 5. 左侧悬浮窗：结构 / 导航窗

左侧能力不固定在主窗体中，而是做成可打开、隐藏、置顶、锁定、记忆位置的悬浮工具窗。

暂命名：

```text
Structure Window / 结构窗 / 导航窗
```

### 5.1 基本职责

左侧悬浮窗负责：

```text
结构树
导航树
目录树
对象树
功能树
模块树
UI 层次树
项目资源树
搜索结果
过滤器
最近节点
异常节点
```

### 5.2 推荐结构

左侧悬浮窗自身可以继续分上下两区：

```text
左悬浮窗：结构窗
├─ 上区：主结构树区
│  ├─ 功能树
│  ├─ 模块树
│  └─ UI 层次树
│
└─ 下区：辅助导航区
   ├─ 搜索结果
   ├─ 过滤条件
   ├─ 最近访问节点
   ├─ 已确认基准节点
   └─ 异常节点
```

### 5.3 控件建议

可使用：

```text
TTreeView
TVirtualStringTree
TreeList
PageControl
Splitter
Panel
```

对于大量节点，优先使用：

```text
VirtualStringTree / TVirtualStringTree
```

### 5.4 设计原则

- 左窗负责“我要看哪个对象”；
- 主窗体负责“对象主要内容是什么”；
- 右窗负责“对象状态、属性、关系是什么”；
- 左窗可以拖到第二显示器；
- 左窗可以置顶；
- 左窗可以锁定当前项目或跟随当前项目。

---

## 6. 右侧悬浮窗：属性 / 探查窗

右侧能力也不固定在主窗体中，而是做成悬浮工具窗。

暂命名：

```text
Inspector Window / Project Inspector / 项目探查窗 / 属性窗
```

### 6.1 基本职责

右侧悬浮窗负责当前对象的细节探查：

```text
属性
状态
来源
位置
可信度
关联
问题
决定
变更
备注
日志
```

### 6.2 推荐结构

右侧悬浮窗自身可以分上下两区：

```text
右悬浮窗：项目探查窗
├─ 上区：当前对象属性区
│  ├─ 基本属性
│  ├─ 状态
│  ├─ 来源位置
│  └─ 可信度
│
└─ 下区：关联与过程区
   ├─ 关联功能
   ├─ 关联模块
   ├─ 关联 UI
   ├─ 问题
   ├─ 决定
   ├─ 变更
   └─ 备注
```

### 6.3 控件建议

可使用：

```text
PageControl
PropertyGrid / 自定义属性表
ListView
Memo
TreeView
Splitter
Panel
```

### 6.4 设计原则

- 右窗负责“当前对象为什么是这样”；
- 不抢主工作区；
- 可跟随当前选中对象；
- 可锁定某个对象用于对照；
- 可显示多 Tab 信息；
- 后续可作为统一 Inspector 框架复用。

---

## 7. 窗口行为标准

所有悬浮窗建议支持：

```text
显示 / 隐藏
置顶 / 取消置顶
锁定 / 跟随
记忆位置
记忆大小
记忆上次打开状态
支持多显示器
可折叠局部面板
可使用 Splitter 调整上下区域
```

可选增强：

```text
吸附屏幕边缘
吸附主窗体边缘
自动隐藏
布局方案保存
布局方案恢复
```

---

## 8. 信息流标准

标准交互流：

```text
用户在左侧结构窗选择对象
    ↓
主窗体中部显示对象主内容
    ↓
右侧探查窗显示对象属性、状态、来源、关联
    ↓
底部信息区显示日志、问题、操作记录
```

对应职责：

```text
左侧：选对象
中间：看内容 / 做主工作
右侧：查属性 / 查依据 / 查关系
底部：看过程 / 看问题 / 看日志
顶部：看全局摘要
```

## 10. 桌面端优势

该结构体现桌面软件相对单网页/单窗口应用的优势：

```text
多窗体
多面板
多页签
多显示器
可隐藏
可置顶
可锁定
可折叠
可拖动
可长期保持布局
```

它适合开发类、治理类、分析类、结构化呈现类桌面软件。
