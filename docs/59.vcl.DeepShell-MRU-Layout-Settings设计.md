# DeepShell MRU / Layout / Settings 设计

> audience: ai, developer
> status: design-contract

## 1. 三者分工

```text
MRU / Recent：用户最近访问了什么
Layout：窗口和面板怎样摆放
Settings：用户偏好和应用配置
```

不要把三者混成一个大 JSON。用户说“MRU 记录状态”时，设计上应理解为：MRU 记录最近项目或视图，并关联对应 LayoutKey / SessionKey。

## 2. MRU 记录什么

MRU 至少记录：

```text
最近项目
最近文件
最近视图
最近命令
最后打开时间
显示名
类型
LayoutKey
是否失效
```

MRU 不记录：

```text
窗口坐标细节
控件树
业务对象指针
密码 / Token / Secret
```

## 3. Layout 记录什么

全局 Layout：

```text
主窗体位置和大小
最大化状态
默认三区折叠策略
左右工具窗默认状态
默认主题 / 字号 / 密度
```

项目级 Layout：

```text
项目 Id
当前视图
当前对象引用
Top/Middle/Bottom 折叠状态
Top/Bottom 高度
Splitter 位置
左右工具窗位置
当前 Tab
```

## 4. Settings 记录什么

Settings 记录用户偏好：

```text
语言
主题
字号
UI 密度
MRU 数量上限
日志保留策略
是否启动恢复上次会话
默认打开结构窗
默认打开探查窗
```

业务设置由下游 SettingsPageProvider 提供。

## 5. 存储位置

DeepBase 配置铁律：

- 唯一外部定位文件是 `root.txt`。
- 正式应用的配置、状态、治理规则应进入 DB1 / ConfigDB 或统一 SettingsStore。
- 不要在下游项目散落 JSON / INI / YAML 配置文件。

DeepShell 核心只依赖 `IShellSettingsStore`。推荐实现：

```text
生产：DB1-backed SettingsStore
测试：InMemorySettingsStore
Demo：InMemory 或临时 DB1
```

## 6. 三段折叠状态

```pascal
TShellPanelState = record
  PanelId: string;
  Visible: Boolean;
  Collapsed: Boolean;
  Size: Integer;
  LastExpandedSize: Integer;
  ActiveTabId: string;
end;
```

`PanelId` 建议：

```text
top
middle
bottom
```

规则：

- Top 折叠后保留摘要行。
- Middle 折叠后保留恢复入口。
- Bottom 折叠后状态栏仍可见。

## 7. 最近工作现场

启动时恢复策略：

```text
1. 读取 Settings: 是否恢复上次会话
2. 读取 Recent: 上次项目
3. 校验项目路径是否存在
4. 读取项目级 Layout
5. 恢复三区折叠和当前视图
6. 如果失败，显示工作台
```

## 8. 异常处理

以下情况不能导致启动失败：

```text
MRU 项路径不存在
项目移动
显示器数量变化
Layout 中的 view id 已不存在
主题不存在
语言包缺失
SettingsStore 不可写
```

处理方式：

- 记录 warning。
- 回退默认布局。
- 显示工作台。
- 保留用户可修复入口。

## 9. 多实例与写入冲突

DeepShell 必须允许用户同时打开多个项目窗口，甚至同一程序多进程运行。第一版不要求实时同步多个实例的 UI 状态，但不能因为状态写入冲突破坏 MRU / Layout。

推荐策略：

- 每个进程或主窗体实例生成 `InstanceId`。
- MRU 写入使用 upsert 语义：以 `ItemKey` 去重，更新 `LastOpenedAt`、`DisplayName`、`LayoutKey`，不要整体覆盖整张 MRU 列表。
- Layout 写入带 `UpdatedAt` 和 `WriterInstanceId`。
- 全局 Layout 使用 last-write-wins；项目级 Layout 按 `ProjectId + WindowRole + LayoutKey` 隔离。
- 如果两个实例同时打开同一项目，允许各自保存不同 `WindowRole` 或 `LayoutKey`，不要互相覆盖当前视图。
- DB1-backed SettingsStore 应使用事务。文件型测试 Store 至少要临时文件写入后原子替换。
- 启动读取到另一个实例刚写入的不完整状态时，应回退默认布局并记录 warning。

第一版不强制单实例。如果下游产品要单实例运行，应由下游在 DPR 或应用生命周期层实现互斥。

## 10. 清理和重置

必须提供命令：

```text
shell.recent.clear
shell.layout.reset
shell.settings.restoreDefaults
```

重置布局不应清除 MRU。清除 MRU 不应删除用户设置。
