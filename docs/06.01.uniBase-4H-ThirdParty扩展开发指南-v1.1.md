# UniBase ThirdParty 扩展开发指南

## 1. 定位

`ThirdParty/` 只放可选的外部服务或 SDK 适配器，例如云存储、支付渠道、社交平台、数据库驱动。

这些扩展必须满足：

- 不进入最小 Core。
- 不强制所有下游工程依赖。
- 不包含业务 UI。
- 不直接保存生产支付密钥到客户端源码或配置库。
- 对接真实外部系统时提供清晰的接口、配置、测试和 README。

## 2. 已有扩展

| 目录 | 说明 |
|------|------|
| `ThirdParty/Cloud/` | 云存储适配 |
| `ThirdParty/DB/` | PostgreSQL / MySQL 等数据库适配 |
| `ThirdParty/Payment/` | Alipay / WeChat Pay / Stripe / PayPal 直连 SDK 能力 |
| `ThirdParty/Social/` | 微信、QQ、微博等社交登录/分享适配 |
| `ThirdParty/UI/` | 可选 UI 主题资源 |

## 3. Payment 与 Commerce 的边界

UniBase 当前采用两层结构：

| 层 | 位置 | 职责 |
|----|------|------|
| 商业流程层 | `Features/UniBase.Commerce.*` | 用户身份、商品、订单、支付意图、支付确认、权益发放 |
| 渠道/后端适配层 | `ThirdParty/Payment/*` 或业务后端适配器 | 调微信支付、支付宝、Stripe、PayPal，或转发到自建/云后端 |

规则：

- `Features/UniBase.Commerce.Service` 是统一入口。
- 真实持久化优先使用 `TCommerceHttpStorage` 调统一后端；如不用 HTTP 后端，也可以在 Persistence 适配器或业务工程中实现 `ICommerceStorage`。
- 真实支付优先使用 `TCommerceHttpPaymentGateway` 调统一后端；如不用统一后端，也可以在受控后端包装 `ThirdParty/Payment` 或自行实现 `ICommercePaymentGateway`。
- 多端统一、需要审计和风控的项目，优先让后端持有支付密钥和数据库，客户端只拿支付参数。
- 小型桌面工具如确需直连 SDK，必须完成签名验签、幂等、防重放、HTTPS 回调和密钥保护。

## 4. 新扩展检查清单

- [ ] 这是外部服务适配，不是 Core 基础设施。
- [ ] 对所有下游工程都是可选依赖。
- [ ] 不把 VCL/FMX UI 放进 ThirdParty。
- [ ] 有统一接口或工厂，避免调用方直接绑定单一供应商。
- [ ] 有单元测试或沙箱测试。
- [ ] README 说明依赖、配置、密钥保存方式和生产限制。

```
ThirdParty/

│   ├── README

├── DB/
│   ├── README

```

命名约定：

| 类型 | 命名模式 | 示例 |
|------|----------|------|
| 类型单元 | `UniBase.{Category}.Types.pas` | `UniBase.Payment.Types.pas` |
| 接口/工厂单元 | `UniBase.{Category}.Core.pas` | `UniBase.Payment.Core.pas` |
| 提供商单元 | `UniBase.{Category}.{Provider}.pas` | `UniBase.Cloud.AWS.pas` |
| 使用文档 | `{Category}/README` | Payment README |

## 6. 测试与文档要求

必须更新：

- 当前扩展目录的 README。
- `docs/00.00.uniBase-文档索引-v1.0.md`，如果新增了面向下游的文档入口。
- 扩展目录 README，如果新增的是用户可见能力。
- 对应测试：`Tests/Test.UniBase.{Category}.pas` 或集成测试。

支付相关扩展还必须验证：

- 签名生成与验签失败路径。
- 通知幂等。
- 金额、币种、订单号匹配。
- 密钥缺失时 fail-closed。

---

## 7. 常见问题

### Q: 我想增加一个支付渠道，应该放哪里？

A: 渠道 SDK 放 `ThirdParty/Payment`；订单、用户、权益流程走 `Features/UniBase.Commerce.*`。如果项目有统一后端，优先直接接入 `TCommerceHttpPaymentGateway`。

### Q: 用户表、订单表、权益表要放哪里？

A: 生产表应放在真实后端数据库或业务数据库中。统一后端路线优先使用 `TCommerceHttpStorage`；开发和单测才使用 `TInMemoryCommerceStorage`。

### Q: 可以在客户端保存微信支付密钥吗？

A: 生产环境不建议。桌面工具临时直连可以用于受控场景，但多端、小程序、网页测评包应由后端保存密钥并处理回调。
