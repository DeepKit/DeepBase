## 1. ThirdParty 扩展概述

### 1.1 什么是 ThirdParty 扩展

UniBase 的 `ThirdParty/` 目录存放**可选的第三方服务集成**，这些模块：

- 不是 UniBase 的核心功能
- 用户可以选择不使用，不影响 UniBase 主体
- 对接外部服务（云存储、支付网关、社交媒体等）

### 1.2 已有的扩展

| 目录 | 模块 | 说明 |
|------|------|------|
| `ThirdParty/DB/` | `UniBase.DB.PostgreSQL.pas` | PostgreSQL 驱动适配 |
| `ThirdParty/DB/` | `UniBase.DB.MySQL.pas` | MySQL 驱动适配 |
| `ThirdParty/UI/` | `UniBase.UI.Themes.pas` | UI 主题系统 |
| `ThirdParty/Cloud/` | `UniBase.Cloud.Storage.pas` | 云存储集成 (AWS/Azure/阿里云) |
| `ThirdParty/AipexBase/` | `UniBase.AipexBase.GeneralOrder.pas` | **支付网关** - AipexBase 统一接口（✅ 已实现） |

### 1.3 参考实现

详见：
- 云存储扩展：`ThirdParty/Cloud/UniBase.Cloud.Storage.pas`（完整实现参考）
- 支付对接：`ThirdParty/AipexBase/UniBase.AipexBase.GeneralOrder.pas` + README

## 2. 开发新扩展前的检查

在开始开发新的 ThirdParty 扩展之前，请确认：

### 2.1 边界检查

- [ ] **这是对接外部服务**，而非应该成为 Core 的基础设施
- [ ] **用户可以选择不使用**，不影响 UniBase 核心功能
- [ ] **不与现有 Core 模块重复**（参考 [01.03 项目定位与边界](01.03.uniBase-4H-项目定位与边界-v1.0.md)）

### 2.2 可行性检查

- [ ] **有清晰的接口抽象**，便于支持多个提供商
- [ ] **维护成本可接受**（外部 API 变化不会频繁破坏兼容性）
- [ ] **有实际使用场景**（至少 2-3 个潜在用户/项目）

### 2.3 不适合放入 ThirdParty 的情况

- 应该成为 Core 功能的基础设施 → 考虑提 PR 到 Core
- 与特定业务强耦合 → 放在业务项目中
- 外部 API 极不稳定 → 等待 API 稳定后再集成
- 只有单一提供商 → 考虑是否需要抽象层

### 2.4 支付集成的规则

**UniBase 支付采用“双模式策略”（按项目风险与部署形态选择）：**

1. **模式 A：ThirdParty/Payment 直连 SDK（当前已实现）**
   - 适用：桌面端/私有部署/轻后端项目，要求快速落地。
   - 实现位置：`ThirdParty/Payment/*`（Alipay/WeChat/Stripe/PayPal）。
   - 要求：必须启用签名验签、幂等、防重放、密钥安全存储。

2. **模式 B：AipexBase 后端代理（推荐企业化）**
   - 适用：多端统一、强审计、密钥集中托管、策略统一管控。
   - 调用方式：UniBase 客户端仅调用 `ThirdParty/AipexBase` 暴露的业务接口。
   - 优势：渠道适配集中在后端，升级与风控一致性更高。

**约束边界：**
- Core 层不放支付渠道 SDK 细节；支付实现仅位于 `ThirdParty/`。
- 新增渠道优先补充 `ThirdParty/Payment` 与测试；企业项目可同步在 AipexBase 后端实现代理路径。

**参考**:
- `ThirdParty/Payment/README.md`
- `ThirdParty/AipexBase/README.md`
- `ThirdParty/AipexBase/UniBase.AipexBase.GeneralOrder.pas`

## 3. 标准架构模式

所有 ThirdParty 扩展应遵循**统一接口 + 多实现 + 工厂函数**的模式。

### 3.1 参考实现：云存储

以 `ThirdParty/Cloud/UniBase.Cloud.Storage.pas` 为例：

```
┌─────────────────────────────────────────────────────────────┐
│                    架构模式                                  │
│                                                             │
│   ICloudStorageClient (接口)                                │
│        ↑                                                    │
│   ┌────┴────┬────────────┬────────────┐                    │
│   │         │            │            │                    │
│ TAWSS3   TAzureBlob   TAliOSS    TMinIO                    │
│ Client    Client       Client    Client                    │
│                                                             │
│   CreateCloudStorageClient() ← 工厂函数                     │
│                                                             │
│   TCloudStorageHelper ← 高级封装 (可选)                     │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 核心组件

1. **统一接口** (`IXxxClient`)
   - 定义所有提供商必须实现的方法
   - 使用 GUID 标识接口

2. **基础实现类** (`TXxxClientBase`)
   - 提供通用逻辑和默认实现
   - 子类只需覆盖特定方法

3. **具体提供商类** (`TXxxProvider`)
   - 实现特定提供商的 API 调用
   - 处理认证、签名等细节

4. **工厂函数** (`CreateXxxClient`)
   - 根据配置创建对应的实现
   - 隐藏具体实现类

5. **Helper 类** (可选)
   - 提供高级封装和便捷方法
   - 如批量操作、目录同步等

```
│   └── UniBase.UI.Themes.pas
├── AipexBase/
│   ├── README.md
│   └── UniBase.AipexBase.GeneralOrder.pas
└── ...
```

### 4.2 命名约定

| 类型 | 命名模式 | 示例 |
|------|----------|------|
| 类型单元 | `UniBase.{Category}.Types.pas` | `UniBase.Cloud.Types.pas` |
| 接口/工厂单元 | `UniBase.{Category}.Core.pas` | `UniBase.Cloud.Core.pas` |
| 基础类单元 | `UniBase.{Category}.Base.pas` | `UniBase.Cloud.Base.pas` |
| 提供商单元 | `UniBase.{Category}.{Provider}.pas` | `UniBase.Cloud.AWS.pas` |
| 使用文档 | `{Category}/README.md` | `Cloud/README.md` |

## 5. 测试要求

### 5.1 必须提供的测试

1. **单元测试** (`Tests/Test.UniBase.{Category}.pas`)
   - 测试接口定义的所有方法
   - 使用 Mock 或 Sandbox 环境

2. **集成测试** (可选，使用真实 API)
   - 标记为需要网络/凭证
   - 不在 CI 中自动运行

### 5.2 文件命名

- 单元测试: `Tests/Test.UniBase.{Category}.pas`
- 集成测试: `Tests/Test.{Category}.Integration.pas`

## 7. 常见问题

### Q: 我想添加某个支付渠道的 SDK 实现，应该怎么做？

A: 两条路径都支持：
1. 在 `ThirdParty/Payment` 增加该渠道 SDK 适配（需补单测和签名/验签安全检查）；
2. 或在 AipexBase 后端扩展渠道，并由 UniBase 走统一代理接口。

建议：企业多端场景优先后端代理；单体桌面工具可先直连 SDK。

### Q: 如何集成一个新的云存储提供商？

A: 参考 `ThirdParty/Cloud/UniBase.Cloud.Storage.pas` 的既有实现，添加新的 `TXxxClient` 类和工厂入口。

### Q: 我的扩展依赖非标准的 Delphi 库，该怎么处理？

A: 在 README 中明确列出所有依赖，包括第三方库的版本要求和获取地址。
