# UniBase 项目定位与开发边界

> **让 Delphi 企业级应用开发像 Spring Boot 一样简单**

## 1. 项目定位

UniBase 是一个 **Delphi 企业级应用开发基础框架**，提供现代化架构模式和常用功能封装，帮助开发者快速构建高质量的业务应用。

### 1.1 核心定位

```
┌─────────────────────────────────────────────────────────────┐
│                    UniBase 定位                              │
│                                                             │
│   ✅ 企业级业务应用基础设施                                   │
│   ✅ 现代化架构模式（IoC/事件驱动/MVVM）                      │
│   ✅ 常用功能的简化封装                                       │
│   ✅ 生产环境可靠性保障                                       │
│                                                             │
│   ❌ 不是游戏/图形引擎                                        │
│   ❌ 不是科学计算库                                           │
│   ❌ 不是网络协议栈                                           │
│   ❌ 不是"大而全"的万能框架                                   │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 目标用户

- Delphi 企业级应用开发者
- 需要快速构建后台管理系统、业务系统的团队
- 希望采用现代架构模式但不想从零开始的开发者

### 1.3 参考框架

| 生态 | 参考框架 | UniBase 对标功能 |
|------|----------|-----------------|
| .NET | Microsoft.Extensions.* | 配置、日志、依赖注入、缓存 |
| .NET | FluentValidation | 验证框架 |
| Java | Spring Boot | IoC、事件、调度、弹性模式 |
| Python | Django | ORM、国际化、模板 |

| UI组件库 | 自定义控件、图表组件 | 应使用DevExpress/TMS等专业库 |
| 文件格式 | PDF生成、Excel操作、Word生成 | 应使用专门库 |

## 3. 代码质量要求

### 3.1 强制性要求

所有已实现代码必须满足：

#### 线程安全
```delphi
// ✅ 正确：使用 TCriticalSection 或 TMonitor
FLock.Enter;
try
  // 临界区代码
finally
  FLock.Leave;
end;

// ❌ 错误：无保护的共享状态访问
FSharedData := NewValue;  // 多线程不安全
```

#### 资源管理
```delphi
// ✅ 正确：try-finally 确保释放
LStream := TFileStream.Create(...);
try
  // 使用 stream
finally
  LStream.Free;
end;

// ❌ 错误：可能泄漏
LStream := TFileStream.Create(...);
// 使用 stream
LStream.Free;  // 异常时泄漏
```

#### 错误处理
```delphi
// ✅ 正确：明确的错误处理
function TryDoSomething(out AResult: string): Boolean;
begin
  Result := False;
  try
    AResult := DoSomething;
    Result := True;
  except
    on E: Exception do
      Log.Error('DoSomething failed', E);
  end;
end;

// ❌ 错误：吞掉异常
try
  DoSomething;
except
  // 什么都不做
end;
```

### 3.2 性能基准

| 操作 | 要求 |
|------|------|
| Config 读取（缓存） | < 1ms |
| Config 写入 | < 10ms |
| i18n 翻译（缓存） | < 0.5ms |
| Log 写入（异步） | < 0.1ms |
| IoC 解析（单例） | < 0.1ms |
| 验证执行 | < 5ms（10条规则） |

### 3.3 代码规范

#### 命名约定
```delphi
// 类型：T前缀
TMyClass, TMyRecord, TMyInterface

// 接口：I前缀
IMyService, IRepository

// 字段：F前缀
FValue, FList, FLock

// 局部变量：L前缀
LResult, LTemp, LItem

// 参数：A前缀
AValue, ACallback, AOptions
```

#### 注释要求
```delphi
/// <summary>简要描述</summary>
/// <param name="AValue">参数说明</param>
/// <returns>返回值说明</returns>
/// <exception cref="EMyException">异常说明</exception>
function MyFunction(const AValue: string): Integer;
```

## 4. 新功能评估清单

在添加新功能前，必须回答以下问题：

### 4.1 必要性检查

- [ ] 这个功能是否属于"企业级业务应用"的常见需求？
- [ ] Delphi 标准库或成熟第三方库是否已提供此功能？
- [ ] 添加此功能是否会增加框架的学习成本？
- [ ] 是否有至少 3 个实际使用场景？

### 4.2 边界检查

- [ ] 此功能是否在"核心功能"列表中？
- [ ] 如果不在，是否有充分理由添加？
- [ ] 是否会导致框架定位模糊？

### 4.3 质量检查

- [ ] 是否能保证线程安全？
- [ ] 是否有完整的单元测试？
- [ ] 是否有性能基准测试？
- [ ] 是否有使用文档？

### 4.4 维护检查

- [ ] 长期维护成本是否可接受？
- [ ] 是否会增加版本升级的兼容性负担？

**如果任何一项答案为"否"，应拒绝添加该功能。**

## 5. 版本规划原则

### 5.1 功能冻结

当前已实现的模块进入**功能冻结**状态：
- 只修复 Bug
- 只做性能优化
- 不添加新功能（除非有重大需求）

### 5.2 后续开发优先级

1. **P0 - 稳定性**：修复现有模块的 Bug
2. **P1 - 性能**：优化关键路径性能
3. **P2 - 文档**：完善使用文档和示例
4. **P3 - 测试**：提高单元测试覆盖率
5. **P4 - 新功能**：仅限核心功能列表内的缺失项

## 6. ThirdParty 扩展包边界

UniBase 的 `ThirdParty/` 目录存放**可选的第三方服务集成**，与 Core 模块有不同的边界规则：

### 6.1 已实现的扩展

| 目录 | 模块 | 说明 |
|------|------|------|
| `ThirdParty/DB/` | PostgreSQL/MySQL 驱动 | 数据库适配器 |
| `ThirdParty/UI/` | UI 主题系统 | Material/Fluent/macOS 风格 |
| `ThirdParty/Cloud/` | 云存储集成 | AWS S3/Azure Blob/阿里云 OSS |

### 6.2 ThirdParty 的边界原则

**适合放入 ThirdParty 的**：
- 对接外部服务的适配器（云存储、支付网关、社交媒体 API）
- 可选的数据库驱动（非 SQLite/FireDAC 默认支持的）
- 可选的 UI 风格包

**不适合放入 ThirdParty 的**：
- 应该成为 Core 功能的基础设施
- 与特定业务强耦合的代码
- 需要频繁更新维护的不稳定 API 封装

### 6.3 开发新扩展的检查清单

在开发新的 ThirdParty 扩展前，确认：

- [ ] 这是对接外部服务，而非核心基础设施
- [ ] 用户可以选择不使用此扩展，不影响 UniBase 核心功能
- [ ] 有清晰的接口抽象，便于替换具体实现
- [ ] 维护成本可接受（外部 API 变化不会频繁破坏兼容性）

详见：[06.01.uniBase-4H-ThirdParty扩展开发指南-v1.0.md](06.01.uniBase-4H-ThirdParty扩展开发指南-v1.0.md)

## 7. 与外部平台体系的关系

### 7.1 UniBase 的独立定位

UniBase 是一个**独立的 Delphi 技术框架**，不强制依赖任何特定后端平台。

```
┌─────────────────────────────────────────────────────────────┐
│                    外部平台体系示例                          │
│                                                             │
│   [ 业务工程 ]  ← 各项目（Touchstone、TwoKeyRun...）         │
│        ↓                                                    │
│   [ 中台层 ]    ← 统一接入规范、API 网关                     │
│        ↓                                                    │
│   [ 平台层 ]    ← SaaS 能力：认证、计费、动态数据引擎        │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                    UniBase 定位                              │
│                                                             │
│   ★ Delphi 客户端/桌面应用的编程基础设施                     │
│   ★ 类似 Spring Boot 在 Java 生态中的角色                    │
│   ★ 与后端平台松耦合，通过 HTTP/API 集成                     │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 与后端平台的集成方式

如果你的业务需要对接后端平台（如 AipexBase、Firebase 等），UniBase 提供的能力：

| UniBase 模块 | 对接方式 | 说明 |
|--------------|----------|------|
| `UniBase.Net` | HTTP 客户端 | 调用后端 REST API |
| `UniBase.Serialization` | JSON 序列化 | 请求/响应数据处理 |
| `UniBase.Authorization` | 令牌管理 | 存储和刷新 JWT/OAuth Token |
| `UniBase.Config` | 配置存储 | 保存 API 端点、密钥等配置 |
| `UniBase.Logging` | 日志记录 | 可配置输出符合后端规范的日志格式 |

### 7.3 横切规范对齐建议

如果你的团队有统一的开发规范（如 05docs 规范体系），UniBase 可以对齐以下横切规范：

| 规范类型 | UniBase 对齐方式 |
|----------|------------------|
| **错误与日志规范** | `UniBase.Logging` 输出可包含 `correlation_id`、`source` 字段 |
| **命名与目录约定** | UniBase 已遵循 snake_case 表名、T/F/L/A 前缀等约定 |
| **数据库规范** | UniBase 表结构遵循 `created_at`/`updated_at` 等字段命名 |

**注意**：UniBase 不强制依赖任何外部规范体系，以上对齐是可选的。

## 8. 后续开发者指南

### 8.1 我想添加新的 Core 功能

1. 阅读本文档的「功能边界」和「新功能评估清单」
2. 确认功能属于「核心功能」列表
3. 遵循「代码质量要求」编写代码
4. 编写单元测试，确保覆盖率 > 85%
5. 更新相关文档（API 参考、集成指南）

### 8.2 我想添加新的 ThirdParty 扩展

1. 阅读 [06.01.uniBase-4H-ThirdParty扩展开发指南-v1.0.md](06.01.uniBase-4H-ThirdParty扩展开发指南-v1.0.md)
2. 在 `ThirdParty/` 下创建对应目录（如 `ThirdParty/Payment/`）
3. 定义统一接口（参考 `ICloudStorageClient`）
4. 实现具体提供商适配器
5. 编写测试和使用文档

### 8.3 我想让 UniBase 对接我的后端平台

1. 不要修改 UniBase Core 代码
2. 在你的业务项目中创建适配层
3. 使用 `UniBase.Net` 调用后端 API
4. 使用 `UniBase.Config` 存储 API 配置
5. 可选：在 `ThirdParty/` 下创建可复用的适配器

### 8.4 我想贡献代码给 UniBase

1. Fork 项目
2. 阅读本文档确认功能在边界内
3. 遵循代码规范和质量要求
4. 提交 Pull Request 并附上：
   - 功能说明
   - 单元测试
   - 文档更新

## 9. 总结

UniBase 的成功不在于功能的数量，而在于：

1. **聚焦核心价值** - 让 Delphi 企业开发更高效
2. **保持简洁** - 易学易用，不增加认知负担
3. **确保质量** - 每个模块都经过充分测试
4. **明确边界** - 知道什么不该做
5. **松耦合设计** - 可独立使用，也可与外部平台集成

> "完美不是无可增加，而是无可删减。" — 安托万·德·圣-埃克苏佩里
