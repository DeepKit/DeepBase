# UniBase 项目定位与开发边界

> **让 Delphi 企业级应用开发像 Spring Boot 一样简单**

## 1. 项目定位

UniBase 是一个 **Delphi 企业级应用开发基础框架**，提供现代化架构模式和常用功能封装，帮助开发者快速构建高质量的业务应用。

### 1.1 核心定位

```
┌─────────────────────────────────────────────────────────────┐
│                    UniBase 定位                              │
│                                                             │
│   ✅ 企业级业务应用基础设施                                   │
│   ✅ 现代化架构模式（IoC/事件驱动/MVVM）                      │
│   ✅ 常用功能的简化封装                                       │
│   ✅ 生产环境可靠性保障                                       │
│                                                             │
│   ❌ 不是游戏/图形引擎                                        │
│   ❌ 不是科学计算库                                           │
│   ❌ 不是网络协议栈                                           │
│   ❌ 不是"大而全"的万能框架                                   │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 目标用户

- Delphi 企业级应用开发者
- 需要快速构建后台管理系统、业务系统的团队
- 希望采用现代架构模式但不想从零开始的开发者

### 1.3 参考框架

| 生态 | 参考框架 | UniBase 对标功能 |
|------|----------|-----------------|
| .NET | Microsoft.Extensions.* | 配置、日志、依赖注入、缓存 |
| .NET | FluentValidation | 验证框架 |
| Java | Spring Boot | IoC、事件、调度、弹性模式 |
| Python | Django | ORM、国际化、模板 |

### 2.3 禁止开发

以下功能**不应该**在 UniBase 中实现：

| 类别 | 示例 | 原因 |
|------|------|------|
| 游戏/图形 | 粒子系统、物理引擎、3D渲染 | 偏离企业应用定位 |
| 科学计算 | FFT、信号处理、机器学习 | 专业领域，应使用专门库 |
| 底层网络 | TCP/UDP协议栈、WebSocket完整实现 | Indy等已经成熟 |
| 数据库驱动 | MySQL驱动、PostgreSQL驱动 | FireDAC已经足够 |
| UI组件库 | 自定义控件、图表组件 | 应使用DevExpress/TMS等专业库 |
| 文件格式 | PDF生成、Excel操作、Word生成 | 应使用专门库 |

## 3. 代码质量要求

### 3.1 强制性要求

所有已实现代码必须满足：

#### 线程安全
```delphi
// ✅ 正确：使用 TCriticalSection 或 TMonitor
FLock.Enter;
try
  // 临界区代码
finally
  FLock.Leave;
end;

// ❌ 错误：无保护的共享状态访问
FSharedData := NewValue;  // 多线程不安全
```

#### 资源管理
```delphi
// ✅ 正确：try-finally 确保释放
LStream := TFileStream.Create(...);
try
  // 使用 stream
finally
  LStream.Free;
end;

// ❌ 错误：可能泄漏
LStream := TFileStream.Create(...);
// 使用 stream
LStream.Free;  // 异常时泄漏
```

#### 错误处理
```delphi
// ✅ 正确：明确的错误处理
function TryDoSomething(out AResult: string): Boolean;
begin
  Result := False;
  try
    AResult := DoSomething;
    Result := True;
  except
    on E: Exception do
      Log.Error('DoSomething failed', E);
  end;
end;

// ❌ 错误：吞掉异常
try
  DoSomething;
except
  // 什么都不做
end;
```

### 3.2 性能基准

| 操作 | 要求 |
|------|------|
| Config 读取（缓存） | < 1ms |
| Config 写入 | < 10ms |
| i18n 翻译（缓存） | < 0.5ms |
| Log 写入（异步） | < 0.1ms |
| IoC 解析（单例） | < 0.1ms |
| 验证执行 | < 5ms（10条规则） |

### 3.3 代码规范

#### 命名约定
```delphi
// 类型：T前缀
TMyClass, TMyRecord, TMyInterface

// 接口：I前缀
IMyService, IRepository

// 字段：F前缀
FValue, FList, FLock

// 局部变量：L前缀
LResult, LTemp, LItem

// 参数：A前缀
AValue, ACallback, AOptions
```

#### 注释要求
```delphi
/// <summary>简要描述</summary>
/// <param name="AValue">参数说明</param>
/// <returns>返回值说明</returns>
/// <exception cref="EMyException">异常说明</exception>
function MyFunction(const AValue: string): Integer;
```

## 4. 新功能评估清单

在添加新功能前，必须回答以下问题：

### 4.1 必要性检查

- [ ] 这个功能是否属于"企业级业务应用"的常见需求？
- [ ] Delphi 标准库或成熟第三方库是否已提供此功能？
- [ ] 添加此功能是否会增加框架的学习成本？
- [ ] 是否有至少 3 个实际使用场景？

### 4.2 边界检查

- [ ] 此功能是否在"核心功能"列表中？
- [ ] 如果不在，是否有充分理由添加？
- [ ] 是否会导致框架定位模糊？

### 4.3 质量检查

- [ ] 是否能保证线程安全？
- [ ] 是否有完整的单元测试？
- [ ] 是否有性能基准测试？
- [ ] 是否有使用文档？

### 4.4 维护检查

- [ ] 长期维护成本是否可接受？
- [ ] 是否会增加版本升级的兼容性负担？

**如果任何一项答案为"否"，应拒绝添加该功能。**

## 5. 版本规划原则

### 5.1 功能冻结

当前已实现的模块进入**功能冻结**状态：
- 只修复 Bug
- 只做性能优化
- 不添加新功能（除非有重大需求）

### 5.2 后续开发优先级

1. **P0 - 稳定性**：修复现有模块的 Bug
2. **P1 - 性能**：优化关键路径性能
3. **P2 - 文档**：完善使用文档和示例
4. **P3 - 测试**：提高单元测试覆盖率
5. **P4 - 新功能**：仅限核心功能列表内的缺失项

---

## 6. 总结

UniBase 的成功不在于功能的数量，而在于：

1. **聚焦核心价值** - 让 Delphi 企业开发更高效
2. **保持简洁** - 易学易用，不增加认知负担
3. **确保质量** - 每个模块都经过充分测试
4. **明确边界** - 知道什么不该做

> "完美不是无可增加，而是无可删减。" — 安托万·德·圣-埃克苏佩里
