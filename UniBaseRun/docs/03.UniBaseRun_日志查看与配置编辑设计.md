# 03. UniBaseRun 日志查看与配置编辑设计

> 本文档描述 UniBaseRun 示例项目中“日志查看 + 配置编辑”小工具的功能设计、界面布局及其与 UniBase 的集成方式（FMX）。

## 1. 设计目标

1. 提供一个 **小而全** 的 FMX 跨平台 GUI 应用示例：
   - 日志查看：直观展示 UniBase 写出的日志文件，支持基本过滤和搜索；
   - 配置编辑：通过 UniBase 访问 `config.db` 中的设置，提供简单的可视化编辑能力。
2. 严格遵守 UniBase 架构与开发规范：
   - root.txt 仅作为项目根目录锚点；
   - 所有配置存储在 `config.db`（由 UniBase 管理），不再使用 INI/Registry；
   - View/Ctrl/uDM 分层清晰，避免逻辑和 UI 混杂。
3. 作为后续业务系统的 UI 与结构模板：
   - 主窗体布局可以直接复制到其他项目；
   - 控制器接口风格可复用到更多业务模块。

## 2. 与 UniBase 的关系

- **root.txt**：
  - 仅包含一行文本：项目根目录的绝对路径；
  - 应用启动时读取 root.txt，交给 UniBase 作为基础路径；
  - 本工具 **不提供修改 root.txt 的 UI**，其内容通常由初始化脚本或部署流程维护。

- **config.db**：
  - 由 UniBase 初始化并管理；
  - 本工具通过 UniBase 提供的接口（如 `UniBase.GetConfig/SetConfig` 等）访问配置项；
  - 若有 Settings 表、I18nTexts 表等，本工具只操作 Settings（或等价配置表），不直接访问系统表与日志表结构。

- **日志**：
  - UniBase 负责日志写入与归档（文本或数据库）；
  - 本工具优先展示文本日志目录 `logs/` 中的内容；
  - 可选：后续扩展为从 config.db 中的日志表读取数据。

## 3. 主窗体布局设计（FMX）

主窗体 `ViewMain` 使用“五面板 + 状态栏”布局：上、下、左、右、中五个区域。

### 3.1 顶部区域（Top）

- **主菜单**（`TMainMenu` 或 FMX等价组件）：
  - 文件（File）
    - 重新加载配置
    - 打开日志目录
    - 退出
  - 查看（View）
    - 显示/隐藏右侧信息面板
    - 显示/隐藏日志过滤区
  - 工具（Tools）
    - 运行自检（检查 root.txt / config.db / logs 目录是否正常）
  - 帮助（Help）
    - 关于（显示版本信息、UniBase 版本、root 路径等）

### 3.2 左侧区域（Left）

- 使用 `TTreeView` 构建一个双根节点树：

  - 根节点 1：配置（Config）
    - 子节点按配置前缀或分组划分，例如：
      - `App.*`（应用相关设置）
      - `UI.*`（界面相关设置）
      - `Log.*`（日志相关设置）
  - 根节点 2：日志（Logs）
    - 子节点为日志文件；
    - 按日期或名称分组，例如：
      - `2025-11-28` → 该日期下的日志文件；
      - `app.log`, `error.log` 等。

- 行为：
  - 点击“配置”树节点 → 中央面板切换到“配置编辑”视图，并选中对应配置项；
  - 点击“日志”树节点 → 中央面板切换到“日志查看”视图，加载对应日志文件内容。

### 3.3 中央区域（Center，多面板）

中央区域使用 `TTabControl` 或多个 `TLayout` 以实现多面板：

1. **配置编辑面板（Config Editor）**
   - 结构示例：
     - 上方：配置项列表（根据左侧树的选择过滤显示）；
     - 下方：选中项的编辑区，包括：
       - Key 显示（只读或可编辑）；
       - Value 编辑控件（文本框、下拉框、复选框等）；
       - 描述/说明标签（从文档或注释中加载）；
       - 保存/还原 按钮。
   - 与 UniBase 交互：
     - 读取：通过 UniBase 封装的 `GetConfig` / 扫描 Settings 表；
     - 写入：通过 `SetConfig` 或专用更新接口，确保变更持久化到 config.db。

2. **日志查看面板（Log Viewer）**
   - 结构示例：
     - 上方：当前日志文件信息（路径、大小、最后修改时间、当前过滤条件）；
     - 中央：日志内容显示区域（支持等宽字体、自动滚动）；
     - 下方：搜索与过滤栏：
       - 文本关键字输入框；
       - 级别选择（Info/Warn/Error 等，取决于日志格式）；
       - 时间范围控件（起止时间）；
       - “应用过滤”、“清除过滤”按钮。
   - 日志读取策略：
     - 默认按行从文本文件读取（可根据文件大小分批加载）；
     - 过滤在内存中执行（基础版）或按需读取；
     - 对特别大的文件可限制显示范围或提示用户。

### 3.4 右侧区域（Right，上下拆分）

右侧可以拆分为上、下两个面板（用 `TSplitter` 或 FMX 等价组件）：

1. **右上信息面板**
   - 用于显示当前选中对象的摘要：
     - 当前配置项：Key、默认值、当前值、说明；
     - 当前日志文件：文件名、大小、行数、当前过滤结果统计（显示行数、错误数等）。

2. **右下操作/状态面板**
   - 集中显示操作结果与提示信息：
     - 最近一次保存配置的时间和结果（成功/失败 + 错误信息）；
     - 最近一次日志过滤操作的耗时与匹配数量；
     - 自检结果摘要（如“root.txt 正常 / config.db 正常 / logs 目录可写”）。

### 3.5 底部状态栏（Status Bar）

状态栏建议显示：

- 当前 root 路径（简写或可点击打开目录）；
- 当前 UniBase 版本或应用版本号；
- 当前登录用户或环境（如 Dev/Test/Prod 标签）；
- 简短状态消息（如“已保存配置”、“日志加载完成（1234 行）”）。

## 4. 控制层职责划分

控制逻辑由一个或多个 `Ctrl*` 单元负责，例如主控制器 `CtrlMain`，其主要职责：

1. **初始化逻辑**
   - 在应用启动时，由 dpr 调用 UniBase 初始化；
   - 控制器假设 UniBase 已可用，仅负责：
     - 读取 config.db 中配置项列表（用于构建“配置”树和编辑界面）；
     - 构造日志文件列表（扫描 `logs/` 目录）。

2. **配置相关接口**（示例）

- `function GetConfigGroups: TArray<string>;`
- `function GetConfigsInGroup(const AGroup: string): TArray<TConfigItem>;`
- `function GetConfigValue(const AKey: string): string;`
- `procedure SetConfigValue(const AKey, AValue: string);`
- `function ValidateConfig(const AKey, AValue: string): Boolean;`

内部通过 UniBase 提供的 API 访问 config.db，不直接操作 SQLite 连接。

3. **日志相关接口**（示例）

- `function GetLogFileList: TArray<TLogFileInfo>;`
- `function LoadLogPreview(const AFile: string; AMaxLines: Integer): TArray<string>;`
- `function FilterLogLines(const ALines: TArray<string>; const AFilter: TLogFilter): TArray<string>;`

大量 I/O 操作可放到后台线程执行，再用 `TThread.Queue` 回到主线程更新 UI。

4. **自检接口**

- 检查 root.txt 是否存在且路径有效；
- 检查 `config.db` 是否存在并可读写；
- 检查 `logs/` 目录是否可写；
- 将结果汇总成结构体/文本，传给 View 层显示。

## 5. 交互流程示例

### 5.1 启动与初始化

1. 应用启动 → dpr 中：
   - 创建 FMX 应用；
   - 读取 root.txt；
   - 调用 `UniBase.InitializeEx`；
   - 创建主窗体 `TViewMain`。
2. `TViewMain.FormCreate`：
   - 创建主控制器实例（或从 DI 容器中解析）；
   - 调用控制器加载配置分组、日志列表；
   - 初始化左侧树与中央面板的初始显示。

### 5.2 配置编辑

1. 用户在左侧树选择某个配置项或配置分组；
2. View 调用控制器接口获取该配置项的详细信息；
3. 控制器通过 UniBase 读取 config.db 中对应值并返回；
4. View 在中央面板展示编辑控件和当前值；
5. 用户编辑值并点击“保存”：
   - View 调用控制器的 `SetConfigValue`；
   - 控制器进行简单校验（如类型/范围）；
   - 合法则调用 UniBase 接口持久化到 config.db；
   - 更新右侧信息面板与状态栏提示结果。

### 5.3 日志查看

1. 用户在左侧树选择某个日志文件节点；
2. View 调用控制器的 `GetLogFileList` / `LoadLogPreview` 等接口；
3. 控制器读取 `logs/` 下对应文件，返回部分或全部行内容；
4. View 在中央日志面板显示日志文本；
5. 用户在过滤区输入关键字/选择级别并点击“应用过滤”：
   - View 组装过滤条件，调用控制器的 `FilterLogLines`；
   - 控制器在后台线程执行过滤，将结果回传给 View；
   - View 更新显示，并在右下/状态栏显示匹配数量和耗时。

## 6. 与后续业务项目的关系

在后续业务项目中，可以按以下方式复用本设计：

1. 直接复制 `ViewMain` 的布局结构（尤其是五面板、菜单和状态栏），再替换中间 Frame 的具体内容；
2. 将“配置编辑面板”作为设置窗口或系统管理模块的一部分重用；
3. 保留日志查看功能，以便在所有 UniBase 项目中快速诊断问题；
4. 按相同模式新增其它工具面板（例如任务队列监控、消息队列监控等），保持界面风格统一。

## 7. 扩展与非目标

- 当前版本 **不会**：
  - 暴露 root.txt 的编辑 UI（避免误操作导致路径错乱）；
  - 直接操作 config.db 的结构（如建表/改表），这些由 UniBase 工具或迁移脚本负责；
  - 集成 madExcept（默认不集成，仅在需要时参考单独文档进行扩展）。

- 后续可以考虑：
  - 从 config.db 中读取 i18n 文本，在界面上演示语言切换；
  - 在日志查看中支持按线程 ID、模块名等高级过滤；
  - 将控制器层抽象为独立单元库，便于被其他 UniBase 项目直接引用。
