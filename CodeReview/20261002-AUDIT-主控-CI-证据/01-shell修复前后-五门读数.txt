自我更正记录：本件第一版（提交 3f466b1）的两处缺陷，均在本次复跑中发现
==============================================================================
缺陷 1（退出码读数失真）：第一版用 `node ... | tail -2; echo $?` 取退出码，
  $? 是 tail 的退出码而非 node 的。四门的 0 因此不可信，已改为子进程
  returncode 直取（见上表，五门逐一重跑）。
缺陷 2（证据件自造丙-C，本次复跑被抓）：第一版为「展示根因」在双向对照段
  逐字抄录了 5.1 误读产生的乱码路径字形。该串是合法 UTF-8、无 NUL、无
  U+FFFD，E1/E2 零感知，但整行可逆回 GB18030 且还原出中文 ⇒ 正是
  evidence-encoding-gate 的 E3（双重编码乱码）判据。第一版读数 EXIT=0 是
  因为该门的默认口径只扫 git 已跟踪文件，而本件当时还未入库；本件入库后
  门禁即判失败并点名本文件。
  修法：乱码路径改按码位转义记载（\uXXXX），字形不复刻 ⇒ 该行不再含表意
  文字，E3 判据第一条件即不成立。修后 evidence-encoding EXIT=0。

连带发现（同型缺陷，非本件引入）：本件第一版与甲 MOE-EV 回执 §六 的四门
  读数都取自「交付件尚未入库」的时刻，因此都没有扫到各自的交付件本身。
  正确口径：跑门前先 git add，或用该门的 --all-worktree 走工作树枚举。
