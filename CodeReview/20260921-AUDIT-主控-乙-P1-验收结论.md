### 4.1 门禁结构性盲区：合法 UTF-8 的**双重编码乱码**

主控在核验 `06-bypass-grep.txt` 时发现其中一行嵌入了乱码 `'鏃ュ織瀵煎嚭 - '`，遂溯源至源文件：

```
Tools/LogAnalyzer/LogAnalyzer.MainForm.pas:997
  实际字节 = ... '鏃ュ織瀵煎嚭 - ' + ExtractFileName(FCurrentDB));
  该文件 valid_utf8 = True, U+FFFD = 0, NUL = 0
```

`鏃ュ織瀵煎嚭` 是「日志导出」经 **GBK 误读 → 再编码为 UTF-8** 的典型双重编码乱码。**编码门禁抓不到**（它是合法 UTF-8、无 U+FFFD、无 NUL）——与乙 R7 的 S-1「内容级乱码（合法 UTF-8 双重编码，门禁抓不到）」**同类同机制**。

**规模（严格判据：含中文行中 ≥50% 可 `gbk→utf8` 可逆，且中文行 ≥3）**：全库命中 14 件，其中非 `CodeReview/` 13 件；剔除 `Tests/Test.DeepBase.Encoding.Fix.PBT.pas`（经查为**故意嵌入** `锟斤拷` 标记的编码检测用例，×3 工作树副本）后为 **10 件真实文件**，含用户可见 UI 字符串：

Tools/Studio/Studio.Resources.pas              17/30   <- 资源字符串
