## 三、验收中亲读坐实的新缺陷：TimeGuard 服务器读数链跨框架裸值混用（派生甲 A13）

主控在复核 A11 接线时亲读 `Features/DeepBase.TimeGuard.pas` 全链，并用自建框架探针（真 `TTimeGuard` + fake transport，原件 `A11-MC-框架探针-服务器读数链坐实.txt` + `附件/A11FrameProbe.dpr.template`）在本机（UTC+8）实测坐实：

```
offset hours (local - utc) : 8.00
utc-framed server (prod)     server=46295.174963 local_now=46295.508296 drift_min=  480.0 -> MajorSkew
local-framed server          server=46295.508296 local_now=46295.508297 drift_min=    0.0 -> OK
watermark write/read (False/False) : 2026-09-30T04:11:56  == utc bare? TRUE  == local now? FALSE
offline rewind fires with utc watermark? False  (local now=12:11:56 vs watermark=04:11:56)
```

- **代码事实**：自研 `ParseRfc822Date`（`:266`）把 HTTP `Date` 头（RFC 822 = GMT = UTC 框架）的数值**原样 `EncodeDateTime`、不换算** ⇒ `Verify` 拿 UTC 框架的 `LServerTime` 与本地裸值 `LLocalNow := Now`（`:413`）直接相减（`:447`）；水位以 `DateToISO8601(ATime, False)` 写 / `TryISO8601ToDate(..., False)` 读，**False/False 往返数值守恒**（探针坐实）⇒ 水位存 UTC 框架、与本地裸值比较。
- **缺陷后果**：UTC+8 上同一真实瞬时的两个读数相减恒得 −offset ⇒ drift 恒 480 分钟 ⇒ `tgOk` 不可达、`Verify` 恒 `tgSkewMajor`；而 `IsTimeTrusted` 三可信态（tgOk/tgSkewMinor/tgOffline）不含 `tgSkewMajor` ⇒ 非 UTC 机器上 `Licensing.IsTimeTrusted` **恒 False**（消费链只读未碰）：试用发放 `Exit(0)`、`GetCorrectedNow` 抛 `EDeepBaseLicensingTimeUntrusted`、`SeedWatermark` 永不播种——**fail-closed 方向的过紧假阳性，用户主力时区全量命中**；回拨检测另被 8 小时偏移钝化（A11 刚接通的 fail-closed 落点被偏移量吃掉）。
- **定性**：与乙 B10 Commerce 旧缺陷**同族同因**（裸值跨框架混用）；**修前既存、非 A11 引入**（A11 工单范围收敛在接线，甲正确地未越界）⇒ 不阻断 A11 验收。
- **处置**：已派生 `docs/ui/work-orders/WO-20260929-AUDIT-甲-A13-TimeGuard服务器读数链框架收口.md`（P1 · 1 项，甲线后位排队；定性两案修法 + 存量水位键必答 + 5 判据），随本结论同批提交。
