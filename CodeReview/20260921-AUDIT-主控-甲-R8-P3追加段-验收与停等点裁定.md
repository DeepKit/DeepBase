## 二、★ 主控新发现：双门禁 **fail-open**（扫描失败即静默放行）—— 真缺陷，高杠杆

**现场（主控亲历，非推理）**：我第一次跑隔离复证时把 `--root` 写成了 POSIX 路径（`/d/_Progs/...`）。结果：

```
编码门禁通过：0 个 .pas（…）        enc EXIT=0
行尾门禁通过：检查了 0 个文件（…）   eol EXIT=0
```

**扫描 0 个文件，却报「通过」并 EXIT=0。** 换成 Windows 路径（`D:/_Progs/...`）后立刻得到 972/1422。

**根因（源码级）**：

```
encoding-gate/check_pas_encoding.js:26   try { ents = fs.readdirSync(dir, …); } catch (e) { return out; }
eol-gate/check_eol.js:23                 try { ents = fs.readdirSync(dir, …); } catch (e) { return out; }
```

`walk()` **吞掉 readdir 异常并返回已收集的部分**；调用方不校验「扫描计数」，直接按 `violations.length` 判绿。⇒ 两条 fail-open 路径：

1. **`--root` 传错/不存在** ⇒ 0 文件 ⇒ **真空绿**；
2. **某个子树 readdir 失败（如 Windows 权限/句柄占用）** ⇒ 该子树**静默漏扫**，其内违规**不可见**，仍判绿（比第 1 条更危险：绿得"看起来有计数"）。

**影响等级**：**高**。门禁是本审计线**一切验收证据的底座**；一个可静默缩面的门禁，会使「EXIT=0」不再等于「全量扫描通过」。本次两处红项若非人工复核，也会被这类误用掩盖。

**处置（已下发）**：登记为 **乙 P1 单 · P0（最高优先）**——修法：
1. `walk` 遇 readdir 失败**不得静默**：记录失败路径集合，**至少一条即 EXIT≠0**（fail-closed）；
2. **扫描计数为 0 时必须 EXIT≠0**（空扫描不是通过）；
3. 输出行强制打印**被跳过/失败的子路径数**；
4. 负向样本（`test_negative_sample.js`）须新增两例：① `--root` 指向不存在目录 ⇒ **必须红**；② 空目录 ⇒ **必须红**。

**主控自律（同步执行）**：读任何门禁结论，**必须核「扫描计数 > 0」且计数与本仓规模同量级**；只看 EXIT 不算取证。
