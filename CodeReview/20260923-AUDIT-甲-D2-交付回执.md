### 3.1 但有一项**未覆盖**，我没绕开

**`GetPluginInfo` 的返回值跨包/宿主边界释放不安全。** 探针实测（`D2-probe-getplugininfo-av.log`，四种模式同一份夹具、同一台机器）：

```
mode=loadcall  → PROBE_LOADCALL_EXIT=0     （加载/调用 POD 导出/卸载）
mode=intfonly  → PROBE_INTFONLY_EXIT=0     （接口调用 + 释放 + 卸载）
mode=lifecycle → PROBE_LIFECYCLE_EXIT=0    （Initialize/Finalize 计数 1/1 + 卸载）
mode=full      → step getinfo ok → step released plugin → step unloaded
                 → Exception EAccessViolation in module d2_probe.exe (offset 1039B)
                   Read of address 000001E2023C0D38    → PROBE_FULL_EXIT=1
```

关键点：**AV 发生在 `UnloadPackage` 之后**，不是在卸载路径里、也不是在接口调用里。归因：`TPluginInfo` 含 5 个 `UnicodeString` 与 1 个 `TArray<TGUID>`，其内存由包侧 RTL 分配；宿主侧在最终 finalize 这个记录时按**宿主**的 RTL 释放 → 跨 RTL 边界释放堆。这是包/宿主的内存所有权设计问题，**不是 A18「卸载后是否仍被占用」这一问题**，也因此超出 D2 的 scope（工单 §五 禁止重构 `Core/DeepBase.PluginManager.pas`）。

处理：单测里**故意不调** `GetPluginInfo`，理由写在测试单元头注释，并单独立此条为限制。**建议主控把它作为独立 PI 开单**（跨边界返回类型 → 应为「包侧分配、包侧释放」的所有权约定，或改为 POD/出参契约），而不是把它塞进 A18 的结论里。
