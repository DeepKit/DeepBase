## 6) eol-gate 计数 1434 → 1435 的归因（不猜测，逐项测量）

`check_eol.js` 的统计口径 = **walk 工作树**上扩展名为 `.pas`/`.md` 的所有实体文件，跳过 `SKIP` 目录集（`.git .claude __history BuildOutput DCUOutput bin dcu node_modules .tmp .superpowers .workbuddy TestResults`）；与是否被 git 跟踪无关。因此该数字反映的是**共享工作树现场**，不是 HEAD。

同刻测量（`git -c core.quotepath=off`，否则中文路径被转义成 `"..."` 导致按后缀过滤漏计）：

| 量 | 命令 | 结果 |
| :--- | :--- | :--- |
| HEAD 树中 `.pas`/`.md` 总数 | `git ls-tree -r --name-only HEAD \| grep -Ei '\.(pas\|md)$' \| wc -l` | 1425 |
| 其中落在 `SKIP` 目录内（不被门禁计入） | 同上 + `grep -E '(^\|/)(\.git\|\.claude\|__history\|…\|TestResults)/'` | 5 |
| 未跟踪且未忽略、且在 `SKIP` 之外 | `git ls-files --others \| grep -Ei '\.(pas\|md)$' \| grep -vE '(^\|/)(…SKIP…)/'` | 20 |
| 其中 `git ls-files --others --exclude-standard` 口径 | 上一条加 `--exclude-standard` | 19（差额 1 件来自非标准 exclude 命中） |
| 工作树中被删除（未提交） | `git diff-files --name-status \| grep -E '^D.*\.(pas\|md)$'` | 3（全为 `docs/规范历史版本与对比库/` 下他人删除） |
| 独立复算：按门禁同款 walk 数文件 | `find . -type d \( -name .git -o … \) -prune -o -type f \( -iname '*.pas' -o -iname '*.md' \) -print \| wc -l` | **1435**（与门禁输出一致） |

要点：
1. `1425 − 5 = 1420` 是 HEAD 侧可扫描面；`+20` 未跟踪、`−3` 已删除后的残余差额来自「未跟踪但被 ignore 规则覆盖、门禁仍会读取」的文件，**该细分对本段结论无影响**，故不强行凑等式（避免给出不可复算的数字）。
2. 与上一段（证据 `20`/`21`，1434）相比 **+1**：发生在**他人工作树**（未跟踪文档集合、`docs/规范历史版本与对比库/` 删除态在 17:37 与 17:55 之间变动），甲本段对 `.pas`/`.md` 的增减为 **0 件**——本段新增的两件证据均为 `.txt`，不在门禁扩展名内；修改的两件文档是已存在文件，不改变计数。
3. 结论：门禁数字属**工作树口径**，跨段比较只能作趋势参考，不能当作「HEAD 行尾一致性」的分子。真正的 HEAD 级行尾核验一律用 `git ls-files --eol`（H14 前置）+ 隔离 `git worktree add --detach` @ 纯 commit 复跑。
