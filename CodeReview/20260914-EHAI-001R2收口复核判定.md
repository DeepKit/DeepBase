## 五、发现的问题（3 项，均非阻断）

### 问题 1｜报告正文数字与事实不符：15 vs 23

- **现象**：报告称「严格将工单涉及的 **15 个**改动与产物文件拆分为 4 个原子提交」。
- **实测**：`git diff --name-only c0ed2ef 66ba6f6 | wc -l` = **23**（5+4+3+11）。报告**自身台账表格**列出的也是 5/4/3/11 = 23，正文与表格自相矛盾。
- **定性**：数字不实（同 AsWish B-1 那一类"措辞替代精确计数"）。因实际提交数**多于**声称数，未构成夸大，不触及 §7.1 恒等式，但对第三方核对是噪声。
- **改法**：正文改为 23，或直接写「4 个原子提交、23 个文件（见下表）」。

### 问题 2｜§6.4 要求的证据缺两列

- **现象**：工单 §6.4 明确要求提供 `Commit SHA / Parent SHA / Changed files / **Insertions / deletions** / **git status**`。
- **实测**：报告提供前 3 项，**未提供**插入/删除行数（仅给文件名），**未附**原始 `git status` 输出（仅散文陈述「已 100% 入库、无关脏改动未混入」）。
- **定性**：证据缺项。缺的正是 §6.4 逐字列明的那两项，属"规定的证据形态未照做"。
- **补法**：见本报告 §3.2 表（已由我实测补齐行数）+ 一段原始 `git status --porcelain` 输出。

### 问题 3｜G1 覆盖范围声明句未落进构建证据本体

- **现象**：工单 §5 要求「本工单只需在 **G1 / build evidence** 中增加以下说明句（原样写入）」，报告称「在**构建台账**及收口文档中原样写入声明句」。
