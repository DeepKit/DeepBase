## 四、关于随单申报的「12:22 eol 基线被清空」—— 主控核实结论

### 4.1 归属：**不追责**（产物无法反推执行方）

- 12:22 正值甲乙双方同时在共享树作业，**指认任何一方都缺乏证据**。主控**不接受无证据的归属**，也不把它记到任何人头上。

### 4.2 但**机制已实证**（主控安全复现，未触碰真实基线）

用 `--baseline` 指到临时路径做演示（真实基线 `git status` 保持干净）：

```
--root ./docs --emit-baseline  ⇒ 写成 { pas_lf 0, mixed 0, md_crlf 116 }   ← 902 项 → 116 项
--root .      --emit-baseline  ⇒ 写成 { pas_lf 658, mixed 25, md_crlf 203 } ← 比在库基线还少 9 项
```

⇒ **`--emit-baseline` 是「从空基线起算、只写本次扫到的违规」的破坏性操作**：

1. **窄根 = 大规模丢数据**（`./docs` 那次把 902 项写成 116 项）;
2. **扫描集合与实仓不一致时 = 直接写空**（225 B 的空基线正是这种形态）;
3. **即使全根也会静默减少**（−9 项）;
4. **无确认、无备份、无「不允许变小」的守卫**。

⇒ 12:22 那次的**机制**已查明，是「emit 在扫描集合为空/偏移时把基线写成 0 项」，而不是有人恶意清空。
