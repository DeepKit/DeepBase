### S1. csOpaque + WMEraseBkgnd=1 + 圆角路径填充 ⇒ 圆角四角显示脏像素（全系控件）

- 位置：`D:\_Progs\02Business\DeepBase\VCL\DeepBase.VCL.HB.Controls.pas:347-348` 与 `:366-369`
```pascal

  ControlStyle := ControlStyle + [csOpaque, csCaptureMouse];
...

begin
  Message.Result := 1; // Prevent background erase flicker
end;
```
- 同模式复制于 `DeepBase.VCL.HB.Cards.pas:204-205` / `:224-227`（THbCard）。

### M9. THbTrayMenuForm：固定 280px 菜单宽 + 用 Screen.PixelsPerInch 缩放（混合 DPI 多显示器错误）

- 位置：`DeepBase.VCL.HB.Tray.pas:294` 与 `:167-170`

- 问题 1：`CalcW := 280` 不缩放，而 Paint 内字体经 `ScaleDIP(Tokens.SizeS)`（`:375`）放大；200% DPI 下字体翻倍而菜单宽度不变，`CapRect`（`:466`，宽 `Width-120`）内文字大量截断。

## 四、可疑区（需要人工确认或运行时验证）

1. **四角脏像素的实际观感（S1）**：取决于 DoubleBuffered 内存位图的初始内容（Windows 版本/驱动差异），可能呈现黑角、白角或复用旧帧。建议在高 DPI + 浅色主题下截图验证一轮。
2. **THbTheme.ApplyTheme 的调用线程纪律（M22）**：全代码库搜索未发现后台线程调用点，但 Core 明确支持跨框架使用；一旦 FMX/服务侧在非 UI 线程切主题即触发。需要架构层面确认"仅主线程切主题"是否成文。
3. **THbVoiceFieldCard.SetItem 的值语义**：`FItem := Value` 后就地改 `FItem.CurrentValue`（Voice.pas:313-319），依赖 `THbVoiceDialog.Execute` 的 `AItems[I] := CardList[I].Item`（:685）回写才生效。任何宿主绕过 Execute 直接用卡片控件时，外部记录不会被卡片内修改同步——record 值拷贝的双刃剑，需确认所有使用路径。
4. **THbTrayMenuForm 弹出期间 Item.OnClick 重入**：`Hide` 后同步调 `Item.OnClick(Item)`（Tray.pas:273-275），若回调里又弹菜单/对话框，会在 KillFocus→Hide 的消息重入路径上叠加。未观察到必然故障，列为重入观察点。
5. **WM_TIMER 精度对 THbStreamBlock 计时的影响**：60ms interval + 0.06 常数在系统定时器 15.6ms 量化下时长显示会漂移（约 ±10%）。思考耗时展示用途可接受，计量用途不行。
6. **THbDialog.CreateNew(nil) 的 Scaled 行为**：Delphi 13 中 CreateNew 生成窗体 `Scaled=True` 且 `PixelsPerInch=96`，运行时手工添加的控件不会二次缩放（M10 的根因确认）。若未来迁到 .dfm 需同步改。

## 五、维度专项结论

1. **正确性**：3 个 🔴（S1 视觉损坏、S2 Hint 污染、S3 瀑布空壳）+ 拖出释放误触发（M1）+ 右键误触发（M2）+ SetState 绕过 setter（M3）等。核心绘制基元（CreateRoundRectPath 的弧拼接/退化保护、GetDisplayValue 掩码、PopupAt 多屏钳制、EnsureRange）实现正确。
2. **内存/句柄安全**：**未发现任何 GDI/GDI+ 对象泄漏**——全部 TGPGraphics/Brush/Pen/Font/FontFamily/StringFormat/Path 均严格 try/finally 配对（含嵌套场景，如 Controls.pas:698-721 四层）；TTimer 均以 Self 为 owner 或显式 Free；THbToastHost/THbVoiceDialog 的析构顺序正确无双重释放。瑕疵仅 B3（try 外一行）与 B4（死分配）。**未发现无 Parent 时的 HandleNeeded/RecreateWnd 非法触发**：SetFocus 调用前均有 CanFocus 保护（Controls.pas:411），FEditBox 惰性句柄安全。此维度整体健康。
3. **DPI 缩放**：Controls.pas 前半（Button/Chip/Badge/Avatar/Toast 等）纪律良好——字体/圆角/内边距全部 ScaleDIP/ScalePixels；但 Cards 后半、Terminal、Dialogs、Voice、Tray、Waterfall 六个单元大面积回退为裸像素（M8/M10/M11/M16/M21），对话框类控件（THbDialog/THbVoiceDialog/THbTrayMenuForm）是重灾区。Tray 的 Screen.PixelsPerInch 语义在多显示器下错误（M9）。
4. **设计令牌一致性**：取色纪律整体优秀，几乎全部颜色来自 THbTheme.Tokens。唯一硬编码魔法色：bkDanger 的 `$FFFFFFFF`（M19）。布局尺寸不走 Tokens.Space* 的情况普遍（各控件自造 8/12/16/24/90/140 等常量），属"令牌有而未用"，建议逐步收敛到 Space 组。
5. **线程安全/异常处理/性能**：异常处理——所有绘制代码 try/finally 完备，Core 广播有 per-listener 异常隔离（Core.pas:830-834）；线程安全——M22 的回调线程边界是唯一实质风险；性能——THbStreamBlock 的 O(n²) 流式重排与固定 160 高度（M13）是最需要跟进的，Skeleton/StreamBlock Timer 空转（M6/M14）次之。

## 七、总体结论

该 HB 视觉系统的**基础绘制层质量高于其上层**：Controls.pas 的原子控件在 GDI+ 对象生命周期管理（零泄漏）、令牌取色纪律、基元边界处理（圆角退化、EnsureRange、多屏钳制）上表现良好；但存在一个必现的全系视觉缺陷（csOpaque+不擦背景+圆角=黑角，S1），且越往后写的单元（Dialogs/Voice/Tray/Waterfall）质量滑坡越明显：DPI 纪律从 ScalePixels 退化到裸像素、published 接口大量"承诺未兑现"（S3 瀑布空壳、M5/M7/M17 死属性群）、交互边界（拖出释放、非左键、命中区错位）系统性欠账，外加 Tray Hint 的累积污染（S2）。建议修复优先级：S1（一行级修复、全局收益）→ S2/S3 → M1–M4（交互正确性）→ M8/M10（DPI 批量整改）→ 其余。
