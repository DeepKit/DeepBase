## 1. DeepBase.VCL.HB.Grid.pas（THbDataGrid）

### G-01 🔴 滚动完全未实现，FScrollTopRow 为死代码
- 位置：`DeepBase.VCL.HB.Grid.pas:60`（声明）、`:123`（唯一赋值 = 0）、`:374`（消费）
- 代码：
  ```pascal
  FScrollTopRow: Integer;                      // :60
  ...
  FScrollTopRow := 0;                          // :123 构造后再无任何写入
  ...
  for R := FScrollTopRow to FScrollTopRow + VisibleRows do  // :374 Paint 消费
  ```
- 问题：全文件无 `WM_VSCROLL`、无 `OnMouseWheel`/`MouseWheel`、无滚动条创建（基类 TCustomControl 亦非 TScrollingWinControl）。`MouseDown:268` 的 `ClickedRow := FScrollTopRow + (Y - FHeaderHeight) div FRowHeight` 同样依赖恒为 0 的 FScrollTopRow。
- 触发条件：RowCount 超过一屏（约 `Height div RowHeight` 行）即必然触发——第 21 行以后的数据永远不可见、不可选。
- 后果：虚拟化网格的核心承诺（注释 :6 "constant memory & 60fps scrolling"）对 10 万~100 万行完全不成立：渲染是虚拟的，但用户只能访问首屏约 20 行。
- 建议修复：为控件实现 WM_VSCROLL/CM_MOUSEWHEEL 消息处理 + SetScrollInfo/SB_THUMBPOSITION 同步 FScrollTopRow，并 clamp（`0..RowCount-1`）；或改为宿主提供 `ScrollToRow(AIndex)` 公开 API 并由外部驱动。

### G-02 🔴→性能 结论修正：数据侧虚拟化成立，但见 G-06/G-07 性能项
（数据取值确实经 `OnGetCellText`/`OnGetCellFloat` 回调按需拉取，`FColumns`/`FSelectedRows` 之外无行级存储，内存侧 O(可视) 设计成立；问题集中在绘制热路径与滚动缺失。）

### G-03 🟡 ComputeSelectionStats 忽略合法的 0 值
- 位置：`DeepBase.VCL.HB.Grid.pas:229`
- 代码：
  ```pascal
  FOnGetCellFloat(Self, R, C, ValFloat);
  if ValFloat <> 0.0 then        // :229  0 被当作“非数值”
  ```
- 问题：货币/百分比/盈亏数据中 0 是合法数值（如“变动 0.00”、“0%”）。此处把 0 当哨兵值，导致 NumericCount、Sum、Min/Max、Avg 全部错误；且当 OnGetCellFloat 未返回数据（保持 0）与真实 0 值无法区分。
- 触发条件：任何选区统计中出现 0 值单元格。
- 建议修复：回调改带 `var AHasValue: Boolean`（或 `AValue: Double; AIsNull`），不得以 0 为哨兵。

### G-04 🟡 Paint 热路径在行/列循环内反复 new/free GDI+ 对象
- 位置：`DeepBase.VCL.HB.Grid.pas:359`（每列）、`:405-406`（每个 HeatBar 单元格）、`:425`（每行）
- 代码：
  ```pascal
  PenDiv := TGPPen.Create(ColorToARGB(Tokens.Border), 1.0);      // :359 列循环内
  BrushTrack := TGPSolidBrush.Create(...);                       // :405 单元格级
  BrushFill := TGPSolidBrush.Create(...);                        // :406
  PenRowDiv := TGPPen.Create(...);                               // :425 行循环内
  ```
- 问题：每次 Paint 创建/销毁 3 个 Font + 7 个 Brush + 3 个 StringFormat + 1 个 FontFamily（每帧 14 个对象），再叠加“列数×1 + 行数×1 + HeatBar 单元格×2”个循环内对象。滚动重绘是 60fps 热路径，此处堆分配/释放会成为瓶颈（大 GDI+ 每对象均封装原生句柄分配）。
- 触发条件：高帧率滚动/ Invalidate 频繁；列数 > 10 时每帧百级对象分配。
- 建议修复：颜色相同的 Pen/Brush 提升为字段级缓存（Tokens 变更时重建）；循环内只复用不创建。无泄漏（try-finally 完备），纯性能问题。

### G-05 🟡 HeaderHeight 属性直写不重绘 + published default 与构造初值不一致
- 位置：`DeepBase.VCL.HB.Grid.pas:88`、`:121-122`
- 代码：
  ```pascal
  property HeaderHeight: Integer read FHeaderHeight write FHeaderHeight default 38;  // :88 无 setter
  ...
  FRowHeight := 34;     // :121  但 :87 声明 default 36
  FHeaderHeight := 36;  // :122  但 :88 声明 default 38
  ```
- 问题：①运行时修改 HeaderHeight 不 Invalidate（RowHeight/RowCount 均有 setter，唯独 HeaderHeight 直写）；②default 声明值（36/38）与构造实际值（34/36）不一致——DFM 流式机制用 default 判断是否写入属性，两处口径不同会造成 IDE 存档/恢复后布局差异（IDE 认为初值是 36，实际代码是 34）。
- 建议修复：补 `SetHeaderHeight` setter（Invalidate）；default 与构造值统一。

### G-06 🟡 ScaleDIP 绑定主屏 DPI（多显示器混合 DPI 下错缩放）
- 位置：`DeepBase.VCL.HB.Grid.pas:108-111`（NavTree :99-102、PageControl :92-95 各有一份相同实现）
- 代码：
  ```pascal
  function ScaleDIP(APixels: Single): Single;
  begin
    Result := APixels * (Screen.PixelsPerInch / 96.0);
  end;
  ```
- 问题：`Screen.PixelsPerInch` 是主监视器 DPI。当控件落在副屏（如主屏 100%、副屏 150%）时字体按主屏缩放，导致字号与控件尺寸不匹配。THbTokens 自带 `ScaleForDPI(APPI)`（Core.pas:108）却未被使用。Delphi 13 正确做法是 `CurrentPPI`（TCustomControl 提供）或经 `ScaleForPPI`。
- 触发条件：Per-Monitor V2 清单 + 混合 DPI 多屏拖动。
- 建议修复：`Result := APixels * (CurrentPPI / 96.0)`，或统一消费 `THbTheme.Tokens.ScaleForDPI(CurrentPPI)`。

### G-07 🟡 布局尺寸裸像素硬编码（DPI 维度清单）
- 位置：`DeepBase.VCL.HB.Grid.pas:121-122`（RowHeight 34/HeaderHeight 36）、`:356`（CurX + 8.0 内边距）、`:404`（HeatBar 轨高 4.0、底距 8.0）、`:418`（CellRect +8/-16）
- 问题：字体走了 ScaleDIP，但行高、表头高、单元格左右 8px/16px 内边距、HeatBar 4px 高全部裸像素——150% DPI 下单元格文字已放大而行高/内边距不变，出现文字贴边/裁切。
- 建议修复：全部经 ScaleDIP；或改用 THbTokens 的 RowHeightScale/SpaceS~SpaceXL 令牌。

### G-08 🔵 HeatBar 数值未钳制 [0,100]
- 位置：`DeepBase.VCL.HB.Grid.pas:409-411`
- 代码：`FillW := (Single(Col.Width) - 16.0) * (CellFloat / 100.0);`
- 问题：CellFloat > 100 时填充条越过单元格（侵入相邻列）；< 0 时 FillW 为负（GDI+ 负宽 FillRectangle 会按 0 处理或画出镜像矩形，取决于实现）。
- 建议修复：`CellFloat := EnsureRange(CellFloat, 0, 100)`（System.Math 已在 uses 外——需补引用或手写 clamp）。

### G-09 🔵 键盘选择修饰键语义与鼠标不一致
- 位置：`DeepBase.VCL.HB.Grid.pas:271`（鼠标用 `ssCtrl in Shift`）、`:285/:291`（键盘用 `ssShift in Shift` 作为“累加选择”）
- 问题：Ctrl+↑ 在键盘上不会累加（语义应为范围扩展），Shift+点击在鼠标上会清空已有选择再选一行，行为割裂；且 SelectRow 无“锚点-范围”实现，Shift 语义实际是“Ctrl 语义”。
- 建议修复：统一修饰键映射；如需范围选择实现 AnchorRow。

### G-10 🔵 FSelection 与 FSelectedRows 双状态可能不同步
- 位置：`DeepBase.VCL.HB.Grid.pas:82`（`property Selection: ... write FSelection` 直写公开）、`:200-206`（ClearSelection 重置 FSelection 但 SelectRow 越界时只清 FSelectedRows 不重置 FSelection）
- 问题：外部直写 Selection 记录不影响 FSelectedRows；SelectRow(越界索引) 清空 FSelectedRows 后 FSelection 保留陈旧 -1 之外的旧值。
- 建议修复：Selection 收敛为方法（SetSelection），删除直写公开。

### G-11 🔵 ComputeSelectionStats 对 FSelectedRows 的全行列遍历含非数值列
- 位置：`DeepBase.VCL.HB.Grid.pas:220-254`
- 问题：选中 N 行 × 全列逐格回调（含文本列的 TryStrToFloat 尝试）；大数据集“全选后求和”是 O(N×列数) 的 UI 线程阻塞。且 `FillChar(Result, SizeOf(Result), 0)`（:214）目前安全（THbGridStats 全为数值字段，见 Grid.Types.pas:69-77），但类型一旦加 string 字段即变成野指针初始化——属于脆弱写法。
- 建议修复：改 `Result := Default(THbGridStats)`；统计仅遍历数值类型列。

### N-01 🔴 THbNavItemData.IconSvg 字段未初始化即拷贝（悬空 string 指针 → 堆损坏/AV 风险）

## 8. DeepBase.VCL.HB.VirtualList.pas（THbVirtualList）

### V-01 🔴 「O(1) 内存虚拟化」承诺不成立：全量 record 常驻内存
- 位置：`DeepBase.VCL.HB.VirtualList.pas:42`（`FItems: TList<THbVirtualListItem>;`）、`AddItem:274`（`FItems.Add(Item)`）
- 类型：THbVirtualListItem（VirtualList.Types.pas:33-47）含 8 个 string 字段 + TArray<string> Tags——每行全量数据常驻堆。

- 触发条件：AddItem 达 10 万量级即内存膨胀+加载缓慢。

### V-02 🔴 无滚动：FScrollOffset 死代码 + Paint 从第 0 行起画
- 位置：`DeepBase.VCL.HB.VirtualList.pas:106`（`FScrollOffset := 0` 全文件唯一赋值）、`:401`（`for I := 0 to FFilteredIndices.Count - 1` 不含滚动偏移）、`:403`（按 Height Break）
- 代码：
  ```pascal
  FScrollOffset := 0;                        // :106 声明后从未更新
  ...
  for I := 0 to FFilteredIndices.Count - 1 do // :401 恒从首行开始

- 问题：与 G-01 同病：无 WM_VSCROLL/MouseWheel/滚动条。10 万行只能看首屏 ~7 行（72px 行高）。FScrollOffset 是为滚动准备的字段但没有任何写入路径——证明滚动是“计划中未完成”。
- 建议修复：实现滚轮/滚动条驱动 FScrollOffset，绘制循环改为 `for I := (FScrollOffset div FRowHeight) to ...` 起点偏移。

### V-03 🔴 AddItem 每次触发全量重建过滤索引 → 批量加载 O(N²)
- 位置：`DeepBase.VCL.HB.VirtualList.pas:275`（AddItem → RebuildFilteredIndices）、`:172-186`（重建为 O(N) 且每次循环做 `LowerCase(Title+Summary+GroupTitle)` 三字符串拼接）

  ```
- 问题：加载 N 条 = N 次 × O(N) 重建（含 N 次三串拼接堆分配）+ N 次全量重绘 = O(N²) 时间与海量临时字符串。1 万条加载即秒级卡顿，10 万条不可用。
- 建议修复：批量加载 API（BeginUpdate/EndUpdate 或 `AddItems(const TArray<...>)`）合并一次重建 + 一次重绘；过滤目标串在 AddItem 时缓存。

## 专项结论

### ① 内存/句柄安全（GDI/GDI+ 泄漏 + 无 Parent 句柄触发）
- GDI+ 侧（Grid/NavTree/PageControl 三文件 Paint）：全部对象在多层 try-finally 中正确释放，包括异常路径（回调抛异常时外层 finally 链生效）——**未发现泄漏** ✔。Winapi.GDIPOBJ 单元 initialization 自动 GdiplusStartup ✔。
- GDI 侧（Gate/VirtualList/CommandPalette/Dock/ShareCard 用 TCanvas）：Brush/Pen 归 TCanvas 管理，无手动 SelectObject 泄漏 ✔。
- TBitmap：ShareCard RenderToBitmap 的 except-Free-raise（:209-212）与调用方 try-finally ✔。
- 无 Parent 句柄触发：9 文件中构造函数均未触碰 Handle/Canvas ✔；AI 的 HandleAllocated 守卫（:238/:247）是正确范式 ✔。唯一主动触碰句柄的是 Dock:228（AForm.Handle，见 D-01）。
- 真正的内存安全问题只有一处：N-01（NavTree IconSvg 未初始化拷贝）——这是本批唯一的“未定义行为”级缺陷。

### ② 虚拟化性能（10 万~100 万行）
- Grid：数据取值虚拟 ✔（回调式），绘制虚拟 ✔（Break 限可视区），但**无滚动**（G-01）使虚拟化无法兑现；热路径对象创建问题 G-04。
- VirtualList：**数据不虚拟**（V-01，O(N) 内存）、**无滚动**（V-02）、**O(N²) 加载**（V-03）——三重失败，与头注释 "O(1) memory ... 100,000+ items" 直接矛盾，是本批最严重的性能级缺陷群。
- CommandPalette/Gate：中等规模可用，但均有 O(N²) 批量注册路径（C-02/T-02）与每帧 O(N) 遍历（T-07）。

### ③ DPI 缩放
- 字体：Grid/NavTree/PageControl 用 ScaleDIP ✔（但绑定主屏 DPI，见 G-06）；Gate/VirtualList/CommandPalette 用 Canvas.Font.Size（point，不随 PPI）🟡。
- 布局/内边距/圆角：除 CommandPalette 外框用 Tokens.RadiusM 外，**所有控件的内边距、行高、圆角、热区均为 96DPI 裸像素**（G-07/N-05/P-08/T-05/V-08/A-05 各清单）。THbTokens.ScaleForDPI 与 RowHeightScale/Space 令牌全部闲置。
- 正确范式建议：统一 `ScaleDIP := px * CurrentPPI / 96`，控件尺寸类属性在 CM_CHILDDPICHANGED/WM_DPICHANGED 重算。

### ④ 门禁三重冗余
- THbGatePanel 行级「颜色+图标+文本」三重冗余**达标**（T 章节开头✔）；汇总按钮亦达标。
- 缺口：Notice 级无过滤入口（T-03）；VirtualList 批量条显隐逻辑正确（✔）但选区与过滤器不同步（V-04）、IsSelected 死字段（V-06）。

### ⑤ 设计令牌一致性
- 三份本地 `ColorToARGB`/`ScaleDIP` 重复实现（Grid:95-111 / NavTree:86-102 / PageControl:79-95）与 Theme.AlphaColorToColor 并存两套色彩转换——维护漂移高发区。
- 字体族令牌（Tokens.FontFamily）仅 GDI+ 三件套消费；Gate 硬编码 'Consolas'/'Segoe UI'（T-05）、ShareCard 硬编码 'Segoe UI'（:141/:148）。

### ⑥ 线程安全

## 总体结论

**不通过（Blocker 级）**。本批下半部控件存在四类结构性缺陷：① **NavTree 的 managed record 局部变量未初始化拷贝（N-01）是唯一可能当场损坏堆/崩溃的未定义行为级 bug，必须最先修复**；② **虚拟化承诺系统性落空**——Grid 与 VirtualList 均无滚动机制（死字段 FScrollTopRow/FScrollOffset 证明为未完成态），VirtualList 数据侧 O(N) 常驻内存 + O(N²) 批量加载，10 万~100 万行场景全不可用；③ **CommandPalette 点击命中与渲染行错位且左键即执行**（C-01），属高频入口的正确性事故；④ **多处“承诺-实现”落差**（AI 控件主体空壳、NavTree 搜索死属性、PageControl 两样式未实现、ShareCard 输出 BMP 冒充 PNG、MRU/拼音未实现）。正面项：GDI/GDI+ 资源释放纪律全批合格（零泄漏）、Gate 的三重冗余达标、Grid 的回调式取数与 AI 的 HandleAllocated 守卫是正确范式。建议按 N-01 → C-01 → 滚动机制（G-01/V-02）→ V-01/V-03 数据虚拟化重构 → DPI 统一（ScaleDIP×CurrentPPI）的顺序安排修复。
