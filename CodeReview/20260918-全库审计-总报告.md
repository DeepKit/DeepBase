## 二、跨模块系统性主题（按危害排序）

以下是重复出现在 ≥3 个模块的**结构性模式**，单点修复无法根治，需按主题立法解决。

### T1 · 安全门禁 fail-open（"校验存在但可绕过"）— 最高优先
签名/权限/只读校验失败仍放行，贯穿全库：
- `Core\DeepBase.Manifest.Verifier.pas:205-232` 签名校验失败仍可放行
- `Features\DeepBase.Updater/AutoUpdate` 验签链三缺陷：算法元数据远程可控 + 两路径输入不一致 + 缺字段=不校验 → 恶意更新包可当合法包安装（RCE 级）
- `Features\DeepBase.UIA.Engine.pas:449-452` `IsMappingIntegrityVerified` 恒 True，签名表从无 Add
- `Governance\ConfigRegistrar.pas` + `ReviewQueue.pas` + `ActionExecutor.pas` 治理门禁端到端可绕过，且篡改后**重新签名销毁痕迹**
- `Core\DeepBase.External.Types.pas` `IsWriteStatement` 黑名单可被 `WITH`/注释/多语句绕过，"外部库只读"契约失守
- `Features\DeepBase.Net` 安全门可被环境变量全局关闭（子进程继承）；SSRF 可被非规范 IP/DNS rebinding 绕过
- `Tools\UpdaterHelper` 不传 `--sha256` 即跳过包校验；SeedTool `EnableHMAC` 单开关整体关闭校验
- `Core\DeepBase.EHAI.Types.pas:306-315` `CreateExplicit` 造出无限额永不过期授权包络（治理门禁 fail-open）

**根因**：校验逻辑采用"缺省=通过"的黑名单式判断，且校验结果与执行路径之间无强制类型约束。建议立法：所有门禁函数返回强类型 `TGateVerdict`，调用侧只接受 `Approved` 构造分支；缺字段/异常/未知算法一律 fail-closed。

### T2 · 加密实现系统性偏离（Core-A）
- `Crypto.AES`：ECB/CFB/OFB/CTR 全部**静默降级为 CBC+PKCS7**；CBC 的 IV 不写头不返回、解密固定全零 → **已落盘密文永久不可解密**（不可逆数据损失）
- `Crypto.Hash.pas:474-532` `VerifyPassword` 从存储串读算法与迭代次数 → KDF 降级攻击面
- `Crypto.PBKDF2.pas:70-88` HMAC 补零与其他三套 PBKDF2 矛盾（必有一套错）
- `Security.pas:299-340` 主口令 = machine-id(0444)+$USER，无用户 secret → 同机低权限用户可离线解密全部 UBS2 密文
- `Services.Protection.pas` 同库第三套加密栈：无认证 AES-CBC（padding oracle）+ 单轮 SHA-256 派生，而库内已有 GCM 与 PBKDF2 未用

**根因**：无跨语言互操作向量测试（KAT），且加密栈存在三份平行实现。建议：单一 Crypto 门面（SSOT）+ NIST/RFC KAT 向量测试入 CI。

### T3 · 线程/生命周期 UAF 家族（贯穿 Core-B/C、Features、FMX、VCL、Persistence）
同一模式反复出现：匿名线程/后台 worker 未 WaitFor 即销毁宿主、`TThread.Queue`/闭包捕获裸 Self、锁/单例在 finalization 释放而 DCLP 无屏障：
- `Browser.CDP.pas:905-1011` WaitForSelector 匿名线程 UAF（历史 F2.B.1 至今未修）
- `Feedback.pas`、`MVVM.pas`、`Pool.pas:1066-1083`、`LLMChatFrame`（VCL+FMX 两处）、`AutoUpdater`、`Commander.pas:349-363`、`IntentClarification.LLMResilience.pas:328/:451`（`LCtx := nil` 与闭包按引用捕获语义相反）、`Resilience.Timeout`（超时路径释放被 worker 持有的锁）
- Reflection/External/AIErrorHandler 等 9 处"单例/锁 finalization 释放 + 退出期晚到异常"

**根因**：缺一条统一纪律。建议：宿主 Destroy 必须"先取消→再 WaitFor→后置 nil"三步模板化，并沉淀 `TManagedWorker` 一类基础组件供全库复用（当前 Scheduler/WorkerQueue 已有雏形但各单元未用）。

### T4 · 含 string/动态数组 record 的 `Move`/批量拷贝 → double-free
`CloudBackup/CloudSync`（历史 F1.9.1 未修）、`SenseVoice.pas:143`、`Compression/ObjectPool` 等。属同一课：托管类型 record 禁止非托管拷贝，应开编译器范围检查或封装拷贝例程。

### T5 · 构建归属漂移 —— "从未进编译器的代码"（结构性）
- 新插件体系 6 单元（`Core\DeepBase.Plugins.*`，2446 行）不在任何 .dpk/.dproj；内含 `PChar` 传 `GetProcAddress` 等**编译级错误**长期潜伏（Core-B B-X-02/B-CM-14）
- `Desktop.Screen.Click.{DPIMapper,RegionLocator,SmartExecutor}` 三件套含 interface 段写函数体等编译错误 + 危险占位（121 次点击扇出、恒 0.5 打分）（Features-A SCM-01/02/03）
- `Engine.WebView2.pas` 被 `{$IFDEF USE_WEBVIEW2}` + 未入 dproj 双重摘除，默认浏览器引擎实际缺席
- Governance/Tools 整体不在 CI profile 内；`DeepBase.Browser.WebElement` 等"传递编译=活代码"与孤儿代码需在构建归属上显式区分
- 旧轨 `PluginManager` 与新轨 `Plugins.Manager` **同名类并存的永久双轨**

**根因**：无"单元必须归属某构建包"的机器门禁。建议 CI 增加 dpk/dproj 与目录清单对账：孤儿单元要么入构建要么显式删除，禁止灰色地带。

### T6 · SSOT 违背与契约分裂
- `IBrowserSession` 同名不同 GUID 两处定义（历史 F2.C.1 仍在）；`CDP.Adapter.SendCommand` 与 `CDP.pas` 双实现
- 熔断器双轨：`Resilience.pas` facade 与子单元并存两套 Registry + 两个同名 `TCircuitBreaker` → 同名服务得到两个各自半失效的熔断器
- `Schema` vs `SchemaAdapter`、`Manager` vs `Manager.*` 边界漂移；`HB.Palettes` 与 `HB.Core` 暖金色值**已漂移**（双真源实证）
- schema 事实源分裂：`sql/tier0-2_init.sql` 全 DEPRECATED、迁移引擎未接生产、代码内 `EnsureSchema` 成第二真源，已致 3 处列名漂移（Persistence SCH-01~04）
- 货币换算（零/三小数位清单）在 `SDKGateway` 与 `PaymentBridge` 重复实现且都错

### T7 · 静默假成功 / 数据完整性谎言
- `LogAlert.pas:1131-1140` 缓冲区只 Add 无 Clear → 满 10000 后告警系统**静默永久失明**
- `CloudSync` 上传失败仍上报"同步成功"；`VerifyBackup` 恒返回失败且恢复从不调用它
- `Speech.ASR.SAPI` 流式空转以 `Success=True, Text=''` 回调；`Commerce.JsonUtil` 未知状态默认 `cosRefunded`；`ParseOrder/ParseEntitlement` 漏读字段致支付/权益守卫被绕过
- `LLM.pas:474/495` `SaveConfig` 恒把 Description 写空（每次保存静默清空既有数据）
- `Tools\CLI.SSH` 后端恒 mock 却伪造成功并用假内容**覆盖本地文件**
- `SchemaAdapter.Registry.pas:61-74` `for` 内误用 `Exit`（应为 `Continue`），一个占位前缀使全部适配器静默不注册

### T8 · 源码编码风险（构建级）
Features-C X-02（🔴）：10 个单元"无 BOM + 含中文字面量"，构建机 ACP=936（GBK）→ 编译即乱码无告警；`DeepBase.AntiTamper.pas:281` 字面量内已存在 3 处 U+FFFD，属**已提交的不可逆源码损坏**。建议：全库 .pas 统一 UTF-8 BOM + CI 增加编码校验。
