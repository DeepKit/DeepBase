## 四、主控裁定（3 条，随结论生效）

1. **A4-01 ② 修复路线：取强路线 (a) 析构登记自动解绑**（甲倾向文档化契约的弱路线）。
   理由：本缺陷形态与乙 B2-14（GCommandBindings 野指针）同源——登记式全局表无所有权管理；乙侧已确立 Ownership/FreeNotification 范式，Core 侧同语言修法可让两仓缺陷修法可对照、可回归。弱路线（仅文档化）把 UAF 留给调用方自觉，与 fail-closed 总原则相悖。修复单须覆盖：析构/Unbind 时登记表自清 + 剩余绑定判断（防误杀兄弟绑定，甲已复现的半条）。
2. **A4-R09 跨层归属：拆两段，甲先乙后**（本项横跨 Core 与 Features，两线文件不相交可并行，但 Feature 侧依赖 Core 侧新时间源符号）。
   - 甲段：`Core/DeepBase.License.pas` 时间源注入（可测试时钟）+ LastSeen 单调性/回拨拒绝，带 DUnitX 回归（假时钟回拨样本）。
   - 乙段：`Features/.../DeepBase.Licensing.pas`（或 TimeGuard 所在单元）接 Core 侧新时间源，消灭裸 `Now` 分叉；两段各自 H15 原子提交，乙段须等甲段符号落地后再开工。
3. **A4-06 修复范围裁定：只修对象号预留（ObjNum+1 不再是「下个对象」），不做字体/TextShow 算子整体返工**。
   甲复算表现根因是单号管理（预分配死循环 `CIDObj := NextObj` 从未使用），算式与 xref 写入逻辑本身无错；修复面锁定在单号分配表一处，附带 PDF 对象号唯一性回归（防其他 TextShow 路径再撞号）。**不采纳**「重写字体嵌入」的大修提案——超范围且无证据表明嵌入本身坏。
