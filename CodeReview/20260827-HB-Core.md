#### F-01 🔴 space 令牌组 JSON 键名与解析器键名完全不匹配，整组静默失效

- **位置**：`D:\_Progs\02Business\DeepBase\Core\DeepBase.HB.Core.pas:577-591`（解析器）与 `D:\_Progs\02Business\DeepBase\Core\DeepBase.HB.Palettes.pas:81-87`（JSON 定义）
- **解析器代码**（HB.Core 577-591 行节选）：
  ```pascal
  Val := AObj.Values['space'];
  if Val is TJSONObject then
  begin
    SubObj := TJSONObject(Val);
    if SubObj.Values['xs'] is TJSONNumber then
      ATokens.SpaceXS := TJSONNumber(SubObj.Values['xs']).AsDouble;
    if SubObj.Values['s'] is TJSONNumber then
      ATokens.SpaceS := TJSONNumber(SubObj.Values['s']).AsDouble;
    ...
  ```
- **JSON 定义**（HB.Palettes 81-87 行）：
  ```pascal
  '  "space": {' +
  '    "spaceXS": 4.0,' +
  '    "spaceS": 8.0,' +
  '    "spaceM": 14.0,' +
  '    "spaceL": 22.0,' +
  '    "spaceXL": 32.0' +
  ```
- **问题描述**：解析器查找键名 `xs / s / m / l / xl`，而所有主题 JSON 实际写入的键名是 `spaceXS / spaceS / spaceM / spaceL / spaceXL`。`SubObj.Values['xs']` 永远返回 nil，`is TJSONNumber` 永远为 False，5 个 spacing 令牌的 JSON 覆盖**全部静默失效**，任何主题的 space 自定义值永远不会生效，运行时永远使用 `DefaultWarmGold` 的默认值（4/8/14/22/32）。
- **触发条件**：任何调用 `THbTheme.RegisterThemeFromJson` 注册的主题 JSON（包括全部 10 套内置主题），其 space 组覆盖值全部被丢弃。当前 gold 主题默认值恰好相同掩盖了症状，但任何想通过 JSON 调 spacing 的主题（如未来 compact 变体）会 100% 失效且无任何报错/日志。
- **建议修复**：二选一并全局统一——(a) 解析器改为读 `spaceXS/spaceS/spaceM/spaceL/spaceXL`；(b) JSON 常量改为 `xs/s/m/l/xl`。推荐 (a)（JSON 键名更具自描述性，且 JSON 是对外契约格式）。同时建议在 `ParseTokensFromJson` 结束时对"存在于 JSON 但未被消费的键"输出诊断日志，防止同类静默失效再次发生。
