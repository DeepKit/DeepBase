## 五、发现：主工作树跑 T0 门禁必红（污染），须强制隔离树口径

**这是本单唯一的技术发现，且不是 A13 的缺陷。**

主控在主工作树原样复跑 T0 门 ⇒ **19/25 dpk `EXIT=1`**，全部同一错误：

```
Core\DeepBase.Security.DPAPI.pas(554) Error: E2251 Ambiguous overloaded call to 'SecureZeroMemory'
```

主因定位：`Core/DeepBase.SecureMemory.pas:19` 与 `:22` 自带两个重载

```pascal
procedure SecureZeroMemory(var Data: TBytes); overload;
procedure SecureZeroMemory(var Data: string); overload;
```

在主树陈旧 DCU 环境下与 `Winapi.Windows` 的 `SecureZeroMemory` 同时进入可见域 ⇒ 调用歧义。

证据链：

- 同一 commit `dfceab7` 下**主树红、隔离 `--detach` 树绿**，两侧 `Core/DeepBase.Security.DPAPI.pas` sha256 均为 `e745d90daa80c39a009f856d071570d486ec474ab55e0a9f1ec3b12353431d60`，源码零差异 ⇒ 判定差异来自环境而非源码。
- 主树存在 **45316 个 `.dcu` + 67 个 `.dcp`**（全部 gitignored）。
- `Core/DeepBase.Security.DPAPI.pas` 自 `9387222` 后未再改动，与本单无关。

**结论**：判据 4 的「隔离 `--detach` 树」口径是**必须而非可选**。在主工作树跑 T0 门禁的任何人都会得到假红。此事需单独立单处置（见 §七）。
