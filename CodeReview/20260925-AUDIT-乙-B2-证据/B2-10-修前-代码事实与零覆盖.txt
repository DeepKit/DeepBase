## 1. 两个请求构造函数都不接流式开关（写入口缺失）

```
:92   function TLLMHttpClient.BuildOpenAIRequest(const AModelId: string;
:93     const AMessages: TArray<TChatMessage>; AMaxTokens, ATemperature: Double): string;
:119  function TLLMHttpClient.BuildAnthropicRequest(const AModelId: string;
:120    const AMessages: TArray<TChatMessage>; AMaxTokens, ATemperature: Double): string;
```
两侧构造体内部都只写 model/max_tokens/(system)/messages，没有任何 `stream` 键 ——
即「流式与否」在这条链上根本没有参数入口，只能在调用处做手脚（见 §2）。

## 2. 单分支硬注入：解析→改对象→再序列化（点名缺陷）

修前 `SendStream` :604-623 原文：

```pascal
  // Build streaming request (add stream:true)
  if SameText(AApiFormat, 'anthropic') then
    Body := BuildAnthropicRequest(AModelId, AMessages, AMaxTokens, ATemperature)
  else
  begin
    // Inject stream:true into OpenAI request
    var MsgJson := BuildOpenAIRequest(AModelId, AMessages, AMaxTokens, ATemperature);
    var Obj := TJSONObject.ParseJSONValue(MsgJson) as TJSONObject;
    try
      if Obj <> nil then
      begin
        Obj.AddPair('stream', TJSONBool.Create(True));
        Body := Obj.ToJSON;
      end
      else
        Body := MsgJson;
    finally
      Obj.Free;
    end;
  end;
```

事实清点：
- 2.1 OpenAI 分支：构造完 JSON 再解析回来塞 `stream:true` 又序列化一遍（第二次序列化即
  请求体的第二个写入口，构造函数改动会被这里覆盖）。
- 2.2 Anthropic 分支（:605-606）：不注 `stream`，但同一函数随后按 SSE 解析增量
  （:645-680 / :707-746），并在 :638 用 `BuildHeaders(..., True)` 声明
  `Accept: text/event-stream`。三分支口径互斥：头说流式、体说非流式、解析按流式。
  ⇒ 工单点名的「强制注入」在 OpenAI 侧，镜像缺陷（该注入的没注入）在 Anthropic 侧。
- 2.3 `Send`（非流式，:415/:417）走同一对构造函数，因此今天的非流式体天然无 `stream` 键；
  但这条正确性完全依赖 §2.1 那段只在 `SendStream` 里的黑魔法，构造函数本身表达不了意图。

## 3. SSE 增量解析是两份重复代码，且只认 OpenAI 方言

把修前两处解析块（:660-679 流式回调 / :723-742 缓冲回退）去缩进后逐行 diff：

```
$ diff <(sed -n '660,679p' head.pas | 去缩进) <(sed -n '723,742p' head.pas | 去缩进)
1c1
< var Chunk := TJSONObject.ParseJSONValue(AChunk) as TJSONObject;
---
> var Chunk := TJSONObject.ParseJSONValue(Data) as TJSONObject;
```
⇒ 两块除入参名外完全相同（复制粘贴分叉），且两块都只读 `choices[0].delta.content`。
Anthropic 的增量事件是 `{"type":"content_block_delta","delta":{"text":"..."}}`，
不含 `choices` ⇒ 即使服务端真按流式返回，Anthropic 侧也一个 token 都收不到，
而 §4 的恒真返回值仍报成功。
