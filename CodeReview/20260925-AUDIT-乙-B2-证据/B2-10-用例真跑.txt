## 5. 负向样本（本轮实测踩到的两个真红，原样保留）

5.1 DUnitX 过滤器语法：`--run=` 不被接受（该 runner 用冒号），且短名 `--run:TTestLLMStreamSwitch`
命中 0 件 —— 探针的 `NO_TEST_EXECUTED` 守卫按 §〇-4 把这种「假绿」判成 RUN_EXIT=2：

```
$ ... --run=Test.DeepBase.LLM.HTTP.Stream
Unknown command line option : --run=Test.DeepBase.LLM.HTTP.Stream
RUN_EXIT=2
$ ... --run:TTestLLMStreamSwitch
Tests Found   : 0
RUNNER_STATS fixtureCount=0 testCount=0 pass=0 failure=0 error=0 ignored=0
RUNNER_VERDICT: NO_TEST_EXECUTED
RUN_EXIT=2
```

5.2 `TProc<T>` 形参不能写 `const`：本件测试最初把回调写成
`procedure(const AToken: string)`，dcc64 直接判引用类型不兼容（编译红，非用例红）：

```
Tests\Test.DeepBase.LLM.HTTP.Stream.pas(184) Error: E2010 Incompatible types: 'TProc<string>' and 'Procedure'
BUILD_EXIT=1  ⇒ 判据不成立
```
最小复现（同一编译器，三种写法各一行）：
```
$ dcc64 .tmp/b2/anon/B2AnonProbe3.dpr   ! M: TProc<string>; M := procedure(const S: string) ... ⇒ 行 12 E2010
$ dcc64 .tmp/b2/anon/B2AnonProbe4.dpr   ! 同件里 procedure(S: string) 形式 ⇒ 通过；带 const 形式 ⇒ E2010
```
⇒ 落笔为注释留在测试单元里（避免下一个人再踩），编译器事实本身留在本证据。
