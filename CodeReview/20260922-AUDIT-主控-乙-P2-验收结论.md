## 三、★ §3.3 打回：两个可复现洞（这是本单唯一不成立项）

### 洞 1 —— `check_eol.js` **零改动**，工单范围内的第二张门禁未收口

工单 §3.3 原文点名的是 **`check_pas_encoding.js` / `check_eol.js` 的 `arg(name, dflt)`**（两张门禁同源）。但 `075d541` 的 5 件交付物**只含编码门禁**，`check_eol.js` 本单**未触碰**。

主控实测（行尾门禁）：

| 输入 | 实测 EXIT | 输出 |
|---|---|---|
| `--rot .` | **0** | 行尾门禁通过：检查了 1451 个文件 |
| `stray` | **0** | 同上 |
| `--root`（缺值） | **0** | 同上 |

代码亦证：`check_eol.js` 内 `KNOWN_ARGS` / `parseFail` 命中数 = **0**（无任何参数校验），`arg()` 仍是原版静默回落。

### 洞 2 —— 编码门禁**大小写变体**仍静默回落默认根（且代码与自己注释相反）

编码门禁新增的校验用 `const key = raw.slice(2).toLowerCase()` 归一，**`--ROOT` 因此被判为「已知参数」而放行**；但取值用的 `arg()` 是**大小写敏感**的 `process.argv.indexOf('--root')` ⇒ **匹配不到 ⇒ 回落到默认仓库根**，并**用真实计数报「通过」**。

**决定性实证（主控自跑，指向一个不存在的目录）**：

```
编码门禁：--ROOT D:/definitely-not-here   ⇒ EXIT=0   编码门禁通过：975 个 .pas …
编码门禁：--Root D:/definitely-not-here   ⇒ EXIT=0   编码门禁通过：975 个 .pas …
编码门禁：--root D:/definitely-not-here   ⇒ EXIT=3   编码门禁无法读取目录: D:\definitely-not-here (ENOENT)
行尾门禁：--ROOT D:/definitely-not-here   ⇒ EXIT=0   行尾门禁通过：检查了 1451 个文件
行尾门禁：--root D:/definitely-not-here   ⇒ EXIT=3   行尾门禁无法读取目录: D:\definitely-not-here (ENOENT)
```

即：**大小写写错 ⇒ 门禁扫的是默认根，却报告「通过」，而操作者以为扫的是自己指定的根**。这正是 §3.3 要堵的「**绿单覆盖了实际未被扫描的目录**」，换了个形状存活下来。

**且代码与自己的注释方向相反**：`:34` 附近的注释写「④ 大小写不符（`--ROOT` 不在 `KNOWN_ARGS` 中**应报错**，而非被静默忽略）」，而同段实现把 key 小写归一后**接受**了它。注释描述的是**应有行为**，实现是**相反行为**。

### 回执不实（连带）

回执 §1.3 称「另收口 2 项：裸位置参数（`stray`）与**大小写不符（`--ROOT`）**。**共 6 类一律 `EXIT=3`**」。
主控实测：`stray` ✓ EXIT=3；**`--ROOT` ✗ EXIT=0**。§1.3 表格内 4 行（`--rot` / `--Root:x` / 缺值 / `--root=x --root`）实测均 EXIT=3 ✓ **属实**，但表格外的这一条**不实**，**且恰好就是残留洞本身**。

### 补做要求（不另开单，回本单 §3.3）

1. `check_eol.js` 与 `check_pas_encoding.js` **共用同一校验实现**（抽成单一函数，禁两份等价物）；
2. 大小写不符（`--ROOT` / `--Root=`）**一律 EXIT=3**，与注释一致——或（若选择「接受大小写别名」）则**取值侧必须同步归一**，二选一，**不得验证器接受、取值器又不认**；
3. **验收判据（决定性）**：`--ROOT <不存在目录>` ⇒ **EXIT=3**；`--ROOT .` 若被接受，则必须**真的按 `.` 扫描**（不得回落默认根）。两组输出须落盘留证；
4. 两门禁各补负样本（未知 / 缺值 / 裸位置 / 大小写 / 值形似参数 五类）。
