## 二、根因定性：极慢，非死锁

### 2.1 排除死锁 / 等待句柄

Gate5 主体（`Tests/Test.DeepBase.HB.Benchmark.pas:561-613`）**不含任何同步原语**：

- 无 `TCriticalSection` / `TMonitor` / `WaitForSingleObject` / `Event` / `TThread`；
- 无跨测试共享状态读写（`Samples`、`Form`、`Card`、`WF` 全部为局部变量，`finally` 中释放）；
- `Application.ProcessMessages` 仅在 Gate6 中出现，Gate5 未调用。

⇒ **无锁可死等**。死锁假设不成立。

### 2.2 排除测试污染

Gate5 仅依赖自身构造的 `TCustomForm` / `THbCard` / `THbFacetWaterfall`，三者 owner 均为该 Form，`finally Form.Free` 兜底释放。前序 Gate1–Gate4 各自独立建销 Form，无单例残留。⇒ 测试污染假设不成立。

### 2.3 根因：离屏坐标 + 全失效重绘的放大效应

Gate5 在源码第 585 行做了这一步：

```pascal
// Off-screen: isolate paint budget from DWM Present / remote-display pacing.
Form.SetBounds(-32000, -32000, Form.Width, Form.Height);
```

随后进入**两段重绘循环**：

| 段 | 位置 | 迭代数 | 每次迭代动作 |
| :--- | :--- | ---: | :--- |
| warm-up | L591-598 | 100 | `SetBounds`（尺寸在 500-700 × 400-550 间跳变）+ `Form.Update` |
| 测量 | L600-613 | 500 步 × **3 次** Update | 同上，另加 `TStopwatch` 采样 |

合计 **100 + 1500 = 1600 次** `SetBounds`+`Update`。而 `Form.Update` 语义为「处理完所有 Paint 消息队列后才返回」，即**同步全失效重绘**。

问题在于宿主控件是 `THbFacetWaterfall`（瀑布流）与 `THbCard`：

- `THbFacetWaterfall.Align := alClient`，随 Form 客户区**满幅**重排；
- warm-up 的尺寸序列 `W := 500 + (I mod 200)`、`H := 400 + ((I*3) mod 150)` **每个 I 都不同** ⇒ 每次 Update 都触发一次**全新布局 + 全新度量 + 全新绘制**，无缓存复用；
- 离屏 `-32000` 使 GDI/D2D 无法命中任何合成器快速路径，反而走软件回退路径。

在远程桌面 / 软件合成（本机为 Windows 11 IoT LTSC 虚显环境）下，单次全幅重绘从本地毫秒级劣化到**数十至数百毫秒级**。1600 次累加 ⇒ **数分钟量级**。这与 Gate1 需 25.6 s、Gate2 需 24.3 s（同属 GUI 度量，同样受虚显拖累）处于同一劣化量级，互相印证。

**⇒ 表现 = 单条测试运行时间从「约 1 分钟」膨胀到「远超人工观察窗」，日志停在 Gate5 BEGIN 后长时间无输出，被观察者判为「卡死」。实际是仍在跑，只是慢。**

