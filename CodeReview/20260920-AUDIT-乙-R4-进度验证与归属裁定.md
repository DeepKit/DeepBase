## 二、★ Schema.pas 成因：主控已锁定（L3 可关闭「机制排查」分支）

乙报告的 `i/-text w/-text` 异常，主控实测结论：

```
Core/DeepBase.Schema.pas
  blob 长度 = 51,626   NUL = 0   CRLF 行 = 970   LF-only 行 = 12   总行 = 982
  工作树长度 = 51,626   NUL = 0   同上           blob == 工作树 ? True（逐字节相同）
  行尾构成：961 行以 \r\r\r\r\n 结尾 + 9 行 \r\n + 12 行 \n
  git diff        = 970/970
  --ignore-cr-at-eol = 961/961（无法消除）
```

**成因 = 961 行的行尾是 4 个 CR（`^M^M^M^M`）。** 依据主控 `git diff | cat -A` 实测：每行显示为 `...^M^M^M^M$`。`.gitattributes` 的 `text` 属性只规范化单个 `\r\n`，剩余 3 个 CR 仍造成逐行差异 ⇒ `--ignore-cr-at-eol` 亦无法清零。

**全库扫描（主控，959 个 .pas 全量）**：多重 CR 行尾文件**仅此 1 件**，范围封闭。

**真实危害**：Delphi 编译器把每个 CR 都视为换行符 ⇒ **该文件 1 行源码占 4 个行号**，编译错误行号与静态分析行号全部错位；任何按行索引的工具（静态检查、门禁脚本、diff 归因）对该文件结论失真。

> **乙原报告「7 假设已排除」中，主控此前的假设全部正确被排除**（无 NUL、无异常控制字节、UTF-8 可解码、无子目录属性覆盖、index=HEAD）。**新结论不在原假设空间内** —— 是行尾层面而非编码层面的畸形。
