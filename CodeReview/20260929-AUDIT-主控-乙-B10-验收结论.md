## 二、主控裁定

### 1. 修法定性：本单是「写→线→读→判」四点闭合，不是顺手改宽

工单四条修法只规定读侧/现在侧。乙申报的写侧连带修改（`Service:391/394/402` + `CommerceNowISO` 改 `AUTCDate=True`）**主控裁为必要组成而非越界**：RTL 的 `DateToISO8601(V, False)` 语义是「数值原样 + 本地偏移后缀、不换算」，只改读侧会把自家写出的 UTC 裸值解析成早一个偏移量的瞬时，UTC+8 上等价于**所有期次提前 8 小时到期**——那是把「多放行 8h」翻转成「误拒 8h」，仍是正确性缺陷。写侧不闭环则读侧闭环无意义。该申报计入交付面，符合工单「枚举先行、判时点两侧统一」的本意。

### 2. 代码正确性（亲读 diff 结论）

三侧改动全部落在同一框架，无一处半改：

- **现在侧**：新接缝 `CommerceNowUtc`（`Types.pas:255`）= `TTimeZone.Local.ToUniversalTime(TDeepBaseTimeSource.Shared.Now)`。四类用点（SafeClient 快照到期、Permissions 宽限、Service 授权种子、Types 可用性+宽限）全改；且 `IsCommerceEntitlementUsable` 只取一次读数存局部 `NowUtc`——两次读数会让宽限判定与可用性判定落在不同瞬时（水位推进时结构不自洽），**这一点工单未要求，乙主动做对**。
- **解析侧**：5 个判时点全 `True`。
- **写侧**：`CommerceNowISO` 与三处授权链全 Zulu；口径 SSOT 收敛到 `Types.pas` interface 的 wire convention 注释，其余三处只指向不复述。
- **错误消息**：`License snapshot has expired` 等逐字未变（MY2/MY3 变异红的消息证实断言锁死了它）。

### 3. RTL 语义地基（主控独立推演 + 乙探针交叉印证）

`DateToISO8601` 两支**都不做数值换算**（True=原值加 `Z`，False=原值加本地偏移后缀）；`TryISO8601ToDate` 的 `True` 支返回**UTC 裸值**、`False` 支返回**本地裸值**。⇒ 修后三元组（写 Zulu / 读 UTC / 现在 UTC）自洽且与服务端线协议一致；旧三元组（写 `+08:00` 包 UTC 裸值 / 读本地裸值 / 现在 UTC 裸值）对**服务端 Zulu 输入**漏 8 小时、对**自家旧写出口**却恰好自洽。这正是缺陷长期只在服务端快照路径暴露的原因。乙 B10-1 探针（纯 RTL、与生产零耦合）与主控推演逐条相符，采信。

### 4. 乙 §五.1「自愈」表述订正（零信任双向，主控发现的表述不准）

乙称存量 `+08:00` 串「下一次校验/续期即由新写侧重写为 Zulu 自愈」。主控 rg 实测：`LastValidatedISO` 全生产**只有一个写点** `Service.pas:402`（授权/grant 时），**校验路径不重写它**。故自愈只发生在**续期/重新授权**，不是普通校验。这不改变裁定（见 §5.1），但使过渡代价的边界更清晰：存量 entitlement 的 `valid_until`/`last_validated` 会一直保持旧形态直到被重新授权，期间按提前 8 小时判定（fail-closed）。

### 5. 乙 §五 6 项登记逐条裁定

1. **存量 `+08:00` 串提前 8h 到期**：**维持不加兼容 shim**。方向 fail-closed（提前到期、绝不多放行），符合「不保留向后兼容」红线与 AGENTS.md 禁历史包袱；代价面为已付费用户最坏提前 8h 看到过期、续期即自愈（§4 已订正自愈条件）。批量回填属存储轨迁移，**本单不做、不派**，登记为已知过渡债。兼容性评估（AGENTS.md 要求）已由乙 §五.1 给出并经主控复核，闭环。
2. **对外契约未变**：`Types.pas` interface 原注释已声明 「All ISO timestamps are UTC」，旧实现名不副实，本单后名副其实 ⇒ 实现向契约收敛，契约未动。**成立**。
3. **`PaymentBridge:261` 跨域待核**：主控复核代码事实相符——`PaidAtISO` 在 Commerce 域内确不参与任何 §2.1 的 5 个解析点，只留痕/转发；其正确性确系于 `ThirdParty/Payment/DeepBase.Payment.PayPal.pas:574/810` 的 `PaidAt := Now`（本地裸值）。**裁定：不越界改，派生乙 B13 单派**（见 §三）。
4. **`Idempotency:119` TTL 墙钟 ⇒ B12**：**裁定归入乙 B12 作为第 2 项**。该点 `PurgeExpired` 两侧同为进程内裸墙钟读数（`CompletedAt` 由同文件 `:170` 写入），不属时区框架混用；真缺陷是「用墙钟测时长」，与 B12 同族同因同向。工单由主控同步扩为 2 项（见 §三）。
5. **UTC 机器 k=0 无鉴别力**：**成立且不可消**。主控自做的 MY1（摘 `ToUniversalTime`）也只在非零偏移机器上咬——这是该缺陷族的固有性质，非本单用例设计缺陷。**裁定：不给 CI 固定时区**（self-hosted runner 实测 UTC+8 有鉴别力；且时钟注入性变异在任何时区都咬，是最强的那道保险）。登记备查即可。
6. **测试件 2471 行 > 2000 行审查线**：**登记并派生甲 A12**（拆分单，按「Service 流程 / SafeClient 线协议 / Permissions 判定 / 时间框架」四职责）。本单「在已注册 fixture 内新增断言」是工单明文要求，不拆分正确；与甲 A9/A10 撞面故排队到甲线后位。
