## 四、根因更正（主控版）

**「全量套件裸跑卡死」= Σ(各 Gate 固有时长) × 并发争用系数，超出人工观察窗后被误判为挂死。**

- **固有时长（静默窗口实测）**：Gate1 8.6 + Gate2 4.2 + Gate3 0.4 + Gate4 0.5 + Gate5 82 + **Gate6 >300**（未跑完）≈ **> 6.5 分钟**；若含套件其余 fixture 更长。
- **并发争用**：本机同时存在多会话（乙 R7 测试、主控审计、其他 worktree）⇒ 每项再放大 **3–10×** ⇒ 全量裸跑进入**数十分钟**量级。
- **日志停在 Gate5 BEGIN 的真相**：杀进程时**恰好**处于 Gate5 阶段（其自身需 73–82 s，且是「打印前做 100 次暖机」的静默段）——**并非 Gate5 不可完成**。甲把「当时所处阶段」误当成了「瓶颈阶段」。
- **Gate5 的正确性质**：**阈值处噪声翻转**（本次 14.248 ms PASS vs 前次 19.808 ms FAIL，阈值 16.6 ms）⇒ 这是一个**真 flaky 的门禁**，属**真缺陷**级（不得用跳过处理）。
- **Gate6 的正确性质**：`C_GATE6_INSTANCES = 10000` × 2 轮 = **2 万次 `THbButton` 窗口创建/销毁**，是**固有的长跑压力测试**，属设计使然，但**必须与快速门禁分离**。

## 六、路径裁定 = **D（分离 + 串行独占）**；否决 A / B / C

| 路径 | 裁定 | 理由 |
| :--- | :---: | :--- |
| A｜接受现状，CI 长超时 | **部分采纳** | 方向对（该套件不该进快速门禁），但**单独的「长超时」不消除争用** ⇒ 并发下仍会假卡死 |
| B｜降采样（100→20 / 500×3→100×3） | **否决** | 掩盖问题 + 损统计置信度，且**完全不处理 Gate6** |
| C｜虚显豁免跳过 Gate5/Gate6 | **否决** | **门禁在隔离环境全部可跑**（Gate1 PASS 476ms、Gate2–4 PASS、Gate5 可跑完）⇒ **不存在「环境度量无效」**，跳过即「以跳过掩盖」，违反工单明令 |
| **D｜分离 + 串行独占**（**采纳**） | ✅ | 既不跳过、也不降低覆盖，直接消除「争用」这个真实变量 |

**路径 D 落地要求（转为甲 R7-P6 验收判据）**：

1. **分离**：把 `Test.DeepBase.HB.Benchmark` 整组从**快速门禁 / 全量裸跑**中移出，作为**独立、串行、独占**的长超时性能作业运行（推荐用 DUnitX 类别 `--include:<PerfCategory>` 机制；默认裸跑 `--exclude`）。**禁**与重负载会话并发（由主控在调度层给独占窗口）。
2. **Gate5 噪声修复**（真缺陷，须修）：20 ms 级波动跨 16.6 ms 阈值 ⇒ 复核统计口径（现为「每步 min-of-3 + 500 步取 Worst」）；须给出**可复现的稳定判定**（如提高采样/改中位数/或明确该门禁语义为「预算上限」而非「步步硬门槛」），并附**多次复跑的稳定性证据**。
3. **Gate6 保持全规模**，仅归入长跑作业；**禁**降规模（降规模会削弱其「GDI/堆泄漏检出」能力，属质量覆盖削减）。
4. **禁止**：env 豁免 / 静默跳过 / 降采样掩盖 / 以长超时掩盖 flaky。
5. 若确需改动 `Tests/DeepBaseTests.dpr`（H2 保护对象）⇒ **先报主控**再动。
