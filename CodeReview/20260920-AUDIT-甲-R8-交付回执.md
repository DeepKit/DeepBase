## 一、P1 POSIX 动态库加载缺口 —— 已交付

### 1.1 改法（与 §一 缺口 B 对应）

`Core/DeepBase.Crypto.OpenSSL.pas`：删除手写的

```pascal
{$IFDEF POSIX}
function dlopen(filename: MarshaledAString; flag: Integer): Pointer; cdecl;
  external 'libdl.dylib' name 'dlopen';   { + dlsym + dlclose }
{$ENDIF}
```

改为从 RTL 取符号：`uses` 增加 `Posix.Base, Posix.Dlfcn`，并把 `LoadLib`/`GetProc`/`FreeLib` 中的 `{$IFDEF MACOS}/{$IFDEF LINUX}` 双分支合并成 RTL 单一路径（`dlopen(PAnsiChar)` 与 `dlsym(Pointer,…)` 等按 RTL 签名统一为 `MarshaledAString` / `NativeUInt` 句柄形）。`dlclose(ALib)` 不再强转 `Pointer`。

原因（写进代码注释）：glibc ≥ 2.34 已把 `libdl` 折进 `libc`，macOS 也早已无 `libdl.dylib` 这个独立文件；手写 `external 'libdl.dylib'` 只能命中一个目标，必然让另一个目标失败。RTL 的 `Posix.Dlfcn` 由平台 SDK 决定实际链接对象，是唯一正确入口。

顺带在同一提交修掉 POSIX 侧的 `Core/DeepBase.Security.MasterKey.pas`：Windows-only 的 `IIf` 改为显式 `if/else` 赋 `OWNER_ONLY_DIR_MODE` / `OWNER_ONLY_FILE_MODE`，消除该单元在 POSIX 目标上的未声明标识符。

### 1.2 法源偏差申报（不自行缩减，此处书面说明）

| WO §二 P1 改法原文 | 实际落地 | 理由 |
| :--- | :--- | :--- |
| 「Linux 用 FPC RTL 的 **`Posix.Dl`（或 `dl` 单元）**提供 `dlopen`/`dlsym`/`RTLD_NOW`」 | 用 **`Posix.Dlfcn`**（+ `Posix.Base`） | Delphi（ dcc* 37.0）RTL 中**不存在** `Posix.Dl` 单元；POSIX 动态加载声明在 `Posix.Dlfcn`。这是法源单元名笔误，非缩减。 |
