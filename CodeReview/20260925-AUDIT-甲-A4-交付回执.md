### A4-01 DataBinding —— 部分成立

**线索核对（字面）**：工单称「控件解绑后仍持 DataSource 引用」。`rg -n DataSource Core\DeepBase.DataBinding.pas` → **exit=1（无匹配）**；`TBindingManager.Unbind`（定位 `:533`）逐条 `FBindings.Delete(i)` 并退订源通知，探针 S1：Bind=1 → Unbind=0 → 释放源+目标后重入 `UpdateAllTargets`/`NotifyTargetChanged` **无崩溃**。⇒ **「解绑后仍持引用」不成立（代码已无此概念）**。`git log -1 -- Core\DeepBase.DataBinding.pas` → `0c899b5 chore: align backlog after QA convergence`（2026-06-15）。

**成立部分（实测）**：

1. **Unbind 误杀同源兄弟绑定**（S2，唯一失败断言）：同源两条绑定，`Unbind(S,T1)` 后 `RemovePropertyChangedHandler` 退订的是**共享 handler**，存活绑定 T2 静默失效（`phase-B` 未传播，`BindingCount=1` 仍在）。
2. **未解绑即释放 = 真 UAF**（S3/S4）：`TBindingEntry` 持**裸 Source/Target 指针**（`FBindings: TList<TBindingEntry>`，定位 `:184`），无 FreeNotification/弱引用登记。S3：释放 target 后 decoy 复用同地址，源通知把 `WAF-SENTINEL` **写进了已释放对象**；S4：释放 source 后 decoy 复用同地址，`UpdateAllTargets` **读到 decoy 值**写入目标。

**最小修复设计**：

- ① `TBindingManager.Unbind`：删除条目前判断该 `Source` 是否仍有剩余绑定，**仅当无剩余时才 `RemovePropertyChangedHandler`**（改动 1 个函数，语义从「按对退订」改为「按源引用计数退订」）。
- ② UAF 窗口为结构性问题，两条路线供主控择一：**(a) 强路线** Bind 时对 Source/Target 建立析构登记（FreeNotification 风格），对象销毁自动 Unbind；**(b) 弱路线** 保留裸指针契约，新增 `FreeBindingOf(Obj)` 并在控件销毁路径调用 + 文档化「必须先 Unbind」。②涉及公共 API 语义，属主控裁定项，本单不预设立场。

**破坏面**：调用方 `Core\DeepBase.MVVM.pas`、`VCL\DeepBase.VCL.BindableControls.pas`、`VCL\DeepBase.VCL.MVVMControls.pas`、`Examples\DataBindingDemo`、`Examples\MVVMDemo`；测试 `Tests\Test.DeepBase.DataBinding.pas`、`Tests\Test.DeepBase.MVVM.pas`（**均无「同源多绑定 + Unbind」与「释放前未 Unbind」用例**）。

### A4-04 IoC 单例双路径 —— 成立

**实测**（`A404_IoC-run.log`）：
