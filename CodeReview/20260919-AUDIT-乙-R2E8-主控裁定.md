## 三、裁定与处置

### 裁定 1：驳回停等

### 裁定 2：renormalize 的解法不是「等甲」，而是「只碰干净文件」

`git add --renormalize` **可以且必须只作用于 `git status` 干净的文件**，从而零携带、零越权：

```
git status --porcelain | sed 's/^...//' | sort -u > /tmp/dirty.txt
git ls-files | grep -v -F -x -f /tmp/dirty.txt > /tmp/clean.txt
git add --renormalize --pathspec-from-file=/tmp/clean.txt
```

乙须自证：`git diff --cached --numstat --ignore-cr-at-eol` 全为 0（纯行尾、零内容变化）；`git show --name-only` 清单与「干净文件集」完全一致、**脏文件零命中**。

### 裁定 3：提交顺序

1. **Step 1（乙，先做）**：renormalize 专项提交 —— 仅干净文件，纯行尾，自证零内容 delta。
2. **Step 2（乙，紧接）**：E8 + 乙 R3 全部 26 项精确 pathspec 提交，其中 3 件 `i/crlf`/`i/mixed` 文件在 `git add` 时同批 `--renormalize`。
3. **Step 3（甲，并行）**：甲 R4 的 52 项同样适用 Step 2 纪律（甲文件若 `i/crlf` 亦须 renormalize）。

> Step 1 与 Step 3 无依赖关系，可并行；Step 2 必须在 Step 1 之后。

### 裁定 4：新增纪律 H14

**H14 · 行尾前置核验**：提交任何文件前必须执行 `git ls-files --eol <path>`；凡 `i/crlf` 或 `i/mixed`，`git add` 必须配 `--renormalize`；回执须**双数字申报**（`raw numstat` + `--ignore-cr-at-eol numstat`），并说明两者差额的成因。
