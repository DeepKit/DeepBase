# 编译门禁（build-gate）说明

门本体：`check_build.js`　负向样本：`test_negative_sample.js`（`node test_negative_sample.js`，EXIT=0 为通过）。

本文件只回答**什么时候跑、怎么跑、跑出来怎么看**。判定规则本体在代码里，此处不复述；
红/绿清单也不在这里维护（会腐），见下方 §六 的指针。

## 一、这道门管什么

`.dpr` 与 `.dpk` 的**编译可行性**。既有五道静态门禁（编码 / 行尾 / 证据编码 / 托管拷贝 / 构建归属）
只能保证编码与引用面，保证不了「dcc64 能不能过」——
`09_工程脚本/README-门禁覆盖面.md` §四-1 登记的正是这个缺口，本门入库后由本门闭合。

`.dpk` 面（WO-20260923-AUDIT-甲-D4 补齐）是本仓的**生产交付形态**：交付物是 BPL，
以前只能靠「编某个 `.dpr` 时顺带把包拖进来」间接覆盖，那条链路一断（改目录、删工程、
换引用方式）生产面就静默失去守护。现在包工程自己进判定面。

开单起因（S-3 事故）与根因双源见
`CodeReview/20260921-AUDIT-主控-乙-P0-HEAD编译断裂修复-请求审核报告.md`：
一笔提交让 HEAD 全库不可编译，而没有任何机械门在拦它，于是这个状态在仓库里躺了几天，
期间全量测试跑不起来、甲乙两条线全部卡死。

## 二、范围怎么声明（别让这道门变成「没人愿意跑所以被绕过」的门）

三种范围声明**互斥且必须给一种**，不给一律 EXIT=3：

| 调用 | 场景 | 量级 |
|---|---|---|
| `node 09_工程脚本/build-gate/check_build.js --dpk <path> [--dpr <path> ...]` | 日常快跑：改完一个工程立刻验 | 秒级到分钟级 |
| `node ... --manifest <file>` | 提交段按契约分层跑（见 §二·契约分层） | 清单里多少件跑多少件 |
| `node ... --all` | 验收段：是「HEAD 全库可编译」这句话的**唯一**证据来源，判定面是任何分层的超集 | 全库 92 件（67 `.dpr` + 25 `.dpk`） |

实测耗时（2026-09-23 甲 D4 重测 @ `ae1638d`，原始输出与口径见
`CodeReview/20260923-AUDIT-甲-D4-证据/D4-10-运行元数据与耗时口径.txt`；
**旧数字 1m37s/4m03s 作废——那轮只编 67 个 `.dpr`，不含包面**）：

- `--all`（92 件）**3 分 35 秒**；
- `--manifest contracts/T0-生产契约面.txt`（26 件）**2 分 27 秒**——包面占了大头，
  25 个包全在 T0 里，所以「阻断提交的那一道」比「全量那一道路」便宜不了多少，这是真实成本，别报乐观数字。

两个数字都是**并发负载下的上界**（同期乙线在跑同一道门，重叠时间窗已登记），单实例更快。

它仍是门禁族里最贵的一道，所以 `--all` 只该出现在提交段/验收段，不该出现在每次保存后。

### 契约分层：T0 / T1 / T2 由外部清单决定

| 层 | 含义 | 红的后果 | 清单 |
|---|---|---|---|
| T0 生产契约面 | 全部 `.dpk` + `Tests/DeepBaseTests.dpr` | **阻断提交** | `09_工程脚本/build-gate/contracts/T0-生产契约面.txt` |
| T1 观测面 | Examples / Templates / 独立小工具 | 记录，不阻断 | `contracts/T1-观测面.txt` |
| T2 待定面 | 引用了仓内不存在的单元、一时补不齐的工程 | 记录并登记待裁定 | `contracts/T2-待定面.txt` |

三条硬口径：

1. **清单是外部声明文件，门禁本体不写任何路径白名单**——分层挪动改清单，不改代码；
2. **清单只做加法**：T1 的行集是 `git ls-files '*.dpr'` 机械派生出来的差集（件数以清单文件为准，本处不复写），
   没有「排除某工程」的写法。新增 `.dpr` 必须显式归面；漏归的后果是它只出现在 `--all`，
   而不是被静默放行；
3. **层数由治理决定，范围内跳过任何人是门禁 bypass，禁止**——门禁本体不存在「按工程路径放行」的形态，
   判定路径上允许出现的唯一 `skip` 是共用的枚举面目录名集（见 §四 的 grep 口径）。

## 三、判定口径（写死，不接受现场协商）

**提交段的编译判定 = 隔离 `git worktree add --detach` 工作树 @ 目标 commit 的 EXIT。**
共享工作树的结果只用于「有没有动别人的东西」的现场观察，**不作判定**。
理由：共享树上别人未提交的改动会同时污染编译结果与 git 状态，绿单覆盖的不是目标 commit。

复现（本门已入库，可直接跑）：

```
git worktree add --detach .tmp/wt_build <目标commit>
cd .tmp/wt_build && node 09_工程脚本/build-gate/check_build.js --all > 证据.log 2>&1; echo EXIT=$?
cd ../.. && git worktree remove .tmp/wt_build
```

提交段跑 T0 同理，把 `--all` 换成 `--manifest "<工作树绝对路径>/09_工程脚本/build-gate/contracts/T0-生产契约面.txt"`。
清单本身在仓库里（是被审对象之一），但 `--manifest` 接受的是文件路径，所以跨工作树引用时给绝对路径。

## 四、退出码与可核数字

`0` 通过 / `1` 有工程编译失败（`.dpr` 与 `.dpk` 同权）/ `2` 枚举或输入面不可信 / `3` 参数不合法。

收尾三行统计带全部可核数字：

```
编译门禁统计：DPR总数=… 成功=… 失败=… 被跳过=… 失败子路径=…
编译门禁统计：DPK总数=… 成功=… 失败=… 被跳过=… 失败子路径=…
编译门禁统计：判定面=… 已跟踪=… 清单来源=… .res生成=… 编译器=… 陈旧DCU清理=…
```

**只看 EXIT 不算取证**：两面的 `被跳过` 恒应为 `0`——本门不提供任何「跳过并继续报绿」的形态，
这个数存在的意义就是让人一眼核对它等于 0。`DPK总数` 必须逐位等于 `git ls-files -- '*.dpk' | wc -l`。

三个 fail-closed 对两面各自成立（`.dpk` 不是二等公民）：枚举面 readdir 失败 ⇒ EXIT=2；
整面计数为 0 ⇒ EXIT=2（空扫描不是「全都通过」）；任一 `BUILD_EXIT≠0` ⇒ EXIT=1。
判定路径上不含豁免概念，可直接核对：

```
grep -inE 'skip|exempt|whitelist|baseline' 09_工程脚本/build-gate/check_build.js | grep -v 被跳过
```

命中**只允许**是一处：与其余四道门共用的枚举面目录名集 `gateSkipSet('Logs')`
（require 行 + 一行注释 + 常量定义，实测 3 行，逐行见
`CodeReview/20260923-AUDIT-甲-D4-证据/D4-04-判据4-判定路径grep.txt`）。
它是「哪些目录不是工程真相源」的目录名屏蔽，不是「范围内放行某个工程」——后者在代码里不存在，
反证有两条：统计行的 `被跳过` 恒为 `0`，且判定路径上没有任何按工程路径提前放行的分支。

## 五、环境真相源与四个环境坑

- **真相源是每个工程自己的 `.dproj`**（`DCC_UnitSearchPath` / `DCC_Namespace`，全部配置取并集，
  避免「门禁恰好挑了个没配路径的配置」造成假红）。无 `.dproj` 的工程退回 `contracts/命名空间声明.txt`
  声明的缺省命名空间集（`default=` 行），单工程要补就在同一文件里加一行 `<工程相对路径>=<命名空间>`。
  缺省值写在门禁代码里会同时造成两个问题：成为第二套真相源，以及「清单少一项」伪装成源码的 F2613 假红。
  合并语义与 fail-closed 口径见 `check_build.js` 的 `readNamespaceContract` / `projectEnv`，此处不复述。
- **包产物重定向**：`.dpk` 的 `-LN`（.dcp）/ `-LE`（.bpl）/ `-O`（搜索面）全部落到
  `.tmp/build-gate/{dcp,bpl}`，且**每次运行先清空**。留着旧 `.dcp` 的话，dcc64 会拿陈旧接口文件
  编下一个包，把真断裂编成假绿——这是包面最容易踩的坑，重定向 + 每轮抹平是判定成立的前提。
  包与包之间的编译顺序由各 `.dpk` 自己的 `requires` 拓扑决定（成环 ⇒ EXIT=2），不是排出来的。
- **`.res`**：`{$R *.res}` 引用的文件是 IDE 生成物且被 `.gitignore` 排除，干净检出里必然不存在；
  门禁按 IDE 行为补一个空资源件（同样落在 `.gitignore` 内，不脏工作树），否则会把好工程报成 E1026 假红。
  `*` 展开成 `package` 语句声明的包名（不是文件名，二者可能不同）。
  复用过的工作树里可能残留上一轮生成的 `.res`，此时 `.res生成=0` 属正常。
- **BUG-285**：dcc64 即使指定 `-N0`，仍可能把早期依赖的 `.dcu` 落进源目录；
  跑完只清**本次新产生**的那些，已存在的（含被跟踪的）一律不动。
- **枚举面目录名集**：`gateSkipSet('Logs')`——与其余四道门同一真相源（`09_工程脚本/gate-skip.js`），
  本门只多一个编译器日志目录 `Logs`；该门不再持有内联副本
  （`09_工程脚本/README-门禁覆盖面.md` §四-5 登记的甲线残留由此清零）。
